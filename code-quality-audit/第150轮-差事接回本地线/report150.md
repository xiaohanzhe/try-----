## 2. 取舍：为什么**不重写**（本轮唯一的决策点）

用户把这条线的技术路线裁定权交给了我（原话「那个线这类的我也不懂，你决定就好」）。
判据是**一条实测**，不是偏好：

```
git apply --3way --check   # 只取产品部分
  ralsei_pet/modules/dialogue_ui.py   → clean
  ralsei_pet/modules/npc_system.py    → clean
  ralsei_pet/src/main.py              → clean
```

三处**全 clean** ⇒ 上游那两笔（`ac3b9e31` 第113轮 / `844bda0a` 第114轮）的**产品部分**
可以原样落到本地线，不需要 `cherry-pick` 整个提交链（那两个提交里还夹着当时的审计目录）。

**为什么不重写**：重写 1200 行只会得到一份**不同源的第二真源** —— 以后改门控、改生命周期，
两边的行为会慢慢分叉，而分叉出来的差异**没有判据能看出来**（本项目最贵的那类坑）。

**但审计套件是重写的**（不进产品 diff）：
`check150` / `mutate150` / `recheck150_core` / 本报告都是本轮新写，
沿用「审计目录与产品解耦」的既有惯例（`git diff ac3b9e31^ 844bda0a -- ralsei_pet` 只取产品）。

## 3. 产品改动：四处，各管什么

| 文件 | 量 | 作用 |
|---|---|---|
| `modules/npc_errand.py` | 新建 400 行 | **机制层**（零依赖）：`Errand` / `ErrandBoard` / `WIRING`。三段单向生命周期 `traveling → working → done`；`result` 在 `done` 那刻**定格**（要可持久化、不依赖过程）；**`npc_id` 零白名单**（用户口径「任何人都可以」） |
| `modules/npc_system.py` | +77/−3 | **章名归一**：`CHAPTER_ALIASES` / `chapter_names` / `same_chapter` / `chapter_matches`。场景侧写 `ut`/`uty`、角色侧写 `undertale`/`undertale_yellow` ⇒ 逐字比**永远不命中**，会把 **29 位** UT/UTY 角色关在自己家门外 |
| `modules/dialogue_ui.py` | +14/−0 | 对话层**派活入口**：`send_message` 里排在「点名之后、闲聊指令之前」查 `handle_errand_command`（返回 `False` ⇒ 一切照旧，零行为变化） |
| `src/main.py` | +705/−0 | **宿主侧**：`assign_errand`（唯一派发入口）/ `_npc_errand_gate`（门控）/ `_npc_errand_tick`（每拍推进）/ `_npc_errand_commit`（结果进记忆）/ `_npc_errand_load` / `_npc_errand_save`（独立一本档）/ `handle_errand_command` + `_errand_parse_intent`（识别） |

三条**设计约束**（都写进了代码注释，也在判据里钉住）：

1. **顺序即优先级**：`_npc_errand_tick` 排在 `_npc_roam_tick` **之后**。
   反过来的话，"派他出门"会在同一拍被 `npc_roam` 摇走 —— 30s 拍上偶发，最难查。
2. **门控只有一份**：`_npc_errand_gate` 只负责喂 `npc_system.world_gate` 三样东西
   （谁 / 目的地属于哪个世界 / 在不在球里），**不另写一张"理由码→人话"映射表** ——
   `world_gate` 每个拒绝分支本来就产出中文人话。调用点**精确三处**：派发当场、
   每拍压位置之前、对话层问路。
3. **与显示彻底解耦**：`npc_errand.py` 里 `switch` / `travel_to` **0 处**（AST 判据）。
   他 `working` 期间位置真源就是 `dest_scene` ⇒ 我中途切进那个场景，
   `_npc_seed_bodies()` 自然把他画在那里 —— "过程可见"不需要额外机制。

## 6. 遗留 / 结转

1. **纯空格 `npc_id` 不拒**（`assign` 只判"非空串"）。够不着（唯一入口先过门控），
   **本轮不修**：改它会动 `ErrandBoard` 的既有契约，收益为零。
2. **`E1` 是结构性盲区**：它断"这一拍什么都没发生"（`puts == []`），
   而"整个功能关掉"也满足它 ⇒ 单靠 `E1` 就是恒真。旁边必须有 `E2` 这个正控制
   （`mutate150 M12` 实证：总开关关掉时 `E1` 照样绿、`E2`~`E8` 全红）。
3. **差事没有"用户取消"入口**：`board.abort()` 目前只被门控调用。
   用户想叫停一次派出，接口在位、没有 UI/指令接线。
4. `_errand_parse_intent` 的**地点别名表**只有作品级前缀（`oneshot`/`ut`/`outertale`/
   `ch1`/`desktop`）。具体房间由 `_index.json` 决定，两处都写就是"同一件事两个真相" ——
   所以「去苏西家的客厅」这类**暂时不支持**，是有意的收窄。
5. 第149轮结转未动：`_item_enter_scene` 无内部调用者；`current_scene` 双语义；
   第142轮"没①≠没违规"8 人是否单独占槽；`queen` 人设内部矛盾；`max_sentences` 仍"读了不用"；
   `check144 B1` 只认 `open(...)` 形态写盘。
