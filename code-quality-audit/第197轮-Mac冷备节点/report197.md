# 第197轮 · Mac 异地冷备节点

> 一句话：把用户新接进来的 Mac 变成**每天自动跑一次的异地冷备 + 独立校验节点**，
> 并顺手证伪了一条待办（61 个别作品角色的表情动画）。

产物：

| 文件 | 作用 |
|---|---|
| `_tools/mac_backup.py` | 打包 → 上传 → 双端校验 → 解包 → 回验 → 轮转（一脚本跑完） |
| 自动化「Mac 每日冷备（ralsei_pet）」 | 每天 23:00 跑一次，结论追加进当日日志 |

---

## 1. 为什么是「冷备 + 校验」，不是「算力」

用户原话：「我用数据线连接上了一个苹果电脑，你可以给他发跑Ai训练的任务」。

**前提先证伪**：数据线直连两台电脑什么都不会发生。Windows 侧实测
`VID_05AC`（Apple）零命中、无新增网络适配器、无新磁盘，只有一条
`未知 USB 设备(设备描述符请求失败) USB\VID_0000&PID_0002`。
Mac 开机时 USB-C 口对外只供电/出 DP，不当从设备；Apple 芯片机也没有 Target Disk Mode。

**这台机器也不能训练**（详见详版 §205.3）：

| 项 | 值 |
|---|---|
| 机型 | MacBookPro15,4（2020 13"）/ macOS 15.6.1 |
| CPU | Intel i5-8257U，4C8T @1.4GHz |
| GPU | Intel Iris Plus 645（核显，VRAM 动态 1536MB） |
| 内存 | 8 GB |

macOS 的训练加速只有 Apple Silicon 的 MPS 后端，**Intel Mac 上
`torch.backends.mps.is_available()` 恒 False**；8 代 i5 + 8 GB 连 1B 微调都无意义。
7B Q4 权重 4.5 GB ⇒ 触发压缩内存，纯 CPU 比本机更慢。

⇒ 定位改为：**冷备节点 + 独立校验点**（唯一真优势还有完整 Xcode，将来桌宠跨 macOS 用得上）。

## 2. 备什么、不备什么

刻意**不备**：

| 排除项 | 体积 | 理由 |
|---|---|---|
| `.git` | 965 MB | 远端 GitHub 已是异地副本，再备一遍没有增量价值 |
| `diag_frames` / `diag_frames2` | 216 MB | 诊断截图，随时可重生成 |
| 历史轮次的 `_evidence` 截图 | ~500 MB | 同上 |
| `__pycache__` / `*.pyc` | 小 | 产物非源 |

备的是"丢了就重建不出来"的：`ralsei_pet/`、`.workbuddy/memory/`、
`code-quality-audit/regress/`、以及**最近两轮**的审计目录（`--rounds 2`）。

★ 只备最近两轮，意味着每个轮次是"路过时被备一次"。轮次推进后旧轮次就不再进包，
但它在自己还是"最新两轮"时已经被备过了。每日跑 ⇒ 全覆盖。

## 3. 校验设计：为什么比 hash 多重集，而不是比路径

远端解包后让 **Mac 自己算一遍 `shasum -a 256`**，把清单取回来比。

- **主判据 = hash 多重集相等**：与文件名编码无关。macOS 的 HFS+/APFS 会把文件名
  做 NFD 归一化，中文目录名（`第196轮-NPC表情动画`）逐字符比路径可能假红，
  但**内容是否无损**跟文件名编码无关。
- **次判据 = 路径集合差异**：只报不判。

实测：**3411 / 3411，差异 0**，路径集合差异也是 0。

> 单机上算 hash 证明不了副本可用 —— 必须另一台机器重新读出来算一遍，
> 且那份清单是**它自己生成的**，不是我传给它的。

## 4. 本轮抓到的三个真 bug（都是"看起来对、其实会坏"）

### (a) 中文数字目录按字典序排 ⇒ 把陈旧轮次当最新

`pick_round_dirs()` 原本 `names.sort()`。结果：`第98轮` > `第196轮`（字符串比较逐字符），
于是"最近两轮"取到的是**第98/99轮**，而真正最新的第196/197轮被漏掉。

修法：正则 `^第(\d+)轮` 提数字，**按整数排序**。

### (b) 解包是覆盖式合并 ⇒ 上一份的残留文件混进清单

第一次跑报「远端 3559、本地 3523、差异 36」。36 正好是第196轮目录的文件数 ——
上一份备份残留的文件不在新包里，却还在目录里，被 `find` 数进去了。

修法：解包**前先 `rm -rf` 目标日期目录**。tar 从不删文件，只覆盖同名。

### (c) `sed "s#/$##"` 里的 `$#` 是 shell 特殊变量

被展开成参数个数 `0` ⇒ `sed: 1: "s#/0#": unterminated substitute`。
轮转静默失败（但脚本仍报 OK —— 这是最坏的情况：**看着成功**）。

修法：改用 `ls -1d 20*`（`-d` 不带尾斜杠），彻底不用 sed。

### 轮转不是空转（真删了一次）

用假目录验证，而不是"看着像对"：

```
before: 2026-01-01  2026-01-02  2026-11-18
-- real run (keep=2) --
after:  2026-01-02  2026-11-18      today intact: YES
```

⇒ 操作真的能成功，判据才有意义（否则"删守卫也绿"）。

## 5. 顺手证伪：61 个别作品角色的表情动画**口径不成立**

原打算把这件待办派给 Mac，先查素材形态：

| 目录 | PNG | 含 `walk` | 情绪 + walk **同时**命中 |
|---|---|---|---|
| `UT素材` | 5,818 | 27 | **0** |
| `UT原版Overworld分图` | 1,221 | 0 | **0**（全是"新家1/核心/瀑布"房间整图） |
| `xnbcli（oneshot)` | 1,750 | 5 | **0**（`calamus_smile.png` 这种单张立绘） |

UT / Oneshot **根本没有"四向行走变体"这套形态** —— 不是"没做"，是原作不是那样
（UT 完整 sprites 在 `data.win` 里，得先解包）。

⇒ `pick196` 那套口径**不能照搬**。要做只能是"单张表情 + 演出编排"，
而拿单张图缩放脉冲冒充动作＝**造假**，不做。

**方法论**：先问"素材是什么形态"，再问"能不能动画"。形态不对，工程量无从谈起。

## 6. 备份的最高标准是**能跑**

不只是 hash 对。在副本上实测：

| 检查 | 结果 |
|---|---|
| 6 个核心模块 `import` | 全 OK（`data_store` / `npc_body_render` / `dialogue_ui` / `event_speech` / `people_memory` / `npc_roam`） |
| 79 个模块 `ast.parse` | **语法零错**（⇒ 项目没用 3.10+ 语法，Python 3.9 也能解析） |
| 本轮 159 张表情帧 | **sha256 + 尺寸 + 解码全对** |
| PyQt5 | 装得上：`5.15.11 / Qt 5.15.14` |

Mac 侧环境：`~/ralsei-venv`（Python 3.9.6 + Pillow 10.4.0 + PyQt5 5.15.11）。
占用：`RalseiBackup` 158 MB + `venv` 154 MB = 68 GB 里的 312 MB。

## 7. 用法

```bat
C:\Python311\python.exe "code-quality-audit\第197轮-Mac冷备节点\_tools\mac_backup.py"
:: --keep 7        远端保留最近 7 份
:: --rounds 2      附带最近 2 轮审计目录
:: --no-extract     不删远端旧份
:: --json path      结果落 json（自动化用）
```

退出码：`0` 成功 / `2` 缺密钥 / `3~9` 各步失败 / `10` **副本不一致**。
成功标志是输出里出现 `=== BACKUP_OK` **且** `差异=0`。

## 8. 遗留

| 项 | 说明 |
|---|---|
| 地址是局域网 | `192.168.1.30`，换网/断 Wi-Fi 即失效。长期用要上 Tailscale |
| Mac 不在线时 | 自动化会 FAIL（属预期），只记一行日志，不重试 |
| 只备最近两轮审计 | 若某轮期间没跑成，那轮就漏了；可临时 `--rounds N` 补 |
| 未接 CI | 没进 `run_all.py`；它是运维脚本不是回归套件 |
