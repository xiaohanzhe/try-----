# 第194轮报告：内在活动「只存关键词」

日期：2026-11-17 22:15–23:35

## 0. 一句话结论

内在活动（`（盘算了一下）`）**不再落原句**，只记四要素：时间（`day`/`tod`）、
地点（`meta.where`）、人物（`meta.who`）、干啥（`text`）。台词照旧入库。
召回靠**地点**做锚点（没人会在聊天时说出"盘算"）。渲染**不说"说过"**。

`check194` 28 条判据全绿；全量回归 **191/191 IDENTICAL、PASS=8432、FAIL=0**。

收口时炸出**两条我自己的判据不保真**（一条要看机器负载、一条钉住了墙钟），
都已修正并把教训写进判据注释与 §202.4。

## 1. 用户口径（原话，逐字）

- 「心里想的东西存在记忆力，后期问起来能说出来就足够了」
- 「**只需要关键词**」
- 「**时间，地点，人物，干啥**」
- 「这些记忆可以有一定偏差，但不能太离谱，就像真人一样」

⇒ 落成：**四要素 + 允许偏差但不离谱**。偏差体现在"记的是动词+地点，忘了原句怎么说的"，
但地点/人物/时间必须真，不能胡编。

## 2. 实现

| 文件 | 改动 | 净行数 |
|---|---|---|
| `ralsei_pet/modules/event_speech.py` | `_INNER_VERB_ORDER` / `inner_verb(act)` / `iter_inner_acts(text)` | **+43 / -0** |

| `ralsei_pet/modules/dialogue_ui.py` | `_drop_paren_span()` / `_current_place_label()` / 重写 `_note_memory()` | +70 / -2 |

### 2.1 为什么是两个出口而不是一个

`event_speech` 里已有 `is_inner_act()`，但调用方还需要"**是哪个动词**"（要存 `text`）。
若让 `dialogue_ui` 自己拿 `_INNER_ACT_VERBS` 再切一遍，动词表就有第二份真相源。
⇒ 在同一个模块加 `inner_verb()`（长词优先，`想了想` 不被截成 `想`）与
`iter_inner_acts()`（按括号逐个吐），动词表**只有一份**。`A7` 钉住两者同源。

### 2.2 为什么地点必须并进匹配面

`recall()` 的 keys 只按 `text` 做子串匹配，而 `_probe` 是**对话里出现过的词**。
没有人会在聊天时说出"盘算"两个字 ⇒ 只存动词的条目**永远召不回来**。
`C3` 是这条的负控制：另造一条 `where` 为空的内在活动，`recall('教室')` 不许命中它。

### 2.3 为什么不能用 `strip_action_parentheticals`

那是**显示层**护栏，它会删掉**所有**括号旁白 —— 包括 §201.4 明确要求"该说出口"的
外在表现（`（推开门）`）。拿它拆记忆 = 把动作也吞了。`E3` 用 AST 钉住
`_note_memory` 里**不许出现**这个名字。

### 2.4 不落原句

`text` 只放动词本身（`盘算`），台词（`要不要开口`）走 `add_fragment` 照旧入库。
`B3` 钉住"fragments 条数不变"。

## 3. ★★★ 收口时炸出来的两条判据不保真

### 3.1 第一条：判据共享可变夹具 ⇒ 绿不绿看机器负载

**现象**：`check194` 单跑 28/28；全量跑 25/28（`C1 hits=0`、`D1/D2` 渲染为空）。**同一份代码。**

**诊断**（临时插 `@@DIAG` 打印后跑全量）：

```
@@DIAG cue_kw=['教室']           ← 抽词正常，不是分词问题
@@DIAG keys=81 inner=80 教室=0   ← 「教室」那条根本不在库里
@@DIAG recall 全部=[]            ← 所以召回必然为空
```

**根因**：B6 灌了 85 条 `note_inner` 把库冲爆；`_trim_inner()` 按 `(last_at, count)`
**升序**删最老的，而「教室」是**最先写入**的那一条。

- 机器快：85 条挤进同一个 `time.time()` 刻度 ⇒ `last_at` 全等 ⇒ 排序退化到按 `count`
  ⇒ `count=2` 让它排最后、**侥幸活着**；
- 机器慢（刚跑完 190 个套件，而且每条 `note_inner` 都要 `autosave()` 写盘）：
  `last_at` 被拉开成严格递增 ⇒ 真 LRU ⇒ 排第一**被裁掉**。

**裁决**：**产品侧没错**（删"最久没想起的"本来就该删它）。错的是夹具 ——
`C1/D1/D2` 复用了被 `B6` 冲爆的那个 `ms`。

**修法**：
- `C1/C2/D1/D2` 各起一个干净库 `_ms_c`（`keys=[]` 后只写一条），与限额测试解耦；
- `B6` **明确不钉**"教室还活着"（钉了就等于把判据绑在机器快慢上），注释写明理由。

### 3.2 第二条：回显墙钟值 ⇒ 基线被钉在"跑的那一刻"

- `B2` 原来回显 `day='2026-11-17' tod='晚上'`；
- `D3` 原来回显 `'刚刚的**晚上**，你说过「…」'`。

实测：22:55 跑是"晚上"，23:0x 跑变成"深夜" ⇒ **同一天换个时段跑就 DIFF**。

修法：回显只给布尔 —— `有day=True 有tod=True` / `含说过=True`。

★ 与 §171「禁写死随轮次增长的绝对数」同族：
**凡是随环境/时间变的量，只许断言它的性质，不许回显它的取值。**

## 4. 4 个老套件的 DIFF 如何归因（§168.4 铁序）

`check188/189/190/192` 出现 DIFF。全部是**行号回显位移**，来源可精确对上：

| 文件 | 真实改动 | 影响区间 |
|---|---|---|
| `event_speech.py` | `@@ -846,0 +847,43 @@` 纯插入 | 846 行后全部 +43（`1044→1087`） |
| `dialogue_ui.py` | 净 +68；`@@ -101,0 +114,17 @@` 等 4 处共 +29，`@@ -1714,0 +1744,9 @@` 之后再加 39 | ≤1714 ⇒ +29；>1714 ⇒ +68 |

按铁序**先机器核对、再 `--update`**，绝不反过来。工具：

`code-quality-audit/第194轮-内在活动关键词/_tools/normdiff194.py`

- 丢掉 `---`/`+++`/`@@` 头 → 取 `-`/`+` 行 → 长 hex（≥8 位 `[0-9a-f]`）→ `<HEX>`、
  数字 → `<N>` → **逐对比较**；
- 两侧行数不等 ⇒ FAIL；**解析出 0 行也 FAIL（分母闸）**。

**负控制三项**（`_evidence/normdiff_neg194/`）：

| 输入 | 期望 | 实测 |
|---|---|---|
| 内容真变（`[PASS]`→`[FAIL]`） | 红 | 红 ✔ |
| 行数不等（多了 1 行） | 红 | 红 ✔ |
| 只有上下文行（0 对） | 红 | **第一版绿（假）** ⇒ 补分母闸后红 ✔ |

★ 第三条正是「扫描器恒空＝恒真的反面」（§168 同款坑）：`0/0` 被判成 `[OK]`。

**实测**：15 对差异、**意外 0 行** ⇒ 才执行 `--update`（合并模式）。
