## 二、为什么是"机制层"而不是"再写一遍 NPC 移动"

`npc_roam`（第79轮）已经能表达**"他自己想去哪"**（`npc_intent.decide()` 的 6 种自发动作）。
但 §109.5 要的是**"我派他去哪、办什么、办完有结果"** —— 这是**被派**，不是**自发**。

三层分工（本轮只加中间那层）：

```
npc_intent   自发：他今天想干什么（wander / visit_friend / …）
npc_errand   被派：有目的地、有期限、有结果          ★ 本轮新增
npc_roam     位置：把"他现在该在哪"落成驻留覆盖（唯一位置真源）
```

差事生命周期（单向，不回头）：

```
traveling ──(到点)──▶ working ──(到点)──▶ done
   在路上 ⇒ scene_now()=None        已到达 ⇒ scene_now()=dest        办完 ⇒ 撤覆盖 + 结果固化
```

## 六、本轮踩到的坑（都是判据/夹具侧，产品零缺陷）

1. ★★★ **`open()` 默认 universal newlines 会把 `\r\n` 归一化掉** ⇒ 用 `src.count('\r\n')` 判 EOL
   会得出"main.py 全 LF"的**假结论**。必须 `newline=''` 读（契约原文即如此）。
   —— 实测 `main.py` 加完 130 行后仍是 **CRLF 16821/16821**（Edit 正确保持了原 EOL）。

   ⇒ 正确判据 = "**没被差事改写**"。**报红先怀疑判据**再次成立。
3. ★★ **`M17` 第一次 MISSED**：变异"`step` 无视 `enabled`"在看板为空时**没有行为差异**。
   ⇒ 补 `F2b`（关闸 + 表里**已有**记录 ⇒ 仍不推进）后才抓住。
4. ★★★ **`rmtree` 累积触发清理守卫**：`mutate113` 第一次跑完就 SIGTERM（零输出）。
   ⇒ 改用 `tempfile.mkdtemp()`（**绝不删**）后正常。

## 八、明文遗留（未做 / 待裁定）

1. **派发入口还没接 UI/对话**：本轮只交付 `assign_errand()` 这个**机制入口**。
   "用户通过自然语言让某个角色去办事"要走对话/指令层 —— 下一步。
2. ★ **办完是 `drop`（回落静态归属 = 回家），不恢复"派出前的那次自主驻留"**。
   理由：差事是"出门办事"，办完回家是自然的。**若用户希望"办完回原处"，改一处即可**。
3. ★★ **世界门控关系待澄清**：`_npc_errand_tick` 直接 `roam.put`，**不走** `world_gate`。
   即"被派"可以跨世界（含 Ralsei 去光世界，不需要球）。既有口径是"自主移动受门控、
   Ralsei 必须靠球" ⇒ **"被派"是否继承门控，需用户拍板**。
4. **差事与 `npc_life.json` 的持久化**：差事看板目前**不落盘**（重启即丢在办差事）。
   `roam` 的覆盖会落盘 ⇒ 重启后他会**停在那个场景**（位置在，差事没了）。
   是否需要"差事也落盘"，待定。
