# 第175轮 · 87 个独立场景文件补 `original_room_id`

> 一句话：**把"靠回退层兜住"换成"文件自己说得清自己是谁"。**
> 全盘自足率 **2079/2166 → 2166/2166**；每个文件只多一行，其余字节零变化。

---

## §1 起点：一个"能跑但说不清"的状态

第173轮收口时留下的事实：

```
88 个独立场景文件里 87 个没有 original_room_id
而 _index.json 的 2166 条登记行全都有（例：card_castle_1f -> 114）
```

产品**没出错**，因为 `scene_system.py` 有一层回退：

```python
# scene_system.py:498
# ★ 独立文件场景（第 36 轮登记的 87 个）**不带** original_room_id ——
#   它写在 `_index.json` 的登记行里。从 entry 补一次，让渲染层
#   无论走哪条来源都能查房间几何（否则这 87 个场景会退化为"房间未知"）。
if scene.original_room_id is None and isinstance(entry, dict):
    _oid = entry.get('original_room_id')
    if isinstance(_oid, int):
        scene.original_room_id = _oid
```

⇒ 行为正确，但**文件本身不自足**：任何绕过 `load_scene()` 直接读文件的地方
（`SceneState.from_dict(raw)`、将来的导出/校验/编辑工具、人工翻 JSON）
看到的都是 `None`。这就是本轮要消掉的隐式依赖。

---

## §2 数据面：2166 = 88 + 2078，一条不多一条不少

| 载体 | 文件数 | 场景数 | 改前自带 `original_room_id` |
|---|---|---|---|
| 独立文件 | **88** | 88 | 1（只有 `desktop.json`） |
| 区域分片 `_zone.*.json` | **76** | **2078** | **2078（全部）** |
| 合计 | — | **2166** | 2079 |

两条交叉验证：

- `_index.json` 可解析房间号的场景 = **2166**；盘上场景 = 88 + 2078 = **2166**；
  `index 有盘上无 = 0`、`盘上有 index 无 = 0`。
- 分片 **2078/2078 本就自带** ⇒ 缺口只在独立文件那 87 个。

★ 同一章内房间号**没有**被两个场景占用（2166 条里 0 冲突）⇒ 值不会串行。

## §3 值从哪来：抄 index，不重算

一律从 `_index.json` 的登记行**抄同一个数**。

理由：产品运行时本来就以 index 为准（`MainWindow._scene_rooms()` 只读 index，
`scene_pathfind._scene_pool()` 也读 index）。从文件抄同一个数，才不会造出
"文件与索引两个真相"。

87 个值分布：

| 章 | 条数 |
|---|---|
| ch1 | 19 |
| ch2 | 21 |
| ch3 | 8 |
| ch4 | 19 |
| ch5 | 20 |

值的独立旁证：87 个里有 **85 个**落在 `_original_rooms.json`（原作剧情房间表）
该章的房间 id 集合内；表外 3 个是
`ch2.queens_mansion.queen_s_mansion_rooftop(199)` /
`…rooftop_2(200)` / `desktop(-1)`。
前两个不是错 —— 那张表只收**剧情主房间**（每章 20/20/9/20/26 个），
`199/200` 是屋顶这两间没进表；`desktop` 的 `-1` 本来就表示"不是任何原作房间"。
三者仍逐条等于 index，**没有任何编造值**。

## §4 写法：文本级行插入，不是 `json.dump` 整写

这些文件是 **2 空格缩进 + CRLF**。整体 `json.dump` 相当于把 87 个文件全部重写：

- diff 里每个文件全红（500+ 行），审的人根本看不出改了哪；
- Python 的 universal-newline 会把 `\r\n` 悄悄变成 `\n`。

而它们缺的只是一个 int。所以用**文本级行插入**：

```python
ANCHOR = re.compile(r'^  "area_name": "[^"\r\n]*",\r?\n', re.M)
line  = u'  "original_room_id": %d,' % rid + eol
new   = text[:m.end()] + line + text[m.end():]
```

四条自检，任一不过就拒写：

1. 插入后 `set(new) - set(old) == {'original_room_id'}`
2. 其余键**逐个深比较**相等
3. 键顺序：`area_name` 的下一个必须就是 `original_room_id`（与 `desktop.json` 对齐）
4. 新文本必须恰好等于"旧文本 + 那一行"

写盘走 `.new` → 复读 → 断言无 BOM → `os.replace`；全程 `newline=''` 保持 EOL。

**实测结果**（git 侧，独立来源）：

```
改动文件=87  新增行=87  删除行=0
```

抽样：

```diff
   "area_id": "card_castle",
   "area_name": "纸牌城堡",
+  "original_room_id": 114,
   "bg": "bg/ch1_card_castle_card_castle_1f.png",
```

## §5 本轮真正的改变：自足率 2079 → 2166

这是唯一一个"改前/改后有明确差值"的量 —— 也是判据的重心。

| 项 | 改前 | 改后 |
|---|---|---|
| 独立文件 `SceneState.from_dict(文件)` 不经回退能拿到房间号 | **1 / 88** | **88 / 88** |
| 全盘自足（分片 2078 + 独立） | **2079 / 2166** | **2166 / 2166** |
| `load_scene()` 完整路径（回退层仍在） | 2166 / 2166 | 2166 / 2166（不变） |
| 给不给 `entry` 结果是否相同 | 只有独立文件不同 | **完全相同** |

★ 第四行是本轮的"副作用证明"：文件自足之后，`load_scene()` 里那层回退
**不再改任何东西**了 —— 但它**没被删**。为什么不删：那是第 36 轮留下的
兼容层，删它属于另一件事（且要确认所有调用方都不再依赖 entry），不在本轮范围。

## §6 判据 `check175.py`：37 条 / 五段

| 段 | 条数 | 内容 |
|---|---|---|
| A 分母与取证 | 9 | 2166 == 88 + 2078 · 分片 2078 **全部**自带（"另一条来源已自足"的对照）· desktop 仍是 -1 · 逐条值 == index · int 类型（非 bool）· 键紧跟 `area_name` |
| B 自足性 | 6 | `from_dict` 单喂 88/88 · 值对 · **全盘 2166/2166** · **负控制抹字段掉 None** · `load_scene` 完整路径 · 给不给 entry 结果相同 |
| C 不变性 | 8 | 除 rid 外指纹 == 改前快照 · 行数 +1 · **字节增量精确到那一行** · **git 改动面恰好 87 个文件** · `+87/-0` · 无 `.new` 残留 |
| D 不造值 | 8 | 都能在 index 找到 · 同章房间号唯一 · 文件名 == `<scene_id>.json` · scene_id 无重复 · 剧情房间表 85 命中 + 3 表外如实点名 · 表外仍逐条 == index · CRLF · 无 BOM |
| E 自检 | 6 | AST 查恒真 · 单一 harness · 条数下限 30 · 不构造真机 · 零外部盘 · 零网络 |

### 为什么不用"文件里有这个字段"当判据

因为改前也有 1 个（`desktop.json`）。写成 `>= 1` 就永远绿 —— 这是本类改动
**最容易犯的恒真**。所以 A5 写成"88 个**全部**有"，B0 写成"**不经回退**也能拿到"，
两条合起来才把"补了"这件事钉死。

### 改前快照 `_evidence/before175.json`

注入器在**改之前**记下每个文件的：

```json
"lines": 行数, "bytes": 字节数, "had_rid": 改前有没有字段,
"rid": 改前的值, "h_rest": 除 rid 外内容的 sha1
```

判据 C 段拿它做三件事：指纹比对、行数 +1、字节增量精确。
★ 防止"快照被一起改绿"的保险：C1 断言快照里 `had_rid=True` 的**恰好只有
`desktop.json` 一个** —— 这就是"改前"的定义，快照若被篡改，这条先红。

## §8 没有老锁被撞（与第174轮对比）

第174轮改的是**数据面**（多 51 条路由 + 51 个物件），所以连带撞了七把老锁。
本轮只补**元数据**、产品行为逐值不变 ⇒ **一套老锁都没动**。

这不代表本轮"没风险"，而是说明风险方向不同：
本轮的风险是**"看起来改了，其实没改"**（恒真判据）和
**"顺手把别的字节改了"**（整文件重写），所以判据重心放在自足率与字节增量上，
而不是条数守恒。
