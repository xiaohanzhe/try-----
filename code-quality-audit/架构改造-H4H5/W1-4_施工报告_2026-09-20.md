## 二、施工口径：只搬方法、不搬状态

严格遵守 H4/H5 铁律 **「只搬方法、不搬状态（转发壳 + 宿主 API）」**：

- 全部视频状态 **仍留在 `RalseiPet.__init__`**：`is_watching_video` / `video_start_time` /
  `video_duration` / `video_watch_history` / `video_preferences` / `video_title` /
  `video_platform` / `current_video_url` / **`video_watching_timer`** →
  控制器只通过宿主引用 `self.p` 读写。
- 控制器**不 import 任何项目内模块**（`logging` / `random` / `time` 三个标准库除外），
  避免重新接上 `logger_utils → data_store → memory_store` 那条初始化环。
- 八个方法体**逐字搬运**，中文注释一字未改 —— 只有**两处白名单改写**（见下）。

### 两处白名单改写（唯一的两处，均带命中计数断言）

```python
REWRITES = (
    ("_log.", "_log_().",      2),   # 见坑 4
    ("QTimer(self)", "QTimer(self.p)", 1),   # 见坑 2
)
```

改写脚本 `_run_w1_4.py` 对每处改写**断言命中次数**（2 次 / 1 次），
并做**反向归一**证明：把改写后的文本反向替换回原样，与父版本逐字节相等。
任何一处命中数不符即 `SystemExit` —— 防"空替换导致改写没发生却假装成功"。

### 双向转发的实现（继承 W1-3 口径 + 一处新增强化）

- **宿主侧**（`RalseiPet.__getattr__`）：常规查找 miss 时，遍历
  `_CONTROLLER_ATTRS = ('games', 'video')`，把名字转给控制器。
  用 `getattr(type(ctrl), name)` 探测，**不**用 `hasattr(ctrl, ...)`。
- **控制器侧**（`VideoController.__getattr__`）：自身 miss 时回落给宿主，
  只在名字**在宿主实例字典里**、或**在宿主类型的 MRO 上**时才返回。
- **★ 新增（W1-3 没有的）：`VideoController.__setattr__`** —— 见坑 3。

## 三、踩坑记录（四条，三条是真产品缺陷）

> **这一节是 W1-4 报告的核心。** 四条坑里有三条**逐字等价断言 100% 测不出来**：
> 源码一个字没改，改的是"这个名字/这个 self 指向谁"。
> 「方法体逐字等价」与「产品还能跑」是两个不同的问题 —— 这是本项目第四次踩到。

### 坑 1（真缺陷）：`QRect` / `QTimer` 变成未定义名字 → `NameError`

被搬的方法体里 `QTimer(self)`（`_start_video_watching_loop`）和
`QRect(...)`（`start_watching_video`）都是**裸用**，在 `main.py` 里靠它**模块级**的
`from PyQt5.QtCore import ...` 解析。搬进新模块后那个作用域没了 → `NameError`，
**真机一点就炸**。

**修法**：控制器顶部加 `from PyQt5.QtCore import QTimer, QRect`（与 `main.py` 同款导入）。

> 为什么静态等价看不见：方法体逐字未改，改名的是**符号解析的模块作用域**。
> 这是 `verify_w1_4_e2e.py` 抓到的 —— 逐字等价（unit）当时全绿。

### 坑 2（真缺陷）：`QTimer(self)` 语义变了 → `TypeError`

在宿主里 `self.video_watching_timer = QTimer(self)` 的 `self` 是 **RalseiPet**
（一个 `QMainWindow`）→ Qt 接受它做 parent，定时器挂在窗口对象上。

搬进控制器后同一个 `self` 变成 **VideoController**（一个 `object`）：

```
TypeError: QTimer(parent: Optional[QObject] = None): argument 1 has
unexpected type 'VideoController'
```

**修法**：白名单改写 `QTimer(self)` → `QTimer(self.p)`。
语义**完全保持**（parent 仍是那个 `QMainWindow`），只是显式写出。

> **这条要进项目施工口径备忘**：`self.xxx` 与 `QTimer(self)` 有本质区别 ——
> 前者是「**取出**宿主上的值」（`__getattr__` 回落能救），
> 后者是「**把控制器自己交出去**」（回落救不了，因为交出去的是 `self` 不是属性）。
> 这是 W1-3 没暴露的类别。

### 坑 3（真缺陷）：`__setattr__` 缺失 → 状态被劈成两份

`__getattr__` 只解决**读**。控制器里 `self.is_watching_video = True` 是**写**，
Python 普通赋值走 `__setattr__` → 默认 `object.__setattr__` →
直接把属性写进**控制器自己的 `__dict__`**。

实测（真踩）：

```
host.is_watching_video == False    # check_entertainment_needs 在宿主上读
ctrl.is_watching_video == True     # _update_video_watching 在控制器里读
```

→ 状态劈成两份。「看完视频」分支**永远不会触发**（宿主那一份永远是 False），
而观看循环自己看到 True。**两边读数不一致，行为静默错乱。**

**修法**：控制器实现 `__setattr__` ——

```python
def __setattr__(self, name, value):
    if name != 'p':
        pet = self.__dict__.get('p')
        if pet is not None:
            if name in pet.__dict__ or any(
                    name in klass.__dict__ for klass in type(pet).__mro__):
                setattr(pet, name, value)
                return
    object.__setattr__(self, name, value)
```

转发名单的判据是「宿主**已经拥有**这个名字」—— 关键好处是**能自动覆盖未来新增的状态名**：
以后 `RalseiPet` 再加 `video_xxx` 字段，只要在 `__init__` 里赋过值，
写进来就自动落宿主，**不需要回来改这份名单**
（「函数写对了但产品用不上」是本项目最贵的坑，这里提前堵住）。

> ⚠️ **必须跳过 `'p'` 本身**，否则 `self.p = ralsei_pet` 会去查宿主有没有 `p`
> 并可能被转发 → 宿主引用丢失 → 全线崩。

> ⚠️ **W1-3 的 `GamesController` 经核实不受此坑影响**（AST 扫描：它唯一的
> `self.X =` 只有 `__init__` 里的 `self.p`；游戏状态全部走
> `self.game_state[...] = ...` 的**下标赋值**，那是在改宿主字典的内容、
> 不产生新属性绑定）。**但这是"恰好没踩"，不是"设计上不会踩"** ——
> 见第七节「下一步」的加固建议。

### 坑 4（设计选择）：`_log` 必须解析成宿主模块的同一个 logger 对象

`_log` 是 `main.py` 的**模块级全局**，既不在宿主实例字典里、也不在宿主类型 MRO 上 →
两条回落白名单都不满足。

不能自己 `logging.getLogger('modules.video_controller')` —— 那会**换一个 logger 名**，
文件落点 / 级别 / 格式都可能变，「行为等价」就不成立。

**修法**：控制器加**普通方法** `_log_()`，从 `sys.modules[type(self.p).__module__]`
取出宿主的 `_log` 全局对象（同一个 logger）→ **逐字节同一条日志**。

```python
def _log_(self):
    import sys
    mod = sys.modules.get(type(self.p).__module__)
    if mod is not None:
        lg = getattr(mod, '_log', None)
        if lg is not None:
            return lg
    return _log
```

方法体里把 `_log.debug(...)` 改成 `_log_().debug(...)`（2 处，带命中断言）。

> **雷区**：类体里不能写 `_log = self.p...`（类体没有 `self`）、
> 也不能用 `@property`（property 对象会**挡住**模块级 `_log`，
> 但方法体里写的是 `_log.debug`，取到 property 对象反而报 `AttributeError`）。
> 正确写法就是**普通方法**，与调用点的 `_log_()` 正好成对。

### 附带：新状态名必须**预声明在宿主**（坑 3 的直接推论）

`video_watching_timer` 是**本轮才出现的新名字**（原 `main.py` 里没有它，
是靠 `_start_video_watching_loop` 里那次赋值首次创造的）。而坑 3 的
`__setattr__` 白名单判据是「宿主**已经拥有**这个名字」→ 首次赋值时宿主没有 →
**会落回控制器**，坑 3 复发。

**修法**：在 `main.py` 的视频状态块（L1169）**显式预声明**：

```python
self.video_watching_timer = None
```

并配注释说明为什么必须预声明。**这条规则下推**：以后每搬一个方法，
若它创建了宿主尚不存在的新属性，就必须同步加进宿主 `__init__` 的预声明区。

> 这是 `verify_w1_4_ab.py` 的场景 `s1b` 抓到的（见第五节）。

## 五、探针自身的坑（都是我写的探针错了，不是产品错）

这一节记下来，是因为 `verify_w1_4_ab.py` 先后报过三次"差异"，**三次都是假差异**。

### 5.1 `random.choice` 未钉住 → 标题漂移假差异

`start_watching_video` 里 `video_type = random.choice(video_types)` 决定
`video_title`。只钉 `random.random` 不够 → 标题随全局 RNG 状态漂移，
报出 `title` 不一致。**修法**：把 `random.choice` 一起钉成 `lambda seq: seq[0]`。

### 5.2 `timer_active` 在 s1 里**没有鉴别力** → 换落点验证

`check_video_apps → start_watching_video` 这条链会调
`QMainWindow.width()/height()` 定位，而探针宿主用 `__new__` +
`QMainWindow.__init__` 造出来**从不 `show()`**，offscreen 下尺寸没真正 resolve。
于是同名链条在**新版本上偶发抛异常**（`QApplication([])` 的返回值没存引用 → 可能被 GC）。

关键判断：`_start_video_watching_loop` 被调用的位置（控制器 L363）
在 `change_animation`（L356）之后 —— 在**宿主**里 `change_animation` 会走到真
`setPixmap/update`（才要求真窗口尺寸），在**控制器**里它是宿主 API 桩（只记录调用）。
**因此 `timer_active` 在两侧不可能同值，这一项在 s1 里没有鉴别力。**
删掉，改由 `s1b` 用直接路径（打桩 `QTimer`）验证落点。

### 5.3 探针宿主复刻漏了预声明 → `s1b` 假差异

探针的 `make_host` 用 `__new__` 跳过 `__init__` → **不会**自动有
`self.video_watching_timer = None` → 控制器 `__setattr__` 白名单里没这个名字 →
首次赋值落回控制器 → 报出"新版本 timer 在控制器上"。

**修法**：在 `make_host` 里补 `pet.video_watching_timer = None`，
**复刻真实 `__init__` 的初始状态**，对照才成立。
补上后 `s1b` 两侧同为 `on_host=True / on_ctrl=False`，
**恰好反证了坑 3 的预声明确实起作用**。

### 5.4 `M.RalseiPet.identify_video_apps` 查不到（类属性查找不走 `__getattr__`）

转发壳只在**实例**属性查找生效。写 `M.RalseiPet.identify_video_apps` 报
`AttributeError: type object 'RalseiPet' has no attribute 'identify_video_apps'`。
**修法**：走实例 `p.identify_video_apps()`（先经宿主 `__getattr__` 转到控制器）。

### 5.5 批量 `str.replace` 补丁打歪（工程教训）

我用一次 `str.replace` 批量修 `verify_w1_4_ab.py`，结果把 `\n` 写成了字面 `/n`、
并留下一段重复的 `def make_host(M, wins):` 残片，文件语法崩坏。
**教训**：多行结构化代码的修改**不要用批量字符串替换** ——
改用 `Edit` 工具做精确块替换，或直接整体重写文件。

## 六、锁的定位器必须跟着代码搬家（`round8_anim` H1.3 假红）

`round8_anim` 有一条锁（H1.3）用 `func_src('_react_to_video')` 取方法源码，
但它的 `_find_func` **只扫 `main.py`**。方法搬进控制器后 → 取不到 → **假红**
（报 `有 note_event=False`）。

**修法（改锁，不改产品、不改基线）**：

- 新增 `CONTROLLER_SRCS` / `ALL_SRC`；
- `_find_func` 返回 `(node, src)` 二元组，遍历
  `main.py` + `modules/games_controller.py` + `modules/video_controller.py`；
