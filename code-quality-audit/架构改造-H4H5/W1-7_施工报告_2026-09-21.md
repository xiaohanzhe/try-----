## 三、两项修正（都不是新写代码，而是**修旧判据**）

### 3.1 W1-3 的 A/B 是假对照 —— 抓到了

W1-3 的 A/B（`verify_w1_3_ab.py`）拿 `_evidence/w1_3_main_before.py` 当"改造前"。
**事后核实那份快照不是父版本**：

| 项 | 父版本 `d8e2878^` | `_evidence/w1_3_main_before.py` |
|---|---|---|
| 行数 | 10481 | 10530（**+49，零删除**） |
| md5 | `196560d7…` | `6df92a3d…` |
| 差异 | — | 3 个 hunk，全是 W1-3 **当轮新增**的转发壳：<br>`import games_controller` / `_CONTROLLER_ATTRS`+`__getattr__` / `self.games = GamesController(self)` |

而且快照里 **7 个方法仍在宿主上定义**（`w1_3_main_before.py` 里 7 个 `def` 齐在）。
于是那次 A/B 量的是：

- **A**：7 方法在控制器，宿主**只能靠转发**拿到
- **B**：7 方法在宿主（直连），**同时转发壳已装好但闲着**

两版的方法体逐字同源、状态都在宿主、RNG 同源 → **"轨迹逐行一致"是必然结果，不是证据**。
它想守的那一维（转发壳本身有没有改变行为）在这把尺子下**零鉴别力**。

**本项修正**：快照改为取 **HEAD 的整棵 `ralsei_pet/`**（`_evidence/w1_7_before/`，107 个文件），
连模块一起换掉，量到的才是真正的历史版本。并且：

- 新增 **`RALSEI_PROJECT_ROOT`** 覆写口（`verify_w1_3_e2e.py`），让同一把尺子能在两个项目根上各量一次；不设该变量时行为与从前**逐字节相同**；
- A/B 脚本加**稳定性对照**（A 组同版重跑），用来区分"真的等价"与"探针本来就不确定"；
- **实测鉴别力**：中间态曾抓到 2 条真差异（搬前 FAIL / 搬后 PASS），证明尺子是活的。

### 3.2 `verify_w1_3_games_extract.py` 的一条**潜伏假绿**

改造后该脚本报 1 条 FAIL：

```
[FAIL] 控制器不持有状态 self.game_state（只借宿主）
```

**是假红。** 唯一命中在 `games_controller.py` L138，是一行**注释**：

```python
# `self.game_state = {...}`，或新增 `self.game_xxx = ...`，赋值就会静默落进
```

原判据是 `('self.game_state =') not in new_src` —— **原始文本匹配**，分不清注释与代码。
它此前一直"绿"只是因为那行注释**碰巧写在** `self.game_state` 的下标用法**之后**、
而 `rfind` 锚点又在正文末 — 属于侥幸，不是判据。

**修法**：换成 AST 级判据（类体内有没有 `self.<状态> = …` 的 `Assign` 节点）+
剥注释后的文本反查 + **反向控制**（断言"注释里确实有、剥注释后确实没有"）。
这正是本项目记过 5 次以上的同型坑：**源码级断言必须先剥注释/字符串**。

## 五、本项额外发现：仓库存在两套换行口径（环境事实）

施工前做「逐字节参照系」时踩到，与产品无关但**会影响任何后续的逐字节比对**：

本机 `core.autocrlf = true` 且仓库**无 `.gitattributes`**，于是：

| 类别 | 数量 | 含义 |
|---|---|---|
| **双口径**（blob=LF，工作区=CRLF） | **14 个** | 含 `dialogue_ui.py`、`ai_driver.py`、`pet_ai.py`、`dialogue_system.py` 等**大文件** |
| **单口径**（两侧都 LF） | 58 个 | 含 `main.py` 与全部 `*_controller.py` |

后果三条：

1. `git archive` 展开时过 checkout 过滤器 → LF 全转 CRLF（`main.py` 9018 行），
   **用它做参照系会全部 md5 不符**。快照必须走 `git cat-file blob`（原始 blob）。
2. `git status` 对这 14 个文件**看不见**工作区与 blob 的差异（双向过滤"洗掉"了），
   所以"工作区干净"**不等于**"与提交逐字节相同"。
3. 改这些文件时**必须保留其原有换行口径**，否则会引入整文件级 diff 而提交层面无感。

**本项处置**：`_evidence/w1_7_before/` 用 `git cat-file blob` 导出（107 文件 /
3540139 字节），并写 `w1_7_before_manifest.txt`（逐文件 md5）作 A/B 锚点；
脚本读写一律 `newline=''`，落盘后**断言 CRLF 计数未变**。
