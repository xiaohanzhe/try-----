## 二、施工口径：只搬方法、不搬状态

严格遵守 H4/H5 铁律 **「只搬方法、不搬状态（转发壳 + 宿主 API）」**：

- `game_state` / `guess_number_game` / `rock_paper_scissors_options` **仍留在 `RalseiPet.__init__`**
  （L426–451），控制器只通过宿主引用 `self.p` 读写。
- 控制器**不 import 任何项目内模块**（`random` / `time` 两个标准库除外），
  避免重新接上 `logger_utils → data_store → memory_store` 那条初始化环。
- 七个方法体**逐字搬运**，中文「修复：…」注释一字未改。

### 双向转发的实现

方法体一字不改，意味着 `self.game_state[...]` 这类写法在控制器里必须能解析。
两侧各加一个 `__getattr__`：

- **宿主侧**（`RalseiPet.__getattr__`）：常规查找 miss 时，把名字转给控制器。
  用 `getattr(type(ctrl), name)` 探测，**不**用 `hasattr(ctrl, ...)`。
- **控制器侧**（`GamesController.__getattr__`）：自身 miss 时回落给宿主，
  但只在名字**在宿主实例字典里**、或**在宿主类型的 MRO 上**时才返回。

于是 `play_game`（L6530/6547）、`update_stats` 的 5 分钟超时（L5093/5095）、
`dialogue_ui.parent.*`（L1249/1658/1662/1666）三处调用点**一个字符都不用改**。

### 刻意不搬的：`handle_game_input`

`handle_game_input`（原 L6787）**留在宿主**。它调用了 W1-2 的 `_abort_hide_and_seek`，
搬走会引入跨控制器依赖，违反 Wave 1 的「零互写」前提。
→ 待 W1-2（躲猫猫）落地后，随该项一起搬。

## 三、踩坑记录（两条，都已根治）

### 坑 1：双向转发成环 → `RecursionError` 崩在构造期

第一版宿主侧 `__getattr__` 用 `hasattr(ctrl, name)` 探测控制器有没有该方法。
真机一跑就崩：

```
File "main.py", line 1313, in randomize_movement_pattern
    if getattr(self, 'game_state', {}).get('is_playing'):
File "main.py", line 495, in __getattr__
    if ctrl is not None and hasattr(ctrl, name):
File "games_controller.py", line 89, in __getattr__
    return getattr(pet, name)
File "main.py", line 495, in __getattr__          ← 无限循环
File "games_controller.py", line 89, in __getattr__
...
RecursionError: maximum recursion depth exceeded
```

**根因**（一个被忽略的时序事实）：`RalseiPet.__init__` 在 **L405** 调 `init_movement()`
→ `randomize_movement_pattern()` → `getattr(self, 'game_state', {})`，
而 `game_state` 直到 **L426** 才赋值。那一刻宿主 `__getattr__` 被触发：

```
宿主 __getattr__('game_state')
  → hasattr(控制器, 'game_state')
    → 控制器回落 getattr(宿主, 'game_state')
      → 宿主 __getattr__('game_state')   ← 回到起点
```

**修法**：宿主侧改为 `getattr(type(ctrl), name, None)` 探测 —— **只看控制器类上定义的方法**，
不去碰实例属性，回路被切断。控制器侧同时收紧为「宿主实例字典 / 宿主类型 MRO 二者之一」。
两侧都成了显式白名单，环不存在了。

> 这条坑的价值：它是**构造期**崩溃，表现为「窗口根本起不来」，
> 而 G2 里只有 16 个套件会 `RalseiPet()`，其中若干还是轻量桩 ——
> **光靠 G2 抓到它的概率很低**。是 `verify_w1_3_e2e.py`（真机 `RalseiPet()`）抓到的。

### 坑 2：我自己的校验脚本假红（计数混了「定义」与「引用」）

第一版 `verify_w1_3_forwarding.py` 用 `refs()`（属性名/裸名计数）断言
"该方法只定义一次"，结果把控制器内部的 `self.end_guess_number()` 三处**调用**
也算成"定义"，报出"实际 4 次"这种**假红**。

**修法**：拆出 `defs_of()`（只数 `FunctionDef` 节点）与 `refs()`（数引用），
两者严格分开。

### 附带：反例控制的 needle 未命中（假通过）

`verify_w1_3_games_extract.py` 的反例控制原本用 `"max_attempts"`（ASCII 双引号）做 needle，
而源码里是 `'max_attempts'`（单引号）→ `replace` 一次都没命中 → 篡改是**空操作**
→ 判据"篡改后仍相等" → **反例控制假通过**。

**修法**：先断言 needle 命中次数 ≥1、再断言文本确实改变、最后才断言判据判为不等 ——
三段递进，任何一段没成立就 FAIL。现在输出 4 条 PASS。

### 为什么必须有 e2e 探针（G2 的空档）

G2 的 24 个套件里**没有任何 games 覆盖** —— 游戏逻辑的行为等价性在 G2 里
**完全测不到**。「方法体逐字等价」只证明"代码没抄错"，证明不了"转发之后产品真的还能玩"。
两者是不同的问题，都要独立证明。e2e 探针覆盖：

- 转发接线：`RalseiPet` 实例经 `__getattr__` 能解析全部 7 个方法
- 状态仍在宿主：控制器实例字典里**不含** `game_state` 等（状态没被复制）
- 石头剪刀布：开局 → 别的游戏进行中时**拒开局**（返回 `False`）→ 打满 5 轮 →
  自动结算 → 统计键更新（`update` 语义保住 `total_wins` / `best_streak`，不 KeyError）
- 猜数字：开局 → 非数字/超范围输入**不消耗**尝试次数 → 二分命中 → 结算
- `handle_game_input` 仍在宿主，识别"结束"并接管（返回 `True`）

### A/B 纪律

先断言 **A ≠ B**：旧版 `main.py` md5 `6df92a3d…`，当前 `0221b561…`，两者不同
（若相同则会 `SystemExit`，因为那意味着探针退化成"自己跟自己比"，结论必然"没差别"
**且非常像真的**）。另加"轨迹行数过少"的兜底，防探针根本没跑起来。
