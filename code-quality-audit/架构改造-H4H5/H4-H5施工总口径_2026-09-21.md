## §0 一句话总览

搬运一个方法进控制器，要过的闸门有 **8 道铁律 + 3 层验证 + 1 条断言分层纪律**。
逐字等价断言（unit）**只**能证明"方法体没写错"；**铁律 1/2/3/4 在 A/B 中结构性地不可见**

## §1 ★ 预声明规则（升格为正式口径）

### 1.1 规则本体

> **控制器在方法体里首次创建的、宿主尚不拥有的新状态名，必须在宿主的 `init_systems()` 里显式预声明。**

### 1.2 判据（唯一）

**「宿主已拥有该名字」** —— 即满足下列任一：

```python
name in pet.__dict__                      # 实例字典里有
getattr(type(pet), name, None) is not None  # 类型 MRO（含类属性 / 方法 / property）
```

**首次出现的新状态名不满足该判据** → 控制器的 `__setattr__` 判定"不是宿主的名字"
→ 赋值落进**控制器自己的 `__dict__`** → **状态被劈成两份**。

### 1.3 后果（实测，W1-4 的 `is_watching_video`）

```python
host.is_watching_video == False
ctrl.is_watching_video == True
```

→ 「看完视频」分支**永不触发**（宿主那份永远 `False`），而观看循环自己看到 `True`。
**两个对象各自"自洽"，没有任何异常抛出** —— 这是它比 `NameError` 危险得多的原因。

### 1.4 ❗ 纠正一处长期错误表述（本次升格的核心动作）

| 来源 | 原文 | 判定 |
|---|---|---|
| 详版 §8.2 搬运铁律 4 | 「**新状态名必须预声明在宿主 `__init__`**」 | ❌ **错** |
| 速查本 §0/§4 | 「新状态名在宿主 `init_systems()` 预声明」 | ✅ **对** |

**实测依据**（本轮硬核实，可复现）：

```
$ python - <<'PY'  # 实际以脚本形式执行
re.match(r"\s*def init_systems", line)  →  L660 : def init_systems(self):
```

* `main.py` L660 = `def init_systems(self):` —— **预声明区在这里**，
  L770–L806 是 `_spell_*` / `_hide_*` 两个状态声明块（正是 W1-1 / W1-2 补的预声明）。
* **为什么不是 `__init__`**：控制器**本身**是在 `init_systems()` 里创建的
  （L743 `self.games` / L746 `self.video` / L751 `self.spell` / L755 `self.hide_seek` / L761 `self.file_sheet`）。
  控制器创建**晚于** `__init__`。把预声明写在 `__init__` 里虽然**也能生效**（因为 `__init__` 更早），
  但会让"状态声明区"与"控制器创建区"分离在两个相距几千行的位置，
  **后续每搬一项都要翻回去找** —— 这是维护性问题，不是正确性问题。
* **实际项目约定**：所有历次预声明都写在 `init_systems()` 的状态声明块里（W1-1 的 `_spell_seen_frame`
  L786 / W1-2 的 4 个 `_hide_*` L803–806）→ **以项目既成事实为准，统一到 `init_systems()`**。

> **⇒ 升格结论：预声明区 = 宿主 `init_systems()` 内的状态声明块。
> 详版 §8.2 铁律 4 的 `__init__` 表述作废，本文为准。**

### 1.5 附带要求：跳过 `'p'`

控制器 `__setattr__` 的转发**必须跳过 `'p'`**：

```python
def __setattr__(self, name, value):
    if name != 'p' and (...判据...):
        setattr(self.p, name, value)
        return
    object.__setattr__(self, name, value)
```

否则 `self.p = pet`（构造期）会被转发成 `setattr(pet, 'p', pet)` →
**宿主引用被自己覆盖** → 全线崩。**实测**：5 个控制器全部实现，`'p'` 相关命中 3–4 处/文件（见 §5.1 表）。

### 1.6 「不搬状态」的情形也要写清楚

W1-6 是**第一个"不搬任何状态属性"**的项（4 个方法全是"读宿主 + 调宿主 API + 用局部变量"）。
其控制器 docstring 明确写了「本项**不搬任何状态属性**，故无需任何预声明：状态劈裂风险为零」。
→ **口径：不搬状态时必须显式声明"不搬"，不允许沉默**（沉默会让后人无法区分"想过"和"漏了"）。

## §2 搬运铁律 8 条（完整口径）

> 全部属于「**方法体逐字等价 ≠ 产品还能跑**」。本项目**已第 4 次**踩到这个坑
> （W1-3 / W1-4 / W1-1 / W1-2 各有实例）。**全部由 e2e 抓到，unit 逐字等价当时全绿。**

### 铁律 1 — `self` 的身份会变（读出能救，传出不能）

* `self.xxx` 是「**取出宿主的值**」→ `__getattr__` 回落**能救**。
* **`f(self)` / `f(self, ...)` 形态**（把 `self` 当对象交出去）→ 交出去的是**控制器本体** → 回落救不了。
  实测：`QTimer(self)` → `TypeError: argument 1 has unexpected type 'VideoController'`。
* **修法**：白名单改写 `QTimer(self)` → `QTimer(self.p)`（**带命中计数断言**）。
* **纪律**：**搬任何方法前先搜 `f(self)` / `f(self,` 形态。**
* 实例：W1-4 恰 1 次；W1-6 **0 次**（干净，块内无 `QTimer`）。

### 铁律 2 — 模块作用域丢失 → `NameError`

* 方法体裸用 `QTimer` / `QRect` 等，在 `main.py` 靠**模块级 import** 解析；搬走后作用域没了。
* **修法**：控制器顶部补 `from PyQt5.QtCore import QTimer, QRect`。
* **逐字等价断言测不出来**（文本没变，只是解析环境变了）。

### 铁律 3 — 控制器必须实现 `__setattr__`（最隐蔽）

* `__getattr__` **只管读**；`self.x = v` 默认落**控制器自己的 `__dict__`** → 状态劈两份。
* **转发判据 = 「宿主已拥有该名字」**（`name in pet.__dict__` 或 `type(pet).__mro__` 上有）
  → **未来新增属性名自动覆盖**（堵住本项目最贵的坑）。
* ⚠️ **必须跳过 `'p'`**（见 §1.5）。
* **通则**：判据用「已拥有」而非「白名单硬编码」，是为了让**新属性自动生效**；
  **反向代价**就是铁律 4（新名字不满足判据）。

### 铁律 4 — 新状态名必须在宿主预声明（**= §1，本文档已升格**）

* 判据是"宿主**已拥有**"，**首次出现**的名字不满足 → 仍落控制器。
* **修法**：在宿主 **`init_systems()`** 显式 `self.video_watching_timer = None`。
  实测该 `None` 预声明确实存在于宿主（W1-4 报告 §五铁律 3/4 引用的 `main.py` L1169 为**当轮行号**，
  当前已随文件增长位移；**以名字为准，不以行号为准**）。
* **通则**：**每搬一个方法，若它创建宿主尚不存在的新属性，必须同步加进宿主预声明区。**
* **这条由 A/B 探针场景 `s1b` 抓到** —— 即 A/B 对铁律 4 **能**抓到（与铁律 1/2/3 不同，见 §3.4）。

### 铁律 5 — `_log` 必须解析成宿主模块的同一个 logger 对象

* 模块级全局不在两条白名单里；自己 `getLogger('modules.video_controller')` 会**换 logger 名**
  → 文件落点 / 级别 / 格式都变 → 行为不等价。
* **修法**：加**普通方法** `_log_()`，从 `sys.modules[type(self.p).__module__]._log` 取同一对象；
  调用点 `_log.debug` → `_log_().debug`（**带命中断言**）。
* ⚠️ **类体赋值不行**（无 `self`）；**`@property` 也不行** —— property 对象会**挡住**模块级 `_log`，
  而方法体里写 `_log.debug` → 取到 property 对象反而 `AttributeError`。

### 铁律 6 — 锁的定位器必须跟着代码搬家

* **成因**：回归套件里的 `_find_func` **只扫 `main.py`** → 方法搬走后取不到 → **假红**。
* **实例**：`round8_anim` H1.3 报「有 note_event=False」（实为定位器取不到函数）。
* **修法**（**不动产品、不动基线**）：新增 `CONTROLLER_SRCS` / `ALL_SRC`；`_find_func` 返回
  `(node, src)` 二元组、遍历 `main.py` + 全部 `modules/*_controller.py`；
  `func_src` / `func_statements` 改用**返回的那个 `src`**
  （`ast.get_source_segment` 必须用**产出该 node 的那份源码**）。
* **验收**：改完仍 `IDENTICAL`、**基线一字节未动** → 证明修的是定位器。
* ⚠️ **禁止**弱化成"找不到就跳过"（= 悄悄扔掉这条锁，它想守的闸门就没人看着了）。

### 铁律 7 — `os.` / `time.` / `random.` 是「裸 Attribute 根」

* **危险点**：只扫「裸 Call 的 name」**完全看不见**它们 —— 因为 `os.path.join(...)` 的
  `func` 是 `Attribute` 节点，不是 `Name` 节点。
* **实例**：W1-6 的 `_open_desktop_item_by_name` 用了 `os.`（5 处），
  但该方法体内**没有** `import os`（其他分支的局部 `import os` 不覆盖它）→ 在 `main.py` 靠
  **模块级** `import os`（L3）解析。搬走后 → `NameError`，**而逐字等价断言测不出来**。
* **修法**：逐个确认模块级 import，在控制器顶部补齐。
* **纪律**：**扫描必须包含"裸 Attribute 根"**（`os.` / `time.` / `random.` / `re.` / `json.` / `math.` …），
  不能只扫裸 `Name`。W1-6 块内**不含** `time.` / `random.` → 比 W1-2 干净。

### 铁律 8 — 桩（stub）打在「方法体里 `self` 的那张类」上 + 夹具噪声查表归一

* **桩必须跟着真实方法面走**（本项目**第 4 次**踩到）。桩打错类 → 测的是别的对象的方法。
* **夹具噪声查表归一**：夹具里的无关差异（时间戳、路径、随机种子）必须**先归一化再比较**，
  否则真差异会被噪声淹没、或噪声被当成差异。

## §3 ★ A/B 失效谱（四形态）与断言分层

### 3.1 四形态总表

| # | 形态 | 症状 | 险恶度 | 本轮实证 |
|---|---|---|---|---|
| 1 | **都没跑到** | 两侧都 0 次命中 → "无差别" | 中 | — |
| 2 | **都抛同一异常** | 两侧同异常 → "行为一致" | 中 | W1-4 `s5_err`（`hasattr` 判空不严，**父版本就有的既有缺陷**） |
| 3 | **跑了但落点被探针形态抹平** | 侧别达到、断言形态看不见差异 | **最险** | — |
| 4 ⭐ | **参照系不是父版本** | A 组拿到的不是真正的旧版 | **最险** | **W1-3 假对照表**（见 §3.2） |

### 3.2 ⭐ 第 4 形态实证：W1-3 的「假对照」

**成因**：快照 = **父版本 + 当轮转发壳**，而不是纯父版本。

```
快照：main.py  10481 → 10530 行   （+49 行 / 零删除）
      7 个方法**仍在 `RalseiPet` 里**
      md5  196560d7…  vs  父版本 6df92a3d…
```

⇒ 实际比的是「**有壳无搬** vs **有壳已搬**」——
**两版的方法都还在宿主上**，因此"归属"这件事根本不在比较范围内。
**鉴别力为零，且结论非常像真的**（会得出"搬运无影响"的假结论）。

**修法（三条，全做）**：
1. 取**父版本**（`--old-rev`，**不是** `git show HEAD:` —— 若改动已提交，HEAD 就是自己 → A == B）。
2. **md5 相同即 `SystemExit`**（硬闸门，不允许"探针退化成自己跟自己比"）。
3. 快照必须**自检布局**（见 §4 换行口径第 ④ 条：`git ls-tree HEAD:<subdir>` 会剥前缀 → 缺层）。

### 3.3 ⭐⭐ 断言分层（第 4 形态的直接推论）

> **A/B 的尺子必须两版都该全绿** ⇒
> **描述"搬运本身"的归属断言绝不能放进共享 e2e**（否则 A 组必红，A/B 报出的是
> 「断言放错层」而非产品缺陷）。
>
> **⇒ 归属断言进专测（`verify_wN_x_move.py` / `_unit.py`），行为断言进 e2e（`_e2e.py`）。**

**实例（本轮）**：W1-7 单写了一份 `verify_w1_7_move.py`（**23 PASS / 0 FAIL**，G1–G7 分组），
**没有**把"`handle_game_input` 已不在 `RalseiPet` 上"这类断言塞进 W1-3 的共享 e2e ——
否则 W1-3 的 A/B 对照（`--old-rev` 到 W1-3 父版本）会因"方法还在宿主"而**必红**，
报出的是假缺陷。

### 3.4 ⭐⭐ A/B 的结构性盲区（**必须记住的边界**）

```
桩：types.MethodType(fn, stub)   ⇒   self 即 stub（不是真控制器实例）
```

⇒ **铁律 1 / 2 / 3 / 4 在 A/B 中结构上不可见**：

| 铁律 | A/B 可见? | 为什么 |
|---|---|---|
| 1 `f(self)` | ❌ | `self` 是 stub，不是控制器 → `QTimer(self)` 不抛 |
| 2 模块作用域 | ❌ | 方法体在 A/B 里被直接调用，不经控制器模块的 import 环境 |
| 3 `__setattr__` | ❌ | stub 没有控制器的 `__setattr__` |
| 4 预声明 | ✅ | 由场景 `s1b` 抓到（读的是宿主属性，两侧都可断言） |

> **⇒ A/B 只回答「行为是否一致」。铁律由 e2e（真控制器实例）负责。**
> **别用 A/B 的"没差别"去否定铁律 —— 那是错的方向。**

### 3.5 A/B 纪律（每次必做）

1. 父 / 当前 **md5 必须不同**（探针未退化）。
2. 探针脚本支持 `--old-rev`，默认取**父提交**。
3. 两侧断言数、场景数一致（不可"某侧少跑一个场景"）。
4. **对照组要重复跑，先量尺子的公差**（本项目实测：同一文件 4 次跑，标记 **1/2/2/3**、
   特征率 **94/97/97/97** → **±2 条就是噪声**）。
5. **计数会被反向激励**（特征率 100% 那版内容最差）→ **永远先读原文再看计数**。

## §4 仓库换行口径（铁律 12，Wave 2 必须遵守）

**本机现状**：`core.autocrlf=true` + **无 `.gitattributes`** → **双口径**。

| 口径 | 文件数 | 含义 | 代表文件 |
|---|---|---|---|
| **双口径**（blob=LF / worktree=CRLF） | **14** | 仓库里存 LF，检出到工作区变 CRLF | `dialogue_ui.py` / `ai_driver.py` / `pet_ai.py` / `dialogue_system.py` / `sound_manager.py` / `entertainment_system.py` / `pet_interaction.py` / `energy_hunger.py` / `config_manager.py` / `customization_system.py` / `api_client.py` / `diag30.py` / `diag_screen.py` / `diag_state.py` |
| **单口径** | **58** | blob 与 worktree 同为 LF | `main.py`、**全部 `*_controller.py`** |

**四条后果**：
1. `git status` 对这 14 个**看不见差异** → **编辑必须保持原 EOL**。
2. **逐字节参照系只能用 `git cat-file blob`**；`git archive` 会把 LF→CRLF、**不能用**。
3. `git ls-tree` 会给特殊字符路径**加引号**（→ `os.makedirs` `WinError 123`）
   → 用 `-r -z` + `surrogateescape`。
4. `git ls-tree HEAD:<subdir>` **剥前缀** → 快照缺层 → **必须从仓库根列 + 自检布局**。

**实测复核（本轮）**：`main.py` = **482686 B / 8987 行 / CRLF=0 / LF=8986** → **单口径**，与上表一致。
⇒ **参与 Wave 2 的 `main.py` 与所有 `*_controller.py` 都是单口径（LF）→ 编辑用 `newline=''` 即可安全。**

> **待议项**：是否加 `.gitattributes` 统一为单口径（LF）。**这是改变仓库约定的动作，应先议后动**（见 §7）。

## §5 Wave 1 已建立的事实基线

### 5.1 5 个控制器（实测，本轮复核）

**全部 5 个都实现了 `__setattr__` + `__getattr__`，全部跳过 `'p'`** ⇒ 铁律 3 已系统性落实。

### 5.2 双向转发链（W1-7 实测全绿的三条路径）

1. **宿主 → 控制器**：`dialogue_ui.py` L1249 `self.parent.handle_game_input(...)`，
   `parent` 是宿主实例 → 宿主 `RalseiPet.__getattr__` 转发（`main.py` L514）。
2. **控制器 → 宿主**：`GamesController.__getattr__` 回落宿主实例字典 / 宿主类型 MRO。
3. **控制器 → 兄弟控制器**：`GamesController.__getattr__` **第 3 条白名单**扫
   `getattr(type(pet), '_CONTROLLER_ATTRS', ())`，跳过 `self`，探测 `getattr(type(_ctrl), name, None)`
   —— **这条是把 `self._abort_hide_and_seek` → `HideAndSeekController` 送过去的链**。
   首次桩运行抛 `AttributeError: _abort_hide_and_seek`，**反向证明了第 3 条白名单是不可缺的组件**。

### 5.3 宿主转发壳的安全边界（`main.py` L477–L499，三条缺一不可）

1. 只转发 `__dict__` 里**真的存在**的控制器实例 —— 用 `self.__dict__.get('games')` 而非 `self.games`
   （后者会递归回 `__getattr__` → `RecursionError`）。
2. `hasattr(ctrl, name)` 而非 `name in dir(ctrl)` —— 前者才走描述符协议。
3. 取不到就抛**原始的** `AttributeError(name)` —— 保住 `hasattr()` / `getattr(x, n, default)` /
   `copy` / `pickle` 探针语义。

⚠️ **绝不能用 `hasattr(ctrl, name)` 探测控制器是否"有"这个名字**：
控制器自己的 `__getattr__` 会**回落给宿主** → 反过来 `getattr(pet, name)` → 回到本函数 → **无限递归**。
**真机踩过**：`randomize_movement_pattern` 里的 `getattr(self, 'game_state', {})` 在 `__init__` 早期
（`game_state` 还没赋值）按下这条链 → **RecursionError 崩在构造期**。
⇒ 所以改成**显式方向**：只有"控制器**自己类上定义的方法**"才转发，属性/状态名一律不转。
