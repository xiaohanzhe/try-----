## 二、施工口径：只搬方法、不搬状态

严格遵守 H4/H5 铁律 **「只搬方法、不搬状态（转发壳 + 宿主 API）」**：

- 全部施法状态**仍留在 `RalseiPet`**：`_spell_stage` / `_spell_target_direction` /

- 控制器**不 import 任何项目内模块**（`logging` / `os` / `time` 三个标准库 +
  `PyQt5.QtCore.QPoint` 除外），避免重新接上初始化环。
- 4 个方法体**逐字搬运**，中文注释一字未改 —— 只有**两类白名单改写**（见下）。

### 两类白名单改写（均带命中计数断言）

REWRITES = (

> 改写脚本对改写**断言命中次数**（11 次：8 + 2 + 1），并做**反向归一**证明：

## 三、踩坑记录（六条，四条是真缺陷）

> **本节是 W1-1 报告的核心。** 六条坑里有**三条**「方法体逐字等价 100% 测不出来」。

### 坑 1：分组器漏标（见第一节，施工前拦截）

已述。**未造成损失，但差点把 290 行做成了 63 行。**

### 坑 2：`_log_` 是**实例方法**，机械改写会产出**裸调用** → `NameError`（★P0）

**这是我自己的改写脚本写错了，而且错误已经随 W1-4 出货。**

W1-4 的白名单改写是：

```python
("_log.", "_log_().", 2)
```

机械地把 `_log.debug(` 变成 **裸的** `_log_().debug(`。
但 `_log_` 是**实例方法**，裸调用没有 `self` → `NameError: name '_log_' is not defined`。

实测最小复现：

```
裸调用  _log_()      → NameError: name '_log_' is not defined
自身调用 self._log_() → 正常返回宿主 logger
```

**本项的 e2e E8（中断路径）第一次跑就炸在 L252**，直接证实。

**修法（两个方向都要修）**：

1. **本项**：11 处统一改成 `self._log_()`；
2. **W1-4 的存量**：`video_controller.py` 有 **2 处**同样的裸调用
   （L426、L505），**一并修掉**。

> **为什么 W1-4 当时没被发现**：那 2 处都坐落在
> `except Exception:` 兜底分支里，而 W1-4 的 e2e 全部场景**没有一个走到那个分支**
> —— 逐字等价（unit）看不见（`_log_` 与 `self._log_` 只差一个属性访问），
> e2e 走不到，A/B 也不触发。
> **这是本项目第 N 次「方法体等价 ≠ 产品能用」**，也是第 N 次
> **「没被覆盖的分支 = 没被测过的代码」**。
>
> **本项已加回归哨兵**（e2e E11）：静态统计 `self._log_()` ≥ 11，
> 并**动态**断言裸 `_log_()` 会抛错 —— 防止复发。

**→ 这条必须写进 H4/H5 施工口径，作为「第 6 条搬运铁律」。**

### 坑 3：`QPoint` 变未定义 → `NameError`（K2 同款，N 次复发）

`_tick_spell_flow` 的走动分支里 `QPoint(...)` 是**裸用**，靠 `main.py` 模块级
`from PyQt5.QtCore import QPoint` 解析。搬走后 → `NameError`。

**修法**：控制器顶部 `from PyQt5.QtCore import QPoint`。

> 与 W1-4 坑 1（`QTimer` / `QRect`）**完全同型**。
> **口径**：被搬方法体里出现的**每一个裸标识符**，都要在控制器模块里能解析。
> e2e E7 专门构造"走动分支"逼出这次构造。

### 坑 4：新状态名必须**预声明在宿主**（W1-4 坑 3 下推）

`_tick_spell_flow` 会写两个**宿主原本没有**的名字：

- `self._spell_seen_frame`
- `self._spell_cast_start_time`

按 W1-4 坑 3 的 `__setattr__` 白名单判据「宿主**已经拥有**这个名字」→
首次赋值时宿主没有 → **会落回控制器** → 状态劈成两份 → 坑 3 复发。

**修法**：在 `main.py` 的 `_spell_*` 状态块（**L766–767，在 `init_systems` 里**，
不是 `__init__`）显式预声明：

```python
self._spell_seen_frame = -1
self._spell_cast_start_time = None
```

> **⚠️ 预声明的位置有坑**：本项目 `RalseiPet` 的属性初始化**不在 `__init__`**，
> 而在 `init_systems()`（L750–767 区段）。我第一版 unit 探针**只扫 `__init__`**
> → 假红（报"没预声明"）。改成遍历**所有非搬运方法**才对。
> **这条也要进口径**：验证预声明时，扫描面 = 整个类体−被搬走的方法。

### 坑 5：控制器必须实现 `__setattr__`（W1-4 坑 3 同款，本项已预置）

`self._spell_stage = 'casting'` 这类**写**走 `object.__setattr__` →
默认落控制器自己的 `__dict__` → 劈裂。

`SpellFlowController.__setattr__` 与 `VideoController` **结构完全一致**，
转发判据同样是「宿主**已经拥有**这个名字」，并**跳过 `'p'`**。

e2e E3a/E3b 实测：控制器 `__dict__` **只有 `{'p'}`**，12 个 `_spell_*` 名字全部落在宿主。

### 坑 6（探针坑，代价最大）：A/B 探针的**三次假绿**

这一节记下来，因为 `verify_w1_1_ab.py` 先后**三次报"全绿"，三次都是假的**，
而且**每一次的假绿长得都像真的**。

#### 6.1 两侧都从 `main.py` 取源码 → 当前侧恒空

第一版把 A/B 两侧都写成"从 `main.py` 提取这 4 个方法"。
但当前版这 4 个方法**已经搬到控制器了**，`main.py` 里没有 → 当前侧 `n=0`。
探针只报了 `AB2b FAIL`，**后面所有场景项照样跑、照样全绿**
（因为两侧都是空壳，轨迹"相同"）。

**修法**：A 取 `git show HEAD:ralsei_pet/src/main.py`，B 取**工作区**
`ralsei_pet/modules/spell_controller.py`；提取函数改为**不预设宿主类名**，
并加硬退：`if len(old)!=4 or len(cur)!=4: sys.exit(3)`。

#### 6.2 只装"被直接驱动的方法" → 两侧同抛 `AttributeError`

第二版按方法名逐个提取、逐个装进 stub。但 `_tick_spell_flow` **会调**
`self._spell_interrupted_reason()` —— 没装 → 两侧**同时**抛
`AttributeError: 'Stub' object has no attribute '_spell_interrupted_reason'`。

**两侧轨迹逐字相同 → 全绿。** 而真相是：**代码根本没跑起来**。

**修法**：改成 `install_code(whole_src, NAMES)` **一次装齐 4 个方法**，
并**新增硬哨兵**：

```python
check('AB7 %-16s 两侧均无异常' % nm, ao['err'] is None and an['err'] is None, ...)
```

#### 6.3 `_log_` 不在 `NAMES` 里 → 装漏了

第三版装齐了 4 个方法，但 `_log_` **不在** `NAMES`，
绑定循环 `for nm in names` **遍历不到它** → 中断路径触发 `self._log_()` 时
抛 `AttributeError: 'Stub' object has no attribute '_log_'`。

**这次哨兵抓到了**（新加的"两侧均无异常"报 FAIL）。
**修法**：绑定循环改为 `for nm in list(names) + ['_log_']`。

#### 6.4 三次假绿暴露的**通用规律**

| # | 假绿表现 | 真相 | 哨兵 |
|---|---|---|---|
| 6.1 | 全绿 | 当前侧空壳 | 提取数硬退 |
| 6.2 | 全绿 | 两侧同抛异常 | "两侧均无异常" |
| 6.3 | FAIL（已抓到） | 装漏 `_log_` | 同上 |

> **规律**：**「A 和 B 结果相同」在 A、B 都失败时同样成立。**
> A/B 探针**必须**配一条"**两侧都要真的跑到了**"的独立断言，
> 否则它测的是"两个空壳彼此相等"。
>
> 这与 W1-4 报告 5.4 那条（"同样性"不等于"正确性"）是同一个家族的坑，
> 只是这次**连"跑没跑到"都要单独守**。
>
> **口径**：A/B 探针的每个场景，都要有①结果一致 ②**两侧均无异常** 两组断言。

## 六、口径沉淀（本项新增/强化）

### ★ 第 6 条搬运铁律：`_log` 改写必须带 `self.`

```python
("_log.", "self._log_().", N)   # 正确
("_log.", "_log_().",     N)   # 错 —— _log_ 是实例方法，裸调用 NameError
```

- 改写白名单里**不允许**出现裸 `_log_()`；
- 每个搬运项都要有**动态**哨兵：断言裸调用抛 `NameError`；
- 已经搬过的项（W1-4）要**回头复扫**同类裸调用。

### ★ 强化：A/B 探针必须守"两侧都真的跑到了"

每个场景两组断言：①结果一致 ②**两侧均无异常**。
否则测的是"两个空壳彼此相等"。

### ★ 强化：锁的定位器要跟着代码搬家（第 2 次复发）

搬完方法后 **grep 一遍**：谁在用 `main.py` 全文、或按方法名在 `main.py` 里找它。
找到就扩定位器。**禁止**弱化成"找不到就跳过"。

### ★ 补强：预声明扫描面 = 整个类体 − 被搬走的方法

`RalseiPet` 的属性初始化**不在 `__init__`**，在 `init_systems()`。
只扫 `__init__` 会漏。

### ★ 口径：`scan_method_index.py` 是下界，不是范围

它与排期方案不一致时**以方案为准**，并把漏标记入本轮报告。
根因是 `group_of()` 的**名字前缀启发式**（`_spell*` / `_start_open_with_spell`），
`_tick_*` / `_cast_*` 会漏。
