一、探针教训（本轮第 1 条，最该记的）
================================================================
❗ 零调用扫描第一版报 **56 个**"死函数"，其中含 `update_movement` / `update_animation`
   / `_on_reply` / `update_ai` —— **这些天天在跑**（用户亲眼看到宠物在动）。

根因：探针只收集了 `ast.Call` 的 func 名。
  而 Qt 的定时器/信号是 **`timer.timeout.connect(self.foo)`** ——
  `self.foo` 是 `ast.Attribute`，**不是 `ast.Call`** ⇒ 全部漏掉 ⇒ 假死报。

修法：被"引用"= `ast.Call` 的 func ∪ **任何 `ast.Attribute` 的 attr** ∪ 任何 `ast.Name`；
  并**跨文件**扫 `modules/*.py`（`dialogue_ui.py:1802 self.parent.handle_window_operation(raw)`
  就是靠跨文件扫描才找回来的）。

修正后 56 → **25**。**误报 31 个（55%）**。
⇒ 再次验证 MEMORY.md §4：「探针不保真 = 报假问题」「必须拿产品函数逐条复核」。

四、★ 真纰漏：孤儿状态位（一旦置 True 永不复位）
================================================================
判据：状态位是否有"周期性复位路径"。

  复位覆盖情况（在 update_animation L8043~L8066 每帧递减）：
    is_surprised  ✓ 有（2.0s）      is_happy   ✓ 有（3.0s）
    is_shy        ✓ 有（2.5s）      is_unhappy ✓ 有（2.0s）

  ✗ **无任何周期复位路径**：
    is_laughing     —— trigger_laugh 置 True，**无人复位**
    is_teasplashed  —— trigger_teasplash 置 True，**无人复位**
    is_victorious   —— trigger_victory 置 True，**无人复位**
    is_rolling      —— 无置 True 处（只 init + reset 置 False）
    is_sliding      —— 同上

  ⚠️ 唯一"看起来能复位"的地方是 `reset_special_states()` ——
     但它 **在产品文件里零调用**（只 .bak 里有同名定义）。

  实际危害评估（不夸大）：
    · is_laughing / is_teasplashed / is_victorious **本身零消费者** ⇒ 当前**零行为危害**
    · 但 `trigger_laugh()` 同时设 `is_happy=True` + `happy_timer=0`，
      而 is_happy **是有消费者的**（L8050 每帧读、3s 后复位）⇒ 这条链是通的 ✓
    ⇒ 定性：**"死状态位 + 半死 trigger 函数"**，属卫生问题 + 扩展陷阱
      （未来若有人读 is_laughing 做判断，会拿到"永久 True"的错值）。
