# 第143轮 · 对话链的超长截断不认 ASCII `.` —— 英文 NPC 被切成半个单词

> 日期：2026-11-03　｜　改动文件：`ralsei_pet/src/main.py`（**纯新增 31 行、零删除**）
> 判据：`check143` **27/0** · `mutate143` **30/0**（7 处破坏）· `recheck143_core` **36/0**

## 0. 一句话

对话链 `_clean_ai_reply` 第 3 步的切点集只有中文标点 + `\n`，**不认 ASCII `.`**。
英文 NPC 用 `.` 收句 ⇒ 一个切点都找不到 ⇒ `cut = -1` ⇒ 走 `t[:200]` **硬截**，
切在半个单词上。语料里 **英文 166 条超限回复中有 61 条（36.7%）被这样切坏**，中文 0 条。

## 1. 先核一个传了三轮的令牌（它是错的）

速查本 §7 一直写着：

> ★ **数句子不含 `…`、切点含 `…`**（两套标点）

本轮把它当**待证陈述**，逐处读源码取真值：

| 位置 | 用途 | 实际字符集 | 含 `…` |
|---|---|---|---|
| `event_speech._SENTENCE_ENDS` | 事件链截断（24 / 40 字） | `。！？!?` + `\n` + `…` | ✅ |
| `common113._sentences` | 训练侧数句子（`TOO_MANY_SENTENCES`） | 正则 `[。！？!?…]+` | ✅ |
| `main._clean_ai_reply` 第 3 步 | 对话链截断（200 / 220 字） | `。！？!?` + `\n` | ❌ |
| `extreme113.RE_SENT` | 极端词密度的分母 | `[。！？!?；;\n]+` | ❌ |

⇒ **"数句子不含 `…`"是错的**（`common113` 含它）。真正不含 `…` 的只有对话链那一处。
连带：第142轮 `measure142b.py` 里 `END` 常量的注释写「与 `common113._sentences` 同口径（不含 `…`）」
—— 那句话与实现相反，本轮一并订正（见 §8）。

**这个令牌必须改**：它把"哪条链不含 `…`"记反了，而下一轮想"统一标点"的人会照着它去改错地方。

## 2. 真缺陷：缺 ASCII `.`（四步取证）

### 2.1 有多少条会进这条分支

语料 = `第113轮/_evidence/raw30/*.jsonl`（77 个角色 / **5592** 条真机回复，冻结证据）。
`max_chars` 取每张卡的 `length_policy.max_chars`（**77 张卡全是 200**）。
超过 200 字的：**336 条 = 中文 170 + 英文 166**
（语言判定：CJK 字符占比 ≥ 30% 记中文）。

### 2.2 硬截有多少

复刻第 3 步（`cut = -1`，六个 sep 各做一次 `rfind`，取最大下标）：
**`cut == -1` 的中文 0 条、英文 61 条**。

61 条的尾字符**没有一条**是句末标点，全是半个单词：

```
[hy_bowll]           … 'tty fragile in'     | 被丢掉的：'side. Stil'
[hy_bowll]           … ' such a tough '     | 被丢掉的：'front. Som'
[hy_bowll]           … 'see beyond the'     | 被丢掉的：' cracks fo'
[hy_chujin_ketsukane] … 'tivities bring'    | 被丢掉的：' you satis'
```

这就是第135轮治过的"吊尾巴"，只是**对话链这一支从来没治**（135/136 轮改的是
`event_speech` 那条链，两者不是同一份实现 —— 第135轮注释里写明了"本轮不动那条链"）。

### 2.3 四个变体对照（同一批 336 条）

| 切点集 | 硬截（中/英） | 说明 |
|---|---|---|
| `。！？!?\n`（原） | 0 / **61** | 缺陷现状 |
| + `…` | 0 / 59 | **只解 2 条** |
| + `.` | 0 / **2** | ★ 采用 |
| + `…` + `.` | 0 / 1 | 多解 1 条，不值 |

**为什么不补 `…`（明明事件链里有它）**：

1. 收益 2/61；
2. 代价：`…` 会**抢走** 8 条本该切在 `。` 上、5 条本该切在换行上的切点（切得更晚）；
3. 而第141轮实测：`…` 在语料里 **97.4% 是当逗号用的** —— 切在它后面 = 切在半句话上。
   两条链的上限本来就不同（事件链 24 / 自主开口 40，切点稀缺；对话链 200，句号供给充足），
   **约束不同 ⇒ 分叉是刻意的**。

### 2.4 补 `.` 会不会伤到中文

中文样本里切点落在 `.` 上的 **15 条**，逐条看**全是真句末**：

| 角色 | 切口 | 后文 |
|---|---|---|
| `hy_ace` | `…Well, well, well.` | ` Let's not ma…` |
| `hy_axis` | `…EVEN IF IT MEANS TAKING LIVES.` | ` 我没有选择…` |
| `hy_moray` | `…Dinner's almost ready.` | ` 有什么我可以做的吗？` |
| `hy_starlo` | `…this ain't right.` | `” 我跟她说…` |

角色本来就在台词里夹英文，切在它的句末点上是对的。
上界统计：336 条里切在 `.` 上共 114 条，**疑似小数/缩写点 0 条**。

## 3. 改动（`ralsei_pet/src/main.py`，纯新增 31 行 / 零删除）

```python
cut = -1
_dot = t.rfind('.', 0, max_chars)
# 小数点守卫：`3.14` 的 `.` 后面跟数字 ⇒ 不是句末，往回再找一个
while _dot > 0 and _dot + 1 < len(t) and t[_dot + 1].isdigit():
    _dot = t.rfind('.', 0, _dot)
if _dot > cut:
    cut = _dot
for sep in ('。', '！', '？', '!', '?', '\n'):
    ...
```

★ 为什么 `.` **不**塞进 `for sep in (...)` 元组：循环里没法对单个字符加守卫
（小数点要跳过去往回再找）。`check143 B3` 钉的是**那一行赋值**，不是"元组里有 `.`"。

改动理由（含四变体表、`97.4%` 依据）**写在改动的地方** —— 改代码的人最先看那里；
`D1~D3` 三条判据钉住这些字面量，防止以后凭直觉把 `…` 补进去。

## 4. 行为面 A/B（不自造夹具）

把产品源码里 `if len(t) > max_chars:` 那一段用 **AST 抠出来**、`exec` 成函数再跑 ——
测的是产品本身，不是"我以为产品长什么样"。

| 判据 | 结果 |
|---|---|
| 英文硬截 | **61 → 2** |
| 中文硬截 | 0 → 0 |
| 截断结果变化 | 107 条（中 15 / 英 92） |
| 15 条中文的新尾都是句末标点 | 例外 **0** |
| 小数点守卫（`a…3.14…b` 不许切在 `3.` 后） | ✅ |
| 正控制：纯英文 → 切在 `.` / 纯中文 → 切在 `。` | ✅ |

**负控制**：把 `_dot` 整块删掉 ⇒ 与改动前**逐条一致**（0 条不一致）。
（第一版负控制用 `replace("'.', ", "")` 拆 `.`，把 `t.rfind('.',` 也拆了 ⇒
报出来的是 `TypeError` 崩溃，不是判据失效。**拆不干净 = 报假问题**，已改成按行删。）
