# 底座换型决策：ralsei:v2(3B) → ralsei:v3(4B)

**日期**：2026-09-19
**触发**：用户决定「**所有对话全权交给 AI，不给内置台词了**」（顶多保留"口头禅"式的固定句，目前还没有），
同一句话里带前提「**如果 AI 能足够生动**」，并明确**授权换模型**。
**结论**：**换**。新建 `ralsei:v3` = `qwen3:4b-instruct-2507-q4_K_M` + 原有采样参数；
`config.json` 的 `model` 由 `ralsei:v2` 改为 `ralsei:v3`。

---

## 一、为什么"3B 够不够生动"必须先用证据回答

用户的前提是个**可证伪的条件**，不是修辞。如果 3B 出的句子本身就寡淡/出错，
那"去掉内置台词"不是升级 —— 而是把每一句话都换成一句平庸的 3B 句子，**比内置台词更差**。
所以先做了一发**生产同形**的抽查（`probe_vividness.py` → `_evidence/probe_vividness.txt`）：

system = `assets/ralsei_persona.md`（= 生产单一真源）、user = 旁白 + 形状约束、
**不带**上下文/历史（= lean），过生产的两道后处理（`first_sentence(24)` → `guard_reaction`）。

### 3B 实测的三类硬错（每条都是真输出）

| 类型 | 输入场景 | 3B 的输出 | 问题 |
|---|---|---|---|
| **客服腔**（persona 第 40~41 行**明令禁说**） | 问候·早上 | 「早安，**有什么我可以帮忙的吗？**」 | 提示词拦不住底座自带的"helpful assistant"倾向 |
| **主体错位** | 累·低档 | 「哎呀，**你今天**过得怎么样呢？」 | 把自己的累说成主人的累 |
| **意思反转** | 拒绝·已经吃饱 | 「不客气啦，**我自己也饿坏了**。」 | 已经吃饱却说饿 |
| **旁白化** | 摔下来爬起 | 「我**扶着墙**站了起来，拍拍身上的尘土。」 | 写成舞台指示，还编了"扶着墙" |

→ 「AI 足够生动」这个前提，**3B 不满足**。

## 二、三向对比（`probe_models_compare.py` → `_evidence/probe_models_compare.txt`）

三个模型吃**同一份** persona、**同一套** options（temperature 0.85 / top_p 0.92 /
repeat_penalty 1.15 / num_ctx 8192）、过**同一道**闸门。所以差异只来自模型本身。

| 模型 | 事件类判退 | 事件首字(中位) | 事件整句(中位) | 全部整句(中位) |
|---|---|---|---|---|
| **3B `ralsei:v2`（原）** | 1 / 28（且另有 1 条**穿闸漏网**） | 530ms | 1214ms | 1192ms |
| **4B `qwen3-4b-instruct-2507`（新）** | **0 / 28** | 829ms | 1815ms | 1738ms |
| 7B `qwen2.5:7b-instruct`（参照） | 0 / 28 | 1041ms | 1996ms | 1908ms |

**质量上 4B 是决定性的赢**（原文见证据文件，摘几条）：

| 场景 | 3B | 4B |
|---|---|---|
| 拒绝·已吃饱 | 「不吃了不吃啦，我自己来一份。」 | **「吃饱啦，再吃会撑的～」** |
| 对话·上班被骂 | 「我明白，歇会儿吧。」 | **「被骂了啊……是因为什么事呢？」**（正是 persona 要的"先就着他那件具体的事问一句"） |
| 问候·早上 | 「早安，有什么我可以帮忙的吗？」（禁语） | **「早啊，主人～今天过得怎么样？」** |
| 累·低档 | 「感觉你也差不多了……」（主体错） | **「脑袋嗡嗡的……好像要睡着了。」** |
| 回执·翻到第3页 | 「好的，我已经到了第三页了。」 | **「翻到了第三页，还差九页呢。」**（信息不丢，还多给了进度） |

**7B 为什么不用**：它也更干净，但**更慢（首字 1041ms / 整句 1996ms，都劣于 4B）且更平**
（「谢谢你。」「好痒啊……」「早安！新的一天开始了。」）—— 没有任何一项指标赢 4B，没有选择它的理由。

**代价（要明说）**：CPU 推理（本机无独显），事件类首字 530ms → **829ms**、
整句 1214ms → **1815ms**。用"多等约 0.3~0.6 秒"换"每句话都是自己想出来的"。
另一面：**去掉内置台词之后，等不到 AI 就是沉默** —— 沉默比一句平庸的固定台词好，但确实要等。

## 三、换模型不能只改 config.json（这一步差点踩空）

`modules/api_client.py` **只发** `temperature` + `max_tokens`；
`top_p` / `repeat_penalty` / `num_ctx` 全部**继承自模型的 Modelfile**。

所以把 `config.json` 的 model 直接指向一个**裸模型**，会**静默**换掉采样参数。
正解是照原样派生：

```
# ralsei_pet/assets/ralsei.modelfile（本文件是唯一真源）
FROM qwen3:4b-instruct-2507-q4_K_M     # 原 FROM qwen2.5:3b
PARAMETER num_ctx 8192
PARAMETER temperature 0.85
PARAMETER top_p 0.92
PARAMETER repeat_penalty 1.15
PARAMETER num_predict 256
```

```powershell
cd ralsei_pet/assets; ollama create ralsei:v3 -f ralsei.modelfile
```
已核验 `ollama show ralsei:v3 --modelfile` 五项参数都在。
`config.json`（仓库模板）与**运行时** `E:\RalseiMemory\config.json` 都已改成 `ralsei:v3`。

> 另一个发现：`ralsei:v2` 的 Modelfile 里 SYSTEM 是 **"You are Qwen ... a helpful assistant"** ——
> 这正是客服腔的来源之一。虽然 App 每次请求都会用 persona **整体替换**它（实测 prompt_eval_count
> 1237 → 41），但底座的倾向压不干净。所以**代码级禁语闸是必需的**，不是可选项。

## 四、配套的代码改动（"全权交 AI"的前置条件）

没有这些，"去掉内置台词"会让禁语**直接显示给用户**：

1. **`speak_event(pool=...)` 的新语义**（`main.py`）
   * 传 `pool=[...]` → 保留内置台词（batch 1/2 的历史调用点，行为不变）；
   * **不传（`pool=None`）→ 不给内置台词**：AI 不可用/超时/判退时**一个字都不说**。
     不是漏兜底，是"沉默 > 一句写死的台词"。返回值同样是 `""`。
2. **判退后自动重采样一次**：同一提示词再要一次（temperature 0.85 会给不同样本）。
   **不改提示词**是为了保住 KV 前缀缓存（改写会让首字从 0.24s 掉回 0.85s 量级）。
   两次都判退 → 沉默。
3. **三道输出闸**（`modules/event_speech.py`，原本只有"出戏闸"一道）：
   * 出戏（AI 自我指涉 / 否认感官）—— 已有
   * **客服腔禁语**（persona 第 40~41 行那批）—— 新增
   * **旁白化**（句首括号/星号 = 舞台指示）—— 新增
   * 禁语表**按"动词块"收而不是按整句收**：三向对比里 3B 有一句
     「早安，有什么我可以帮忙的吗？」**穿过了**只写"有什么可以帮"的旧表
     （下一个字是"我"而不是"你/到/上"）。这条已写成回归锁 A20b。
