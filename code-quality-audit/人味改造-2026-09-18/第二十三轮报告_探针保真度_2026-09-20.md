## 1. 为什么盯上"探针保真度"

前两轮各撞一次**同一类错**，而且**两次都差点据此去改本不该改的东西**：

| 轮次 | 漏掉哪道闸 | 假问题长什么样 | 差点的误判 |
|---|---|---|---|
| 二十二 | 长度闸 | 量到"召回让回答 214 字" | 以为召回让它变啰嗦（其实 214 已被 150 砍过） |
| 二十二 | 动作闸 | 报出「（停顿了一下）」 | 以为产品漏删旁白（其实是探针没跑 0a） |
| 二十三 | markdown 闸 | 报出 `**…**` | 以为产品漏剥 markdown（其实是探针没跑 0b） |

> 通则（已入 MEMORY §5）：**探针的保真度本身也要被质疑**。
> 它报出的每个异常，先问「产品真的会这样吗」，再问「是不是我没复刻全」。

第三处（markdown）是本轮**跑完第一遍真机探针时**发现的：Q3 的"闸后"文本里
明明白白留着 `**当两位英雄相遇时……**`。按上一轮同样的流程求证：
拿这条回复喂产品的 `_clean_ai_reply`，`**` **确实被剥掉了**。于是当场决定：
既然要保真，就一次补齐。这条求证已经固化进 W2 的样本集
（`('那个结尾是说：**世界才会真正开始重置。**', None)` 一条，可复算）。

## 2. 补齐后的六道闸（与产品逐步对应）

`ralsei_pet/src/main.py::_clean_ai_reply` 的完整顺序（顺序即优先级，**不许调**）：

| 步 | 做什么 | 判退？ | 探针怎么拿判据 |
|---|---|---|---|
| 0a | 删句中括号动作旁白 | 删净则判退 | `from modules.event_speech import strip_action_parentheticals` |
| 0b | 剥 markdown 标记 + 去包裹引号 | 空则判退 | 正则**从 main.py 源码抽取**（`_load_md_strip_re`） |
| 0c | 出戏 / 客服腔 | **判退** | `from modules.event_speech import looks_out_of_character / looks_like_assistant_speak` |
| 1 | 自问自答续写截断 | 截空则判退 | 正则**从 main.py 源码抽取**（`_load_role_marker_re`） |
| 2 | 车轱辘话判退 | **判退** | 重写一份（唯一例外，见 §4） |
| 3 | 超长截断 | 否 | 常量 `AI_REPLY_MAX_CHARS` 源码抽取 |

### 为什么"判据"不能都 import，只能分三路拿

- **动作 / 出戏 / 客服腔**：判据在 `modules/event_speech.py`，该模块 **Qt-free** →
  直接 `import`，**绝不另抄**（项目铁律：判据只许有一处）。
- **常量与正则**（上限 / 角色标记 / markdown）：判据在 `src/main.py` 里，
  而 **import main 会拉起 PyQt 依赖链** —— 实测**托管 3.13 里根本没有 PyQt5**，
  探针必须能在裸 python 下跑。所以改为**从源码抽取**（正则/常量都取得到）。
- **第 2 步**：判据写在实例方法里、依赖 `self` 与 `difflib` 运行时，
  **取不出来**，只能重写 —— 所以必须配一条等价性锁（§4）。

> 一句话记住：**"能从源码拿的就别 import，能 import 的就别重写，
>  不得不重写的必须锁等价。"**

## 3. 为什么要复刻 0b / 0c（它们和内容有关）

上一版探针的说明写着"只复刻**与内容无关**的闸"。本轮推翻了这条界限：

- **0c（出戏/客服腔）必须复刻**：若不复刻，模型**真吐了客服腔**时，
  探针会把它当成一条正常回复去判 hit/bad → 可能报出一个**假 PASS**
  （bad 词表里虽有"有什么可以帮"，但那是探针自己在数，不是产品在拦）。
  复刻后它会被**如实判退**，与产品一致。
- **0b（markdown）必须复刻**：否则报出的"用户实际看到的文本"里带着
  `**` `#` `>` 这些产品早就剥掉的东西 —— 又是假问题。

两处都不是"锦上添花"，而是"不复刻就会说谎"。

## 4. 唯一不得不重写的判据：第 2 步（并锁死等价）

`_is_repeat_of_recent` 的两条互补判据（第十八轮定的经验值）：

1. 整体相似度 `difflib ≥ 0.82` **且** 长度差 `≤ 6` —— 抓"只改两三个字"的整句复用；
2. 最长公共匹配块 `≥ 12` 字 —— 抓"整体 ratio 不到 0.82，但有一大段原样搬来"。

归一化先去掉 `[\s，。！？!?、~…—\-（）()「」“”"'’*`]`；文本与样本都要求 `len ≥ 6`。

### 等价性怎么保证（不止靠肉眼）

- **`check_probe_fidelity.py`**：拿 26 条样本同时喂「探针复刻品」与「产品真身」，
  **逐条比对输出**，必须 26/26 一致（证据 `probe_fidelity_2026-09-20.txt`）。
- **W2 锁**：把这件事做成回归 —— 每次 G2 都跑一遍 26 条样本的等价比对。
- **W3 锁（鉴别力）**：把 `recent` 抽掉后，车轱辘话样本**必须不再判退** ——
  证明第 2 步真的在跑，W2 不是恒真。

## 5. 探针新增：判退（RETN）单列 + recent 逐题累积

- **`recent` 由探针自己维护**：产品里 recent = "他自己最近说过的回复"；
  探针里就是**本轮已产出、且真的会显示给用户的那句**（判退的不进 recent，
  因为产品里判退的会重采样、用户看不到它）。
- **判退计为 `RETN`，单列不算分**：探针**不模拟重采样**（那要多打一次模型）。
  这一点在报告头与尾部都写明了，避免把"会被重采样"误读成"用户看到了这句"。
- 真机 12 题本轮 **0 判退** —— 说明当前输出风格没有触发护栏。

## 8. 本轮踩的三个坑（都是"夹具在说谎"的同型）

W 组一进 G2 就连红三次，每次都是**断言/夹具本身**的问题，不是被测物的问题：

1. **裸子串命中注释**：`'import main' in 源码` 命中了探针注释里的
   "为什么不直接 import main 里的…" → 假红。改走 `code_no_comment`（剥注释）。
2. **剥注释仍命中 docstring**：探针的 docstring 里写着"（不 import main，
   只正则抓常量）"——docstring 是 STRING，被 `code_no_comment` 保留 →
   抹平空白后变成 `importmain` → 又假红。正解：
   **"有没有 import 语句"看 `code_only_src`（连字符串一起剥），
   "是不是从 main.py 抽的"看 `code_no_comment`（要看得到字符串里的 `main.py`）**。
3. **`runpy` 不加脚本目录**（最隐蔽）：`python verify_persona_chat.py` 会把脚本
   目录放进 `sys.path[0]`，于是 `import verify_persona_worldview` 成功；
   而 G2 是用 `_seed_runner.py` 以 **`runpy.run_path`** 执行的 ——
   **runpy 不会自动加脚本目录** → 同一句 import 在 G2 里 `ModuleNotFoundError`。
   表现为"**单跑绿、进 G2 红**"。修法：W 组显式 `sys.path.insert(0, HERE)`。

> 通则（与 MEMORY §5 同源，再次验证）：**先怀疑夹具，再怀疑被测物**。
> 三次"红了"没有一次是被测物的问题。
