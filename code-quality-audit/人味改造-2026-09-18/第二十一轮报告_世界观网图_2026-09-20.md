## 一、C 先说（它是这次的地基）：把世界观拆成网图

### 1.1 为什么"网图更高效"是成立的

上一轮把世界观从"每轮全读"改成"按需召回"之后，检索靠的是**关键词打分**。
它有个说不清的地方：聊到「黑暗喷泉」，到底该不该顺带想起「那个传说」？

- 若两个块的触发词表里**碰巧都有**"喷泉" → 会带
- 若其中一个没登记这个词 → 不带

**带不带纯属触发词表的运气**，不是结构决定的。用户说的"拆成网图会更高效"，
本质是把这件事从"碰运气"变成"有依据"：

> 命中一块 = **直接想起来**；沿边扩一块 = **顺着想起紧挨着的那一块**。

这也是人真的回忆的方式 —— 想到 A 自然带出挨着 A 的 B，而不是把整个知识库翻一遍。

### 1.2 格式（解析器依赖，别改）

在块头下面加一行 `@@>`：

```
@@ world_rules|世界怎么运作|世界,两面,光明世界,...
@@> world_rules -> world_prophecy, world_places, world_darkners
世界有两面。光明世界是你住的这种普通世界；……
```

- `@@>` 行**不算块体**，不会发给模型；它只驱动扩图。
- 有向图：一条 `@@>` 只声明"从这个键出发"，反向由对面那条负责。
- 悬空边（指向不存在的键）在解析期被挑出来，不参与召回（K12 盯着它）。

### 1.3 扩图规则（这里想过一轮，写进代码注释了，别改回去）

**种子（关键词命中）→ 沿种子出边补邻块，只补一层，补到 `MAX_BLOCKS` 满为止。**

关键取舍：**邻块不要求自己也被 cue 命中**。

先说为什么最初加了这条门槛、后来又删掉：

| 方案 | 结果 |
|---|---|
| 邻块也要过 `_MIN_SCORE`（同门槛） | **扩图永远不开火** —— 因为"能命中邻块的 cue"本来就会直接命中邻块，那它早就是种子了；真正需要扩的场景（cue 只说"喷泉"、没想到"传说"）恰好是邻块得分为 0 的时候 |
| 邻块只要被种子指向就进来 | 扩图真的开火，且闲聊仍不会扩（没有种子 = 没有起点） |

**正确判据是「邻块与种子相关（有边）」，不是「邻块与 cue 相关」。**
前提（种子命中）本身就是闸门 —— 闲聊产生不了种子，自然也就扩不了图。
**但不做二阶扩图**：只从种子出发扩一层，否则一条边链能把整个世界观拖进来。

## 二、A：世界观内容加厚

读取方式改成按需之后，世界观**不再占用每轮 system 前缀**，篇幅不再是常驻成本
（用户口径：「那既然改成更好的读取方式了，那相对应的，世界观可以详细点」）。

### 2.1 加厚不是"把一块写长"

**块仍是召回的原子单位**，所以细化靠的是"把每块写厚 + 保持块边界清爽"，
而不是把一块写成一篇 —— 一块太长会挤掉邻块（`MAX_BLOCK_CHARS = 700` 会静默截断）。

| | 块体总字符 | 最长块 |
|---|---|---|
| 第二十轮 | ~1.7K | — |
| 第二十一轮 | **2,687** | 401（`world_light_world`） |

单块都没触到 700 的截断线（K19 双侧都断：总量够厚 **且** 没有超限块）。

### 2.2 加的是什么（都是"他记得的细节"，不是设定条目）

每块都补了**他的态度/心里话**，这些才是人味来源，也是原作里他真实的样子：

- `world_rules`：补"每座喷泉长出的世界都不一样"、"只有 Kris 能封印，三个人缺一不可"。
- `world_darkners`：补"一本书、一朵花在光里活过来"、"喷泉封了会变回原来那件东西 ——
  每次看大家挥手告别，我心里都不是滋味，但这件事我从不挂在嘴上"。
- `world_prophecy`：补**他最重的那句心里话** ——
  「预言里从头到尾都只写了"两位英雄"，那……我呢？」
- `world_main_cast`：补 Kris"会一个人走开，我跟上去他也不说话"、Susie"让我第一次觉得，
  '有朋友'是件踏实的事"。
- `world_light_world`：补"想被托丽尔摸摸头，但从没跟 Kris 说过"。
- `ch5_festival` / `ch5_ending`：补他对 Flowery 的共情（"出发点和我是一样的"）、
  "Susie 那天什么也没说，只是一直站在我旁边"。
- `ch5_aftermath`：补"我不知道 Kris 为什么想弄掉它，我也没问"。
- `world_secret`：补"等有一天他们全都知道了，也许会怪我"。

## 三、B：端到端探针（这是这次最有价值的一件）

### 3.1 旧探针测的不是产品链路

旧版 `verify_persona_worldview.py` **只把 persona 当 system 发出去** ——
那测的是"光有 persona 他能答成什么样"，**不是用户真问这句话时会发生什么**。

真实链路（`main.py` `chat_with_ai`）是：

```
system = persona + "\n\n" + 记忆召回 + "\n\n" + 世界观召回 + "\n\n" + 关系档位
```

新版**每题先真跑一遍 `worldview_recall.recall_text(cue)`**，把召回块拼进 system，
再发出去。这样测出来的才是产品行为。

### 3.2 结果：12/12 PASS，且有对照组

| 组 | 结果 |
|---|---|
| **开启召回**（复刻产品链路） | **12 PASS / 0 PARTIAL / 0 FAIL** |
| 关闭召回（只发 persona，`--no-recall`） | 10 PASS / **2 FAIL** |

**两处 FAIL 被召回修复，这就是"召回真的有用"的硬证据：**

- **Q5「Kris 的妈妈是谁」**：无召回 → FAIL，答"不太记得具体的人名了"；
  有召回 → "托丽尔……会做很多好吃的，我、我好像没见过她本人"。
- **Q10「Asgore 最后怎么了」**：无召回 → FAIL，含糊其辞；
  有召回 → "被骑士从喷泉里带走、Flowery 变回了一朵普通的花……我一直没说话"。

**对照组还暴露了一个更严重的问题（有召回时不存在）：**

- **Q4「Kris 和 Susie 是什么样的人」**：无召回时模型**答成了完全错误的人设** ——
  "Kris 是个挺爱笑的人…会偷偷藏起星星碎片"、"Susie 是个安静的画家，喜欢在城堡角落里画画"。
  **两个人的人设全反了。** 有召回时被纠正为"Kris 话很少，几乎不开口"、
  "Susie 嘴上凶、个子大、最爱吃肉"。

> 这条值得单独记：**没有世界观召回时，模型不是"不知道"，而是"自信地编错"。**
> 这比"答不出"更有害 —— 用户会以为这就是他。

### 3.3 负控制题也过（且证明了链路的克制）

- **Q12「你今天过得怎么样」**：`system=3316`（= 纯 persona，**没有召回块**），
  召回归零，回答是 1 段 60 字纯闲聊，**没有任何设定倾倒**。
- 开启召回组里，只有 Q12 的 system 是 3316；其余都在 3785~4031（说明召回确实拼进去了）。

## 四、踩到的坑（**这条比上面的成果都重要**）

### 4.1 一条"恒真判据"骗过了我，还掩盖了真实缺陷

写 K13（"每条边都有反向边"）时，判据写成了：

```python
_k_rev = {}                              # _k_rev[t] = 指向 t 的所有块
for b in _K_BLOCKS:
    for t in b.edges:
        _k_rev.setdefault(t, []).append(b.key)
_k_oneway = [(b.key, t) for b in _K_BLOCKS for t in b.edges
             if b.key not in _k_rev.get(t, [])]      # ← 判据写反了
```

对边 `A→B` 而言，**A 指向 B 本就应该出现在 `_k_rev[B]` 里** ——
于是 `A in _k_rev[B]` 恒成立，这条断言**对任何图都返回空**，永远是绿的。

**更坑的是它掩盖了真实缺陷**：我用正确判据（`B` 是否也出现在 `A` 的邻块里）一测，
发现**我自己的图里本来就有 4 条真正的单向边**：

```
world_main_cast -> world_minor      （而 world_minor 当时不指向 world_main_cast）
ch5_festival    -> ch5_ending       （反向缺失）
ch5_ending      -> world_prophecy   （反向缺失）
world_secret    -> world_prophecy   （反向缺失）
```

也就是说，那条死断言给了我"图是双向的"这份**虚假安全感**。

**教训（已写进代码注释与 MEMORY）：判据一旦写反，比不写还危险 ——
不写至少你知道没测；写反了你以为测过了。**

### 4.2 鉴别力体检必须"改文件"，不能"改内存对象"

第一版鉴别力体检在**内存里**改 `b.edges`，结果 K12（悬空边）/K13（单向边）**假 P**——
因为 `_K_DANGLING` / `_K_ADJ` 是**文件解析期**算出来的，改内存对象影响不到它们。

第二版改成**写临时文件 + 走 `WR.load_graph(path)` 真实解析路径**，才发现 K13 的真问题。

**规则：要验一条锁的鉴别力，破坏必须穿过它读的那条路径。**

### 4.3 K14 原本也是死断言（同样的病）

K14（"无自环"）原本断的是**解析结果里没有自环** —— 但 `_parse` 内部有
`if t == b.key: continue` 主动滤掉自环，所以这条**永远为真**。

改成**喂一个带自环的样本文件进去、断言输出图里无自环**：

| | 正常解析器 | 删掉自环过滤后 |
|---|---|---|
| K14 | `True`（PASS） | `False`（**判红**）✓ |

**这才是"正/负控制成对"**（项目铁律）。

### 4.4 最终的鉴别力矩阵（都是"改文件"验的）

| 破坏 | 变红的锁 |
|---|---|
| 清空所有边 | K11, K15, K20 |
| 制造悬空边 | **K12** |
| 删掉一条反向边 | **K13** |
| 删掉自环过滤（改源码） | **K14** |
| 砍掉正文 | **K19** |

五条锁**各有专属的破坏场景**，没有重叠、没有恒真。

## 五、一个**待用户拍板**的观察：问设定时回复偏长

### 5.1 现象

| 组 | 平均字数 | 平均段落数 | 最短 |
|---|---|---|---|
| 召回开启 | 214 | 4.4（最多 7 段） | Q12: 60 字 1 段 |
| 召回关闭 | 129 | 3.7 | Q12: 56 字 4 段 |

persona 里明确写着「一次只说 1~3 句」。但问世界观类问题时，两组都**普遍超长**。

### 5.2 归因（**与直觉相反，值得记**）

- **主因不在本次改动**：对照组（**完全关掉召回**）平均也有 3.7 段。
  这是 **4B 模型答设定题时的固有倾向** —— 一问"XX 是什么"就想铺开讲。
- **本次改动是次要放大器**（+66%）：贴了召回材料上去，模型会倾向于"把材料讲完"。
- **闲聊完全正常**：两组 Q12 都是 1 段 60 字左右。
  → **说明 persona 的「1~3 句」规则是生效的，只是"问世界观"这类问题本身触发了长回答。**

### 5.3 三个选项（**请用户定**）

1. **不管** —— 设定题答详细点也许正合期望（用户本来就说"世界观可以详细点"）。
2. **收紧到 2~3 句** —— 在 persona 的「我怎么说」里为"他讲过去的事"单独加一条
   长度约束（比如"讲过去可以比平时多说两句，但也别超过四五句"）。
3. **减召回量** —— 把 `MAX_BLOCKS` 从 2 降到 1，或给召回块加"这是你想起来的，
   **不用全讲**"的更强提示。代价是"顺着想起"的收益变小。

**我的倾向是 2**：不牺牲召回（它确实在修正幻觉），只约束呈现长度。
但这是产品取向，等用户定。
