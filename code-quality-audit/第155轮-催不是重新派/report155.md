# 第155轮 · 「催」不是「重新派」

> 用户口径（逐字，第154轮沿用）：「**按照人类的逻辑来就好**」
>
> 已经在办的人，被催一句**不该被打回起点**。

---

## 1. 结论

第154轮只做到「同一件事重说一遍**不写假记忆**」，**没有**解决"重说一遍就重新计时"。
本轮把这条遗留做掉：

| 位置 | 改什么 | 效果（实测数值） |
|---|---|---|
| `assign_errand` | 同一件事（地点 + 事由都不变）⇒ **原样返回手上那条**（不覆盖、不重计时、不清进度、不写记忆），且这条短路放在**门控之前** | `status` 仍 `working`、`arrive_at` 仍 90、`finish_at` 仍 390、`working_positions()` 里那条**还在** |
| `_errand_ack` | 「催」有**自己的一句 brief**：说明"他已经在办、这次没有重新出发也没有重新计时"，并按 `prev.status` 分"还在去的路上 / 已经到了正在办" | 提示词从 **118 字（与首次一字不差）** 变成 **185 字且说的是"已经在办"** |

判据 **37/0**、负控制 **12 处各断言恰好变红**、探针 **4/4**、复检 **40/0**、
全量回归 **PASS=7138 / FAIL=0 / 154 套件全 IDENTICAL**。

## 2. 改前实测（不靠读代码推断）

`probe155` 的「改前」一半，数值都是跑出来的（`ErrandBoard` 默认 `travel=90 / work=300`）：

他 `t=0` 被派去 `oneshot.barrens.Blue` 擦柜台，`t=100` 时**已经到点、正在办**。
这时把**同一句话**再说一遍：

| 量 | 改前 | 后果 |
|---|---|---|
| `status` | `working` → `traveling` | **进度清零**，被打回起点 |
| `arrive_at` | `90.0` → `190.0` | 又要"再走一趟"（**推迟 100 秒**） |
| `finish_at` | `390.0` → `490.0` | 办完时间整体推后（**推迟 100 秒**） |
| `working_positions()` | `[('ralsei', 'oneshot.barrens.Blue')]` → `[]` | **位置钉住资格被撤** ⇒ 下一拍 `roam.put` 就把他从目的地撤走。用户看到的是"我催了一句，他反倒掉头往回走" |
| 返回对象 | 新的（`is` 旧条 = `False`） | 宿主手里那份引用成了孤儿 |
| `done` / `result` | `0` / `''` | 旧那条不进结果 |
| ack 的 brief | 与第一次**一字不差**（都是 **118 字**，都写「他已经在路上了」） | 模型只会说"好，我让他去了"，而他其实已经干了一会儿 |

其中「位置钉住资格被撤」是**最可见**的那条：`npc_errand` 的 `working_positions()` 是
宿主每拍压 `roam.put()` 的唯一来源，它一空，人就从目的地被撤走。

## 3. 两处补

### 3.1 `assign_errand`：同一件事 ⇒ 原样返回

```python
_prev = board.active_of(npc_id)
if getattr(board, 'enabled', False) and _prev is not None \
        and _errand_same_job(_prev, dest_scene, what):
    _log.info('催（不重启）：%s 已经在办「%s」（%s，状态=%s）', ...)
    return _prev
```

三条理由都写进代码注释了，这里只列结论：

1. **不覆盖**：`assign` 是"覆盖"，一调就造新 `Errand` ⇒ 时间重算、状态归零。
2. **在门控之前**：没重新派 ⇒ **不需要新的通行许可**。反例是真会发生的 ——
   他已在目的地干活，这时球被拿走，门控判他"去不了" ⇒ 这次"催"会写下
   「我本来要去 X，但去不了」，而他**人就在 X**。这是第154轮那类**假记忆**的同型。
3. **带 `board.enabled` 闸**：类属性那里的契约是「关掉它 ⇒ `assign_errand()` 恒 `None`」。
   若这里返旧条，就是"看板不推进"却回报"已派出"，用户会一直等一件永不发生的事。

> ★ 顺带删掉第154轮留在这条链上的**第二份判断**
> （`if _new is not None and _prev is not None and not _errand_same_job(...)`）。
> 短路在上面已经 `return` 过 ⇒ 能走到那一行，`_errand_same_job` 必为假，
> 那是**永远为假的第二份规则**。删掉之后 `C4`（"两侧各只调一次"）才有意义。

### 3.2 `_errand_ack`：给"催"单独一句

```python
_same = (prev is not None and _errand_same_job(prev, dest_scene, what))
if _same:
    _st = getattr(prev, 'status', None)
    if _st == npc_errand_mod.WORKING:   _doing = u'他已经到了那里、正在办'
    elif _st == npc_errand_mod.DONE:    _doing = u'他其实已经办完了'
    else:                               _doing = u'他还在去的路上'
    brief = ('…这件事**他已经在办**（%s），这次**没有**重新出发、也没有重新计时。…' % …)
else:
    brief = <原「他已经在路上了」>
```

★ 为什么读 `prev.status` 而**不**让调用方另传一个状态：催不覆盖 ⇒ `prev` 就是看板里
那条**活对象**，它的 `status` 是当前真值。另传一份 = 同一件事两个真相（第136轮口径）。

★ 台词一个字没写死 —— 只给**事实**，说成什么样仍由模型决定（第114轮口径）。

## 4. 三处"差一点写错"

### ① 门控顺序（第一版会写假记忆）

最自然的写法是"在门控之后判同一件事"。那样门控一旦拒（球被拿走），
催一句就会落一条「我本来要去 X，但去不了」—— 而他**就在 X**。
`A11` / `P4` 就是钉这条的：门控拒 + 同一件事 ⇒ **仍返旧条、零记忆**。
负控制 `A12` 成对：门控拒 + **真改派** ⇒ 照旧 `None` + 一条"去不了"（说明门控没被废掉）。

### ② 冗余的第二份判断（第154轮留下的）

见 3.1 末尾。它不会报错，只会让"同一条规则"有两个家 —— 以后改一处忘一处。
`C4` 用 AST 数"两侧各只调一次"把它钉住。

### ③ ★ 探针夹具越过了被测分支

`probe155` 第一版写 `h2.npc_errand.step(1e18)` 想把他推到"正在办"，
结果**直接推过了 `finish_at`** ⇒ 差事进 `done`、`_active` 里没了 ⇒ 再"催"就是
**重新派**（`prev=None`）⇒ `P2` 当场 red。

不是产品坏了，是**夹具越界**：`step` 的入参必须落在 `arrive_at` 与 `finish_at` 之间。
改成 `_time.time() + 100.0` 之后 P2 绿。**这就是"报红先怀疑判据/夹具"那条的又一次兑现。**

## 9. 遗留 / 结转

1. **一次改派只留一条痕**：连续改三次，记忆里是三条独立的"又被派去了"，没有
   "最早那件"的追溯聚合。人会说"我本来要办三件事，一件都没办完"。
2. **三条 ack 的"用户不在场也照样发起"仍未统一**（派活 / 叫停 / 交差）—— 第153轮 §8.3 原样保留。
3. 第150~153轮结转未动：纯空格 `npc_id` 不拒 · 地点别名只到作品级前缀 ·
   否定闸整句从严 · `_item_enter_scene` 无内部调用者 · `current_scene` 双语义 ·
   `max_sentences` 读了不用。
