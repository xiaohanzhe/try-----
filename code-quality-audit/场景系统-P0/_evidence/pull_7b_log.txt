本文件原为废弃脚本 E://Download//_tmp//_pull7b.py 的原始 stdout 捕获（12006 行，
含进度条二进制噪声），已替换为可读摘要。

## 发生了什么

1. 用 `ollama pull qwen2.5:7b-instruct-q4_K_M`（经代理 7897）拉取 7B
2. 下载缓慢且不稳定：速度在 70 KB/s ~ 12.9 MB/s 之间大幅波动
3. 一度误判为"已下满、卡在合并分片"（详见下方教训）
4. 于 48.08%（2.097 / 4.361 GB）时**主动停止**，把决定权交回用户

## ★ 教训：判断进度不能看文件大小

| 看什么 | 看到什么 | 真相 |
|---|---|---|
| `blobs/sha256-xxx-partial` 文件大小 | **4.361 GB** | 稀疏预分配，**与进度无关** |
| `/api/pull` 的 completed/total | **2.097 / 4.361 GB** | ★ 唯一可信的进度源 |
| 16 个 `-partial-0`~`-partial-15` | 每个 58~68 字节 | 进度标记，**不是数据分片** |

## 恢复方式

磁盘上留下 2.1GB 的 `-partial`，重新 pull 会**从这个进度续传**（不会从头）：

    ollama pull qwen2.5:7b-instruct-q4_K_M

## 停止理由

1. 不影响本轮任何交付物（路由层/回归锁/G2/报告均已推送）
2. 用户诉求（1~3s）下 7B 大概率不达标，且真瓶颈是 prompt eval，换 7B 只会更慢
3. 先把「要 / 不要 / 试 Vulkan」的决定权交回用户
