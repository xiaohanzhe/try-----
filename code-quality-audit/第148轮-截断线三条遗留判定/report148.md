## ① 对话链兜底：真的有病吗

`ralsei_pet/src/main.py` 的 `_clean_ai_reply` 第 3 步：

```python
cut = -1
...（先 `.`，带小数点守卫；再 `。！？!?` + `\n`，取最靠后）...
t = (t[:cut + 1] if cut > 0 else t[:max_chars]).strip()
                          ^^^^^^^^^^^^ 第 4 处硬截
```

### 量出来的数（`_tools/measure148.py`，`_evidence/measure148.json`）

语料：77 人 / **5592 条**真机回复（仓库内冻结证据 `第113轮/_evidence/raw30`）。

| 指标 | 数 |
|---|---|
| 超 `max_chars` 的回复 | **336**（中文 170 / 英文 166） |
| 走到兜底（`cut <= 0`） | **2**（中文 **0** / 英文 **2**） |

| 行为变化 | **0 条** |

### 这 2 条为什么不切在词中（`_tools/diag148.py`）

| 样本 | 长度 | 第 200 位 | 结果尾部 |
|---|---|---|---|
| `hy_dalv` | 280 | `.`（**不在** `_WORDY`） | `…enough to notice` |
| `ut_napstablook` | 208 | 空格（**不在** `_WORDY`） | `… oh, here we` |

`_hard_cut` 的判据是"切点**两侧都是 ASCII 词字符**"。这两条的第 200 位一个是句号、
一个是空格 —— 都不是词字符 ⇒ 判据**正确地**说"没切在词中间"。

★ 这不是判据漏网，是判据**在真实样本上的正例**：`hy_dalv` 若为了"统一"而退，
会从 200 字退到 **193**（最后一个空格在第 193 位），**白丢 7 个字**换不到任何完整性 ——
`…to notice` 本来就是完整的词。

### 为什么不合并进同一份实现

技术上很便宜（`main.py` 已经 `from modules.event_speech import ...`，加个公开别名即可），
但：
1. **无可测收益**（0 条变化），改了也无法证明任何改善；
2. `_clean_ai_reply` 是对话链**主护栏**，`persona_chat` 一串判据钉着 —— 风险非零、收益为零；
3. 更关键：两条链的**切点集本来就不一样**（对话链不含 `…`，第143轮登记的刻意分叉）。
   硬统一兜底，会把"两条链各自明确"变成"看起来统一、其实只有兜底那行一样"。

⇒ 第147轮那句"一处实现取代三处复刻"指的是**事件链内部**那三处；对话链是**另一条链**，
它的兜底没有病。**不改，并把触发条件记在这里**：若将来 `_WORDY` 或切点集变动，
重新跑 `measure148.py`，`old_midword` 一旦 > 0 就该重开这个判定。

## ② 中文 959 条"24 字内无标点可切"

第145轮实测：事件链 24 字链上，中文有 959 条找不到句末标点 ⇒ 硬截。
第147轮加退让之后**这些一条都没变** —— 因为它们**不该变**。

依据是第147轮那条最贵的课：`str.isalnum()` 对 CJK 也返回 True。中文**每个汉字都是独立单位**，
"切在字与字之间"不产生"半个词"。第一版判据把中文也算进"切在词中"，结果中文被改坏
**151 / 57 条**（退到空格往往落在英文人名前，白丢 4~8 个汉字），改 ASCII 白名单后归 0。

⇒ 中文 959 条是**正常现象**，不是遗留缺陷。真要"更自然"只能引入中文软切点（在 `，` 处切），
但 24 字内连 `，` 都没有才叫"无标点可切"，那就无处可退。**不改。**

## ③ `extreme113.RE_SENT` 的"两把尺"

| 位置 | 正则 | 用途 |
|---|---|---|
| `第113轮/_tools/extreme113.py:44` | `[。！？!?；;\n]+` | **每句指标的分母**（`excl`/`caps`/`emph`/`ellip`/`apol` 都是 `计数 / n_sent`） |
| `第113轮/_tools/audit_persona113g.py:37` | `[。！？!?…]` | 从人设里**筛出"像一句话"的引号**（第二版判据，注释自己写着"还是错"） |

第145轮把它记成"缺 `…` 多 `；;`"，隐含"应该统一"。核完源码后：

1. **分母那把我支持现状**：`；;` 当句末、`…` 不当 —— 与**对话链切点口径完全一致**
   （第143轮实测 `…` 在语料里 97.4% 当逗号用）。当分母用的尺必须跟"人怎么断句"一致，
   不能跟"哪里能切"混为一谈。
2. **筛例句那把已废弃**：`audit_persona113g` 的第三版判据换成了 `RE_FRAME`
   （祈使框架 + 台词），`RE_SENT` 只剩"候选引用"这一层过滤。改它等于给废代码续命。
3. **冻结证据的可比性**：`extreme113` 产出的数字进了第113轮的训练卡与后续多轮引用
   （`247 条` / `38/76` / 5592 条语料的句数分布）。改尺 = 历史数字全部不可比。

⇒ **不改**，并把"两把尺量的是两件事"写进记忆，避免下一轮又当成 bug 去治。
