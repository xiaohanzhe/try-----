## 1. 两套袋子（原作数据结构，逐条实证）

### 1.1 暗世界：`global.item[12]` + `global.keyitem[12]`

`scr_itemget`（`_evidence/gml/gml_GlobalScript_scr_itemget.gml`）:

```gml
function scr_itemget(arg0) {
    i = 0; loop = 1; noroom = 0;
    global.item[12] = 999;          // 哨兵：第 12 格永远不为 0
    while (loop == 1) {
        if (global.item[i] == 0) { global.item[i] = arg0; break; }
        if (i == 12) { noroom = 1; break; }
        i += 1;
    }
    script_execute(scr_iteminfo_all);
}
```

- 容量 **12**；第 13 格（下标 12）是**哨兵 `999`**，用来让循环撞到 12 时走 "满了" 分支。
- **关键物品是另一条数组** `global.keyitem[12]`（`scr_keyitemget` 同构，容量也是 12）。
- 取到东西后调 `scr_iteminfo_all` 把 id **展开成名字/描述缓存**（`global.itemname[]` / `itemdesc[]`）。

### 1.2 光世界：`global.litem[8]`

`scr_litemget` 与上面**同构**，只换数组与容量：

- 数组 `global.litem[8]`，哑元 `global.litem[8] = 999`，判满 `i == 8` ⇒ **容量 8**。
- 配套 `scr_litemcheck / scr_litemremove / scr_litemshift / scr_litemname / scr_litemdesc / scr_litemuseb / scr_lrecoitem / scr_lweaponeq`。

### 1.3 函数族对照（两套完全平行）

| 语义 | 暗世界 | 光世界 |
|---|---|---|
| 取得 | `scr_itemget` | `scr_litemget` |
| 拥有判定 | `scr_itemcheck` | `scr_litemcheck` |
| 移除 | `scr_itemremove` | `scr_litemremove` |
| 左移整理 | `scr_itemshift` | `scr_litemshift` |
| 名字 | `scr_itemname` → `scr_itemnamelist` | `scr_litemname` |
| 描述 | `scr_itemdesc` | `scr_litemdesc` |
| 使用 | `scr_itemuse(id)` | `scr_litemuseb(slot, id)` |
| 关键物品 | `scr_keyitem*`（get/check/remove/shift/info） | —（光世界不单设） |
| 专用 | `scr_healitem / scr_healitem_all / scr_healitemspell / scr_healallitemspell`、`scr_weaponcheck_inventory`、`scr_armorcheck_inventory` | `scr_lrecoitem` → `scr_lrecover`（回 HP）、`scr_lweaponeq`（换武器） |

> ⇒ **产品侧不必自己发明「两套袋子」**：照抄 12 / 12 / 8 三个容量 + 两套平行函数名即可，
> 且"回光世界后暗世界道具不可用"就是原作的默认行为。

## 3. ★ 「非当前场景不可用」的原作依据

`scr_litemuseb` 的 `case 201`（`_evidence/gml/gml_GlobalScript_scr_litemuseb.gml` L74–L128）：

```gml
case 201:
    tempsaid = 0;
    snd_play(snd_phone);
    global.msg[0] = ...gml_72_0...;
    global.msg[1] = ...gml_73_0...;
    if (room == room_krisroom || room == room_krishallway || room == room_torbathroom) {
        tempsaid = 1;
        global.flag[268] = 1;
        scr_torface(1, 0);
        global.msg[2] = ...; global.msg[3] = ...; global.msg[4] = ...;
        scr_noface(5);

    }
    if (room == room_torhouse) {
        tempsaid = 1;
        global.msg[0] = ...; global.msg[1] = ...; global.msg[2] = ...;
    }
    if (tempsaid == 0 && global.plot >= 250) {
        if (global.flag[272] == 0) { global.msc = 365; scr_text(global.msc); }
        if (global.flag[272] == 1) { ... }
        if (global.flag[272] >= 2) { ... }

```

**读法**：同一个道具（201）在不同 `room` 下给**不同台词**，且有一个显式的

⇒ 用户口径「在其他场景使用非当前场景的道具就显示『一股神秘的力量阻止了你』」
**在结构上与原作同形**（按场景门控 + 一句兜底台词），只是把兜底台词换成了产品自定文案。

## 6. 菜单的外部形态：`scr_84_draw_menu` 家族

> 原件：`_evidence/gml/gml_GlobalScript_scr_84_draw_menu.gml`、`_add_menu_item.gml`

`scr_84_draw_menu(list, x, y, vspacing, selection_indices, func_depth, menu_depth)`：

- 列表是 `ds_list`，**每 3 个元素一组**：`(type, item, name)`。
- 选中前缀 `"> "`，未选中 `"  "`（**两个空格**）——像素等宽字体下靠空格对齐。
- `type == "[group]"` ⇒ 渲染成 `"[ 名字... ]"`，且**递归展开**子列表（`func_depth + 1`）。
- 选中项会更新 `global.chemg_max_depth` / `global.chemg_cursor_y`（给外部读光标位置）。

⇒ 产品侧要做同一套"可展开的分组菜单"时，**照抄这个三元组协议**最省事。

### 6.1 另一个同名家族：`DEVICE_MENU` ≠ S 键菜单（避免误用）

`DEVICE_MENU`（`_evidence/gml/gml_Object_DEVICE_MENU_*.gml`）是**标题画面 / 存档选择**菜单，不是场内菜单：

- `MENU_NO` 分页 0..7，`MENUCOORD[8]`；`MENU_NO == 0` 是 3 个存档位 + COPY / ERASE / CHSELECT（**选择章节**）/ 语言 / 退出。
- 判据：`FILE[i]`、`NAME[i]`、`TIME_STRING[i]`、`ossafe_file_delete("filech1_" + ...)`、`game_end()`、
  `Draw_0` 结尾硬编码 `"第1章"`。
- `Create_0`：`if (ossafe_file_exists("filech1_3"/"4"/"5")) TYPE = 1;` ⇒ 按存档切"豪华版/普通版"外观。

⚠️ 它**同时也叫 `MENU_NO` / `MENUCOORD`**，与本轮真正要复刻的
`global.menuno` / `global.menucoord` **只差一个下划线/大小写**。写代码时**极易混用**。
