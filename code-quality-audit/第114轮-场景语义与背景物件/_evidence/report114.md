## 1. 三个问题的答案

### ① 「拆出来背景物件后的空缺你能自己填上吧」

**不需要填。** OneShot 的每间房都是 3 个 tile layer 叠出来的（`L0` 地面/墙体铺满全房，`L1` 物件，
`L2` 再上层）。拆一件家具 = **少画那几格**，底下 `L0` 的地板天然露出来。

实测（`census_objects114.py`，263 间全量）：

| 分类 | 块数 | 含义 |
|---|---|---|
| `removable` 可拆 | 4196（74,557 格） | 每一格底下都有 L0 地板 ⇒ 拆了**不露洞** |
| `partial` 部分可拆 | 94 | 一部分格压在“本来就是地面”的边界上 |
| `solid` 不可拆 | 90（4585 格） | 它本身就是地面（暗世界草地/水面），拆了整片塌 |

抠除实测：`map4` 拿掉一块 8×5 的沙发后，抠除区域**透明像素 0 / 10240**，目视对照无接缝、无黑洞。

> 之前为什么会“留洞”：拿 `assets/scenes/bg/oneshot_map*.png`（**合成后**的整张图）当底图去
> “整格复制地板”，砖缝接缝指标 9.31 → 81.49（恶化 9 倍）。根因是**底图已经被合成过**，
> 不是“底图错了”。
>
> ★★ **勘误：「那批 PNG 不可信」是我自己搞错的，已撤回。** 早前拿逐层渲染直接和 PNG 比，
> 得到「只有 80 间一致（30.4%）」，据此还说 `map1` 是「黑底加紫竖条」（其实那就是 `INIT` 的
> 真实样子）。重验（`check_bg114.py` → `bg_verdict114.py` → `bg_base114.py`）：
>
> | 口径 | 结果 |
> |---|---|
> | 直接比（**不补底色**） | IoU≥0.95 的 165 间；**109 间被判「不一致」，其实只是缺一层底色**（`oneshot_map_colors.json`） |
> | 补上底色后逐像素 | **222 / 263 间差异 ≤1%**；41 间 1%~12.5%；**中位 0.0000**、均值 0.8%；`map1` = **0.0000** |
> | 41 间的差异落在哪 | 几乎全在**半透明瓦片**（水面/阴影）：差异像素里「我的 alpha<255」占比 0.87~1.00；`map74` 是 0.37（例外） |
> | 具体数值 | 我给 alpha 109~115、PNG 给 192~193；对应 RGB 也随之偏亮 |
> | **错位负控制** | 把渲染右移一格：差异从 0.000/0.077/0.125/0.043 涨到 0.114/0.231/0.400/0.286 ⇒ **判据看得见错位（4/4 PASS）** |
>
> ⇒ 那批 PNG 是第100/101轮从同一份 tmx + 底色合成的，**版面与 tmx 一致，没有布局错误**，
> 差的只是半透明像素的 alpha 合成方式。**不需要替换。**
>
> ★★ 两个教训：
> 1. **拿「合成图」当基准比较时，必须先把底色层补上**，否则会把 109 间好图判成坏图。
> 2. 第二版判据我本来写的是「两边 alpha>0 的像素集合相同」，还得出「263/263 几何完全一致」——
>    **那是恒真判据**：底色不透明 ⇒ 合成后整张图 alpha 全 255 ⇒ 差集永远是 0。
>    是**错位负控制**把这个恒真结论顶出来的，差一点就写进报告。

### ② 「没有功能简介的物件，列出来，我后期自己填写」

签名 = 主图集名 + 相对 bbox 原点的逐格 `(dx, dy, tsx, 局部id)`，签名相同 = 外观同一件东西，
**命名一次覆盖全部出现位置**。

| | 类数 | 覆盖块数 |

| 已有原作名字（可信口径） | 359 | 2205 |
| **待填（本清单）** | **815** | **2123** |

待填清单又分两组：

- **A 组「典型物件」643 类 / 1885 块** —— 单块 ≤ 8×8 格（128×128 px），按**复用块数**降序。
  前 20 类就覆盖 451 块，前 100 类覆盖 967 块（占待填的 45.5%）。**先填前面，性价比最高。**
- **B 组「大面积拼合」172 类 / 238 块** —— 4-连通把贴在一起的墙/窗/门并成了一坨
  （`map40 Alula` 整张 70×70 是一个连通块），是场景结构不是物品。**不想填可以整组留空。**

## 2. 事件名挂载质量（口径收紧的原因）

普查用「事件坐标落进块 bbox（容差 1 格）」把原作名字挂到物件上。这套办法**会挂错而且不报错**，
所以 `events_audit114.py` 把三种出错形状都数了一遍：

| | 数量 | 说明 |
|---|---|---|
| 事件总数 / 其中有名字 | 11364 / 3459 | 有名字的只占 30% |
| A 一块挂多名 | 250 处 | 其中 bbox ≤2 格（最可能是容差吸进来）24 处 |
| B 同一房间内一名多块 | 290 处 | `water` ×106、`tree` ×18 —— 这类是**同一个东西有很多件**，正常 |
| C 名字一个块都没碰上 | 1516 个 | 门/站位/触发区，不是可拆物件；最常见 `pixel X,Y`（495）、`ladder`（126） |

因此「有名字」的判据收紧成 **非元事件名 + 单块 ≤64 格**：
`pixel 0,0` / `Map Events` / `init` / `noloop` / `force meet` 这类是**元事件，等于没名字**；
>64 格的块会把一屋子事件全吸进 bbox（`map40 Alula` 70×70 一块挂了 35 个名字），挂什么名字都是错的。
收紧后 924 → 734 块有名，190 块回到待填。

小件挂多名**不砍**（`bed top left / bed bottom right` 就是一个床的四个角，是合法的）。

## 3. 踩过的坑（都留在代码注释里了）

1. **`(x0, y0)` 不能当块键** —— `map37` L1 (49,50) 和 `map121` L1 (51,14) 各有一对块共用左上角
   （一个 1×1 孤立格正好压在大块左上格的斜对角上，4-连通里不相连）。拿左上角当键会**静默覆盖**
   掉一个块，而且总数照样是 4380 对得上 —— 只有 `assert` 能抓住。
2. **累计格数 vs 单块格数** —— `e['cells']` 是所有实例累计，拿它和 64 比会把「3 格的东西出现
   50 次」算成 150 格，误判进「大面积拼合」。
3. **按面积排序把「整面楼」排第一** —— 4-连通的产物不是物品，改成按复用块数排序。
4. **gid 翻转位（已排除）** —— `probe_flip114.py` 实测 263 间房**没有任何一格**使用
   `0x80000000/0x40000000/0x20000000`。⇒ 图案签名可以按局部 id 合并，渲染不做镜像也是对的。
   换版本后要**重跑**这个脚本：哪天报非零，签名要带翻转位、渲染要支持镜像。
5. **图集要按目录分桶** —— `tsx` 的 `image source` 是相对 tsx 自己的（`../../Content/autotiles/…`），
   `tilesets/` 和 `autotiles/` 两边都有 `blank.png`/`black.png` 但内容不同，只认 basename 会静默画错。
6. **`xnbcli.exe` 必须先 `env -u NODE_OPTIONS -u NODE_PATH`** —— 本机 `NODE_OPTIONS` 指向
   WorkBuddy 的 shim ⇒ `Cannot find module ... node-language-shim.cjs`。
7. **23 间渲染全透明不是 bug** —— 实测 `map10/103/155/165/167/173/174/175/223/224` 各层非空格 = 0
   （真空图），`map179/203` 用 `blank.tsx` 铺满（`autotiles/blank.png` 全透明）。数据如此。
8. **游戏目录被挪过** —— 写死 `桌面\珍贵的回忆\…` 会 `FileNotFoundError`，现改多候选探测，
   全不中抛错并列出试过的路径（**报错比猜一个安全**）。

```bash

       --out D:/_tmp/render_all --all

# 2) 普查（物件块 / 可拆性 / 事件名）

# 3) 图案签名库 + 待命名清单

# 4) 缩略图对照表（要先有 2 的产物）

# 7) 事件名挂载质量
python _tools/events_audit114.py

# 8) 翻转位证据（换版本后重跑）
python _tools/probe_flip114.py

# 9) 背景图对账（三步走，别跳步 —— 第①步单独看会误判 109 间）
python _tools/check_bg114.py $(seq 1 263)   # ① 逐层渲染 vs PNG：IoU/尺寸
```
