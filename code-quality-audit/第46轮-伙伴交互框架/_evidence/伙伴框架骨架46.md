## 三、判据侧的三条教训（比产品 bug 更值得记）

### 3.1 判据报红 ≠ 判据错 —— 先看自己的代码

`A4` 首版写的是"`companion` / `companion_roster` 的函数内没有 import"，跑出来**报红**。
第一反应容易是"判据太严"，实际是**我的代码确实藏着局部 import**。
⇒ 顺手把它升级成一条更强的、对三个模块一律成立的不变量：**零函数内 import**。

### 3.2 文本判据会咬到文档字符串

`A5` 首版：`'scene_walk' not in files['companion_roster']` → 报红。
原因：`companion_roster` 的**文档字符串**里写着「第 45 轮的 `scene_walk` 仍有用」
（一句**正当的注释**）。这正是"判据过窄 = 误报"的经典形态。
⇒ 改成 **AST 判 import**，并补 `A5c` 正控制：
"文本里提到 `scene_walk` 但没 import 时判据不误报"。

### 3.3 鉴别力体检里「破坏手法失效」与「判据恒真」必须分开

`disc_companion46` 首版"破坏14"改的是 `start = i + 1` → `start = 0`，
**完全不报红**。但如果就此判定"判据恒真"就错了 ——
真正在守"不许自己接自己"的是下面那句
`if c.speaker_id != self._last_from`，`start` 只影响找起点的效率。
⇒ 把破坏改成**破坏真正的守卫**（把整段轮转换成 `return members[0]`），立刻报红 3 条。
**判据没错，是破坏手法没打到要害。** 这两种假象要分开处理，否则会：
① 白改一遍正确的产品代码；② 或者相反，把真恒真的判据放过去。

⇒ 本轮**只加孤立的三个模块**，不碰 `main.py` / `scene_controller` / UI。

**G2 42 套件全部 IDENTICAL + `_CTL_ALLOWED` 不需要改** 这两条硬证据。
