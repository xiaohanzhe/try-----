## 3. 候选根因（"消失 / 约60px" 的来历）

**R1（主嫌疑）—— 坐标空间错位 = 任务栏高度 72px。**
场景 / 画布 / 门用 `_primary_screen_size()` = 全屏 **2560×1600（含任务栏）**；宠物定位用 `availableGeometry` = 工作区 **2560×1528（不含任务栏 72px）**。两套坐标系差一个任务栏高，正是"约 60px"的量级。可见表现：
- 画布 `[0,0,2560,1600]` 延伸到任务栏后面 72px；
- **下门底边贴到 y=1600**，其中 72px 沉进任务栏后面，肉眼看到的下门只剩 52px 高。

**R2 —— 第200轮 0.5→1/3 的观感变化。**
`SCENE_FIT_FRACTION` 0.5→1/3 使宠物从 133px 缩到 88px（−45px）。这是用户批准的"缩到 2/3"，但缩完后宠物偏小、位置感随之变，可能被记成"尺寸异常/位置不对"。

**R3 —— 宠物 idle 漫游。**
取证第1帧 `(2410,1378,100,100)` → 第60帧 `(2215,1402,42,88)`，3 秒内左移 224px。宠物本就会在桌面游走，位置随时刻漂移，"约 60px"可能是漫游中的瞬时读数，而非系统偏差。

## 4. 建议怎么验 / 下一步

1. **截图定案**（"以画面为准"）：`Win+D` 后抓屏，确认 ① 宠物视觉可见、② 下门是否被任务栏盖住 72px。
2. **若确认 R1 是要修的**：先裁定口径——"屏幕四边"是「整块屏（门会被任务栏盖 72px，当前实现）」还是「工作区（门贴任务栏上沿）」。这决定下门/画布/相机映射是否要从全屏改成工作区坐标。
3. 本轮不产代码改动；修复进后续轮（等口径裁定）。
