> 起点：用户说「继续」。上一轮刚把门画在屏幕边缘，本轮去验**能不能真的走进去**。

## 一、真机探针抓到的两个真 bug（都不是"看错了"，是**功能死了**）

方法：`_tools/probe118_doors.py` 真起 App（沙箱三闸），把桌宠窗口**中心**摆到每扇门
**画出来的位置**、朝屏幕外，再调产品自己的 `interact_scene_prop()`。

### 1.1 站哪扇门，都进三角符文

| 门 | 改前选中 | 改前进入 |
|---|---|---|
| A（正上 OneShot） | `obj_doorD` | `ch1.hometown.town_mid` ❌ |
| B / C / D | `obj_doorD` | 同上 ❌ |

**真因链**：交互实体取的是**灵魂** → 桌面上的灵魂恒停 `(2487,1500)`（第116轮已实证）
→ 射线永远从右下角出发、永远打不到门（门在房间四角）→ 降级"离**灵魂**最近"
→ 门 D 的 `pos(140,42)` 恰好最近 ⇒ **永远是它**。
而门自第112轮续四起就**画在屏幕坐标**里，与 `desktop.json` 的 `pos` 早就不是一回事。

**修**：`main._desktop_door_pick()` —— 桌面场景里用 **宠物盒 ↔ 门屏幕矩形** 的
`door_reveal.rect_gap` 选最近那扇（与门渐显**同一把尺**），接线排在房间坐标射线之前。

### 1.2 推过一次门之后，所有可交互物全失灵

`Interactable.interact()` 在 `on_interact()` 返 True 时**保持全局锁**，靠 `update()` 的
`dialog_done()` 解锁 —— 而**全仓从来没有人调过 `update()`**。换场景时旧道具被丢掉，
锁的持有者成了僵尸 ⇒ 之后 `try_acquire` 永远失败。
（探针里表现得很直白：门 A 成功之后，B/C/D 全 `False`。）

**修**：① `_tick_item_props()` 挂在 30ms 帧钩子，逐件 `update(dt=0.03)`（循环体 try/except）；
② `_rebuild_item_props()` 在清空列表**之前** `bus.release(旧持有者)`。

### 1.3 附带：桌面上「Niko 的家」永远触发不了

桌面 `_soul_visible()` 为真（覆盖层窗口显示着，但那个灵魂恒停且屏幕上看不见）
⇒ 主体恒为 `'soul'` ⇒ 判成"用户" ⇒ **永久拒绝**，三连确认一次都弹不出。
**修**：桌面场景主体一律 `'pet'`（用户看到/操作的是 Ralsei 本人）；非桌面不动。

## 7.2 我自己的三个夹具错（都已修，且各留一条"反向判据"）

写这一节是因为：**这一轮真正拖时间的不是产品，是我的取证工具。**

**(a) 同一个 QTimer 不能在自己的槽里重入自己。**
第一版把 `interact_scene_prop()` 直接写在 `tick()` 里；彩蛋门会开 `exec_()` 嵌套事件
循环，而 Qt 不允许同一个 QTimer 在自己槽函数还没返回时再次触发（`QTimerInfo::activateRef`）
⇒ **模态那 8.3 s 一帧都没录到**，`choice_1to1_*.png` 一张没生成，我的"抓默认态 / 发 ↑ /
发 Esc"一次都没跑。→ 改成 `QTimer.singleShot(0, …)` 派发到另一个定时器事件。
（这一条走过弯路：中间我用"没有输出"推断"主线程被饿死"，还写了一个测量脚本
`probe118_egg4.py`，实测 `update_movement` 只占 32% 墙钟 —— 说明**判据被"没有输出"
喂饱了**。真凶是重入，不是饿死。）

**(b) 存 PNG 时把 BGR 当 RGB，红蓝颠倒。**
`QImage.grabWindow()` 给的是 `Format_RGB32`，内存里 BGRA 小端 ⇒ `arr[y,x]=(B,G,R)`。
喂 `cv2.VideoWriter` **要的就是 BGR**（所以 avi 是对的），喂 `PIL.fromarray` 会当 RGB ⇒
**红蓝互换**。素材 `spr_heart_0.png` 是纯红 `(255,0,0)`（188 个不透明像素），裁图里那颗心
量出来是纯蓝 `(0,0,255)` —— 我差一步就报了"红心画成蓝的"这个**假 bug**。
（第117轮的裁图也有这个错，只是当时判的是亮度/ΔE，通道颠倒不改亮度，所以没暴露。）

**(c) 对话气泡的矩形没进 csv。**
所以 `check118_rec` 的 C10 只能退一步判"框底边明显高于旧摆法"，没法直接判"框与气泡不重叠"。
补在 `check118` 的 G11/G12 里用**行为级**补上了（见 7.4）。

* `check118` **G11**（行为级：造一个可见的假气泡 ⇒ 框 `bottom <= 气泡 top`）

## 7.5 边界（我没做的）

* **门 C 视觉上仍偏小**（45 px 宽，站在壁纸上不容易认出是门）。这是"按原作等比"的
  必然结果 —— 要单独放大它，就等于放弃"门彼此之间的大小关系照原作"。属**产品口径**，
  留给你定，我没动。
* 选择框与对话框仍是**两块窗口**（原作里是一块）。要真正合成一块，得让
  `dialogue_ui` 支持"框内多行选项"，那是下一轮的活。
* 人味线 L2 / L3 未动（本轮全部时间在门与选择框）。
