原作的移速是**一张表**（光 3 / 暗 4 为基准，跑动按 `runtimer` 三段加码），
加速**不是从按键那一刻开始**、而是"跑表"推进的结果；

## 1. 锚点（逐字，来自产物）

### 1.1 基准速度（`gml_Object_obj_mainchara_Create_0`）

```gml
darkmode = global.darkzone;
...
wspeed = 3;
bwspeed = 3;
if (darkmode == 1)
{
    bwspeed = 4;
    wspeed = 4;
}
```

⇒ `bwspeed` = **光世界 3 / 暗世界 4**。`wspeed` 是"这一帧实际用的速度"，初值同 `bwspeed`。

### 1.2 跑动三段（`gml_Object_obj_mainchara_Step_0`，`if (run == 1)`，起始行 70）

```gml
if (run == 1)
{
    if (darkmode == 0)
    {
        wspeed = bwspeed + 1;
        if (runtimer > 10) { wspeed = bwspeed + 2; }
        if (runtimer > 60) { wspeed = bwspeed + 3; }
    }
    if (darkmode == 1)
    {
        wspeed = bwspeed + 2;
        if (runtimer > 10) { wspeed = bwspeed + 4; }
        if (runtimer > 60) { wspeed = bwspeed + 5; }
    }
}
```

**合并成表**（本项目要照抄的那张）：

| 世界 | 走（不按跑键） | 跑段 1（`runtimer ≤ 10`） | 跑段 2（`10 < runtimer ≤ 60`） | 跑段 3（`runtimer > 60`） |
|---|---|---|---|---|
| 光（`darkmode == 0`） | **3** | 3+1 = **4** | 3+2 = **5** | 3+3 = **6** |
| 暗（`darkmode == 1`） | **4** | 4+2 = **6** | 4+4 = **8** | 4+5 = **9** |

★★ 注意两处**不是等差**，别"顺手规范化"：
- 暗世界跑段 1 是 `+2`（不是 `+1`）⇒ 6；
- 暗世界跑段 3 是 `+5`（不是 `+4`）⇒ 9。
两处都是原作的**有意设计**（暗世界加速更陡），改了就与原作不符。

### 1.3 松手立即回落

```gml
if (run == 0)
{
    wspeed = bwspeed;
}
```

⇒ **没有残速**：一松跑键，`wspeed` 立刻等于 `bwspeed`（3 或 4）。
本项目 `PossessionState.drive()` 原本已写"松键即停"，此处只需保证**速度档也回落**。

### 1.4 跑表 `runtimer` 的推进（`obj_mainchara_Step_0`，起始行 350）

```gml
runmove = 0;
if (run == 1 && xmeet == 0 && ymeet == 0 && xymeet == 0)
{
    if (abs(px) > 0 || abs(py) > 0)
    {
        runmove = 1;
        runtimer += 1;
    }
    else
    {
        runtimer = 0;
    }
}
else
{
    runtimer = 0;
}
x += px;
y += py;
```

★★★ **这是 I1 最容易被做错的地方**（三条，缺一条就不是原作）：

1. `runtimer += 1` 的前提是"**按住跑键 且 这一帧真的动了**"（`abs(px) > 0 || abs(py) > 0`）；
2. **只论"有没有动"，不论"撞没撞墙"**（`xmeet/ymeet/xymeet` 是撞墙标记，
   `xmeet/ymeet/xymeet` 非零 ⇒ 整条 else 分支把 `runtimer` 清零）；
   所以"按住跑键顶着墙原地不动"⇒ `runtimer` 归零、速度**退回走速**；
3. `runtimer` 是**帧计数**（30fps 下 60 帧 = **2 秒**）。

⇒ 实际手感：按住跑键、顺畅地跑 **0.33 秒**后进段 2，**2 秒**后进段 3；
中途停下或撞墙超过一帧就**从头再来**。

### 1.5 `autorun`（过场脚本用的自动跑）

```gml
if (autorun > 0)
{
    if (autorun == 1) { run = 1; runtimer = 200; }
    if (autorun == 2) { run = 1; runtimer = 50; }
}
```

⇒ `autorun` 是"直接置位、跳过加速过程"的两种档（对应段 3 / 段 2）。
本项目**不做**（没有过场脚本的自动跑需求），仅登记在此，避免将来"看到变量找不到出处"。

### 1.6 跑键本身（`gml_Object_obj_mainchara_Step_0`，起始行 40）

```gml
if (global.flag[11] == 1)
{
    if (button2_h() && twobuffer < 0) { run = 0; }
    else { run = 1; }
}
else if (button2_h() && twobuffer < 0) { run = 1; }
```

⇒ 跑键 = `button2_h()`（**按住型**，`_h` = held）。
`global.flag[11]` 把语义**反转**（"按住才是走"）—— 本项目**无此 flag**，按常规分支：
**按住跑键 ⇒ `run = 1`；松开 ⇒ `run = 0`**。

## 2. `global.interact` 全局闸（I4）

`obj_mainchara_Step_0` 的**整段移动代码**都裹在：

```gml
if (global.interact == 0)
{
    ... 全部按键读取 / 跑表 / 位移 ...
}
```

取值（本项目产物里可核到的）：

| 值 | 出处 | 含义 |
|---|---|---|
| `0` | 常态 | 可自由走动 / 可交互 |
| `1` | `obj_interactablesolid_Other_10` | 对话中（**锁住主角输入**） |
| `5` | 菜单键分支 | 菜单打开 |

★★ 语义：`global.interact != 0` ⇒ **主角整帧不动、也不响应任何键**。
本项目对应物 = `self.item_menu_ui.is_open()`（菜单打开时方向键归菜单）。
I4 要做的是**在附身/灵魂驱动这一侧也加同一道闸**，而不是只看菜单。

### 2.1 被交互者的三态 `myinteract`（`obj_interactablesolid`）

| 步 | 出处（产物逐字） | 动作 |
|---|---|---|
| 建 | `Create_0` | `myinteract = 0;` |
| 触发 | `Other_10` | `myinteract = 3;` ＋ `global.interact = 1;` ＋ 建 `obj_dialoguer` |
| 收尾 | `Step_0` | `myinteract == 3` 且对话器已销毁 ⇒ `global.interact = 0; myinteract = 0;` ＋ **`onebuffer = 5`** |

逐字（`gml_Object_obj_interactablesolid_Step_0`，全文 213 chars）：

```gml
if (myinteract == 3)
{
    if (instance_exists(mydialoguer) == false)
    {
        global.interact = 0;
        myinteract = 0;
        with (obj_mainchara)
        {
            onebuffer = 5;
        }
    }
}
```

★★★ **`onebuffer = 5` 就是 I5（"对话结束 5 帧输入缓冲"）的真身** ——
它写在**被交互者**身上、`with (obj_mainchara)` 投给主角，
于是主角 `Step_0` 里那条 `if (onebuffer < 0)` 在接下来 5 帧**不响应确认键**。
**本项目没有 `onebuffer`/`twobuffer`/`threebuffer` 这套缓冲** ⇒ I5 是**新增**（照抄这条形状）。

## 3. `global.plot` —— 剧情进度计数器（I10 的唯一真源）

### 3.1 全产物里 `global.plot` 被比较的**每一处**（共 5 处）

```text
gml_Object_obj_doorX_Alarm_2          :   72 | if (global.plot < 120)
gml_Object_obj_doorX_Alarm_2          :   96 | if (global.plot < 150)
gml_Object_obj_doorX_Alarm_2          :  107 | if (global.plot < 150)
gml_Object_obj_mainchara_Step_2       :   26 | if (global.darkzone == 0 && global.plot >= 245)
gml_Object_obj_npc_susiedark_Create_0 :   12 | if (global.plot >= 30)
```

⇒ `global.plot` 是一个**单调递增的剧情进度计数器**：
- 增量方向：`>= 30`、`>= 245`（**进度过某点**）；
- 反向：`< 120`、`< 150`（**进度还没到某点**）；
- 全局表登记：`{"name": "plot", "instance": "Global"}`（另有同名 Local/Self，**全局的那个才是它**）。

### 3.2 ★★★ I10 的真身（`gml_Object_obj_npc_susiedark_Create_0`，逐字）

```gml
if (global.plot >= 30)
{
    instance_destroy();
}
else
{
    s = instance_create(450, 950, obj_soliddark);
    s.image_yscale = 8;
}
```

**读法（三件事，必须说清）**：
1. 它写在**创建事件（Create）**里 ⇒ 房间加载时**就决定这个 NPC 出不出场**；
2. `instance_destroy()` 销毁的是**这一个实例**（那个 NPC），
   **不是存档、不是道具、不是玩家的进度**；
3. 语义 = 「**剧情走到 30 之后，这个 NPC 不再出现**」—— 是**出场门控**，不是"自毁"。

⇒ 所以用户口径「**别毁，就是已经过完剧情了就好**」与原作**不冲突**：
原作此处本来就是"过完剧情 ⇒ 不再生成"，本项目只要把**"过完剧情"这件事记下来**即可，
**不需要、也不允许**去删任何东西。

### 3.3 本项目落地口径（I10，按用户裁定 —— ★★★ 已裁定，非"待议"）

用户第85轮裁定（逐字，两条）：

> 「**别毁，就是已经过完剧情了就好**」
> 「**只要不是在剧情里死了的npc就可以出现。不用。**」

| 问题 | 裁定 |
|---|---|
| 要不要 `instance_destroy()` 等价物？ | **不要**（「别毁」）—— 本项目**零销毁** |
| "剧情过完" ⇒ 该 NPC 不再出现？ | **不采用** —— 出场**只被"剧情里已死亡"挡** |
| `global.plot` 阈值当出场门控？ | **永不** —— `plot_threshold_reached()` **不接线、不得用于出场判定** |
| UI 显示"剧情已过"？ | **不做**（「不用」） |

⇒ 落地形态：**只打标记、零删除、零门控**。

- **只打标记**：`plot_mark` 记录"这件事/这段剧情已经过完了"，
  形如 `{'plot:<事>': {'done': True, 'schema_version': 1}}`；
- **零删除**：不 `instance_destroy` 等价物、不删 NPC 实例、不删道具、不清存档；
- **零门控**（★ 已裁定）：标记**不得**作为"谁不出场"的依据；
  出场判定**只认另一套语义 ——「这个 NPC 在剧情里死了没有」**；
- **语义分离**（防"同一份规则两处算"）：`plot`（进度）与"死亡"（生死）**不同源、不同真源、不许互相替代**；
- **可读但不接线**：标记可被后续轮次读取，但**没人**拿它挡出场 ——
  由 `check85` F2 段以 AST 全仓扫描守住（含"假模块真调用必须被抓"的负控制）。

> ⚠️ 原作**没有**给玩家任何"剧情已过"的文本提示
> （`dr85_strings.json` 里含 `plot` 的条目 = 0）。
> ⇒ 本项目**也不做** UI 显示（用户口径「**不用**」）。
