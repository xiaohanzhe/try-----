## 2. 发声直显：先量，再改

### 2.1 量出来的盘子很小

419 条 `ACTION_PAREN` 跑完第188轮护栏后，**仍在的**括号里按"像不像发声"分类：

| 类别 | 处数 | 形态 |
|---|---|---|
| 英文笑声 | 25 | `（NYEH HEH HEH!）` 19 · `（NYEH HEH HEH！）` 5 · `（NYEH HEH HEH!)` 1 |
| 标签冒号式 | 5 | `（笑声：Geh ha ha ha ha）`（rouxls） |
| 中文拟声 | **0** | 语料里一例都没有 |
| 合计 | **30 / 4 种** | |

### 2.2 边界靠白名单，不靠"英文大写"

同样是大写英文，`（SANS! STOP BEING LAZY!）` **4 处**是**台词被塞进括号**（D 族），
不是发声。所以判定不是"看大小写"，而是**每个词都在笑声表里**：

```
_LAUGH_EN = {ha, haha, heh, hehe, nyeh, mweh, geh, huh, ho, hoho, hee, nyah, ...}
```

`STOP / BEING / LAZY` 不在表里 ⇒ 天然不命中。判据 `B1`（行为）与 `E4`（实测 8 处仍在）成对钉。

### 2.3 修法：己闸排最前

```
己  _rescue_voice    发声直出      ← 第189轮新增，排第一个
丁  _rescue_quoted   救引号台词
甲  _ACTION_PAREN_RE 动作动词开头
丙  _kill_narration  叙述
戊  _kill_bare_label 裸情绪标签
```

**为什么己闸必须排第一**：发声既不是"该删的旁白"，也不是"该救的引号台词"，
它是一条独立的"**转译**"规则（括号 → 声音）。排最前可以保证后面四道闸对**其余**括号的
行为**逐字不变** —— 回归面最小（`D2` 用 AST 钉"己闸必须是第一个 `_ANY_PAREN_RE.sub`"）。

己闸三支：① `标签：内容` ② 整段中文拟声 ③ 整段英文笑声白名单。都不命中 ⇒ 原样返回。

### 2.4 实测

|---|---|---|---|
| 残留括号轮 | 312 | 243 | **230** |
| 残留发声形括号 | 30 | 30 | **0** |

`（哈）` 这种**单字**拟声**故意不做**（更像标签、也可能误伤），`C3` 钉住。

## 3. 口癖频控

### 3.1 先纠正一个我自己的误判

第一版测量按"这一轮有没有命中**任一** marker"算，结果 **16 人 100%** —— 全部是假信号：
`ut_asgore` 的 markers 是 `哦 / 嗯 / 这样啊`，这些**通用语气词**当然每轮都有。
更关键的是：**`Howdy` 根本不在 asgore 的 `voice_markers` 里**，`voice_markers` 也只是
**评测口径**（回复里出现任一 marker 就算命中），**根本不进 prompt**。

### 3.2 真正的根因：人设原文

`assets/npc/persona/asgore.txt` 第 33 行原文：

> 你**经常使用**"Howdy"作为打招呼的方式。你的**句子结构偏长**，有时会絮絮叨叨……

第 39 行「你的经典台词包括」**第一条就是 "Howdy，Kris！"**。
模型只是在**照抄人设**。这也解释了为什么第187轮"往 prompt 加禁令"无效 ——
禁令斗不过人设里的事实陈述。

### 3.3 已改（asgore）

- 第 33 行：`经常使用` → **`偶尔……十次里一两次，不是每次开口都带（原作里你没有固定口癖）`**；
  同时把 `句子结构偏长` 改成 `句子短、想到哪说到哪，别端着`，并给一条**中性口语正例**。
- 第 39 行：`Howdy，Kris！` 从**首位**挪走，并标注"只偶尔用，别每轮都拿它开场"。

★ 为什么不写"别每轮说 Howdy"这种禁令：第161/187 已实证禁令无效；而第113g 的实证更狠 ——
**规则里只要带上"描述那种行为长什么样"的括注，同类违规率就从 1/10 涨到 10/10**。
所以这里给的是**频率事实 + 中性正例**，不是负面样例。

### 3.4 全员普查：7 处「每轮必念」集中在 5 人

排除通用语气词与纯标点（`……` 不是口癖）后，≥80% 的 marker 只剩 7 条：

|---|---|---|

| `ot_kidd` | Yo | 48/48 = 100% |
| `ut_monster_kid` | Yo | 48/48 = 100% |

**本轮未改这 5 人**：每人要读一遍人设才能改准（改错就是把角色性格改没），
留给下一轮逐人处理。名单与数据已落 `_evidence/measure189.json`。

## 4. 口语化：测完的结论是**不改护栏**

用户口径：「你觉得正常人说中文会那么书面语吗，口语化些，**所有角色都是**」。

### 4.1 量出来的三个数（3696 轮）

| 指标 | 值 |
|---|---|
| 平均句长 | **16.96 字** |
| 长句（≥40 字）占比 | **4.08%** |
| 含书面连接词的轮 | **9.50%**（尽管 150 / 不仅 51 / 总之 43 / 即便 37） |
| 含口语词（啊呢吧嘛呀哦啦…） | **60.63%** |
| 用敬语「您」 | 0.14% |
| 句末 `。` 收尾 | 48.05% ／ `！`·`？` 收尾 23.19% |

### 4.2 ★★★ 两个反证

1. **书面度最高的角色不是"病"，是设定**：
   `rouxls` 60.4%（他说文言 —— 原作人设 `you/thou/-est`）、`hy_guardener` 43.8%、
   `hy_ceroba` 33.3%、`berdly` 27.1%（原作就是爱用大词的优等生）。
   ⇒ 「全员口语化」如果无差别执行，**先被抹掉的就是这几个人的性格**。
2. **共享规则里早就写了口语要求**：`npc_persona.SPEAK_RULES` 第 616 行
   「像真人在聊天框里随手打字」、第 626 行「每句话本身也要短，一句话就是一口气的长度」、
   第 647 行给了中性正例「嗯，我知道了。那我先去看看。」
   ⇒ 问题不在规则缺失，而在**人设例句压过规则**（与 §3.2 同因）。

### 4.3 所以本轮只做一件事

改 asgore 人设的风格描述（§3.3 已含），**不动 `SPEAK_RULES`**（它是全员共享、且有
`check113g` 按 AST 钉常量值），**不动护栏**（口语化不是"可以删掉的东西"）。

★ 真正的杠杆是**人设例句**。要验证这一点需要 A/B：同一角色，改例句前后各训 48 轮比书面词率。
这是下一轮的事，不能在没测量的情况下把 77 份人设批量改掉。

## 6. 施工中撞出的自伤事故（已修 + 已锁）

这一节不是"计划内的工作"，是本轮**把回归跑红之后查出来的三处自伤**。
写在这里，因为下一次改人设还会走到同一条路。

### 6.1 事故一：`cards113.py --all` 会清空训练成果

改完 `asgore.txt` 后按惯例重建训练卡，结果 **59 张卡的 `patch`、61 张卡的 `eval` 被清空**，
**10 张卡的 `voice_markers` 被抽回第113轮r 手工剔掉的灌水项**（`想` / `……` / `[……]` / `I` / `时候`），
另有 62 张 CRLF 卡被统一成 LF。四处老锁同时红：

| 套件 | 红在哪 |
|---|---|
| `check139` | `A0` / `A3`（卡里 patch 与索引不漂）/ `D5` |
| `check142` | `A4`（三份副本"带①"集合一致）/ `C1`（三处都 38 条） |
| `test_evalpick113s` | `L4b` / `L4c`（susie 的补丁变成 0 字） |
| `test_markers113r` | `H`（真卡名单被改） |

**根因**：`build_card()` 里 `patch` / `eval` 恒写 `''` / `{}`；而 `cards113.py` 里
**早就写着**"重建索引不许冲掉训练结果"—— 它保的是 `_index.json` 的 `patches` / `trained`，
**卡片那一侧一直没保**。于是索引还记着 59 条纠正，卡片里全空了。

**修**：新增 `carry_trained(card, path)`，三处写盘点全部经过它：
`patch` / `eval` 新卡为空而旧卡非空 ⇒ 沿用；`voice_markers` 在**人设 sha256 没变**时沿用
（人设没改，抽出来的就该跟上次一样；不一样只可能是 113r 的手工剔词被冲掉，打印一行让人看见）。

**第二次踩**：把守第一版写成 `old.get('voice_markers')`（判"非空"），而 `hy_chujin_ketsukane`
的名单被 113r 清成了 `[]` —— `[]` 是 falsy ⇒ 又抽出 `["I"]`。改成判**"有这个字段"**才对：
空列表也是结论。

**本轮怎么改的 asgore 卡**：不跑 `--all`，用 `sync_card189.py` 只重建这一张
（走产品自己的 `build_card` + `carry_trained`），行尾沿用该文件原本的 CRLF，
索引只改 `persona_chars` 一行。最终训练目录的 diff 就是 `asgore.json` 3 个字段 + 索引 1 行。

### 6.2 事故二：编辑工具把 `asgore.txt` 整体改成了 LF

改完人设后 `body CRLF = 0`（其余 75 份是 108 处），`sha256` 与 `sha256_lf` 变得**相等**
—— 正常应当不同。违反"保持原 EOL"。
修：`fixeol189.py` 按该目录既有体例重建 `正文(CRLF) + '\r\n\n' + 尾块(LF) + '\n'`，
尾块取索引 `tail_text`（单一真源，取前先核对磁盘尾块与它一致），
并做**独立校验**：准备写的字节按 LF 归一后必须与磁盘原文逐字节相同 —— 证明"只动了换行符"。

### 6.3 事故三：`_personas.json` 索引派生字段没跟着变

`check115 C2f` 报"5 个字段重算没全中"。
**不能**用 `personas113.py --write` 去修：它的口径是"用源文件正文**覆盖**人设文件"，
一跑就把 189 轮对人设的改动冲回源文。
修：`reindex189.py` 只读磁盘、只重算 `chars/bytes/sha256/sha256_lf/sections/tail_*`，
dry/`--write` 两态，写后回读 + 重 load 再 dump 的体例自检，重跑第二次 0 份更新（幂等）。
结果只有 `asgore` 一条记录变（`chars` 6814→6890、`bytes` 18225→18453）。

### 6.4 锁（`check113` 49 → 56 条）

| 判据 | 钉什么 |
|---|---|
| `A5b` | AST：`cards113.py` 每一处写卡都经过 `carry_trained`（3 处） |
| `A5c` | 行为：旧卡有 `patch`/`eval` ⇒ 重建后沿用，markers 不被重新抽取覆盖 |
| `A5d` | 负控制：旧卡本来没有 ⇒ 不许凭空造 |
| `A5g` | 旧卡把 markers 清成 `[]` 也照样沿用（第二次踩的那个坑） |
| `A5h` | 负控制：人设 sha256 变了 ⇒ **必须**重新抽取 |
| `A5e` | 端到端：asgore 走 "`build_card` + carry" 后与磁盘卡逐字相同 |
| `A5f` | 破坏性负控制：把 `carry_trained` 打回恒等 ⇒ 重建出来的 patch 必为空 |
