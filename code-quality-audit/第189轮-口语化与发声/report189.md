## 2. 发声直显：先量，再改

### 2.1 量出来的盘子很小

419 条 `ACTION_PAREN` 跑完第188轮护栏后，**仍在的**括号里按"像不像发声"分类：

| 类别 | 处数 | 形态 |
|---|---|---|
| 英文笑声 | 25 | `（NYEH HEH HEH!）` 19 · `（NYEH HEH HEH！）` 5 · `（NYEH HEH HEH!)` 1 |
| 标签冒号式 | 5 | `（笑声：Geh ha ha ha ha）`（rouxls） |
| 中文拟声 | **0** | 语料里一例都没有 |
| 合计 | **30 / 4 种** | |

### 2.2 边界靠白名单，不靠"英文大写"

同样是大写英文，`（SANS! STOP BEING LAZY!）` **4 处**是**台词被塞进括号**（D 族），
不是发声。所以判定不是"看大小写"，而是**每个词都在笑声表里**：

```
_LAUGH_EN = {ha, haha, heh, hehe, nyeh, mweh, geh, huh, ho, hoho, hee, nyah, ...}
```

`STOP / BEING / LAZY` 不在表里 ⇒ 天然不命中。判据 `B1`（行为）与 `E4`（实测 8 处仍在）成对钉。

### 2.3 修法：己闸排最前

```
己  _rescue_voice    发声直出      ← 第189轮新增，排第一个
丁  _rescue_quoted   救引号台词
甲  _ACTION_PAREN_RE 动作动词开头
丙  _kill_narration  叙述
戊  _kill_bare_label 裸情绪标签
```

**为什么己闸必须排第一**：发声既不是"该删的旁白"，也不是"该救的引号台词"，
它是一条独立的"**转译**"规则（括号 → 声音）。排最前可以保证后面四道闸对**其余**括号的
行为**逐字不变** —— 回归面最小（`D2` 用 AST 钉"己闸必须是第一个 `_ANY_PAREN_RE.sub`"）。

己闸三支：① `标签：内容` ② 整段中文拟声 ③ 整段英文笑声白名单。都不命中 ⇒ 原样返回。

|---|---|---|---|
| 残留括号轮 | 312 | 243 | **230** |

## 3. 口癖频控

### 3.1 先纠正一个我自己的误判

第一版测量按"这一轮有没有命中**任一** marker"算，结果 **16 人 100%** —— 全部是假信号：
`ut_asgore` 的 markers 是 `哦 / 嗯 / 这样啊`，这些**通用语气词**当然每轮都有。
更关键的是：**`Howdy` 根本不在 asgore 的 `voice_markers` 里**，`voice_markers` 也只是
**评测口径**（回复里出现任一 marker 就算命中），**根本不进 prompt**。

### 3.2 真正的根因：人设原文

`assets/npc/persona/asgore.txt` 第 33 行原文：

> 你**经常使用**"Howdy"作为打招呼的方式。你的**句子结构偏长**，有时会絮絮叨叨……

第 39 行「你的经典台词包括」**第一条就是 "Howdy，Kris！"**。
模型只是在**照抄人设**。这也解释了为什么第187轮"往 prompt 加禁令"无效 ——
禁令斗不过人设里的事实陈述。

### 3.3 已改（asgore）

- 第 33 行：`经常使用` → **`偶尔……十次里一两次，不是每次开口都带（原作里你没有固定口癖）`**；
  同时把 `句子结构偏长` 改成 `句子短、想到哪说到哪，别端着`，并给一条**中性口语正例**。
- 第 39 行：`Howdy，Kris！` 从**首位**挪走，并标注"只偶尔用，别每轮都拿它开场"。

★ 为什么不写"别每轮说 Howdy"这种禁令：第161/187 已实证禁令无效；而第113g 的实证更狠 ——
**规则里只要带上"描述那种行为长什么样"的括注，同类违规率就从 1/10 涨到 10/10**。
所以这里给的是**频率事实 + 中性正例**，不是负面样例。

## 4. 口语化：测完的结论是**不改护栏**

用户口径：「你觉得正常人说中文会那么书面语吗，口语化些，**所有角色都是**」。

### 4.1 量出来的三个数（3696 轮）

| 指标 | 值 |
|---|---|
| 平均句长 | **16.96 字** |
| 长句（≥40 字）占比 | **4.08%** |
| 含书面连接词的轮 | **9.50%**（尽管 150 / 不仅 51 / 总之 43 / 即便 37） |
| 含口语词（啊呢吧嘛呀哦啦…） | **60.63%** |
| 用敬语「您」 | 0.14% |
| 句末 `。` 收尾 | 48.05% ／ `！`·`？` 收尾 23.19% |

### 4.2 ★★★ 两个反证

1. **书面度最高的角色不是"病"，是设定**：
   `rouxls` 60.4%（他说文言 —— 原作人设 `you/thou/-est`）、`hy_guardener` 43.8%、
   `hy_ceroba` 33.3%、`berdly` 27.1%（原作就是爱用大词的优等生）。
   ⇒ 「全员口语化」如果无差别执行，**先被抹掉的就是这几个人的性格**。
2. **共享规则里早就写了口语要求**：`npc_persona.SPEAK_RULES` 第 616 行
   「像真人在聊天框里随手打字」、第 626 行「每句话本身也要短，一句话就是一口气的长度」、
   第 647 行给了中性正例「嗯，我知道了。那我先去看看。」
   ⇒ 问题不在规则缺失，而在**人设例句压过规则**（与 §3.2 同因）。

### 4.3 所以本轮只做一件事

改 asgore 人设的风格描述（§3.3 已含），**不动 `SPEAK_RULES`**（它是全员共享、且有
`check113g` 按 AST 钉常量值），**不动护栏**（口语化不是"可以删掉的东西"）。

★ 真正的杠杆是**人设例句**。要验证这一点需要 A/B：同一角色，改例句前后各训 48 轮比书面词率。
这是下一轮的事，不能在没测量的情况下把 77 份人设批量改掉。

## 6. 施工中撞出的自伤事故（已修 + 已锁）

这一节不是"计划内的工作"，是本轮**把回归跑红之后查出来的三处自伤**。
写在这里，因为下一次改人设还会走到同一条路。

### 6.1 事故一：`cards113.py --all` 会清空训练成果

改完 `asgore.txt` 后按惯例重建训练卡，结果 **59 张卡的 `patch`、61 张卡的 `eval` 被清空**，
**10 张卡的 `voice_markers` 被抽回第113轮r 手工剔掉的灌水项**（`想` / `……` / `[……]` / `I` / `时候`），
另有 62 张 CRLF 卡被统一成 LF。四处老锁同时红：

| 套件 | 红在哪 |
|---|---|
| `check139` | `A0` / `A3`（卡里 patch 与索引不漂）/ `D5` |
| `check142` | `A4`（三份副本"带①"集合一致）/ `C1`（三处都 38 条） |
| `test_evalpick113s` | `L4b` / `L4c`（susie 的补丁变成 0 字） |
| `test_markers113r` | `H`（真卡名单被改） |

**根因**：`build_card()` 里 `patch` / `eval` 恒写 `''` / `{}`；而 `cards113.py` 里
**早就写着**"重建索引不许冲掉训练结果"—— 它保的是 `_index.json` 的 `patches` / `trained`，
**卡片那一侧一直没保**。于是索引还记着 59 条纠正，卡片里全空了。

**修**：新增 `carry_trained(card, path)`，三处写盘点全部经过它：
`patch` / `eval` 新卡为空而旧卡非空 ⇒ 沿用；`voice_markers` 在**人设 sha256 没变**时沿用
（人设没改，抽出来的就该跟上次一样；不一样只可能是 113r 的手工剔词被冲掉，打印一行让人看见）。

**第二次踩**：把守第一版写成 `old.get('voice_markers')`（判"非空"），而 `hy_chujin_ketsukane`
的名单被 113r 清成了 `[]` —— `[]` 是 falsy ⇒ 又抽出 `["I"]`。改成判**"有这个字段"**才对：
空列表也是结论。

**本轮怎么改的 asgore 卡**：不跑 `--all`，用 `sync_card189.py` 只重建这一张
（走产品自己的 `build_card` + `carry_trained`），行尾沿用该文件原本的 CRLF，
索引只改 `persona_chars` 一行。最终训练目录的 diff 就是 `asgore.json` 3 个字段 + 索引 1 行。

### 6.2 事故二：编辑工具把 `asgore.txt` 整体改成了 LF

改完人设后 `body CRLF = 0`（其余 75 份是 108 处），`sha256` 与 `sha256_lf` 变得**相等**
—— 正常应当不同。违反"保持原 EOL"。
修：`fixeol189.py` 按该目录既有体例重建 `正文(CRLF) + '\r\n\n' + 尾块(LF) + '\n'`，
尾块取索引 `tail_text`（单一真源，取前先核对磁盘尾块与它一致），
并做**独立校验**：准备写的字节按 LF 归一后必须与磁盘原文逐字节相同 —— 证明"只动了换行符"。

### 6.3 事故三：`_personas.json` 索引派生字段没跟着变

`check115 C2f` 报"5 个字段重算没全中"。
**不能**用 `personas113.py --write` 去修：它的口径是"用源文件正文**覆盖**人设文件"，
一跑就把 189 轮对人设的改动冲回源文。
修：`reindex189.py` 只读磁盘、只重算 `chars/bytes/sha256/sha256_lf/sections/tail_*`，
dry/`--write` 两态，写后回读 + 重 load 再 dump 的体例自检，重跑第二次 0 份更新（幂等）。
结果只有 `asgore` 一条记录变（`chars` 6814→6890、`bytes` 18225→18453）。

  "像机械播报、不用语气词"、`berdly` 爱用大词，这三位不算缺陷，见 §4.2）。
- **基线**：`_evidence/raw30` 现有 48 轮，**一个字节不动**。
- **臂**：`armB` = 在「语言风格」段后追加 **2 条**中性正例；`armC` = **6 条**同风格正例。

  口径**逐字照抄** `measure189.py`（词表、切句、字段 `final`）——自己另定一套就不可比。
  ★ `--check` 已用基线复算验证：22.9 / 18.8 / 14.6 与 §4.1 一致，说明新脚本与旧测量同口径。
- **安全**：改人设前把原始字节读进内存 + 落 `_persona_bak/`；每臂 `finally` 按字节写回并 sha256 自检；
  `atexit` 兜底；输出写 `_evidence/ab189/<arm>/{raw,tr}`，**不写 `raw30`**。

### 9.1 结果：**例句确实是杠杆**，但**不是越多越好**

三个角色 × 两臂 × 48 轮，共 288 轮，CPU 推理用时 4 小时 16 分。产出
`_evidence/ab189/{summary,analysis}.json` + 每臂 `raw/*.jsonl`、`tr/*.md`。

| 角色 | 基线书面% | armB（+2 条） | armC（+6 条） | 逐字搬例句（B / C） |
|---|---|---|---|---|
| `hy_martlet` | 22.9 | 18.8 | **14.6** | 0/48 · 0/48 |
| `hy_ace` | 18.8 | **6.2** | 10.4 | 1/48 · 2/48 |
| `os_niko` | 14.6 | **2.1** | 4.2 | 0/48 · 0/48 |

口语词轮占比（同口径）：`hy_martlet` 54.2 → 72.9 / 75.0；`hy_ace` 87.5 → 87.5 / 81.2；
`os_niko` 87.5 → 95.8 / 95.8。平均句长：20.73→22.83/19.98、19.25→19.9/16.22、19.1→17.63/17.71。

**三条结论（按重要性）**

1. ★★★ **根因确认：人设例句压过规则。** 一行规则都没动、只往「语言风格」段加 2 条中性中文正例，
   书面语轮占比就从 22.9→18.8 / 18.8→6.2 / 14.6→2.1。**3/3 全部下降，两人砍到 ≈1/4 或 1/9。**
   ⇒ §4.3 的判断成立：`SPEAK_RULES` 不缺，缺的是**人设里的示范**。
2. ★★ **剂量不是线性的：2 条好于 6 条（2/3 人）。** `hy_ace` 6.2 → 10.4（回弹 4.2），
   `os_niko` 2.1 → 4.2（回弹 2.1）；只有 `hy_martlet` 是单调（18.8 → 14.6）。
   ⇒ **落地口径：每角色补 2~3 条就够，堆到 6 条会开始稀释人设**（同 113g "给描述反而变差"的形态）。
3. ★★★ **不是靠"复读例句"换来的。** 逐字命中正例的轮数只有 **0~2/48**（`hy_ace` 最多 2 轮），
   而且基线是 **0/48**（负控制：判据不会乱匹配）⇒ 降书面语是**风格迁移**，不是背句子。
   这一条必须先排除，否则"加正例"会重蹈 A12d 的老路。

**两个必须一起看的副作用**

- ★ **口癖率会随口语化一起上去**：`os_niko` 43.8 → 72.9%（两臂同值），`hy_ace` 6.2 → 14.6%（armC）。
  原因不是"模型更爱念口癖"，而是 `os_niko` 的 markers 就是 `嗯……/那个……`，**口语化的对话天然更多语气词**
  ⇒ 以后拿"口癖命中率"当唯一指标会**反向惩罚口语化**，两个指标必须分开报。
- ★ **`hy_martlet` 的句长逆势上升**（20.73 → 22.83）而书面语只降 4.1：它是三份人设里最大的
  （24 KB，`hy_ace` 20 KB、`os_niko` 17 KB）⇒ **2 条正例在长人设里权重更低**。
  这解释了为什么"补正例"在小人设上立竿见影、在大人设上要补更多条。

**设计缺陷（如实登记）**

`hy_ace` 的插入锚点写成了**半行**（只截到"…你会放下你的扑克术语。"），而 `apply_arm` 当时只判
`count(anchor) == 1`，于是正例被插进句子中间、把后半句（`你会说"Starlo…"`）挤到示例行末尾。
两臂用的是**同一段代码**，artifact 完全对称，故 armB/armC 之间的比较仍成立；
但**绝对水平**与"干净插入"会有细微差别。已修：`apply_arm` 现在断言锚点**必须是整行**
（`txt[i-1] == '\n'` 且 `txt[i+len] == '\n'`），`hy_ace` 的锚点也补成整行 ⇒ 重跑不会再切句。

### 10.1 结果：**"旁边加一句偶尔"基本无效；有效的是"删掉强化语 + 说绝对频率"**

6 人 × 24 轮 = 144 轮，用时 82 分钟。产出 `_evidence/requirk189/summary.json`。

| 人 | 任一命中（改前→改后） | 关键 marker 逐项 |
|---|---|---|
| `lancer` | 100% → 91.7% | **本大爷 48/48(100%) → 21/24(87.5%)**；嘿嘿嘿 31/48 → 7/24；嚯嚯嚯 10 → 4 |
| `ot_kidd` | **100% → 100%（逐字零变化）** | **Yo 48/48 → 24/24** |
| `ut_monster_kid` | **100% → 100%（逐字零变化）** | **Yo 48/48 → 24/24** |
| `ot_muffet` | 97.9% → 91.7% | 亲爱的 46/48(95.8%) → **10/24(41.7%)**；小可爱 24/48(50%) → **19/24(79%)** ↑ |
| `ot_sans` | 95.8% → 83.3% | welp 44/48(91.7%) → **13/24(54.2%)**；heh 17 → 9 |
| `ut_sans` | 100% → 100% | **welp 46/48 → 0/24**；hey 46 → 6；heh 5 → 1；ok 20 → 0；**k 48/48 → 24/24** |

均次数/轮：`lancer` 2.10→1.71、`ot_muffet` 1.46→1.21、`ot_sans` 1.62→1.54、`ut_sans` **4.31→1.50**、
`ot_kidd` 1.08→1.08（不动）、`ut_monster_kid` 1.00→1.00（不动）。

**四条结论**

1. ★★★ **"Yo" 那两处改写完全无效**：`ot_kidd` / `ut_monster_kid` 的 `Yo` 都是
   **48/48 → 24/24，命中数一个不差**。原因不在措辞够不够强调，而在**同一份人设里还留着
   强化语**——「这是你的**标志**」「**不要忘记**“Yo!”」「最**标志性**的口头禅」。
   我只在旁边加了"一轮一两次就够"，**强化语的压力压过了频次句**。
   ⇒ **限频必须删/改强化语**，光加一句"偶尔"是白写。
2. ★★★ **条件式限频在"条件恒真"时无效**：`lancer` 改成"只有吹牛、自称坏蛋、给自己壮胆时
   才换成'本大爷'"，而他**几乎每一轮都在自称坏蛋**（角色本身就是自封坏蛋）⇒ 100% → 87.5%，
   基本没动。**要用绝对频率（"十句里一两句"）＋中性正例，不能用触发条件。**
3. ★★ **改"行为描述"而不是改"频次形容词"才有效**：`welp` 两条写的是
   「但**不是每轮都要来一次**，多数轮次你只是正常说完就停」——`ut_sans` 46/48 → **0/24**
   （彻底消失），`ot_sans` 44/48 → 13/24。这两条**没有并行的强化语**，所以生效。
4. ★★ **压一个 marker 会把同槽位的另一个顶上来**：`ot_muffet` 的 `亲爱的` 95.8%→41.7%，
   而 `小可爱` 50%→79%。⇒ 限频要**按"槽位"整体限**（这一整类称呼都降频），
   不能只点名一个词。

★ `ut_sans` 的 `k` 仍 100%：那是他的**接话方式**（"k"＝"ok"），不是口癖病，不列入缺陷。

**⇒ 第190轮的活（已定，不再试错）**：对这 6 人「删掉强化语 + 改绝对频率 + 补 2 条不含口癖的
中性正例」（A/B 已证 2 条正例就能改风格，§9.1），然后按本脚本同一口径复测。

★ 口径注：基线是 48 轮、复测是 24 轮，两边都是**比率**可直接比；
本机 40~75 s/轮，48 轮 × 6 人会顶到夜里预算上限，故取 24（见 `requirk189.TURNS` 注释）。
