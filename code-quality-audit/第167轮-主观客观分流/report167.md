## 3. ★★★ 关键论证：下楼侧不存在「还站在板上却够不着」

`walk_induced` 的 `new_h != old_h` 来自 `get_current_floor(当前位置)`，而它只认**楼板可见区域**。
一旦落点被判到**更低**层，就说明脚底锚点**已经不在旧楼板里**（第163轮把锚点定在脚底）
⇒ 此刻脚下确实是空的。

因此：

- 下楼侧「够不着就掉」== **已经在空中失败** ⇒ 正是用户要的「如实掉落」，不是缺陷；
- 「还站在平台上」只存在于**上楼侧**（`new_h > old_h`，物理上仍站在旧板上）
  ⇒ 那里已经是「保持原楼层 + 求助」＝用户说的「求助或干脆不去」。

⇒ **不需要改 `start_falling` 的触发条件**。这是本轮不写代码的唯一理由，也是它的证据。

## 4. 「尽力后才掉」的次序（不是一够不着就掉）

`_start_floor_jump` 失败 → `_on_jump_rejected`：

1. `too_far`（水平速度不够）⇒ **先排助跑** `_try_runup`
2. `too_high` / 助跑也不行 ⇒ **试分段** `_try_segment`（只拆一层，递归有闸）
3. 都不行 ⇒ `start_autonomous_speech('jump_blocked')` **求助一句**
4. 仍在楼层判定里 ⇒ `start_falling()`

## 5. 近跳：有意保留旧口径

近跳（未助跑）`vx0 = |dx|/T`，**不会**先退后冲。理由：近跳多承担**情绪表达**。

- 锁：`check166 B1`（近跳逐值不变）、`B5c`（近跳不受 run 倍率影响）
- ★★ 以后**别**按「真物理」把它改成必须先退再跳 —— 用户明确否掉这个观感
- 助跑只在 `_jump_reach_ok` 判 `too_far` 时出现
