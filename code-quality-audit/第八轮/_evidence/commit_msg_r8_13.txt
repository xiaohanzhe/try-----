用户反馈（第八轮）四条，逐条落地：

1) "其余特殊动画都只交给 AI 判断是否播放，别和抽风似的突然一下"
   - 侦察发现除已收口的两处外，还有 2 个环境自动触发点在自行播特殊动画：
     react_to_desktop_element（update_movement 每 5s 凑近桌面图标 -> look_up/act/
     surprised/wave）与 _react_to_video（陪看视频 10% 随机 -> laugh/dance/surprised）。
   - 修法：规则系统从"演员"降级为"眼睛"。ai_driver 新增环境事件通道
     note_event(text, emotion_hint) + _pending_events 队列，_build_prompt 渲染成
     "- 刚刚：…" 交给模型（看过一次即消费）；main.py 新增
     _note_desktop_observation() 上报"我凑近了「x」（易碎/金属），心里有点想抬头看看"。
     AI 未启用时事件只静静攒着，零可见行为（守住"AI 关闭必须沉默"）。
   - 长期闸门：verify_round8_anim H1.1 断言所有 play_animation_once 归属函数都在
     白名单内（用户显式交互 / 物理状态机 / AI 决策），将来再加自动触发会立刻打红。

2) "播放就播完，不要打断，也不要边播放边移动（只针对特殊动画）"
   - _is_special_anim + _special_anim_locked；change_animation 拦截特殊→特殊
     （force 也拦，同名重播放行）；play_animation_once 用 _play_once_arming 只放行自己那次。
   - update_movement 移动锁放在拖拽保护之前（那些分支都会 move 后 return），
     只暂停本 tick 的移动、不清跟随意图，播完照常继续跟。

3) "待机动画要在原地不动 3 分钟以上才会播放，而不是停止就播"
   - 原 if idle_timer>=180: idle / else: idle 是死分支（两分支同值），一停就播 5 帧循环。
   - 改为 IDLE_LOOP_MIN_SECONDS=180 + _idle_loop_active，未到门限把帧钉在第 0 帧。

4) "鞠躬动画像镜头也在移动"
   - 根因是素材锚点不一致：idle 画布 69x47 而角色 alpha 包围盒只有 (1,6,27,40)，
     右侧 41px 透明留白 -> 切动画时角色横移 40px（scale=2）。
   - 新增 _anim_anchor_offset（按 alpha 包围盒中心，动画级缓存）与
     _compose_anchored_sprite，两处渲染分支接入 -> 跨动画角色位置差 <=1px（修前 40px）。
