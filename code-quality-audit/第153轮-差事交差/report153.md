## 2. ★★★ 真缺口：结果只写进了**他自己**的记忆

`_npc_errand_tick` 的 `finished` 分支原来只做两件事：

```python
for nid, err in (out.get('finished') or ()):
    roam.drop(nid)                      # 回家
    self._npc_errand_commit(nid, err)   # 结果写进 npc_memory（who=nid）
```

而 `ErrandBoard` 那边给宿主准备好的两个读口 ——

| 接口 | 全仓调用次数 |
|---|---|
| `board.result_of(npc_id)` | **0** |
| `board.take_results()` | **0** |

⇒ 结果**只存在于他脑子里**。用户那边看到的是"人没了，然后回来，什么也没说"。
「**产生结果**」这件事在用户视角等于没发生 —— 这和第152轮那个
「`abort()` 接口在位、零接线」是同一种病（**接口不是功能**）。

## 3. 三条不变式（都在判据里钉死）

1. **`remember=False`** —— 结果已经由 `_npc_errand_commit` 记进他的记忆了，
   这句只是"说给用户听"的措辞。再记一次 = 同一件事两条（`B1b` + `C3b` 字面量锁）。
2. **说话人只能是办事的那个人** —— `ralsei` 走主链路（`speaker=None`，
   用 `assets/ralsei_persona.md`）；别的 NPC 必须**有人设**，没有就**不开口**。
   ⚠️ 这里**故意不**沿用 `_errand_ack` 的"回落成 Ralsei"：
   那会让「我办完了」出现在 Ralsei 嘴里 —— **串味比沉默坏得多**（`B3`）。
3. **空结果不开口** —— 没结果就没得交差，「办完了」这种空话正是第152轮
   明令不许造的假结果（`B4`）。

### 3.1 为什么不用 `npc_speak()`（明明是"NPC 说话的唯一出口"）

`npc_speak(npc_id, text, on_reply)` 的 `text` 语义是「**对方说的那句话**」，
它会把 `text` 以 `who='player'` 记进该 NPC 的记忆，然后才去生成回应。
它**没有"系统提示"通道** ⇒ 把 brief 塞进去等于**伪造一句玩家发言**。

而交差的核心恰恰是「**带着结果说**」（模型必须知道"你刚办完什么、结果是什么"）
⇒ 只能走 `chat_with_ai(brief, …)`，与派活/叫停两条既有 ack **同规**
（`C2` 用 AST 锁死"体内不许出现 `npc_speak`"）。

## 5. 五条教训（前三条是我自己的判据先错，后两条是夹具）

### ① `A2` 第一版把两条判据写成了同一条信号

```python
# 错：总数 == 1
check(u'A2 …不重复交代', len(_h1.chats) == 1)      # ← M1（根本不交差）也会让它红
```

`M1` 一拆，"根本没交代"和"交代了两次"在这条判据上**长得一样**（0 也是 ≠1）。
⇒ 改成断「**没有新增**」：

```python
_n_before = len(_h1.chats)
_h1._npc_errand_tick(200.0); _h1._npc_errand_tick(400.0)
check(u'A2 …不重复交代', len(_h1.chats) == _n_before)
```

这样 `M1` 只红 A 段那几条、`A2` 留给了专门的破坏 `M13`（对 `done` 全体交差）。
**一条判据只考一件事**，否则坏了一个地方会红一片，看的人根本分不清是哪个坏。

### ② 破坏"没生效"其实是**异常被 tick 吞了**

`M13` 第一版写成：

```python
for nid, err in (list(board.done.values()) or ()):   # ← 拆包失败
```

`done.values()` 里是 `Errand`，而 `finished` 里是 `(nid, Errand)`
⇒ `cannot unpack non-iterable Errand object` ⇒ 被 `_npc_errand_tick` 的
`except Exception as e: _log.debug(...)` **默默吞掉** ⇒ 表现为
"`drops` 为空、一句没发、`A5` 的事件表整段是 `[]`"。

★ **看起来像"这个破坏没效果"，实际是"整段被跳过了"。**
定位方法：把 logger 挂到 stdout 再跑一次（`_log` 默认写文件），
异常原文立刻出来。**"破坏不报红"的第一步永远是确认破坏真的执行了。**

### ③ 锚点三处同形（`M7` 报"出现 3 次"）

`None, speaker=speaker, remember=False,` 在 `_errand_ack` / `_errand_cancel_ack` /
`_errand_report_ack` **三处一模一样** ⇒ 必须把锚点延长到 `model=(self._npc_model(npc_id) …)`
那一行才唯一。这与第152轮"变异锚点禁 `replace(old,new,1)`"是同一条纪律的延伸：
**唯一性靠上下文，不靠运气**。

### ④ 旧夹具补装 —— §152.7 那条纪律**当场复发**

产品在 `_npc_errand_tick` 里新调 `_errand_report_ack` ⇒ 所有"挂真 tick"的桩
少了这个协作者 ⇒ `AttributeError` **被 tick 自己的 `except` 吞掉**
⇒ 症状**不是报错**，而是"`finished` 那一段整段没执行"。

⇒ 五个文件各补一个**空桩**（不动它们任何一条判据）：

| 文件 | 补什么 | 补后 |
|---|---|---|
| `第150轮/_tools/check150.py` | `def _errand_report_ack(self, *a, **kw): return None` | 104 / 0 |
| `第151轮/_tools/check151.py` | 同上 | 27 / 0 |
| `第151轮/_tools/seed151.py` | 同上 | 7 步 OK |
| `第152轮/_tools/check152.py` | 同上 | 37 / 0 |
| `第152轮/_tools/seed152.py` | 同上 | 6 步 OK |

★ 为什么给**空桩**而不是挂真函数：这四个套件考的是位置 / 门控 / 叫停，**不考台词**；
挂真函数会连带要求 `_npc_ai_available` / `npc_persona_of` 等一串外围，
那是在别人的锁里偷偷装一套新依赖。看台词的地方是 `check153`。

### ⑤ `M14` 不报红 —— 桩比产品"聪明"，把要测的值提前吃掉了

`_npc_scene_id()` 取不到时返回 `None`（它的纪律是"**不编一个**"），
产品里我补了人话兜底：`here = self._errand_place_label(self._npc_scene_id()) or u'桌面'`。

`M14` 把这个兜底拆掉，`B9` 却**没红**。原因在夹具：

```python
# 错：桩自己把 None 变成了空串
def _errand_place_label(self, scene_id):
    return _PLACES.get(scene_id, scene_id or u'')      # ← None → u''
```

产品 `_errand_place_label` 的契约是"**查不到 ⇒ 原样回 `scene_id`**"（`None` 就是 `None`）。
桩擅自把 `None` 变成空串 ⇒ brief 里出现的是「」而不是「None」⇒ `B9` 那句
`u'None' not in _t9` **永远成立**（恒真）。
⇒ 改成 `_PLACES.get(scene_id, scene_id)`（与产品同形），`M14` 立刻红 `B9`。

★ 这正是第107轮那条「**桩比产品旧 = 假红**」的镜像：**桩比产品"聪明" = 假绿**。
写桩的第一原则是**照抄契约**，不是"帮它处理掉边界"。

## 6. 那条差事的收尾（`seed153.py` 的实况）

```
  1. 派出         OK    状态=traveling，10 秒到 / 100 秒办完
  2. 到达         OK    状态=working，位置已压到 oneshot.barrens.Blue
  3. 办完         OK    状态=done，结果「那边的灯塔还在工作，没人受伤。」
  4. 回家         OK    drop 1 次 ⇒ 回落静态归属
  5. 记忆         OK    1 条 ⇒ 「（那边的灯塔还在工作，没人受伤。）」
  6. 交差         OK    发起 1 次（speaker=None / remember=False）；brief 里带了结果
  7. 不重复        OK    再推 1000 秒：发起仍 1 次、drop 仍 1 次
```

发给模型的 brief（**原文**；真正那句台词由 7B 生成，脚本不替它写）：

```
（系统提示，用户看不到）你刚刚被派去「oneshot.barrens.Blue」办「去看看」，
**已经办完了**，结果是：那边的灯塔还在工作，没人受伤。
你现在已经回来了；用户此刻在「desktop」。
请用你自己的语气，简短地跟用户交代一句（一到两句，把结果说清楚；
如果用户并不在你刚才去过的地方，就不用说"回来了"这种话）。
**不要**提到这条提示，也不要复述本句。
```

★ 最后那句括注是有意的：**"用户此刻在哪"是给模型的输入，不是让代码替它决定措辞**。
用户不在他刚去过的地方时，模型自己会说人话（而不是被硬塞一句「我回来了」）。

## 8. 遗留 / 结转

1. **`take_results()` 仍然零调用** —— 它的语义是"取走全部结果并清空"，
   给**持久化宿主**用的备选口子。本轮走的是 `finished` 那条（`done` 保留，
   `result_of()` 仍可查），所以**没有接它**：接了会把 `done` 清空，
   等于拆掉第150轮"结果可查"的语义。⇒ 登记，不修。
2. **一拍内多个人同时办完 ⇒ 各说一句**（每人一个气泡）。没有做"合并成一句"：
   `_active` 上限 64，实际同时办完两件以上很罕见；真出现了模型会各自交代清楚。
3. **没有"待交差"队列** —— 用户不在场时那句话照样发起（气泡是全局的）。
   这与派活/叫停两条既有 ack 的行为一致（**不引入新语义**是这个项目的纪律）；
   真要按场景门控，应当三条 ack 一起改，不该只改这一条。
4. 第150/151/152轮结转未动：纯空格 `npc_id` 不拒；地点别名只到作品级前缀；
   否定闸整句从严；`_item_enter_scene` 无内部调用者；`current_scene` 双语义；
   `max_sentences` 读了不用。
