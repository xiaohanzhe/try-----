## 3. 未完成事项（按优先级）

### 3.1 ★★★ 桌面四扇门贴屏幕边（方案已定，未实施）

**现象**：4 扇门画在屏幕**中部**那块 711×533 的取景框边缘，看着浮在壁纸中间。

**根因**（已实证，别再查第二遍）：
- `_room_geometry.json` **没有 `desktop` 键** ⇒ 桌面走"一屏一房间"回落
- 房间 = `cam.scoped_size()` = **320×240**（第107轮契约恒锁），乘 `scale` 2.222 ⇒ 711×533
- 取景框摆在屏幕 (924,534)，门的"边缘"是这个框的边缘
- **不能靠放大视口解决**：`plan_viewport()` 会把视口收缩回房间像素，`scoped_size()` 恒等于 320×240；只放大 `size` 的后果是四门被 `visible_in_view` 全剔除 ⇒ `behind` 为空 ⇒ 画布判空而隐藏 ⇒ **门和本体一起消失**（真机已复现）

**方案（屏幕空间物件，不动 320×240 契约）**——只改 `src/main.py` 的 `_update_scene_layer` 桌面分支：
1. `view = (屏宽, 屏高)` 取代 `plan_viewport()` ⇒ 绘制坐标空间 = 屏幕像素，1:1
2. `canvas.set_output_offset(0, 0)` ⇒ 去掉居中偏移
3. `plan_frame` 之后，把 4 个 `desk_door_*` 条目的 `rect` 就地改写为屏幕坐标：
   - `desk_door_oneshot` 上：`x=(屏宽-w)/2, y=0`
   - `desk_door_niko_home` 下：`x=(屏宽-w)/2, y=屏高-h`
   - `desk_door_ut` 左：`x=0, y=(屏高-h)/2`
   - `desk_door_deltarune` 右：`x=屏宽-w, y=(屏高-h)/2`
   - `w/h` 保持 `sprite_size × scale` 不变
4. `_pin_desktop_doors()` 改为只记录边缘归属，不再参与房间坐标换算

**验收**：
- 截图上四门贴住屏幕四边（±0 px）
- 日志 `behind=4`、`kinds=['obj']`、`canvas_visible=True`
- 左右门"靠近渐显"（第112轮口径）仍生效
- 非桌面场景**逐像素不变**（回归 `scene_p0` / `round5_smoke` 必须 IDENTICAL）

## 4. 环境坑（踩过的，别重踩）

1. **沙箱会连带收掉子进程** ⇒ 起服务、起程序、操作、抓帧必须挤进**同一个脚本**，或用后台任务。
2. **`EnumWindows` 在本进程枚举整个桌面返回 0 个窗口**（阳性对照也是 0）⇒ **禁止用"窗口存在性"当证据**，一律以**画面**为准。
3. **桌面场景不置顶**是设计 ⇒ 任何窗口都会盖住它，观察前必须 `Win+D`。
4. **单实例锁** `Global\RalseiPetMutex` ⇒ 已有实例时会挡回新启动（日志「已经在运行中了」）。
5. **EOL 红线**：`desktop_interaction.py` / `scene_controller.py` / `main.py` / `scene_camera.py` 纯 CRLF；`autonomous_agent.py` 纯 LF。改文件必须保持原 EOL。
6. **E 盘有坏点** ⇒ 临时文件用 `D:\_tmp\`。
7. **别在 bash 里内联带反引号的 Python** ⇒ 反引号会被 shell 当命令替换，注释内容被吃掉（本轮已踩，留下过 `只放大  的后果` 这种残句）。
8. **`ollama app.exe` 会在跨工具调用时被收** ⇒ 需要常驻时用后台任务。
