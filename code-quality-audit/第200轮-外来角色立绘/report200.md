## 2. OneShot **不是单张立绘，是格子表**

这是本轮最大的发现。`os_*` 的 96×128 / 120×200 / 448×320 都是 **4×4 帧表**：

| 画布 | 格 | 实例 |
|---|---|---|
| 96×128 | 24×32 | `niko.png`、`green_npc_*`、`red_*` |
| 120×200 | 30×50 | `red_kip.png`、`blue_npc_silver.png` |
| 448×320 | 112×80 | `contacts_kelvin.png` |

**实证不是推算**：`os_ling/contacts_ling.png` 恰好 **30×50** —— 正是 120×200 表的一格。
另外我用"整行/整列全透明"的缝隙去切（`grid200.py`），四列间距 24 / 30 / 112 全部对上。

行序 `down / left / right / up` 由**三条独立证据**定：
- 狐形 `os_rue`：第 1 行**尾巴在右**（⇒ 朝左）、第 2 行**尾巴在左**（⇒ 朝右）；
- 人类 `os_niko`：第 1 行鼻尖朝左、第 2 行朝右；
- 人类 `os_kip`：同。

三条一致才敢写进表。**这一条是"看图"看出来的，不是查文档查到的。**

## 5. 判据抓到一个**真缺陷**：同方向帧高不一致 ⇒ 脚底会跳

第一次落盘后 `C4` 直接红了：

```
hy_ace/down=[(22, 48), (23, 46)]
```

UTY 的帧是**逐帧紧裁剪**的，同一方向 4 帧里尺寸并不一致。渲染层按"脚底 = 窗口下沿"定位，
帧高一变脚底就上下跳 —— 走起来像在跺脚。

修法：把**一个人的所有帧**贴到同一张（最大宽, 最大高）画布，**底部对齐、水平居中**；
本来尺寸就相同且非切格的走 `copy2`，保持与源**逐字节相同**
（这样 `check191` A5 的 sha 对账仍然成立，不会因为"重存了一遍 PNG"而全员报红）。

变异自己抓出我两个问题：
1. `M4`（把 up 换成 down）第一版**只改清单不动文件** ⇒ 红 0。E3 比的是磁盘像素，
   改清单它根本看不见 —— 等于那条判据没被测到；
2. 往清单里塞一个"有名字没目录"的人，会让 C 段 `os.listdir` **抛异常**。
   判据要"红"不要"崩"（崩了 run_all 只看到"跑不起来"，红数无法计入）⇒ 补了 `isdir` 闸。

另外 `check191` 的 `A1` 原来写死 `round == 191`，把"合法的扩充"判成红 ⇒ 改成"不低于 191"
（schema 仍是 v1），并 `--only check191 --update` 刷基线。

## 7. 我自己犯的错

1. **照着 8px 小字抄文件名**：`spr_axis_left_walk_0` —— 盘上根本没有 `_walk`（真名 `spr_axis_left_0`）。
   拼版图上的文件名**当不了凭据**，只有 `os.listdir` 算。已写进 `pick200.py` 的注释。
2. **`w == h` 判头像**：`dialog_smiling.png` 是 292×293，**差一个像素**就漏过去了，
   结果把整张对话头像当走路帧切了。改成 `min(w,h) > 200`。
3. **模板里没写 `.png`**：拿带扩展名的文件名去匹配 ⇒ ut/ot/hy 全军覆没，
   只有走 `grid` 分支的 os 侥幸通过（"部分通过"最容易骗过人）。
4. **`_rx` 只认 `{k}` 不认 `{K}`**：OverTale 用的是 `iocSansDown`，大写，11 个人全部落空。
5. **Mac 在收尾时掉线**（SSH 22 端口超时，试一次即止，不循环重试）。
   前面三轮拼版都是 Mac 渲染的（56 张走路拼版 + 14 页看图纸 + 18 张切格页，sha1 双端一致）；
   最后这张总览图是本地补出来的 —— 同一份脚本，只换了机器，**没换口径**。
