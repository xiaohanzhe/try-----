# 第179轮 · 「站在谁上面」优先于 Y 排序（修第178轮的自伤）

> 一句话：第178轮把遮挡改成纯按屏幕 Y 排序，结果宠物会被**它自己站着的那块窗口**盖住。
> 本轮把优先级定死 —— **站在窗口楼板上 ⇒ 无条件插到那块窗口之前**；Y 排序只在**站在桌面**时生效。

---

## 1. 第178轮做对了什么、漏了什么

第178轮把「宠物与窗口谁压谁」从"看窗口自己的 z 序"改成"**看谁更靠下**"：

| 概念 | 用什么代表 |
|---|---|
| 宠物离观众多远 | **脚底** `pos().y() + height()` |
| 窗口离观众多远 | **下沿** `top + height`（半开口径，不是 `QRect.bottom()`） |
| 谁挡谁 | 窗口下沿 **>** 脚底 ⇒ 窗口在前 ⇒ 挡住宠物 |
| 一个前挡者都没有 | `HWND_TOP` |

这个口径本身是你第164轮裁定的（`BBA` 第三项），对**站在桌面**的情况完全正确。

漏掉的那一格是：**它自己站着的那块板**。

## 2. 现场复现（`_evidence/repro179.txt`）

`get_current_floor()` 判"站在哪块楼板"用的是 `floor_visible_contains(pos)`
= `rect.contains(宠物的点)` —— 也就是说，宠物**站在窗口矩形内部**。
`main.py` 里落点 `target_y` 本来就被夹在
`window_rect.top() + 标题栏 + 20 … bottom() - h - 20` 之间，也是矩形内部。

```text
窗口 A = QRect(100, 500, 800, 400)  ->  下沿 = 900
宠物   pos.y = 700, height = 100    ->  脚底 foot = 800

pick_insert_after_by_foot_y(800, [A]) = (170, {'reason': 'behind', 'bottom': 900, 'n_front': 1})
```

`170 == 0xAA`，就是 A 自己。于是 `set_window_behind(宠物, A)` ⇒
宠物被插到 A **之后** ⇒ **被它自己站着的窗口盖住、直接看不见**。

既然站在矩形**内部**，那块窗口的下沿**必然**大于宠物脚底 ——
这不是偶发边界，而是**每时每刻都成立**的恒等式。所以第178轮那个纯 Y 规则
一上线就是「宠物站到任何窗口上都会消失」。

## 3. 本轮口径（三条）

```python
if foot_y is not None and self.underlying_windows:
    # ① 站在窗口楼板上 ⇒ 必须在那块窗口之前（否则被自己站的板挡住）
    _stand = floor.get('window_hwnd') if isinstance(floor, dict) else None
    try:
        _stand_alive = bool(_stand and win32gui.IsWindow(_stand))
    except Exception:
        _stand_alive = False
    if _stand_alive:
        self._last_z_pick = {'reason': 'standing_floor', 'bottom': None, 'n_front': 0}
        return _stand
    # ② 站在桌面（或楼板窗口刚好被关掉）⇒ 按屏幕 Y 排序
    anchor, info = pick_insert_after_by_foot_y(foot_y, self.floors)
    self._last_z_pick = info
    return anchor
```

| # | 情形 | 锚点 | 理由 |
|---|---|---|---|
| ① | 站在窗口 A 上（A 还活着） | **A** | 可见性不可违反：站在谁上面就得画在谁前面 |
| ② | 站在桌面 / 所站窗口刚被关掉 | Y 排序结果 | "走到窗口背后被挡住"真正发生的场景就是桌面 |
| ③ | 没给 `foot_y` / `underlying_windows` 为空 | 老逻辑一字不变 | 向后兼容是硬要求（见 §5） |

**取舍口径（要记住的这一句）**：Y 排序真正的生效面**只有"站在桌面"那一条**。
站在楼板上时"谁在前"由**窗格拓扑**决定（谁托着谁），不由屏幕高度决定 ——
把一个正托着宠物的窗口挪到宠物前面，语义上就是"地板盖住了站在地板上的人"。

`A3` 就是给这条口径兜底的判据：**同一脚底、同一份楼层表，只改 `floor` 参数，
两条路径的锚点必须不同**。若两者相等，说明 `floor` 根本没参与判定 —— 那正是第178轮的病。

## 4. ★★ 我上一轮（178）漏判的原因：只验了"函数被调用"，没验"站在谁上面参与判定"

第178轮的 38 条判据里，C 段（真对象行为）跑的是：

```python
fm.get_insert_after_hwnd(DESKTOP, foot_y=...)      # 只喂了桌面
```

**没有一条喂"站在窗口楼板上"的 `floor`**。于是：

- 纯 Y 规则在这些判据下**全绿**（桌面路径它是对的）；
- "被自己站的板挡住"这个后果**没有判据能看见**。

教训（写进详版 §181）：**改一个"谁优先"的判定时，判据必须把每条分支各喂一遍**，
尤其是"看起来最普通的那条"。这轮 `A` 段六条就是补这个：站楼板 / 站桌面 /
两者必须不同 / 脚底极低 / 所站窗口失效 / `floor=None`。

## 7. 夹具/判据自己的两处错（实测后改的）

1. **`C0/C1/C2` 假红**：`_W32.valid` 只放了 `A_HWND`、`B_HWND`，
   但 `set_window_behind` **第一步就校验 target**（宠物自己的句柄 `0x1234`/`0x2345`）
   ⇒ 不合法直接 `return False`、`_stub.sp` 为空。
   改成 `valid=(A_HWND, B_HWND, 0x1234, 0x2345)`。
2. **`M1` 的期望值写错了**：我原来期望 `M1`（拆掉站楼板分支）能抓到 `A5`。
   实测红项是 `['A1','A3','B1','C1','D1','D3']`，**不含 `A5`** —— 而这是**对的**：
   `A5` 判的是"所站句柄已失效 ⇒ 不许把野句柄交出去"，与"这条分支存不存在"无关
   （分支拆掉后 `_stand` 仍是失效句柄、`IsWindow` 照样失败、照样落到 Y 规则）。
   ⇒ 期望改成 `('A1','A3','B1','C1')`。

   这条和第176轮 `M5` 那次同型：**把与变异无关的判据塞进期望**，
   等于要求变异去改变它不该改变的东西 —— 那种"红"不代表判据有效，只代表期望写错了。
