# 第113轮g · 新规则验证批判读（6 人 × 12 轮）

> 用户口径（2026-10-25 逐字）：
> 「不要过度突出个人特点，要不然会显得过于暴躁，过于柔弱等等后果，**要和正常人一样**」
>
> 上一轮（113g）在 `SPEAK_RULES` 追加了 4 句性格校准规则。**规则本身绿了 18 条判据**，
> 但那只是"字在 prompt 里"，不是"行为变正常"。本批是行为侧的第一份证据。

## 三、三个真问题

### 1. `mike` 台词复读（过火轮 3 → 12，excl 0.72 → 1.16）

原文（第 1、2 轮几乎相同）：

```
#1  喂，你来这里做什么？！你没看见门上写着什么吗？！……那你还进来！？你在找什么？…
#2  嗯，我知道了。那我先去看看。喂，你来这里做什么？！你没看见门上写着什么吗？！…
```

查人设，两处都是**逐字给出去的**：

- 【核心性格】「你的经典反应是：“喂，你来这里做什么？！你没看见门上写着什么吗？！”」
- 【语言风格】「**你的经典台词包括**：“喂，你来这里做什么？！”“没看见门上写着什么吗？！”…」

第 2 轮开头那句「嗯，我知道了。那我先去看看。」是**我上轮加进规则里的中性正例**。
⇒ 我一边在规则里写"别演过头"，一边给了一个可整段搬走的例句 ——
正是记忆里第 A12d 条锁着的东西（失真头号来源＝可逐字搬走的固定例句），这次自己犯了。

### 2. `hy_guardener` / `hy_axis` 整段英文（中文占比 0.00）

**不是 bug，是人设明文要求**：

- Guardener：「你的说话方式全部大写。你像 Axis 一样，所有对话都以大写字母输出」+ 元音替换（`FORGI>ABLE`）
- Axis：「你的说话方式全部大写，简短，直接」+ 受损混数字（`I H4VE no_CHOICE`）

这和 10-24 22:38（`4bd720b`）定的「所有 NPC 说中文」直接冲突 —— 而那次的理由写得很清楚：
「对中文用户来说这不是风格差异，是这个角色不可用」。⇒ 得在**人设侧**解决，不是再加 prompt 规则。
`hy_axis` 新批次中文占比从 0.00 回到 0.52，说明那条中文规则起了一半作用，剩下的一半被语言段压住了。

### 3. `hy_axis` 括号旁白 0 → 10/12

原文里是「（排气管喷出蒸汽）」这类**第三人称舞台指示**。来源是人设【外观】段把
「肩部的排气管会喷出烟雾」写得很细，7B 模型把它当表演素材写进台词。
产品侧 `strip_action_parentheticals` 会剥掉，用户看不见；但训练侧会一直触发重采样，
且 `TOO_LONG` 8/12（均长 199 字，产品硬约束 220）—— 这是真问题。

## 四、四个判据缺陷（都是我这边的，不是模型的）

### 1. `REPEAT` 只判整条全等 ⇒ **整段复读漏报**（已修）

`gate_reply` 原本是 `p.strip() == t`。mike 第 2 轮 = 我的例句 + 同一段台词，
跟第 1 轮**不相等** ⇒ 一次都没报，整场 12 轮「0 违规」，可它每轮都在搬同一段话。
⇒ 补子串级判据：与任一前轮有 **≥20 字连续逐字相同**即算复读。
锁在 `check113 B4d`（含正控制：换一句话不报、8 字短呼应不报）。

### 2. 「过火率 ≤ 旧+0.05」在 12 轮样本下**数学上不可达**（已改）

12 轮最小可分辨变化 = 1/12 = **0.083** > 0.05 ⇒ 只要多响一轮就必判红。
`susie` 0 → 1 轮被判 FAIL，而那一轮是「烦死了，别跟我扯这些虚头巴脑的！」
—— 那是 Susie 的设定，不是过火。⇒ 改成「过火轮数 ≤ 旧 + 1 轮」。

### 3. 单句轮次里一个强调词必判红（已修）

`extreme113` 的口径是"每句"比值 ⇒ 一句话里出现一个「特别」，比值必然 1.0 > 0.5。
`asgore` 第 12 轮就因为「那个夜晚特别漫长」被判过火 —— 分母太小，不是模型过火。
⇒ 要求绝对次数 ≥ 2（`MIN_EVIDENCE`）才计入 hit。

### 4. 拿 `len(system)` 比语料 `system_chars` 是**无效判据**（已废弃）

`system_for` 会注入 `relation_patch` / `evolution_patch`，这两份卡随训练一直在变
（toriel 实测 7761 vs 7864，差 103 字纯粹是关系卡更新）。
拿长度当判据 ＝ 把"关系卡变了"误报成"prompt 没换"。
⇒ 改成直接断言「当前代码产出的 prompt 里逐句含新四句」，锚点用 AST 从 `check113g.MUST` 取。

### 5. 「硬违规不增加」对三个角色是**跨版本比较，本身无效**

`NOT_CN` 是 10-24 22:38 才引入的（`4bd720b`）。`mike`(21:24) / `hy_guardener`(19:44) /
`hy_axis`(18:01) 的旧记录全在它之前 ⇒ 旧批次"0 违规"不是"以前更好"，是**当时没这条判据**。
⇒ 旧记录早于该时刻一律标 `N/A`。`susie`(04:59) / `asgore`(03:31) 在那之后，才可比。

## 五、结论与下一步

**不开全量 77×48。** 72 轮里已经有 3 个真问题，全量会把它固化进 48 轮语料。

按优先级：

1. **人设侧**：`hy_guardener` / `hy_axis` 的【语言风格】段改中文机械腔（保留"句短、无语气词、
   程序式措辞"，专有名词仍写成 `AXIS MODEL 014` 这种大写）；`mike` 去掉「经典台词包括」台词库
   与「经典反应」逐字句，改写成语气描述。
   ⚠️ 改人设必须同步 `_personas.json` 的 `chars/bytes/sha256/sha256_lf`（`check113` A 面锁着）。
2. **规则侧**：`SPEAK_RULES` 里的中性正例「嗯，我知道了。那我先去看看。」是**可整段搬走**的形态，
   要么改短到"搬运无害"，要么换成不可整段复用的写法。
3. 上述改完，重训这 3 人 12 轮复验，再决定全量。

**已修并落地的（本轮）**：`REPEAT` 子串判据 + `check113 B4d` 锁；`verify113g` 四条判据修正。
全量 G2：**PASS=5462 / FAIL=0 / 105 套件 / 零 DIFF**（`check77` 基线因第80/99轮契约扩容而过期，已刷新：
`wired_how` 1504→2534，其自身 exit 0 / PASS 29 / FAIL 0）。
