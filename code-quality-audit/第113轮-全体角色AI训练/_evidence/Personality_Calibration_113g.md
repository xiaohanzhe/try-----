# 第113轮g：性格校准 —— 「不要过火，要和正常人一样」

> 用户口径（2026-10-25 逐字）：
> 「对，但**不要过度突出个人特点**，要不然会显得过于暴躁，过于柔弱等等后果，**要和正常人一样** ok？」
>
> 这是对早先「**尤其性格，也要好好做**」的限定，不是撤销。两条合起来才是真口径：
> **性格必须存在（没有＝失败），但不许演成极端（过火＝也失败）。**

---

## 1. 结论（含一次自我推翻，务必读完）

### 1.1 最重要的一条：**当前 prompt 下，过火这件事没有被数据证实**

| 批次 | 角色数 | 最高过火率 | 说明 |
|---|---|---|---|
| **新 prompt**（含「用简体中文说话」「每句话本身也要短」等条款） | 23 | **0.06**（`ot_alphys`） | susie 0.02 / asgore 0.00 / 其余多为 0.00 |
| 旧 prompt | 25 | 1.00（`hy_guardener`） | **不是当前表现** |

⚠️ 我一度根据混在一起的普查点名了 `hy_guardener`(1.00)、`hy_axis`(0.33)、`mike`(0.31)，
**这三个全是旧 prompt 的产物**。核实过程见 §3.4 —— 这三条语料跑于 10-24 16:11~21:56，
`system_chars` 比现在少 **545 字**，压根没有那几条规则。
**拿旧数据说「现在过火」是错的，已撤回。**

### 1.2 那这轮还要不要改？

要，但性质变了：**不是「修一个已证实的缺陷」，而是「加一道预防性的护栏」**。
理由：用户明确要求；且旧批次里那种把性格演成大字报的倾向是**真实存在过的**
（`mike` 那句 `！！？` 密集是真样本），新批次只有 23/77 个角色验证过。

### 1.3 治「过火」的写法有一条硬约束

**不能写「不要过于暴躁／不要过于柔弱」**——实测那样等于**给极端做示范**（§2）。

## 2. ★★★ 为什么不能写「不要过于暴躁」—— 探针实测

`probe_paren113g.py`（3 变体 × 3 角色 × 10 轮）第一组 susie：

| 变体 | 括号命中 |
|---|---|
| P0 base | 0/10 |
| **P1P** 只讲原则，且**不出现「括号」二字** | **10/10** |
| **P1N** 同 P1P + 一条**中性正例**「嗯。我明白了。」 | **1/10** |

`P1P` 里那句是：

> 「不要写动作、表情、心理活动，也不要写从外面看自己的句子（**比如描述自己的神态**）」

它**描述了旁白长什么样** ⇒ 就成了旁白的模板。
而 `P1N` 只多加一句「正确长什么样」的正例 ⇒ 立刻跌回 1/10。
asgore 侧同向：`P1P` 也是 10/10。

**推论（直接决定规则怎么写）**：
- 写「不要过于暴躁」「不要动不动就发火」＝ 把「暴躁」示范一遍；
- 正确写法 = **只描述「正常」是什么样 + 给一条中性正例**，**一个极端词都不提**。

> ⚠️ 诚实标注：本组 susie 的 `P0 base` 是 0/10，而上一版 f 探针同角色是 6/6 —— 两次基线**整体反转**。
> 一部分原因是 `stable_seed` 标签串从 `'probe113f'` 改成了 `'probe113g'`（种子变了），
> 所以**不能与 f 版逐值对比**；但 P1P / P1N 之间**同 seed**，这个对照有效。
> 教训：跨版本比必须**沿用同一 seed 标签**重跑，否则差异里混着「换了种子」。

## 3. 「过火」怎么量（`extreme113.py`）

### 3.1 为什么不用人工阈值

每个角色的正常区间本来就不同（susie 正常说话就比 toriel 冲），拍一个「感叹号 > N 就算过火」
必然一边放过一边冤枉。⇒ 改成 **6 个可解释分量 + 有语义的软上限**，并把上限表打印出来接受复查。

| 分量 | 上限 | 单位 | 为什么是这个位置 |
|---|---|---|---|
| `excl` 感叹号 | 0.75 | 每句 | 每句都带感叹号 = 靠吼叫撑情绪；正常人只在真激动时用 |
| `multi` 连续重复标点 | 1.0 | 每轮 | 一轮最多一处「！！」；再多是漫画式夸张 |
| `caps` 6+ 字母大写 | 0.5 | 每句 | 每两句最多一个大写词；成片大写 = 一直在吼 |
| `emph` 强调副词 | 0.5 | 每句 | 每两句最多一次「超级/绝对/根本」；句句加码 = 用强度冒充性格 |
| `ellip` 省略号 | 1.5 | 每句 | 每句最多一个半「……」；通篇省略号 = 柔弱/欲言又止演过头 |
| `apol` 道歉自责 | 0.5 | 每句 | 每两句最多一次道歉；句句自责 = 过度卑微 |

### 3.2 这个度量自己栽过三次（全靠正/负控制抓住）

1. **过宽（v1）**：复合判据用「任一分量 > P90」，而 `apol`/`multi` 的 P90 撞到地板值 0
   ⇒ **出现一次就判过火**（正常人也会说一句「抱歉」）⇒ 改为软上限表。
2. **假红（v2 首跑）**：5 条正常台词判红 1 条 —— `这个我不太确定` 里的「**太**」被当成强调副词
   （其实是**减弱**语气）⇒ `EMPH` 去掉裸「太」，只留多字词；`caps` 从 4+ 字母放宽到 6+
   （`Howdy` 不是吼）。
3. **取值 bug**：`pick_latest` 把整个语料 dict 当成时间戳塞进 `dropped` ⇒ 输出 161 KB。

现在：**鉴别力 PASS** —— 暴怒样本判 `excl/multi`、柔弱样本判 `ellip/apol`、
正常样本不判红、5 条正常台词 0 误伤。

### 3.3 一次差点酿成大错的混样

v1 把 53 条语料（29 条旧 \+ 24 条新）放在**一个分布**里算 P90，
`hy_guardener` 那种旧产物就被当成"当前表现"排到榜首先。

**判据：`metrics.lang` 是不是 null**（该字段是第113轮后续才加的）。
- 有 → 新 prompt；
- 没有 → 旧 prompt。两批 `system_chars` 实测差 545 字（`hy_guardener` 旧 9838 / 现 10383）。

⇒ v2 起按批次拆两表，**只用新批次下结论**。

|---|---|---|
| `ot_alphys` | 0.06 | emph |
| `os_george` / `os_niko` | 0.03 | excl / emph |

## 4. 旧批次里的两种毛病（**不是当前表现，仅作参考**）

**`mike`——真「暴躁演过头」的样本（内容其实很好，是标点在替情绪干活）**
```
喂，你来这里做什么？！你没看见门上写着什么吗？！那你还进来！？你以为自己是谁！？
```
同一段后面接的是很细腻的自我怀疑独白。⇒ 要治的**只是标点密度**，不是内容。

**`hy_guardener` / `hy_axis`——不是性格问题，是语言崩坏**
```
HE-HELLO THERE. WAS IT YOU WHO DISTURBED THE FLORA? ... _IT IS FORGI>ABLE.
T-O-D-A-Y... 1 HAV3 N-O C-HOICES. 1 R-O-L-L A-ROUN-D
```
`FORGI>ABLE` / `_RESPECT` / `GARRDEN` 是人设原文带下来的噪声；`T-O-D-A-Y` 是把
「机械/结巴」演成了拼写级。这两条**与性格无关**，属语言崩坏线。

## 5. 一个被我自己推翻的结论（留档，避免重犯）

我一度写：「`SPEAK_RULES` 里中文规则确实在 prompt 里，但 `hy_guardener` 中文占比 0.00 ⇒ **规则无效**」。

**这个结论不成立**。核实：
- `hy_guardener` 语料 `started_at = 2026-10-24 19:44`，`system_chars = 9838`；
- 用当前代码现场生成同一角色的 prompt = **10383 字**；
- 差的 545 字正是后续加的那几条规则；
- 且该语料的 `metrics.lang = **null**`（字段本身是后来才加的）。

⇒ **旧语料里没有那条规则，「规则无效」无从谈起。要判断有效性必须在新 prompt 下重跑。**

> 教训：**看到「规则在 prompt 里」不等于「这批语料跑的就是这条规则」**。
> 判据必须是「该语料生成时的 prompt 是否含此规则」，间接证据（语言占比、system_chars）都得对得上时间。
