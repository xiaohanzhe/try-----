## 3. 改了什么 / 明确没改什么

**改**：整句英文台词 → 中文。内容、节拍、路线分支、故障错字全部保留。
故障错字按中文重建（对应原文的 `FORGI>ABLE` / `S4VE` / `no_CHOICE`）：

    FORGI>ABLE → 原>谅      S_SEEMS → 似_乎      _RESPECT → _尊重
    S4VE       → 救4下      no_CHOICE → 选_择    TH3 SAME FaTE → 同一个结_局

**没改**（原作依据，一个都不许动）：
- 专名：Axis / Model 014 / Steamworks / Chujin / Ceroba / Clover / Kanako / Asgore / The Furnace / Plan B
- `[ticked]` / `[forget]` / `[screw]`：这是「程序过滤器输出」的视觉符号，**单词级英文不会引发整句照搬**
  （旁证：`os_rowbot` 每句都有 `[...]`，读数是健康的 0.68）。而且它不在示例段，不参与密度计算。

**大小写口径统一**（原「不要使用小写字母」是 0.00 的**最初触发点**）：
中文没有大小写，写「全部使用大写字母说话」＝执行不了 ⇒ 模型只能改说英文。
三处（`hy_guardener` L82/L104、`hy_axis` L18/L88/L113）统一改成：

显示层真实存在：`dialogue_ui._caps_on()` 按 `_kinds.json` 的 `caps` 登记做大写化（`check113h B1~B4` 锁着）。

## 4. 本轮踩到的 4 个坑（都是「判据/工具说谎」）

### 4.1 `apply_loc113i.py` 的 EOL 判据只判「有没有 CRLF」= 等于没判

第一版：`c3 = (old_crlf > 0) == (new_crlf > 0)`。
后来我用编辑器改 `hy_guardener` 一个字，工具把整份文件的 CRLF **全抹成 LF**（112 行、94 个 CRLF → 0），
这条判据照样绿。真判据是 **CRLF 个数必须一个不差**（译版是整行替换、行数不变）。
已改为 `old_crlf == new_crlf`，并把该行内容重算索引（`7696 → 7698` 字）。

### 4.2 这些人设是**混合 EOL**，不是纯 CRLF

    hy_guardener  112 行 / 94 个 CRLF（18 行纯 LF）
    hy_axis       121 行 / 112 个 CRLF（9 行纯 LF）

第一版 `localize_axis113i.py` 用 `splitlines()` + `'\r\n'.join()` 重建 ⇒ 把 9 个 LF 行也改成 CRLF，
于是「尾部运行口径块逐字不变」直接报红（尾块本身没动，是**行分隔符**被改）。
改成 `splitlines(keepends=True)` + 原位替换（行尾原样带过去），并加
`assert ''.join(lines) == raw` 自证。

### 4.3 锚重复：`· 你其实很孤独。Chujin 死了…` 在 L31 和 L73 逐字相同

第一版锚校验只判「全文唯一」，两条撞车直接拒绝运行（好的一面：它拒绝跑了，没写半截）。
改用**行内片段**做锚（`THAT IS MY FUNCTION` / `PROTECTED。”但你的功能不只是保护`），
校验条件 = 「本行命中 1 次 **且** 全文唯一」。

### 4.4 `replace()` 没命中却照样打印「已修改」

给 `check113h.py` 插 `import re` 时，脚本执行 `t.replace('import os\nimport sys', ...)` —— 而文件是 **CRLF**，
模式根本不存在，`replace` 静默返回原串，脚本却打印了 `added import re` 并写回。
结果 `NameError: name 're' is not defined`。
⇒ 修法：`assert OLD in t` / `assert t2 != t` / 写回后回读断言。**「改了」和「打印改了」是两件事。**

### 4.5 `cards113.py --all` 会**静默抹掉训练产物**（patch / eval）

改人设后必须重建训练卡（`check113 A4` 比 `persona_sha256`）。但 `cards113.py` 是从人设**重新抽取**，
它把 `patch`（训练后写进卡里的纠正句）和 `eval`（实测违规记录）一并重置成 `""` / `{}`。

全量重建的实测后果：96 张里 5 张有训练产物（`kris` / `rouxls` / `susie` / `tenna` / `ut_frisk`），
全部被清空（`kris.patch` 从「不要用括号写动作或表情，只写你说出口的话。」变成 `""`）。
`A4` 只查 sha，**查不出这个**。

处置：`git checkout --` 恢复那 5 张（它们的人设没动，恢复是对的），只保留 2 张目标卡的改动。
`hy_guardener` / `hy_axis` 的旧卡 `patch` 本来就是空的，所以这次没丢东西。
⇒ **待办**：给 `cards113.py` 加重建时保留 `patch`/`eval`，或给 `check113` 加一条「重建后训练产物不许丢」的判据。

## 8. 本轮第 5 个「判据说谎」

`bkp_train113i.py restore` 的判据写成 `ok = (exp is None) or (got == exp)`。
清单文件读不到时 `exp` 恒 `None` ⇒ **每一项都打 OK**，还打印「与备份逐字节一致」。

真判据：`git status --porcelain <这 4 个文件>` 为空（训练前它们与 HEAD 一致，回到 HEAD 即等价于回到备份）。实测为空 ✓。

附带教训：**E 盘抖动期「写成功」不等于「落盘成功」** —— 备份完 `listdir` 是空的（4 个文件 + 清单全没了）。
备份脚本必须**回读校验**；我只记了 size/sha，没回读。
