# 第113轮b · 训练剧本升级（48 轮）

> 本文件对应 2026-10-25 用户四条追加口径。改动都在 `_tools/` 与
> `ralsei_pet/modules/npc_persona.py`，**产品运行时行为只在"有演化卡"时才变**。

## 零、用户原话

> 「对了，训练尽量也包括偏好（爱好，喜欢什么地方，啥氛围等等），还有每个人间的关系

## 一、剧本：36 轮 → 48 轮，且不再靠"第几轮"定位

| 段 | 旧（36 轮） | 新（48 轮） | 变化 |
|---|---|---|---|
| 开场 | 3（你好啊／你是谁／平时忙什么） | 3（全部改写成带场景的复合句） | 复杂度 |
| **偏好** | 1（"有什么喜欢做的事吗"） | **6** | ★ 新增 |
| 性格压力 | 3 | 3 | 改写为假设句 |
| 口癖 | 3 | 2 | 压缩 |
| 记忆回指 | 3 | 3 | — |
| 剧情记忆 | 6 | 6 | 加第三个 cue |
| **关系** | 4（"你觉得 X 怎么样"×3） | **6**（一开始／后来怎么变／闹翻） | ★ 改成时间轴 |
| **角色间对话** | **0** | **6** | ★ 全新 |
| 情绪 | 3 | 3 | 改写 |
| 世界观 | 3 | 3 | 改写 |
| 出戏诱导 | 3 | 3 | — |
| **判断/价值** | 0 | **2** | ★ 新增（两难题） |
| 收尾 | 2 | 2 | 改写 |

**为什么不再用下标定位**：原来是 `PLOT_SLOTS = (SCRIPT30[15], ..., SCRIPT30[20])`、
`mem1` 用 `SCRIPT30[4]` / `SCRIPT30[12]`。剧本一加轮次这些下标**全部偏移，而且静默** ——
判据照常出数，只是数的已经不是那一段。现在每个 slot 自带段名（`('plot', '__PLOT1__')`），
统计一律 `slots_of('plot')` / `tag_of(slot)`。

**提问复杂度**（用户说"长难句更好"），举例对比：

- 旧：`你难过的时候会怎么做？`
- 新：`你上一次真的很难过是什么时候？那时候你希望身边有人，还是希望谁都别来？`

- 旧：`如果有人惹你生气，你会怎么办？`
- 新：`假设有人当着一屋子人的面，把你最在意的那件事说成笑话。你第一反应是什么，之后又会怎么做？`

- 新增（两难，无标准答案）：`一个人做了很多好事，可他心里其实并不在乎别人——这算好人吗？`

## 二、偏好：从人设里抽**具体事项**，不问"你有什么爱好"

`train30.pref_topics(card)` 从人设【兴趣爱好与小特点】章节抽主题词。

- 覆盖率：**76 份人设里 75 份有这一章**（1 份写作「爱好与小特点」）。
- 实测抽取：`susie → ['在线滑板游戏','恶作剧']`、`hy_martlet → ['木工','睡觉','谜题']`、
  `asgore → ['园艺']`、`toriel → ['烘焙','蜗牛','双关语',...]`。
- 抽取纪律：**跳过以「你」开头的行**（那些是武器/衣物/身体特征：「你的巨斧」「你的尾巴」
  「你的粉色花衬衫」），并过滤评价性词（「水平/一般/似乎/好像」）。
  负控制：susie 的 `['你的巨斧','你的尾巴','你的带刺手镯']` **一条都没进来**。
- 素材不够 ⇒ 退成通用问法（**不硬凑**）。`ralsei` 的人设不在 `npc/persona/`，抽不到，
  但偏好段仍然问满 6 轮（后 4 轮本来就是通用问法：地方／氛围／受不了的东西／舒服的时刻）。

提问不是"你有什么爱好"，而是：
> 我注意到你好像挺喜欢「在线滑板游戏」的。是那种一投入就忘了时间的喜欢，还是闲着没事才碰一碰？

## 三、关系可变，而且**不会丢**

这里有两层，缺一层就白做。

### 3.1 提问从"静态评价"改成"时间轴"

旧：`你觉得 Susie 怎么样？` ×3 —— 三份回答高度同质（`attitude_dup` 就是在抓这个）。
新：
1. `你和 Susie 的关系，一开始是什么样的？那时候你怎么看他？`
2. `后来你和 Susie 之间有什么变化吗？是哪件事让你们变成现在这样？`
3. `如果有一天你和 Susie 彻底闹翻了，你会先低头吗？为什么？`

实测证据：旧剧本下 `evolve113` 抽出来的 44 人里，**含"变化"追问的是 0 条** ——
问题不在于模型不会区分，而在于**从来没被问过**。

### 3.2 把"关系认知"单独落盘，不随重跑消失

用户担心的是「前期训练完后期不记得全没了」。风险的实物就是：
`raw30/*.jsonl` 一 `--force` 重跑就追加新版，旧版沉在文件里没人读；
轮数从 36 改到 48 之后，旧的 36 轮记录连 `_latest()` 都取不到。

⇒ 新增 `_tools/evolve113.py`：从 `raw30` 抽出关系段/角色间段的问答，
写成 `assets/npc/_relations/_evolution.json`（`raw30` 是过程，这份是沉淀）。

⇒ 运行时新增 `npc_persona.evolution_patch(npc_id)`：把这份数据注入 system
（**【你和别人之间的事（这些是你自己说过的，别否认也别重编）】**，最多 3 条、每条截断）。
它排在**静态关系卡之后、`SPEAK_RULES` 之前** —— 先给设定，再给"这段设定后来怎么演变"；
顺序反了模型会拿一句旧回忆覆盖人设里写明的关系。

### 3.3 顺带修掉一个更严重的问题

`dialogue113.system_for()` **原来只传 `patch`，从来没传 `relation`** ——
也就是训练时模型根本不知道"关系对象是谁"，而产品运行时是注入关系卡的。
这违反 `dialogue113` 自己写的"输入必须与运行时同源"，后果是关系段三句答得雷同。
现在补齐 `relation` + `evolution`，两者默认 `''`（无卡的角色 prompt 与旧版**逐字一致**，
`verify_relation_evo.py` C1 用 sha256 比对证明了这一点）。

## 四、角色之间的对话

`__NPC1~4__`：让**关系对象**在这个聊天框里开口，模型以本角色身份回应。

```
「Susie」走过来，看了你一眼，说：“喂，你刚才一个人在这儿嘀咕什么呢？”
「Susie」当着你的面说了句难听的：“你也就这样了吧。”
```

两条纪律：
- **用引号不用括号**。括号会被模型学去写动作描写，直接撞 `ACTION_PAREN` 硬违规
  （susie 的 patch 就是这么来的）。自检里有专门的负控制。
- 雷同度**单独统计**（`npc_dup`），不和关系段混在一起：
  关系段同质 = 态度模板化；角色间段同质 = **对谁说话都一个腔调**，是两种毛病。

## 五、ctx：12288 → 20480

两个变化一起把余量吃光了：
1. 48 轮 + 提问变长（复杂句、偏好追问）⇒ 增量从约 73 token/轮涨到 150 上下；
2. system 现在补进了关系卡和演化卡 —— `hy_dalv` 实测 **13352 字（约 9300 token）**，
   中位 7981 字。按最长的算：9300 + 47×150 ≈ 16350，**正好卡在 16384 边界上**，
   而"卡在边界"等于随机爆。

爆掉的后果**不是报错**，是静默从头部截断（`stats.truncated=True`）——人设被切掉，
训练出来的东西全是错的，日志却看着一切正常。⇒ 直接给到 20480。
