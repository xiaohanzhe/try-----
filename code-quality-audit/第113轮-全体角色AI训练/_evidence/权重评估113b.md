# 权重微调：做不做、为什么（2026-10-24 实测结论）

> 你的原话：「**权重这个东西要是影响大的话那就你看着怎么处理一下，要是不大那就先放着吧**」。
> 结论：**先放着**。但理由不是"影响不大"，而是**这台机器做不了 + 投入产出极不成比例**。
> 下面每条都有实测依据，不是拍脑袋。

---

## 1. 硬件事实（今天的实测）

| 项 | 实测值 | 对训练的含义 |
|---|---|---|
| 显卡 | **Intel(R) Arc(TM) Graphics**（核显，`AdapterRAM` 报 2 GB，实为共享内存） | 无独立显存 |
| CUDA | `nvidia-smi` / `nvcc` 均不存在 | **没有可用的 GPU 训练后端** |
| CPU | Intel Core Ultra 5 125H，14 核 | 只有它 |
| 内存 | 33.9 GB，实测可用 **6.2 GB**（今天）/ **0.6 GB**（昨晚模型常驻时） | 波动极大 |
| 现有模型 | `ralsei:v4` = qwen2.5-7b-instruct **q4_K_M** | 已量化，**不能直接拿来训练** |

关键：**q4_K_M 是推理用的量化格式，不能反向传播**。要做 LoRA 必须另下一份 F16/BF16 权重（7B ≈ **14 GB**），本机可用内存 6.2 GB —— 连加载都做不到。

## 2. 就算硬上，时间成本是多少

用实测的 CPU 速度反推（`probe113b.py` 实测 prefill **约 45 tok/s**）：

| 步骤 | 估算 |
|---|---|
| 一条 SFT 样本（512 token，含前向+反向） | ≈ **34 秒** |
| 最低可用规模（2000 条 × 3 epoch = 6000 步） | ≈ **56 小时** |
| 而且是 14 GB 权重常驻 + 梯度/优化器，**要和现在 7.6 GB 的推理服务抢内存** | 大概率 OOM |

对照一下：**今晚现有的 prompt 层训练，77 人 × 30 轮 ≈ 8.5 小时**，覆盖 2310 轮真实对话。同样的时间，权重路线连一个 epoch 都跑不完。

## 3. 收益对比：prompt 层已经拿到多少

| 指标 | 当前实测（4 轮基线） | 权重能再改进什么 |
|---|---|---|
| 硬违规 | 77 人里 **75 人零违规**，2 人补训后归零 | 减少"要靠长 prompt 压住"的依赖 |
| 对他人态度 | 36 人 / **66 组对比 0 同质** | 更自然的语气差异 |
| 格式合规 | **90.8%** | 剩下 9.2% 的漂移 |
| 改一次人设的代价 | **改一个 txt，下次对话立即生效** | 权重要重新训练一遍（56 小时） |

最后一行才是决定性的：你要求的「**用 7B 就是要他贴合人物且不出 bug**」，靠的正是"人设改了马上能看到效果"这个循环。上权重会把这个循环从**秒级**变成**两天级**，反而更难调到你要的样子。

## 4. 结论与触发条件

**现在：不碰权重。** 继续走 prompt + 语料 + 评测闭环（L1 层），这是这台机器上唯一能日更的路线。

**什么情况下重新考虑**（写清楚，免得以后又反复讨论）：
1. 有了 NVIDIA 独显（≥12 GB 显存）或能租云 GPU —— 那时 QLoRA 训 7B 是几小时的事；
2. prompt 已经撑不住（比如人设长到 1 万字、响应明显变慢），需要"把 prompt 蒸馏进权重"来省 token；
3. 要做**离线小模型**（比如 1.5B 跑在桌宠里，不依赖 Ollama）—— 那是另一条产品线，权重是必需品。

**真要做时的现成材料**（已经备好，不用重做）：
- `_evidence/raw/*.jsonl` —— 308 轮真实对话（含 system、每轮问答、判据结果）；
- `_evidence/raw30/*.jsonl` —— 本轮 77 人 × 30 轮（规模上够做一次像样的 SFT）；
- 77 份人设 txt + 关系卡 —— 可直接组装成 instruction 数据集；
- `npc_persona.build_system_prompt` —— 训练与产品同一出口，不会训出"只在训练里有效"的东西。

## 附：为什么"用 q4 权重直接微调"这条捷径不存在

量化后的权重里，每个权重被压成 4-bit 整数 + 一组 scale。反向传播需要**对权重求梯度**，
而 4-bit 量化的前向是**分段常数**（step function）—— 梯度几乎处处为 0。
业界做法（QLoRA）是：把量化权重视为冻结，只训练插入的 LoRA 适配器（本身是 bf16），
所以它仍然需要 F16 基础权重在显存里，只是省了优化器状态。
⇒ 省的是显存，**不是"能在 CPU 上跑"**。
