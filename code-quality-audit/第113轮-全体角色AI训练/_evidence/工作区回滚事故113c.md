### 2.2 "回滚"的判定方法（不是看 diff，是看哈希）

2. 与 `HEAD:path` 比；
3. 不等的话，再与"最近 3 个改过该文件的提交"里的版本逐个比；
4. **命中某个旧提交 = 回滚**（工作区内容是旧版，不是新改动）。

## 4. 复检判据的连带修正（判据自己也会说谎）

第⑥项原来写成"`git status` 里所有条目都必须落在预期路径内"，
首跑得到 **1122 条越界 / 1133 条** —— 一个永远 FAIL 的守卫，等于没守。实测后改成三条窄判据：

| 判据 | 内容 | 为什么这么切 |
|---|---|---|
| ⑥a | **未跟踪**文件必须全在预期路径 | 这才是"临时文件落进仓库"的真实风险 |
| ⑥b | 产品**代码**（`modules/` + `src/`）本轮只许改 `npc_persona.py` | 资产 JSON 属数据面，历轮遗留的改动不算越界（只报数） |
| ⑥c | 产品代码/人设数据**不许有文件被删**；资产与评测目录的历史删除只报数 | 1018 条里 812 条是未接线的 OneShot 背景，属存量 |

另外两个真踩到的坑，都写进注释了：
- **`git status` 必须 `-c core.quotepath=false`**：中文路径默认被 C 引号包成
  `"\347\254\254113..."`，连"预期路径"都匹配不上 —— 首跑的 1122 条里有一大半是这么来的假象。
- **不能按"暂存列"切"本轮的手"**：实测工作区 `63 ' M' + 1020 ' D' + 50 '??'`，
  那 1020 条历史删除**并没有暂存**（全是工作区侧 ` D`），按暂存列切会把它们当成本轮的手。

### 新增第⑦项：反回滚闸

⑥ 只看"路径是否越界"，**看不出"内容倒退"** —— 这次事故正好落在它的盲区里。新增：

> 产品文件的**行数不许比 `HEAD` 缩水 >30%**，且 14 个关键文件一个都不缺。

负控制 3 条（缩水 40% 要抓得住 / 变多不许误报 / **文件消失要抓得住**）。
其中"文件消失"这条首跑是 **FAIL** —— 因为最初写成
`disk_src is not None and ratio < 0.7`，把"整个文件没了"判成"没有缩水"，
恰恰是最该报的情况漏掉了。**负控制当场抓住了判据自己的 bug。**

## 5. 续查：回滚的**不只是产品代码**，还有回归脚手架（更危险）

第一轮还原只处理了 `git status` 里 ` M`/` D` 的文件。跑 G2 后发现两处对不上，
顺着查下去，回滚范围比想象的大：

| 文件 | 磁盘 | HEAD | 后果 |
|---|---|---|---|
| `code-quality-audit/regress/run_all.py` | 93 个套件 id | **102 个** | `check101/102/103/104/105/106/107/109/111/112` **全部掉出 SUITES** ⇒ G2 照常"跑绿"，只是**少测了 9 轮** |
| `code-quality-audit/regress/baseline.json` | 按被回滚的树录的 | 与 HEAD 同时代 | 基线对不上当前树 ⇒ 24 处 DIFF 满天飞，但看不出根因 |
| `ralsei_pet/src/main.py` | 混合态（旧基线 + 本轮接线） | 旧基线，**缺本轮接线** | 按 HEAD 还原后 `check113 C5/C10` 直接报红（`training_patch` / `relation_patch` 没接上） |
| `.workbuddy/memory/MEMORY.md` | 停在 §100（`js_len=10050`） | 到 §110 | 注入的记忆少 10 轮；且 **js_len 已超 10000**，`check95 A2` 必红 |
| `.workbuddy/memory/参考-契约与历轮（详版）.md` | 11054 行（停 §100.5） | **12436 行**（到 §110） | 详版丢了 10 轮细节 |

### 5.1 由此得到的两条硬教训

**★★★ ① "少测了"比"测红了"危险得多。**
`run_all.py` 少 9 个套件，G2 输出依旧是 `FAIL=0` 的一片绿 —— 因为你少测的那 9 轮
本来就不会报错。**回归入口自己必须被回归**：本轮把 `run_all.py` / `baseline.json`
加进 `recheck113b` 的 **⑦ 反回滚闸**（16 个文件），守的就是"行数不许缩水 >30%"。

**★★★ ② 判据/脚手架都在"工作区"里，也可能被回滚。**
前几次事故（第93轮"被 10-05 reset 冲掉"）只关注产品代码；
这次证明**校验器、基线、回归清单、记忆文件**同样会被换掉，而且**换了之后所有绿灯都是假的**。
⇒ 复检第⑦项必须覆盖"产品 + 脚手架 + 记忆"三类，不能只覆盖 `ralsei_pet/`。

### 5.2 main.py 本轮接线的找回

按 HEAD 还原 `main.py` 后，`check113 C5/C10` 报红 —— 说明混合态里那 `+74` 行中包含
本轮新增的接线，而 HEAD 没有。按判据把它补回唯一出口 `npc_system_prompt()`：

```python
        return npc_persona_mod.build_system_prompt(
            npc.name, persona, entries, npc_id, self._build_npc_context(npc_id),
            life=self._npc_life_blocks(npc_id),
```

  会造出混行、以后每次 diff 都变整文件。改用 `newline=''` 读写 + 按 CRLF 拼，
  改完实测 `lone_lf=0`、CRLF 16526 → 16531。
