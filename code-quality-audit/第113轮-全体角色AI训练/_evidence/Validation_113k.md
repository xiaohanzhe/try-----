# 第113轮k · 验证报告：特定事件 → 去哪儿

> 用户口径（2026-10-26 逐字）
> 「那就继续训练吧，对了，我说的**特定事件**就是指，**吃饭，活动，休息，做任务**等，
>   他能**识别出来要去哪**，并**给出建议**这样的，就像是人类之间问，咱吃饭去吧，
>   别人会回答，**那要不去 XXX 家餐厅**？这样的话一样」

---

## §1 口径拆成三件事（混成一件就会做错）

| # | 要什么 | 落在哪 | 关键约束 |
|---|---|---|---|
| ① | **听懂**别人在张罗什么 | `npc_life.detect_activity()` | 只认**意图词**（吃/饿/累/玩/买…），认不出就说认不出 |
| ② | 知道**哪儿真能干这事** | `npc_life.place_matches()` + `main._activity_places()` | 只认**地点词**；**只能在本章**；原作里没有的不许编 |
| ③ | 能**自然接一句建议** | `npc_life.activity_hint()` | 只给"有哪些地方"，台词由模型自己组织 —— **不写死模板** |

★ ① 和 ② **必须是两张表**。混成一张就会因果倒置：变成「因为人在餐厅，所以他在吃饭」，
而人说话是「我想吃饭，所以去餐厅」。这一条写进了 `npc_life` 的注释和 `check113k` 的套件说明。

★ ③ 为什么不写死台词：第113轮i 的 **A12d** 已经裁定「**可逐字搬走的固定例句**是人设失真的
头号来源」。所以提示块只说事实 + 一句"用你自己的说法，别照着念"。

## §2 本轮抓到的 **5 个真错误**（全部靠"全量人读"，6 个样本一条都看不出）

### 2.1 `diner` 被吃掉，说不清"是哪一家"（用户例子里的那个 XXX 没了）

第一版端到端输出的原文：

```
【这会儿能张罗的事】要去吃点东西，你们这儿真有的地方：家乡（第一章 · 黑暗世界）。
```

**用户要的是「那要不去 XXX 家餐厅」，而"餐厅"这一层信息根本没进 prompt。**
根因：`ch1.hometown.diner` 的 `name` 是 `家乡·diner`，但 `name_derived=True`
⇒ `_scene_place_label()` 判它"无名"，只剩区名 `家乡`；`diner` 在 **id 末段**里，无人读取。

修法（两处，各管一段）：
- `npc_life.place_label(area, detail, core, hits)` —— 真名优先 → 否则用**原作 id 末段**，
  再补一个**中文类型名**括注 ⇒ `家乡 · diner（餐厅）`。
- `main._activity_label()` —— 借 `_scene_place_label(sid, with_chapter=False)` 拿真名那一支，
  处理不了的部分交给 `place_label` 用 `core` 补。
- `_scene_place_label` 新增 `with_chapter=True` 形参：**默认路径逐字不变**（113j 的 30 条判据
  钉的就是带章括注的位置块）。活动候选**不带**章括注 —— 候选本来就被限定在同一章，
  四项各带一遍「（第一章 · 黑暗世界）」纯属噪音。

### 2.2 同一家医院的走廊/大厅/病房被当成三个"去处"

```
要去办点事，你们这儿真有的地方：家乡 · hospital hallway（医院）、
家乡 · hospital lobby（医院）、家乡 · hospital room2（医院）…
```

用户要的是「那要不去 XXX」**一个**建议，给他三间同院房间只会挑花眼。
⇒ `_activity_places` 加**去重键 `(区名, 中文类型名)`**，保留 sid 升序第一条。
去重后正是原作里家乡真有的三类：**医院 / 图书馆 / 学校**。

★ 去重**不许过度**：`我的城堡镇` 的餐馆 与 `我的城堡镇` 的咖啡店类型不同，两条都留
（`check113k` 的 D5 就是守这一侧）。

### 2.3 `hospital hallway` ⇒ "去医院走廊办事"

去重保留下来的细节词是 sid 升序第一条，于是取到 `hospital hallway`。
⇒ 新增 `trim_core_at_type()`：**截到类型词为止**。
- 类型词**之后**是同一栋楼里的房间（`lobby`/`hallway`/`upstairs`/`interior`/`overworld`）⇒ 截掉；
- 类型词**之前**是店名前半截（`icee pizza` 的 `icee`、`castle cafe` 的 `castle`、
  `fire restaurant` 的 `fire`）⇒ 必须留着，否则同城几家店糊成一个。

### 2.4 `Research Station（车站）` —— 翻译表越权

`station` 在 OneShot 的幽谷里是**研究站**，不是火车站。**猜错的翻译就是编造地名**，
比留英文更糟（模型自己看得懂 `Research Station`）。
⇒ `station` / `dock` **退出** `PLACE_GLOSS`。表格里只放**我确定**的翻译，宁缺毋滥。

### 2.5 `系统与演出 · shop（商店）` —— 把调试房当去处推荐

`ch5.system` 是三个**调试房**：`plat_lab`（平台测试）/ `rhythmgame_editor`（节奏游戏编辑器）/
`shop_ch5`。推荐它等于让 NPC 把人送进测试关。
⇒ 新增 `PLACE_SKIP_AREA_IDS`（按 **区 id** 判，不按区名 —— `系统与演出` 读起来像真地名，
按名字判会漏）。位置标签**照旧显示**：人在里面也得知道自己在哪。

### 2.6（顺带）`Citadel · c asgore kitchen` —— id 单字母残留

`c_`/`a_`/`f_`/`w_` 是 Outertale 把区名缩写进 id 的产物。
⇒ `strip_room_index` 丢掉**行首的单字母字母 token**（`House 1 - stew` 的 `1` 不在行首，不受影响）。

## §3 人味上的一处真错：`我不饿` 会触发推荐餐厅

用户说「我不饿」，旧逻辑命中 `饿` ⇒ 产块 ⇒ 模型很可能接「那要不去家乡那家餐厅？」
—— **用户刚说吃饱，桌宠还劝他吃饭**。这正是"不像人"的典型。

⇒ `detect_activity` 认**否定**：意图词前面 3 个字内有否定词（`不没别甭勿莫`）⇒ 该词不算。
两条硬约束都是踩出来的：
1. **只否被否的那一处，不整句丢弃** —— `我不累，出去逛逛` 里 `出去` 仍该命中 `play`。
2. **否定不跨句** —— 第一版没加断句符（`_NEG_BREAK`），`出去` 与 `不` 之间隔了个逗号仍被否，
   于是退回命中更靠后的 `逛`（kind 对了，**命中的词错了**）。
   `check113k B9` 因此断言的是 `('play', '出去')` 而**不是**只断言 kind ——
   只判 kind 这条 bug 会被漏掉。
3. 已知代价：`好不容易吃上了` 会被误否（`不` 在窗口内）。错的方向是**沉默**不是乱推荐，
   可以接受，写在注释里。

## §6 已知缺口（明确没做）

1. **否定只认近距窗口**：`我一点都不想吃` 能认（`不` 在窗口内），
   `你怎么还不去吃饭` 会当成 eat（`不` 隔得远）。语序/反问/条件句一概没做。
2. **一件衣服两个类型词**（`restaurant`+`cafe` 同房）时只括注第一个类型。
3. `ch1` 的 `rest`/`play` 永远是 0（原作事实）。若用户希望"累了"也能有个去处，
   需要一个**跨章/回桌面**的口径，本轮**故意不做**（跨作品推荐是硬错）。
4. `churchb` 这类 id 片段仍会出现在标签里（`第二圣域 · churchb library（图书馆）`）——
   它是原作房间名的一部分，没有可靠办法判"这是开发者的缩写"。
5. 还没做的：把"去哪儿"接到**实际移动**（`npc_roam` / `travel_to`）上。
   本轮只解决"知道哪儿能去、并说得出来"，**走过去**是另一层。
