## 1. 为什么必须重跑，而不是拿旧的 36 轮记录凑

`_evidence/raw30/` 里已有 **47 人 × 36 轮** 的记录，看上去"再补 12 轮"就够了。**不行**，两条硬理由：

| 维度 | 36 轮旧记录 | 今天的产品 |
|---|---|---|
| 剧本 | 第 4~6 轮是「今天过得怎么样？」「有什么喜欢做的事吗？」 | 偏好段 6 轮（`__PREF1__` + 4 条地方/氛围问法），**旧剧本里根本没有这一段** |
| system | `system_chars` 7.1k（ctx 12288） | 113i 本地化 + 113l AI_SELF 后 7.8k+（ctx 20480），且 `hy_*` 语言已改中文 |
| 关系卡/演化卡 | `system_for` 漏传（113b 修） | 已补 `relation` + `evolution` |

⇒ 36 轮记录是**旧口径**，混进新报告等于把两代数据搅在一起。一律重跑到 48 轮。

## 2. 开跑前体检：两个"疑似度量缺陷"**证死**（都不是 bug）

上一轮收尾时我登记了两处"训练完也读不出东西"的隐患，开跑前必须证死，否则白跑 18 小时。

### 2a. 「偏好 0 / 0 轮（0 人有可判素材）」

**复现**：`report30.py --turns 36` ⇒ 仍然 `0 / 0`；`--turns 48`（当时只有 asgore/susie 两人）⇒ `2 / 12 = 17%`。

**根因**（实测，不是猜）：36 轮记录的第 4~6 轮 slot 是旧问句，与 `train30.PREF_SLOTS` **零交集**：

```
berdly.jsonl    36 轮记录里 PREF 命中 = 0 / 6
   第 4~6 轮 slot: 今天过得怎么样？ / 有什么喜欢做的事吗？ / 说说你最近遇到的事吧。
hy_mooch.jsonl  36 轮记录里 PREF 命中 = 0 / 6
```

`metrics_of` 里 `pref_rel_n` 只数"落到 `PREF_SLOTS` 的轮次"，没有这种轮次 ⇒ 分母为 0。
**不是 `load_card` 拿不到人设** —— 顺带也证了：`roster 77/77`、`_persona_text` 为空 0 人、`pref_topics` 非空 **56/77**（`asgore ⇒ ['园艺']`、`berdly ⇒ ['电子游戏']`、`gerson ⇒ ['写作','双关语','可丽饼']`）。

### 2b. 「口癖 0 / 36 轮」

**普查**（37 个有登记 `voice_markers` 的角色）：

| 类别 | 人数 | 说明 |
|---|---|---|
| 命中 > 0 | **28** | 证明匹配器有牙：`lancer 36/36`、`mike 36/36`、`noelle 36/36`、`asgore 33/48` |
| 命中 = 0 | **9** | `hy_ace`／`hy_ed`／`hy_mooch`／`os_alula`／`os_calamus`／`os_george`／`os_maize`／`os_prophetbot`／`os_silver` |

9 人的登记项本身**不是口头禅**：`财务主管`、`救世主`、`真正的你`、`y'know`（要求英文而模型说中文）、`[……]`。
⇒ 这是**登记质量问题**，不是度量坏了。**本轮不动**（改动最小原则 + 它是参考指标不判红），记进待办。

### 2c. 顺带查出来的**反向**问题：登记项会让命中率虚高

145 条登记项里 **20 条**不可能当口头禅用（单字/纯标点/恒真泛词）。其中真正会把命中率**灌水**的是这 12 条：

| 角色 | 登记项 | 为什么是灌水 | 命中 |
|---|---|---|---|
| `hy_chujin_ketsukane` | `I` | 英文代词，任何英文句子都含 | 31/36 |
| `hy_guardener` | `_` `;` `>` | 终端控制字符残留（明显是原文本没洗干净） | 6/36 |
| `kris` | `想` | 中文里恒真 | 7/36 |
| `mike` / `noelle` | `……` | 标点，任何人说话都可能有 | 36/36 |
| `os_prototype` / `os_rowbot` / `os_silver` | `[……]` | 同上（方括号版） | 2 / 6 / 0 |
| `os_watcher` | `时候` | 常见名词，不是口头禅 | 12/36 |

（另 `呼`/`呃`/`嗯`/`啊`/`喂`/`哼`/`哦`/`羊` 这 8 条虽也是单字，但**确实是口癖**，不算灌水。）

⇒ 看报告 ③ 那列时要记住：`hy_chujin_ketsukane` 31/36、`mike` 36/36、`noelle` 36/36 这三个数**不可信**。
`voice_markers` 只存在于 `assets/npc/_training/cards/*.json`，**产品侧完全不读**，所以修它零风险；
但改在训练中途会让先跑完的角色留着旧登记项（记录里存的是跑那一刻的值），
⇒ **统一放到训练结束后一次性修**，而不是现在动。

### 成本天花板：`asgore` 87.6 分钟 / 48 轮

`asgore` 48 轮里 **48 轮全部** 撞 `ACTION_PAREN`，每轮重采样 2 次（共 3 次采样）⇒ 109.5 s/轮。
同类高危：`os_cedric`（36/36，75.7 s/轮）、`hy_martlet`（34/36，52.1）、`hy_dalv`（27/36，43.1）、`hy_bowll`（25/36，35.8）。

根因已在 `Parenthetical_TwoRulers_113e.md` §5 写明：**76 份人设文件全部含括号，共 1262 处**，模型在模仿人设的写法。
`SPEAK_RULES` 里已有「不要用括号描写动作」，但 113g 探针实测**往规则里加"描述那种行为长什么样"的括注，违规率从 1/10 涨到 10/10** —— 所以治本不是"加一句话"，需要单独做 A/B。
⇒ **本轮不治本**（重采样是设计行为、判据诚实），只记录代价。

## 4. 启动参数

```
python train30.py --turns 48 --sleep 5 --pause-every 10 --pause-sec 45
```

- `ctx = 20480`（不是 12288）：48 轮 + 关系/演化卡后最长 system 约 9300 token，卡 16384 边界会**静默从头部截断**。
- `PREDICT30 = 110`（产品侧 160 不动）。
- `MAX_RETRIES = 2`（与产品"判退必重采样"同口径）。
- 断点续跑：按 `turns_n == 48` 判重，每完成一人落一条 `raw30/<id>.jsonl`，中途死只损失当前一人。
- 看护：`thermal113.py --watch 30` 后台跑（内存 <250MB 停、吞吐跌破基线 55% 连续 3 次停）。
