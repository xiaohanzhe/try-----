## 2. 改了什么（产品）

### 2.1 `modules/npc_life.py`（1243 → **1378** 行）

新增（全部零依赖，只 import `re` / 标准库）：

| 名字 | 作用 |
|---|---|
| `has_cjk(text)` | 这段文本里有中日韩**文字**吗（★ 刻意不含标点，见 §3.1） |
| `speakable_en(text, proper=())` | id 末段 → 能说出口的英文地名：下划线转空格 · 楼层说人话 · 逐词 Title Case（虚词除外）· 人名 + 地点词 ⇒ 所有格 |
| `de_cjk_names(text, names_en)` | 地名里夹着的中文人名换英文（长名优先，避免留半截） |
| `label_key(text)` | 地名归一键（只留字母数字），判"两个标签是不是同一个地方" |
| `PLACE_CONTAINER_IDS = {'rooms'}` | **id 形态**的容器区（`ut.rooms.*` / `uty.rooms.*`） |
| `_ABBR_EN` / `_FLOOR_EN` / `_EN_MINOR` | 已知缩写（`tv`/`ut`/`uty`/`truelab`）· 楼层（`2f` ⇒ `Second Floor`）· 虚词（`of`/`the`/`in`…） |

改：

- `place_label()` 从"中文区名 + 英文 id + 中文括注"改成**全英文**；`detail` 只有在**不含中文**且**不是区名复读**时才用；中文类型名（`place_type_name`）退到**内部去重键**，不再进 prompt。
- `activity_hint()` 加 `cross=` 参数：混了别处候选就说「有的不在你这一带 —— 提的时候把"在哪儿"也说出来；还用你自己平常的说法，别照着念」；纯同章仍说「你们这儿真有的地方」。
- `strip_room_index()` 加"去行首纯数字"（`1 library` ⇒ `library`），房号/首字母两条原有规则不动。
- `ACTIVITY_SAY['play']` 从 `出去转转` 改成 `转一圈`（模板是「要去%s」，原先把"去"叠成"要去出去转转"）。

### 2.2 `src/main.py`（16797 → **16909** 行）

- `_activity_places(kind, chapter='')`：**跨区域**。扫全库、按 `(章, 区 id, 中文类型名)` 去重、返回前**同章优先**排序。
  - ★ 缓存只存**章无关**的那一份（`(kind,)` 键），同章优先在返回时再做 —— 否则第二个章会拿到第一个章的排序，且**不报错**。
- `_activity_label()`：区名取**区 id** 整形（`hometown` ⇒ `Hometown`），不取中文区名；容器区换成**作品缩写**（`ut.rooms.*` ⇒ `UT · Water Shop`）。
- 新增 `_place_proper()`（人名集合，从 `npc_registry.ids()` 现取）与 `_place_names_en()`（中文名 ⇒ 英文名，从 `name_cn`/`name`/id 末段取）。
- `_scene_place_label()` 剥"场景名自带区名前缀"改成**大小写不敏感**（英文名常是小写 id 配 Title Case 区名）。
- `_npc_life_blocks()` 活动段：算 `_cross`（前 4 条里有没有不在本章的）传给 `activity_hint`。

## 3. 抓到的八个真错误（都是人眼读出来的，判据当时是绿的）

按发现顺序，每条：症状 → 根因 → 修法。

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | `Rooms · Water Shop`（1251 间房全这样） | `ut.rooms.*` / `uty.rooms.*` 的 `rooms` 是我们的**房间容器**，不是地名；中文过滤（`全部房间`）管不到英文 id | `PLACE_CONTAINER_IDS` + 容器区改用**作品缩写** ⇒ `UT · Water Shop` / `UTY · Shop` |
| 2 | `要去出去转转` | `ACTIVITY_SAY['play'] = '出去转转'` 拼进「要去%s」 | 改 `转一圈` |
| 3 | `Garden · Way Home` 之外还有一条 `Garden`（丢了店名） | `name_raw` 为空 / 只存区名时 `core` 取到区名，剥前缀匹配不上 | `core` 为空或等于区名 ⇒ 用 **sid 末段**兜底 |
| 4 | 同上，修完 #3 仍只剩 `Garden` | `detail`（真名）**只是区名的复读**，被当"有细节" | `label_key(detail) == label_key(area)` ⇒ 视为无细节，退回 core |
| 5 | `Noelle's S House` | id 的 `noelle_s_house` 里 `_s_` 是**所有格分隔**，`_`→空格后 `s` 变独立词 | 单独词 `s` 并入前词：`words[-1] += "'s"` |
| 6 | `Noelle's's House` | 前词已按人名加过 `'s`，`s` 又加一次 | 前词已以 `'s` 结尾则跳过 |
| 7 | `Cyber Field · Cyber Field Arcade` | ① 剥区名前缀用 `startswith(area)`，英文大小写不一致；② core 来自 `room_word()`（**已把 `_` 转空格**），而 `area_id` 是下划线形态 ⇒ 两种写法都拼不上 | 大小写不敏感；区名前缀按 **`cyber_field` 与 `cyber field` 两种写法**各试一次 |
| 8 | `Steamworks Factory 01` / `Dunes 30 House 1` / `1 Library` / `Tv World` | `detail` 分支绕过 `strip_room_index`；行首纯数字没去；缩写被 Title Case 成 `Tv` | detail 也过 strip；加"去行首数字"；加 `_ABBR_EN`（`tv`⇒`TV`，`truelab`⇒`True Lab`） |

**★ #7 是"诊断输入造假"的教训**：我手工调 `_activity_label(sid, 'arcade', ['arcade'])` 时它是对的 —— 因为我把 `core` 写成 `arcade` 了；真调用里 `core` 是 `cyber field arcade`。**判据/诊断必须用真实输入**，否则测的是我自己想象的那条路径。

**★ #5/#6 是本项目"两处算同一件事"的又一次**：所有格由 `speakable_en` 和 id 分词**两处**决定，一边加一边不知道，就出了 `'s's`。

## 9. 续：出戏的元词汇（AI_SELF）—— 修的是**尺子**，不是台词

用户说「继续吧」之后做的是上一轮排的第一件事：给「自称 AI / 提示词」那一类写通用纠正句。
结论和计划相反：**尺子修准了，纠正句反而要撤掉**。原因在下面三层实测里。

### 9.1 起点：报告说 18 人，一手记录是 22 人

`report30.md` 的「待写纠正句名单」列了 18 人。我没有直接信它 —— 从
`_evidence/raw30/*.jsonl`（49 个文件、**1956 轮回复**）自己重扫了一遍，得到 **22 人**，
多出 `asgore` / `os_cedric` / `os_kelvin` / `os_prototype` 四个。

差在哪：md 是照「主码」截的，那 4 人是**次码**（同一条轮次里第二个违规），没进名单。

### 9.2 机制诊断：他们不是在"承认"，是在"回声"

- 22 条判红里，**21 条的命中词都是「提示词」**；
- 原句几乎全是**否认**：「我没有提示词」「我不知道啥是提示词」「我知道这只是个设定」；
- ⇒ 失败机制不是"自认是 AI"，而是**把提问里的词学了回来**（用户问什么词，就答什么词）。

这直接推翻了原计划：旧纠正句「你不承认自己是程序或 AI…」**答错了题** —— 他们本来就不承认。
而且**旧句自己就写着「程序」和「AI」**，注入 system 等于亲手把禁词教给模型。

> ★ 这里有一处**实测打脸**，值得单独记：我原以为"旧句含禁词 ⇒ `_AI_RE` 必然命中它"，
> 正控制当场证明**不命中** —— 正则要的是「我是程序」「我是 AI」，而旧句写的是
> 「自己**是**程序或 AI」，主语不是「我」。
> ⇒ 判据从"整句正则"改成**按词根逐个查**（`_BANNED_ROOTS` / `patch_is_clean()`），
> 并把这条结论本身也锁成判据（`check113l` B2）。

### 9.3 发现二：尺子本身太窄，漏了 3 倍

旧 `_AI_RE` 只认**句式**。换成一词一词地扫全库：

| 判据 | 结果 |
|---|---|
| 旧 `_AI_RE`（记录里的 `violations`） | **22 条 / 22 人** |
| 另有漏报（`AI` / `提示词` / `训练数据` / 语言模型…） | **48 条 / 25 人** |
| 换尺子后（现行 `_AI_RE`） | **75 条 / 34 人** |

漏报的典型形态：`不是AI哦`、`你觉得我真的像是个 AI 吗`、`我知道这只是个设定`、`只是个程序`。
它们不是「我是…」句式，所以一条都没判。**这不是角色变差了，是同一批数据换个尺子才看见。**

但「程序」**故意不禁** —— 这是看样本之后定的，不是拍脑袋：

- `hy_sousborg`：「Crack. Fry. Season. 是不变的**程序**」—— 厨房工序；
- `os_prophetbot`：「只要那是我的**程序**允许的」—— 它本来就是机器人，自称机器是人设内。

对这两个人判"自称 AI"，等于**要求角色违反自己的设定**（和 `_PERSONA_PAREN_EXEMPT` 同一个道理）。
所以 `程序 / 机器人` 只在「我是…」这种自指句式里算违规。

### 9.4 发现三：纠正句不但没用，还会**加重**

原计划给 22 人写一句通用纠正。写之前先做了 A/B——结果三轮都指向"更差"：

| 实验 | 设计 | 结果 |
|---|---|---|
| 顺序四臂 | A 空 / B 描述话题 / C 点名词表 / D 极简行为，各 9 样本 | 含禁词：**A 1 条、B 4、C 3、D 4** ⇒ 三个候选全比"不加"更差 |
| 反向交替对照 | A 与 D 各 12 样本；奇数块正序、偶数块**反序** | A 判红 2/12、含禁词 3/12；**D 判红 3/12、含禁词 8/12** |
| 判退重采样 | 不加纠正句，`MAX_RETRIES=2`，18 样本 | 首轮 **8 条** → 终轮 **3 条** |

（原始回复全文在 `_evidence/ab_aiself113l.json` / `ab_aiself113l_zigzag.json` / `ab_retry113l.json`。）

机制解释：**任何**纠正句都得提到那个话题（"你怎么被弄出来的""别把人那套词学回来"）。
7B 拿到这个提示之后，处理方式是把概念**说出来**，而不是绕开 —— 负向指令里出现过的词，出现率反而升高。

探针本身也踩了两次，都记下来：

1. **单轮空上下文不忠实**。真实失败发生在剧本第 32/33 轮，紧接在「你该不会是个 AI 吧？」之后；
   单独问一句时 A 臂测出 0/3 干净，会让人误以为"问题很小"。⇒ 必须把前一句当上下文喂进去。
2. **按臂连跑引入时间漂移**。本机是 CPU 推理（1~2 分钟/请求），为了用上前缀缓存只能按臂连跑
   ⇒ 越靠后的臂看起来越差，那可能只是机器越跑越热。⇒ 加了 `--zigzag`（奇数块正序、偶数块反序），
   每个臂都出现在前半和后半，线性漂移对两臂抵消。**没有这个对照，9.4 的结论就不成立。**

### 9.5 决策（写下来，防以后凭直觉改回去）

1. `PATCH_RULES` 里**不设** `AI_SELF` —— 写了、测了、撤掉。`build_patch` 对它不产出任何句子。
2. `_index.json` 的 22 条纠正句**全部撤销**；撤销后与 `HEAD` **零 diff**（往返自证通过才写盘）。
3. 剩下的唯一防线是**判退重采样**（产品 `train30.MAX_RETRIES=2` 同口径），实测 8 → 3。
4. 把这个决策**锁成判据**：`check113l` A 组 + 负控制。以后要加回来，必须拿出新的 A/B。

### 9.7 已知缺口（不当成绩报）

1. `我不像某些电子宠物那样只是个程序罢了` 仍判**干净** —— `程序` 故意不禁（见 9.3）。
   不为这一个样本继续加正则：那把判据拧到过窄，误报的代价比漏这一句大。
2. `我只是一个角色`（`kris` 实测出现）没判 —— `角色` 未入表。
3. **重采样后仍有残留**（3/18 ≈ 17%）：这三次是模型"稳定地"提到那个词，换种子也没绕开。
   要压到 0，只能靠生成后的硬替换，那会造出"罐头台词"，与"不许有可逐字搬走的固定例句"冲突。
4. 新口径会让 `train30` 的重采样变多 ⇒ 训练变慢。这是"宁可慢也别放过"的取舍。
