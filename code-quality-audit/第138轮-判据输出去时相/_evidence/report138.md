# 第138轮报告 · 判据的输出里不许含"时相量"

## §1 结论

| 项 | 结果 |
|---|---|
| 修的病 | **判据自己**：把行号 / 文件体积 / 字面量出现次数打进 extra ⇒ 判定没变也报 DIFF |
| 发作次数 | 第129/132/135 各 1 次，**第137轮一轮之内咬两次**，累计 **8 次** |

| 自纠 | **3 处**（§5） |
| 全量 G2 | 见 §7 |

原则一句话：**不改判定，只改 extra**。语义是处数/顺序/越阈值，就只回显处数/布尔/`n/m`。
判据的鉴别力一点没降（§6 的 E 段专门证明这件事）。

## §2 病是什么

`run_all.py` 的判据是"输出逐行比对"。于是：

```python
check(u'D2 也恰好 1 处', len(_pre_p) == 1, u'%r' % (_pre_p,))
#                                          ↑ 打印 [14806] —— 行号
```

我在 `chat_with_ai` 上方加 4 行注释 ⇒ `[14806]` → `[14810]` ⇒ **判据全绿、基线却 DIFF**。
然后我得人工确认"这不是行为变化"，再 `--update`。**每改一次注释，重复一次。**

累计账单：

| 轮 | 判据 | 变的是什么 |
|---|---|---|
| 129 | `D5` | `main=744500`（字节数） |
| 132 | `D3/D4` | `[(15130, [...])]` / `行号=[15130]` |
| 135 | `F1` / `G4` | `第 [12395] 行` / 常量全文 |
| 137 | `D1~D3` | `[14231]` / `chat [14226] vs [14231]` |
| 137（收口时又咬一次） | 同上 + `check134 B1c2` | 我再改文案 ⇒ 全变一遍 |

★ 这不是"判据写错了"，是**判据的判据**（基线比对）和**判据的措辞**（回显绝对量）打架。

## §4 元判据 `check138`：怎么防"下次又写回去"

### 4.1 只扫**进 SUITES** 的脚本

第一版扫了 `code-quality-audit/**/_tools/*.py` 全部 **964 个**文件，红了一片——
但命中的大半是 `recheck*.py`（一次性复检脚本，**打印行号是诊断需要**，不进 SUITES、
不产生基线 DIFF）。把它们一起判红，等于把"守基线"扩大成"守所有脚本"。

⇒ 从 `run_all.py` 的 `SUITES = [...]` 用 AST 解析出 `script=` 路径（**不 import**，它有主流程），
只扫这 **136** 个。

### 4.2 ★★★ 教训一：harness 签名不能猜

全仓实测：

```
check：desc, cond, detail / desc, cond, extra / name, ok, detail /
       cond, msg / tid, title, cond, detail / name, cond, star=False … 共 24 种
ok   ：cond, msg / name, cond, detail / cond, name, detail / m / msg … 共 16 种
```

第一版按"`ok` 的输出位是 `args[1]`"去取，于是 `check107 E8b` 被误判：

```python
ok(u'E8b …', _pm_init is not None and _pm_init.lineno != _rp_init.lineno,
   u'都在=%s 同一行=%s' % (bool(…), bool(… .lineno == … .lineno)))
#                          ↑ args[1] 是**条件**，我把条件位当成了输出位
```

⇒ 规则改成**位置**：输出位 = 第 3 个位置实参（下标 2）；4 参形态再取下标 3；
两参形态（`cond, msg`）取不到 ⇒ **登记为已知盲区**，不假装覆盖。

### 4.3 ★★★ 教训二：`.lineno` 参与算布尔 ≠ 印行号

`check107 E8b` 的 detail 里**确实有** `.lineno`，但它被 `bool(...)` 包着，
打印出来是 `True`/`False` —— **合规写法**。

⇒ `_prints_lineno()` 只认两种形状：

1. `.lineno` 直接当 `%` 的一个元素 —— `u'第 %s 行' % (n.lineno,)`
2. "取 `.lineno` 的列表推导"当元素 —— `u'%r' % ([n.lineno for n in x],)`

`bool(...)` / 比较 / 算术包一层就放行。

★ **盲区如实登记**（`C5` 判据钉住）：`u'%r' % (_same_if,)` 里那个变量装着
`(lineno, names)` 元组 —— 静态源码看不出有行号，本闸**抓不到**。
这一类只能靠 B 段逐个钉。**不假装闸门万能。**

### 5.3 又一次纯文本扫误伤（第 8 次）

`B3` 第一版：`u'原文出现 %d 次' not in _txt[u'check134']` ——
而我在同一处写的注释里就有「旧写法 `u'原文出现 %d 次' % _n_mut` …」⇒ 当场误伤。
⇒ 改 AST 查"输出位里还有没有引用 `_n_mut`"。

★ 这已经是第 8 次。规律很清楚：**只要判据的形态是"某串是否出现"，注释就能骗过它**。

### 7.1 ★★★ 验收实验：加一行注释，看还 DIFF 不 DIFF

这是本轮**唯一有说服力的验收**——"我改得对不对"不看判据，看**场景是否消失**。

**做法**：往 `main.py` 的 `chat_with_ai` 里插一行注释
（`# 第138轮 DIFF 实验（验完删除）…`），它会把后面所有行号 +1。

**改之前**：这一步必然产生 4~5 条 DIFF（`check132 D3/D4`、`check135 F1`、`check137 D1~D3`、
`check129 D5` 体积也会变）。

**改之后实测**：

```
cd code-quality-audit/regress && python run_all.py \
  --only check129 --only check131 --only check132 \
  --only check134 --only check135 --only check137
合计：PASS=177 FAIL=0  套件=6      ← 全部 IDENTICAL
```

**六条全部 `IDENTICAL`。** 然后把那行注释删掉，复跑：

```
check132 / check133 / check135 / check137 → 合计 PASS=118 FAIL=0，全 IDENTICAL
main.py 回到 17337 行、CRLF 17337 / 裸 LF 0（行尾没被编辑工具改坏）
```

⇒ 场景**真的消失了**，不是"我改了几个字面量"。

### 7.2 顺带清掉两处**描述里的**行号

`run_all.py` 的 `desc` 也是基线比对的一部分，里面同样有会漂的行号：

★ 这两处不只是行号问题：`check133` 那句里的**说法**（"一个字节都不变"）也已被第137轮改正，
描述跟正文对不上。⇒ 一起改，`--update check132 check133`（62/0）。

## §8 遗留

1. **仍有盲区**：`u'%r' % (变量,)` 里装着行号 —— 静态抓不到（`C5` 已登记）。
   要彻底解决得让 extra **只用结构化值**（如统一 `detail=` 关键字 + 格式约定），那是更大的重构。
2. 其它"时相量"类型还没纳入闸门：**字符串长度**、**帧率**、**耗时**（`run_all` 的归一化
   已处理日期/地址/耗时，但不含"长度"）。
3. 第137轮遗留：patch ① 与人设重复（去重要重跑训练卡，会冲 `voice_markers`）。
