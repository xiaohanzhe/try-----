## 2. ① 的完整推导（含两次被自己推翻的错误结论）

### 2.1 第一版探针：报 30px —— 作废

`probe163_feet.py` 的公式是

```
脚底 y = (BOTTOM − 容器高×scale) + bbox_bottom×scale
```

它假设**帧在窗口内左上对齐**。实际产品路径是：

- 窗口尺寸 = 容器（本动画最大帧）× scale
- `sprite_label` 是 **AlignCenter**（先按画布居中）
- 然后 `_compose_anchored_sprite` 再按锚点平移

⇒ 漏了居中项 `(容器 − 帧)/2` 与锚点项 `−off_y×s`。所以那 30px 里有一半是探针自己造的。

### 2.2 第二版：报 0.0px —— 恒真判据

改成走产品自己的 `_compose_anchored_sprite` 合成后再量，结果"34 个动画脚底全部 =
1000.0，跨度 **0.0px**"。这个数字太整齐，按纪律先查判据，于是写了
`probe163_bbox_selfcheck.py` 喂**已知答案的图**：

```
[FAIL] 全透明 10x10 → None                        got=(0, 0, 10, 10)
[FAIL] 20x20 只在 (8,3)-(12,7) 有不透明 → (8,3,12,7)  got=(0, 0, 20, 20)
[FAIL] 20x20 顶部 2 行不透明 → 底=2                  got=(0, 0, 20, 20)
[FAIL] 20x20 底部 2 行不透明 → 底=20                 got=(0, 0, 20, 20)
[FAIL] 20x20 左侧 1 列不透明 → (0,0,1,20)           got=(0, 0, 20, 20)
[FAIL] 下移 4px 底必须跟着变 4px                     got=(20, 20)
```

**6 项全红。** 根因是我图省事写了 `img.convertToFormat(4)`，而 PyQt5 里
**4 = `Format_RGB32`（无 alpha）**，转换后所有像素 alpha 变成 255 ⇒ 整张图都"全不透明"
⇒ 函数恒返回整张画布 ⇒ "脚底 = 画布底" 恒成立。

改成具名常量 `QImage.Format_ARGB32` 后 **6/6 PASS**。

> 教训：**禁魔法数字枚举**。一个 `4` 就造出了一条恒真判据，而且它报出的数字
> （0.0px，完美）比报错更危险。

### 2.3 第三版：真值 10px，且归因是解析式

修正后跨动画 **10.0px**、帧间最大 `act` **10.0px**。逐动画空隙表：

```
idle      容器高 47  空隙 [4.0,4.0,4.0,4.0,4.0]
sit_rest  容器高 44  空隙 [5.0]
act       容器高 40  空隙 [1.0,2.0,9.0,10.0,9.0]
run_up    容器高 35  空隙 [0.0,0.0,8.0,3.0,3.0]
land      容器高 41  空隙 [6.0,5.0,0.0]
spell     容器高 47  空隙 [1.0,6.0,6.0,3.0,3.0]
...（其余 20+ 个多为 0.0，即贴底）
```

根因是第 98 轮的垂直口径「本体**中心**对齐画布中心」：

```
本体下沿在画布内的位置 = ch/2 + 本体高×s/2
⇒ 距画布底的空隙     = (ch − 本体高×s)/2      ← 只取决于本体高
```

也就是说：**本体变矮多少，脚底就抬高它的一半**。代入 `act` 的空隙 `[1,2,9,10,9]`
反解出本体高 `38→37→25→24`，即"蹲下 14px、脚抬 10px"。

再叠第 162 轮的 `anchored_resize_xy`（垂直**保画布底边**）⇒ 保的是画布底，
而画布底 ≠ 本体脚底 ⇒ **"保底边"没能保住脚底**。

### 2.4 改法

`_compose_anchored_sprite` 的垂直落位从"本体中心对齐画布中心"改成
"**本体下沿对齐画布底沿**"，水平**仍保中心**（第 98 轮专治 `act` 爱心撑宽 20px 横跳的成果，不动）。

- 新增 `_anim_anchor_bottom()` + `_anim_bottom_cache`，与锚点表**同一次**
  `_alpha_row_bits` 循环算出，不重复扫像素
- 拿不到本体（空帧/纯透明）时退回旧中心口径，绝不跳到别处
- 不会裁头：本体下沿 ≤ 帧高 ≤ 容器高 ⇒ `dy = ch − 下沿×s ≥ 0`

改后逐动画复测：跨动画 **10.0 → 1.0px**、帧间 **10.0 → 1.0px**，`idle`/`neutral`/`sit_rest`
从悬空 4~5px 变成贴底（剩 1px 是 `int()` 取整）。

## 4. ② 静止时零动画（**待裁定，未动手**）

### 4.1 证据链

素材（`assets/animations.json`）：`idle` **5 帧** / `sit` **4 帧** / `sit_rest` **1 帧**。

`idle` 5 帧循环的激活条件是 `_idle_loop_active`：

```python
self._idle_loop_active = bool(
    self._lounge_since is not None                       # 窝着
    or self.idle_timer >= self.IDLE_LOOP_MIN_SECONDS)    # 静止满 600s
```

两条门限**都走不通**：

| 路径 | 为什么到不了 |
|---|---|
| 不窝着 | `update_movement` 空闲分支每次休息满 `max_idle_duration`（随机 **2~12s**）就调 `randomize_movement_pattern()` 并把 `idle_timer` **清零**。实测自然运行 20s：**峰值 1.47s**，离 600s 差 400 倍。 |
| 窝着 | `_lounge_since` 非空 ⇒ `_idle_loop_active` 为真，但 17395 行把 `new_animation` 改成 **`sit_rest`**（**只有 1 帧**）⇒ 仍然零动画。 |

### 4.2 运行时 A/B（`probe163_round2.py`，真事件循环采样）

```
[A] 自然静止（idle_timer 从 0 起）  → current_animation = ['idle','walk_right']，_idle_loop_active 0%
[B] 门限成立（idle_timer=700）      → current_animation = ['idle']，_idle_loop_active 96%，4.88 fps  ✅ 机制正常
[C] 窝着（_lounge_since 非空）      → current_animation = ['idle','sit_rest']，换帧 1 次，0.41 fps
[D] 自然运行 20s                    → idle_timer 峰值 1.47s，current_frame 覆盖 {0}
```

**B 组 4.88 fps** 证明"机制本身没问题"（设计值 6fps，离屏采样损耗后 4.88）；
**D 组 `current_frame` 恒为 0** 证明"真机永远走不到 B 组那个状态"。

> 这一条也是本轮修的一个夹具错误：上一支探针报"强制 `_idle_loop_active=True` 后仍 0.00 FPS"，
> 而 `_idle_loop_active` 在静止分支**每个 tick 都会被重算**，手动置的值下一个 tick 就被覆盖
> ⇒ 是探针假象，产品没问题。B 组改用"让门限条件本身成立"才测得到真值。

### 4.3 为什么不动手

用户第 51 轮口径是「待机动画要在原地不动**3 分钟以上**才会播放，而不是停止就播」（现为 600s），
第 54 轮又指定窝着时用 `sit_rest`。**这三条口径互相锁死**：随机漫游会打断"静止"，
唯一能连续静止的场景就是窝着，而窝着又指定了单帧。

三个可选方向（都要用户选，因为都会改变可见行为）：

| 方向 | 效果 | 代价 |
|---|---|---|
| A. 把门限计时从 `idle_timer` 换成"距上次**移动**" | 站着不动 600s 后开始 5 帧呼吸循环 | 有随机漫游时仍几乎到不了；等于没做 |
| B. 窝着时改用 `sit`（4 帧）循环 | 坐姿有动，最贴"像贴图"的抱怨 | `sit` 是**坐下过程**的 4 帧，循环播会"反复坐下" |
| C. 保留 `sit_rest` 静帧，另开"窝着时偶发小动作"（走现有 `play_animation_once` 通道，如 `look_up`/`happy`） | 不动现有口径，靠偶发动作破静 | 属于"其他功能"，不是纯动画修复 |

> ★ **2026-11-05 用户口径「咱该有的功能都有了，别加了」⇒ 三个方向一律不施工。**
> 本节只作证据存档：以后若用户明确抱怨"静止时太死板"，再从 A/B/C 里挑一个；
> **没有这句抱怨就不动**。原先这里写过"我判断 C 最稳"，已被该口径覆盖。

### 5.2 `SAOS-3624/dsh-see-now`（DeepSeek 视觉插件，JS/Node）

  桌宠没有这个需求。

从 39KB 写成 72KB」）的**同型漏项**——补了设备探测，漏了兜底目录。

补法：加 `_MSTORE.default_memory_dir = _sandbox_memdir`（指向 `%TEMP%\check162_work\init`）。
补后 `check162` 回到 **IDENTICAL 30/0**，且桌面文件 mtime 不再变化。

> 这是**修环境依赖**，不是改判据语义 —— 30 条判据条文一条没动。
