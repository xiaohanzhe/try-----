## §1 ★★★ 先纠正我上次的一个错误判断

上次（§174.7）写的结论是：

> 提权通道：结论：**本会话做不到，必须用户手动**。
> `admin=False`；安全策略拦截 `Start-Process -Verb RunAs` ⇒ 交付给用户的步骤：
> 管理员终端跑 `chkdsk E: /f`。

**这个结论是错的。** 错在把"需要管理员"当成了已知事实，**没实测**。

本轮实测：

```powershell
& chkdsk.exe E: /f /x          # 非管理员身份，直接跑
```

- 提权那条路确实被拦（`Start-Process ... -Verb RunAs` ⇒ *spawns a child process that bypasses validation*）；
- **但 `chkdsk /f` 本身在 exFAT 可移动卷上，普通用户权限就能跑完并修复** ——
  第一次就成功，耗时 7 分 27 秒，`rc=1`（发现错误并已修复）。

⇒ **教训：把"需要提权"当结论之前，先试一次不带提权的调用。**
   推断和实测之间差着一整个未验证的前提。

## §2 第二个错判：`fsutil dirty` 说"没有损坏"不等于没问题

```
fsutil dirty query E:   →   卷 - E: 没有损坏
Get-Volume E            →   HealthStatus = Healthy / OperationalStatus = OK
```

两条都"健康"，但只读 `chkdsk E:`（152 秒扫完 950 GB）报出：

```
Windows 在磁盘上发现错误，但是不会修复这些错误；因为不带 /F 参数运行了磁盘检查。
检查文件和目录时发现损坏。
检查卷位图时发现损坏。
坏扇区            0 KB
```

⇒ **dirty bit 没置位 ≠ 文件系统没坏。** exFAT 的卷位图（allocation bitmap）与目录项
损坏不会置 dirty bit，只有 chkdsk 自己扫得出来。

⇒ **"坏扇区 0 KB"** 也推翻了上次"散落坏点是介质读取超时"的猜测 ——
**物理介质是好的**，坏的是文件系统元数据。

| ① 只读 `chkdsk E:` | 152 s | 3 | 发现损坏（文件/目录 + 卷位图），不修 |

| ③ 只读复查 | 152 s | 3 | 还有损坏，**全部集中在 `\_tmp\`**（同一批目录项，反复报） |

## §5 剩下的死区：`E:\_tmp` 的目录表

| 事实 | 值 |
|---|---|
| 目录现状（改名后） | `E:\_tmp_BROKEN_20261109` |
| 单层列举 | **0 条**（0.01 s，读得动，就是空的） |
| chkdsk 认为里面有多少条 | **8,000+ 个损坏目录项**（索引跑到 8060） |
| 内容 | 读不出来，也列举不出 ⇒ 无可救的数据 |
| chkdsk 能不能修 | **不能**（三遍都报同一批，末尾 `未指定的错误(volume.c)`） |

**为什么没删**：删除是不可逆动作，而且是对一块"看起来空、但 chkdsk 说里面有 8000 条"
的区域。按你"只禁用、不直接删，这样有余地"的规矩，我先**改名隔离**（已完成）。

**要彻底清掉它，跑这一条**（普通权限即可，跑完盘就干净）：

```powershell
Remove-Item -LiteralPath 'E:\_tmp_BROKEN_20261109' -Recurse -Force
chkdsk E: /f /x
```

★ 判断依据：`E:\_tmp` 不是任何工具链的固定路径（我的临时区是 `D:\_tmp` 和
`E:\Download\_tmp`，都不是它），内容列举为 0 条 ⇒ 删除不会有可见数据损失。
★ 但"列举为 0"本身可能是坏目录表导致的假象 ⇒ 所以这一步留给你点头，我不代做。

## §6 以后的规矩（更新 §174.8）

1. 手机接电脑用 **MTP**，不要当 U 盘直插；拔之前「安全删除硬件」。（原规矩，不变）
2. **"需要提权"必须先试一次不提权** —— exFAT 可移动卷上 `chkdsk /f` 普通权限就能跑。
3. **`fsutil dirty` / `Get-Volume` 说健康不算数** —— exFAT 的位图与目录项损坏不置 dirty bit，
   只有 `chkdsk` 扫得出来。
4. **"坏扇区 0 KB" ⇒ 别往介质坏上想**，先按文件系统元数据坏处理（那种 `/f` 能修）。
5. `chkdsk /f` 经常**要两遍以上**才收敛；`rc=1` 是"修了"，`rc=3` 是"还有"，别混。
