## §2 为什么这条链值得看一眼（结构，不是猜测）

产品里"模型说出来的话"有两条互不相干的链路：

```
对话：send_message → chat_with_ai(lean=False)
      system = 人设 + 此刻 + 关系段 + 回忆 + 历史 …
      → _clean_ai_reply()  ← 第 0c 道：looks_like_meta_leak（第132轮装的）

事件：poke/pet/feed … → chat_with_ai(lean=True)
      system = **人设，一个字节都不变**（14171 行注释原话）
      → guard_reaction(first_sentence(reply, 24))  ← 只四道闸，没有元话语
```

两条链**用同一个人设**，而第132轮的取证已经定死：泄漏源就是人设「语气示范」第 136/147/148 行。
于是一条装有闸、另一条没装 —— 这道不对称本身就是漏洞。第128轮为"同一道额度只在一条链上生效"
栽过一次（自主开口/事件台词没走 `set_head_hesitation_allowance`，会顺手用上一条对话留下的值）。

**但这只是"结构上暴露"，不等于"实际上发生"。**所以本轮先采数据。

## §3 真机 42 条：干净，而且干净得能解释

条件：`ralsei:v4`、`temperature=0.85`、`num_ctx=8192`、system = 人设原文 4,493 字符、
user = 产品自己的 `build_prompt(kind)`（不手写）、14 个 `TIER_AI` 事件 × 3 采样，
先热身 1 条丢弃。全表在 `_tools/probe133_event_out.txt`，原始记录 `_evidence/event133.jsonl`。

| 观测位 | 命中 | 说明 |
|---|---|---|
| `meta_raw`（模型原样输出） | **0/42** | 连后段都没有 |
| `meta_first`（截到 24 字后） | **0/42** | |
| `meta_final`（过完 `guard_reaction`） | **0/42** | |
| `ooc_raw`（出戏） | 0/42 | ★ 0 命中**没有鉴别力**（131 轮的老教训：空集证明不了任何事） |
| `banned_raw`（客服腔） | 0/42 | 同上 |
| 空 first | 0/42 | 分母有效 |
| 首句平均字数 | **7.4 字** | 输出形如「谢谢你」「好痒」「嗯，晚安」 |

**为什么这么干净**：事件提示词尾部是硬形状约束 ——
「用一句话很短地回应（最多 24 个字），只输出这一句话本身。不要提问，不要解释，不要加任何标记或旁白。」
模型实际只吐 7 个字。**泄漏需要的是"谈论自己该怎么说话"，而这条链根本没给它这个话头**（事件都是触觉反应）。

## §4 否定结果：**照搬对话链的做法，救不了那 3 条**

把第131轮被判为泄漏的 3 条原文，按产品口径 `first_sentence(reply, 24)` 截断后再喂给闸：

| 样本 | 截断结果 | 还命中吗 |
|---|---|---|
| `before/Q3 #3` | 「那听起来挺辛苦的。」 | 否 |
| `before/Q7 #2` | 「你说的是坏消息吗？\n\n你说的是坏消息的时候我不该」 | 否（`我不该` 后面被截断，没有"开头/语气/问一句/留个"） |
| `before/Q7 #3` | 「你说的是坏消息吗？\n\n先就着你说的那件事问一句」 | 否（`问一句` 后面没有冒号） |

⇒ 两条结论一起登记：

1. **24 字上限本身就压掉了**这次观测到的泄漏形态。—— 这是事实，不是我们的功劳。
2. **"把闸接进 `guard_reaction`、对截断后的文本判"抓不到那 3 条。** 谁要拿这 3 条当"闸已生效"的证据，
   谁就是在用**取证链之外的样本**冒充效果。

顺带暴露一个**本轮不改**的真问题：那两条截断结果本身就是坏台词 ——
一句问句重复两遍、尾巴吊在「我不该」/「先就着」。四道闸一条都不拦，会原样显示在气泡上。
（→ §7 遗留 1）

C4 就是典型 —— 我守的不是"别漏判"，而是"我以为 strip 会删它"。

## §6 那为什么还是装了

三条理由，按强度排序：

1. **显示窗口容得下**。24 字里放得下「我不该用亮起来的开头」（10 字）这种整句自述 ——
   也就是说"截断会压掉泄漏"只在**这一次观测到的样本形状**上成立，不是普遍保证。
2. **不对称会咬人**。同一份人设、同一个模型、两条链只一条有闸。真要出一次，用户看到的是
   气泡里一句"我不该…"，而不是日志里的一行。
3. **成本实测为零**。42 条真机输出逐字不变、12 条构造负样本全放行、342 条历史池（第132轮）
   0 命中 —— 累计 **396 条真实语料 0 误伤**。

代价也写清楚：一旦命中就**整句作废**（事件没给 `pool` 时等于这次不说话）。
这是与另外两道闸一致的取舍 —— 宁可安静，不甩一句念规则的话。

## §7 遗留（都不阻塞，按优先级）

1. **截断会造出"吊尾巴"的坏台词**（§4 那两条）。现在四道闸都不管，会原样显示。
   要么加一道"结尾悬空"的判据，要么把 `first_sentence` 的切分改成"整句不完整就不取"。
   —— 动它会碰 `s7_event_speech` 与第128轮的结巴截断，需要单独一轮。
2. **括号外的第三人称旁白**没人管。真机 `#05` 输出「嗯 (~(￢_¬)~) 好奇他怎么了」——
   `好奇他怎么了` 是**描述自己**，既不是括号、也不在 OOC/BANNED 表里，四道闸全放行。
3. `energy_low` 的旁白是"你开始有些精力不足"，模型 3/3 答成「听起来好辛苦哦」
   —— 把它当成"用户在抱怨"。这是**旁白措辞**问题（第 98 轮那批同型），值得单独看。
4. 本轮 n=3/事件，只够说"没观测到"，不够说"不会发生"。真要定论需 n≥10（CPU 约 20 分钟）。
