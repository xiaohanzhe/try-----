## 3. 两条硬发现（决定了方案长什么样）

### 3.1 不能"直接把 NPC 的内在活动写进现有记忆库"——会串味

`memory_system.MemorySystem` 是**单主体**的：`self.keys` / `self.fragments` 都没有 owner 维度，
而 `recall()` 的 keys 匹配面是 `text + ' ' + meta.where`，**不含 `who`**。

⇒ 如果 Lancer 在教室盘算过一次，写进同一个库，那么问"教室"时 **Ralsei 也会想起来**。

这正是当初 `MiniMemory` 被设计成"一人一文件"要躲的问题（它的注释里写着：
「不是"一个大文件按 id 分桶"：分桶写法只要有一处忘了带过滤就会串」）。

⇒ **必须先给每个 NPC 一个独立记忆库**，再谈接线。

### 3.2 表情动画对 NPC 是"有意关掉"的，不是漏做

`main.play_expression_anim` 第一行就是 `if char_id: return False`。
理由是对的：Ralsei 只有一个身体，让他的身体替 Lancer 做动作会出戏。

⇒ 要让 NPC 也有动作，需要的**不是接线，是每个 NPC 自己的动画素材**（目前 18 人有立绘，
其中多少有帧动画未盘）。这条属于"要看素材才谈得上"的一类，建议**单独立项**，不混在这一轮。

## 4. 分批计划（按依赖顺序，不是按重要性）

| 批 | 内容 | 为什么在这个位置 | 规模 |
|---|---|---|---|
| **1** | **给每个 NPC 一个独立记忆库**（懒加载，一人一目录） | 是一切"内在同级"的地基；不做这步，后面全都会串味 | 中 |
| **2** | NPC 内在活动 + 台词 + 关键记忆 全部接到第 1 批的库上 | 这一步做完，NPC 才真的"记得住" | 小 |
| **3** | **记错机制（B）**：地点/时间可偏，**人物不许错**，关键记忆不参与 | 依赖第 1/2 批（有记忆才谈得上记错） | 小 |
| **4** | 口癖补齐（70 份人设） | 独立、纯文本、可批量 | 中 |
| **5** | NPC 情绪 / 关系 | 要先定"对谁"（对玩家？对彼此？）需设计 | 大 |
| 单列 | NPC 表情动画 | 缺素材，先盘清 18 人有没有帧动画 | 待议 |
| 单列 | 62 个外来角色的立绘 | 纯素材活，与代码无关 | 待议 |

## 5. 需要用户点头的三个决策

1. **记忆库放哪**：与 Ralsei 同级放 `D:\RalseiMemory\npc_mem\<id>\`，
   还是另起一个根（`D:\RalseiMemory\people\<id>\`）？我倾向前者，因为已经在 D 盘、迁移路径一致。
2. **"记错"错到什么程度**：地点和时间可以偏、**人物不许错**（我的建议）。
   另外要确认：错得**每次都一样**（同一条记忆永远错成同一个地点，像真的记岔了），
   还是每次回忆都可能不一样？我倾向"每次都一样"，因为那更像人，也让回归可测。
3. **哪些能力对某些人不适用**：比如 `not_a_person` 那 8 个（招牌/垃圾桶）不需要情绪和关系；
   `foreign` 里没立绘的 62 人，记忆/情绪照做，但视觉层只能等素材。
