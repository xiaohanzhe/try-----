## 5. 用户 3 条真机观察的查证结论

### ① 坠落触发逻辑 · ②「没有窗口也判移动了窗口然后摔倒」

**代码事实**（`main.py`）：
- `start_fall(reason=...)` 的**唯一调用点**是 `_follow_floor_move()`（`8462` / `8474`）
- 该函数的前置条件是 **`old_floor.get('type') == 'window'`**（`8632-8635`）
  ⇒ 宠物站在**桌面**（`desktop_floor` 的 `type == 'desktop'`，`floor_manager.py:158`）时
  **不会**走这条路
- `desktop_floor['type'] = 'desktop'`（`floor_manager.py:158-163`）✅
- `get_all_visible_windows()` 用 `system_classes` 过滤
  `WorkerW / Progman / Program Manager / Shell_TrayWnd / TrayNotifyWnd / ClockWClass`
  （`desktop_interaction.py:1225-1229`）⇒ 桌面/任务栏**不会**被当成楼板

**真机实测**：run1（600s，**沙箱桌面恰好没有窗口**）⇒ **坠落 0 帧、无任何无端摔倒**
（B1b 零位移 1.1%、E1 无并存）

⇒ **在"完全没有窗口"的环境里复现不出来**。需要用户补充：当时屏幕上到底有没有窗口、
是不是拖动过它、以及"摔倒"是**生气动画**（`fall_mad`）还是**普通坠落**。

### ③「他站起来不需要揉眼睛」

**代码事实**：
- 起床路径 `wake_up()`（`main.py:9211-9228`）用的是 **`pose`** 动画 —— **没有"揉"**
- `fall_back_rub`（"揉"）全项目**只有 2 个使用点**：
  - ✅ `main.py:9109` —— `handle_fall` 的 **`dazed` 阶段**：
    摔倒流程 `splat（摔扁）→ dazed（fall_back_rub + 「呜...头好晕...」）→ recovering（land 爬起）`
  - ❌ `emotion_system.py:910` —— `'disappointed'` 情绪 `'high'` 强度。
    但 `get_animation_for_emotion()` **全项目零调用**（`main.py:10059` 的注释
    明确记载这条非 AI 入口**已被移除**）⇒ **死代码，不会播放**

⇒ 用户看到的"揉"**最可能**是**摔倒链路**里的 `dazed` 阶段。
需要用户确认：是"**摔倒后爬起来**"时看到的，还是"**睡醒起床**"时看到的。
