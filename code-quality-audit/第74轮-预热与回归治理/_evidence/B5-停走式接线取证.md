### ★ 两个关键实现点（都配了判据）

1. **浮动偏移保护**（`_follow_to` 的核心）
   `y` 上挂着 ±2 三角波（`step_levitate`）。若每帧 `self.y = 目标 y` 再走浮动，累加器被**每帧清零** ⇒ 僵在 `目标 + 0.1`。
   修法：先量 `off = self.y - self.starty`，把 `starty` 搬到新位置，再把 `off` 还回去。
   判据 **C46**（130 帧实测偏移区间不为单点）+ **C47 负控制**（坏写法必须被抓）。
   ⚠️ C46 曾**判据侧失手**：只跑 40 帧，实测 `[-2.0, +0.2]` 却按 `[-2.0, +1.9]` 比（三角波一个来回要 ≥130 帧）⇒ 改跑 130 帧。

2. **`is_moving` 不在 `__init__` 预声明** ⇒ `_ghost_moving_now()` 必须 `getattr(self, 'is_moving', False)`。
   判据 **E38** 同时扫 `Attribute` / `Name` / **`ast.Constant`** —— 因为它在源码里是**字符串字面量**。
   ⚠️ 首版只扫前两者 ⇒ **漏掉**、报假红（判据侧问题，不是功能问题）。

### ★★ 本轮暴露并修掉的三个**判据侧**问题（"判据本身也是被测物"）

1. **live67 采样靠固定 22s 窗口碰运气** —— Qt 顶层窗是**第一次 `show()` 才创建原生句柄**的；幽灵在"走动"档下 alpha 恒 0 ⇒ 从不 `show()` ⇒ `EnumWindows` 一条都枚举不到。于是"宠物恰好一直在走"的那次跑，A2/A3/A7 会全红，**而功能完全正常**。
   ⇒ 改成**等待式**：先等幽灵窗首次可见（≤75s），等到再采 14s。

2. **A7 拿"跑动帧"算距离** —— 跑动时窗口被 `hide_ghost()` 收掉、且位置还会受**虚拟屏边界钳制**，量到的是"钳制差"不是"跟飘偏移"。
   ⇒ 只在 `ghvis=True`（站住显形、未被钳）的采样点上取中位。

3. **`pet` 只按标题筛会混进同进程别的浮层**（气泡 / 场景画布 138×94、620×236）。
   ⇒ 在标题命中的里面挑**最贴近桌宠尺寸 (42,82)** 的那个。

4. **结论行写死 "A1~A6 全绿"**，加了 A7 之后成了假陈述 ⇒ 改成把登记过的编号逐个列出。

> 另外确认：`alpha` 的**跟飘偏移量**是 `GHOST_FOLLOW_OFFSET_X = -46.0`（我自己定的，让幽灵贴在宠物**左边**），

## 6. ⚠️ 本轮的一次**操作失误**（如实登记）

诊断"幽灵帧为什么打不出来"时，我用 `git checkout -- ralsei_pet/src/main.py` 还原一行临时改动，
**把 B5 在该文件上的全部未提交改动一起还原掉了**（`GHOST_MODE` / `_ghost_moving_now` / 显式传 `mode=` / `moving` 透传 / 诊断字段）。

- **发现方式**：重建临时改动时 `assert s.count(old)==1` 失败，追查发现 `old` 串里的 `模式=%s` 已不存在。
- **处置**：按上下文记录**逐处重建**，随后 `check67` **152 PASS / `IDENTICAL`**、`tamper67` 10 条全 OK
  ⇒ 重建版与丢失版**行为等价**（`main` 的 sha256 由 `2849d84a…` 变为 `cd3bb6ab…`，差异仅在注释文案更完整）。
- **教训**：局部还原**绝不**用 `git checkout <file>`（那是整文件回滚）。本项目已有"临时改动落 E 盘、用后即删"的纪律，
  但**未提交的正式改动**在编辑期同样脆弱 ⇒ 编辑期的临时探针应走**独立包装脚本**（如 `probe_ghost75d.py`
  用 `logger_utils.set_level` + `runpy`），而**不是**去改产品文件。
