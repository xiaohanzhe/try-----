## 二、四门实测（真机，画布 2560×1528）

```
门A  rect=(1183,    0, 194, 129)  alpha=1.0000 恒定（不参与渐显）
门B  rect=(1183, 1399, 194, 129)  alpha=1.0000 恒定
门C  rect=(   0,  714,  45, 100)  alpha=0.1400 恒定（渐显下限）
门D  rect=(2378,  685, 182, 157)  alpha=0.2906~0.2959（随桌宠距离微动，最大跳变 0.0035）
```

统一倍率 **k = 1.011613**（`fit_doors_uniform_scale`，`DOOR_FIT_CAP=1.6`）：
四门尺寸 = `round(原尺寸 × k)` 逐门精确成立 ⇒ 仍是「按原作等比放大」，没有逐门调。

## 三、两个"取证不保真"的坑（都在我自己的脚本里，已修）

### 3.1 画布尺寸传错 ⇒ 门 B/C/D 整体偏 72 px
第一版用 `primaryScreen().geometry()` = 整屏 **2560×1600**；
产品真实画布是 `window._desktop_layer_size()` = 工作区 **2560×1528**（扣任务栏）。
⇒ 门 B 的 y 从 1399 变成 1471，**72 px 落进任务栏**，看起来像"门跑到任务栏里了"。
**这是夹具的错，不是产品的错。** 改后 rect 与静态抓图（`shot117_doorform`）逐门一致。

### 3.2 两个"口径"混用 ⇒ 假红 17 分
- 门 A 的 `mean_lum` 第一版是**整矩形平均**（含壁纸）⇒ 19.8 被量成 **65.1**。
  必须**只在贴图不透明区**取（alpha≥250 + 腐蚀 1 px）。
- 录像帧是 mp4（有损）⇒ 逐像素比对会虚高：门 B 逐像素 **17.08** 但分块 8×8 只有 **5.14**。
  真因是细网格品红线被 4:2:0 + 量化压糊。**换图会差 30+**（门 D 硬比 34 就是证据，它 alpha=0.29）。
  ⇒ 录像帧用**分块均值**当主判据，逐像素只作 INFO。**这是换口径，不是放宽。**

## 四、采样率与它的边界（不夸口）

| 通道 | 实测 | 能判什么 |
|---|---|---|
| `rec117.avi`（全屏 + mp4 编码） | **3.26 Hz**（grab 78 ms / encode 19 ms） | 逐帧画面、几何、颜色、遮挡 |
| `fast117`（单次全屏抓取 + 裁剪） | **5.8 Hz**（grab 76 ms） | 像素时序 |
| `fast117` 的**写入路径插桩** | **51 次调用 / 8 s**（中位间隔 104 ms） | **精确序列、零混叠** ⇒ 判"闪不闪"的最硬一条 |

★ 为什么不再追高帧率：6.9 Hz 采样对 5~7 Hz 闪烁会混叠。**但写入路径插桩绕过了这个问题** ——
闪烁必然表现为 alpha 向量反复变化，51 次调用**一次都没变**，比任何像素采样都硬。
（曾试 GDI `BitBlt` 提速，探针在 `Qt`/`GDI` 双通道对账阶段挂住 ⇒ 已弃用，不在产线留半成品。）
