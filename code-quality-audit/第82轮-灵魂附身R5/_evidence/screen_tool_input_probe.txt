三、pcm_h5_msg ×2 关闭失败（三层原因，逐条实证）

  [1] WM_CLOSE 被拒
      PostMessage(WM_CLOSE) 报成功，但窗口仍在（推广层不接受标准关闭）。

  [2] 不能杀进程（会连带关掉用户的主界面）
      PID 42872 同进程另有 hwnd=13833654 LENOVOPCMANAGER「联想应用商店」
      PID 52068 同进程另有 hwnd=1577722  LENOVOPCMANAGER「联想应用商店-不常用」
      ⇒ LenovoAppStore.exe 共 15 个实例，还挂着用户正在用的搜狗输入法窗口。

  [3] ★★★ 屏幕工具的鼠标输入在本会话完全无效（决定性证据）
      实验 A：task click --point 900,900   → ok:true
              随后 mouse position      → (2258, 1437)   ★ 光标纹丝不动
      实验 B：mouse move --point 1200,800  → ok:true
              随后 mouse position      → (2258, 1437)   ★ 光标纹丝不动
      ⇒ **CLI 报 ok:true，但屏幕上没有发生任何输入**。
      ⇒ 点击 (2450,994) 与 (1633,663) 两次均无效（不是 DPI 问题）。

    截图 2560x1600 = **物理像素**；坐标读数是 **物理像素**。

五、★ 另一条独立结论：list-visible 不是完整列表
    同一时刻三种口径的可见顶层窗口数：
      cli window list-visible   → 3   （仅 pcm×2 + Progman）
      EnumWindows+IsWindowVisible → 22  （含 WPS/WorkBuddy/资源管理器等）
      （更早一次 list-visible 报 7）
    ⇒ **既漏报（桌宠透明窗口）又漏报（大量已存在窗口）**，
      不能拿它当「要关哪些窗口」的依据。
      正确做法 = 独立 EnumWindows 枚举 + IsWindowVisible 判可见。

六、结论
    · 本会话内，小助手的**只读能力（截图/OCR/窗口枚举/几何）可用**；
    · 小助手的**输入能力（mouse move/click、推而广之 keyboard）在本会话无效**，
      表现为 CLI 报 ok:true 但屏幕零反应；
    · 疑似原因：小助手进程完整性级别 / UIPI 拦截 SendInput（未进一步验证）。
    · ⇒ 需要真实鼠标键盘的任务，本会话**只能请用户手动操作**。
