## 2. 结论先行

1. **三条规则全部落码并实测**：Ralsei 无球进光世界被拒（`light_needs_bubble`）、装进球里放行；
   其他角色进光世界不需要球；Ralsei 可跨暗世界，他人异章被拒（`foreign_dark_world`）。
2. **球真的被画出来了（接线闭环）**：`scene_render` 出四层指令 → 后层进 `scene_canvas`（角色之下）、
   前层进新控件 `BubbleOverlay`（`raise_()` 到角色之上）⇒ 等价原作 `frame2 → 角色 → frame3 → frame1`。
3. **塑料滤镜零副作用**：不给 `sprite_label` 换 pixmap，只在角色之上叠一层冷色
   （`cover = 1 - alpha = 0.12`），可逆、不污染 sprite 缓存。
4. **新增回归锁 `bubble_round50`：76 判据全绿**；第49轮套件按新口径修订后 **82/82 全绿**。
5. **鉴别力体检 12/12 精确报红**（逐条真改盘上文件 → 命中期望 id → 还原后 hash 一致、全量复绿）。

## 4. 关键取证（本轮踩到的真实事实）

### 4.1 球素材**每帧尺寸不同**（不是猜测，实测）

`assets/bubble/spr_dw_tv_gachaball_transparent_*.png`：

| 帧 | 角色 | 尺寸 |
|---|---|---|
| 0 | 整球 | **62×62** |
| 1 | 上罩 `top` | **60×48** |
| 2 | 下半后层 `back` | **60×51** |
| 3 | 下半前层 `front` | **60×47** |

⇒ **每层必须取自己的素材尺寸**（拿一个尺寸套三层会把球壳拉变形）。

### 4.2 UTMT 导出的 PNG **没带每帧 offset**

原 sprite 的 origin 是 (31,31)，但逐帧尺寸不同 ⇒ 按 origin 硬对齐会让三层整体偏下。
**改为按「球心」居中**（三层同心，实测 `centers_y = [240.0, 239.5, 240.5]`，偏差 ≤ 1px）。
`BUBBLE_ORIGIN = 31` 仅**归档**、不参与对齐（注释已写明）。
★ 要**精确**复刻分层需导出每帧 offset —— **登记为缺口**（见 §7）。

### 4.3 球的缩放由角色显示像素反推

`scene_render.fit_scale(char_w, char_h)` = `max(cw/62, ch/62) × 1.25`。
不硬用原作 `SCALE_DEFAULT = 1.55` —— 小角色会顶出球外（穿模）。

### 4.4 分层为什么必须用两个控件

角色是 `sprite_label`（Qt 控件）画的，场景是 `scene_canvas` 画的，两者是**同级兄弟**。
若把 `front/top` 也画进 `scene_canvas`，球壳会被角色盖住（看着像"角色站在球前面"，与用户要的相反）。
⇒ 前层必须有**自己的控件**并 `raise_()` 到角色之上；两个控件靠**绘制序物理遮挡**，不需要任何 mask。

## 6. 教训（可复用）

1. **判据"看起来在守"和"真的在守"是两回事**（本轮又抓 4 次）：
   - `C3` 首版断 `behind + front == plan` 全局序 —— **错**。分流是"稳定分桶"，
     边框在球之后却属 `behind` ⇒ 正确不变量是「**无丢失/无重复 + 各自保相对序**」。
   - `G11` 首版断 `toggle_bubble` 缺省值 `== 'ralsei'` —— **过窄判据**。
     源码是 `char_id=None` 哨兵 + 体内兜底 ⇒ 正确判据 = 缺省为 `None` **且**体内出现 `'ralsei'`。
   - `B9/B10` 首版夹具用了 **plain dict** 当场景 —— `getattr(dict, 'objects')` 恒取不到
     ⇒ `objects` 与 `room_border` 永不产出 ⇒ 两条判据退化为恒真/恒假。
     ★ **夹具要保真**：用 `SimpleNamespace`（与冒烟探针同）。
   - `F4` **弱判据**（鉴别力体检专抓）：首版用 `ch5` 测"Ralsei 跨暗世界" —— 但
     **Ralsei 登记的章节本来就是全五章** ⇒ 走的是"本属章"分支，`free_dark_roam`
     是否生效**测不出来**。改用未登记章节 `ch9` + 与 Toriel 成对（同输入、只因身份结果相反）。
     ⇒ **"能过"不等于"测到了"**：判据必须能区分"这条代码有没有生效"。
2. **负控制必须真落进被测分支**（鉴别力体检两处踩坑）：
   - 首版用"把 `setAttribute(..., True)` 改成 `False`"测 `G16` —— 判据只看**标识符是否出现**，
     改值摘不掉标识符 ⇒ 假阴性体检。正确做法 = 整行换成 `pass`。
   - 首版把 `lancer` 加进 `ALWAYS_EJECTABLE` 测 `E2` —— `ejectable()` 先判 `NEVER_EJECTABLE`
     （优先级更高）⇒ 结果不变 ⇒ 体检**测不动**。正确单变量 = 让 `NEVER` 分支返回 `True`。
   - ★ 体检工具自己也要"能被证伪"：**若某例改完判据仍全绿，先怀疑用例没落进分支**。
3. **报红先怀疑判据**：本轮共 7 次报红（含 G2），**2 次是产品口径变更（有意）**、
   **5 次是判据/夹具问题**（3 判据写错 + 2 夹具不保真），**0 次是产品 bug**。
4. **判据里不许写"行号"这类漂移量**：`pathfind_round45` 的 `E6` 把 `main.py` 行号打进消息，
   本轮给 `main.py` 加球容器接线（+5 行）⇒ 行号位移 ⇒ 基线假报警。
   ⇒ 行号不是稳定可观测，**消息里只留计数**（计数才是判据本体）。
5. **裸子串扫描 = 过宽判据**：`canvas_round44` 的 `A3` 用 `'scene_canvas' not in 源码` 判"单向依赖"，
   我给 `scene_render` 的文档字符串写了指向消费方的注释就撞上了。
   ⇒ 真正的风险是 **import 反向依赖**，改用 AST 看 import（口径不变、鉴别力不减）。
6. **常量刻意写两份 + 靠回归锁抓漏改**：`scene_render`（渲染层）与 `bubble_system`（规则层）
   各自持有球名/帧号/前缀。这不是冗余 —— 改了一边忘另一边，`bubble_round50` 的 A3~A5 立刻报红。
7. **口径变更要连带更新既有锁的描述**：`SCENE_LAYER_ENABLED` 由 `False` 改 `True`（第18项），
   `canvas_round44` 的 `E4a` 与 `run_all.py` 的描述文案都同步改了，避免"锁说的和产品做的不一致"。
