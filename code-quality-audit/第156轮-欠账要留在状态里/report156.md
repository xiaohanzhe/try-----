# 第156轮 · 欠账要留在状态里

> 落点：`report155.md §9` 第 1 条遗留 —— **连续改派没有"最早那件"的追溯聚合**。
> 用户口径仍是那一句：「**按照人类的逻辑来就好**」。
> 分支：`local-156`。改动面：`main.py` +136/−6（18690 行，全 CRLF）。

## 1. 结论

连着被改派三次的人，会说"我本来要擦柜台、收杯子，都没办完，又被叫去扫地"。
第155轮之后的行为是：**每条痕迹只提"上一件"**（A→B 说 A，B→C 说 B），最早那件只在
**更早那条**痕迹里 —— 而痕迹本身会被记忆窗口裁掉。本轮把它拆成两件事：

| | 改前 | 改后 |
|---|---|---|
| 最后一条痕迹带几件欠账 | 1 件（要答"最早那件"得往回翻） | **2 件（全量）** |
| 欠账会随记忆出窗吗 | 会（2 条痕迹 + 12 句闲聊 ⇒ 整段没了） | **不会（挂在 prompt 尾部，与窗口无关）** |
| 没被派过差事的人 | — | prompt **逐字不变**（空账返回 `''`） |

一句话：**欠账是"当前状态"，不是"历史事件"** —— 历史会被窗口裁掉，状态不会。

## 2. 改前实测（`probe156.py`，不靠读代码推断）

三种派活（擦柜台 → 收杯子 → 打扫前院）之后，产品实际写下的两条痕迹：

```
[1] （我本来要去 oneshot.barrens.Blue 办「擦柜台」，还没办完，又被派去 ut.rooms.room_area1 办「收杯子」了）
[2] （我本来要去 oneshot.barrens.Blue 办「擦柜台」、去 ut.rooms.room_area1 办「收杯子」，
     还没办完，又被派去 ch1.hometown.town_mid 办「打扫前院」了）      ← 本轮之后
```

- **改前（模型复算，对应 `mutate156 M12`）**：第 2 条只写"办「收杯子」"⇒ 手里 2 件欠账，
  **最后一条只答得上 1 件**；
- **改后（真跑）**：最后一条自己就把两件都写全了。

更要命的是第二刀（`P2`，对**真实产品**观测）：把这两条痕迹后面跟 12 句闲聊喂给
`npc_persona.history_block(entries, max_lines=12)` —— 它只取**最后 12 条** ⇒ 段落只剩
139 字闲聊，**命中的欠账件数 = 0**。所以"把话写全"只是第一层，**必须另有一条不随窗口
移动的通道**，否则问起时他仍然答不上。

## 3. 五处补

### 3.1 `assign_errand`：痕迹写**全量**

改派时先把旧那件记进 `self._errand_given_up`，再用**整张表**拼这句话：

```python
_errand_given_up_add(self, npc_id, _p_dest, _p_what, now=now)
_items = _errand_given_up_of(self, npc_id, now=now)
_all_txt = u'、'.join(_errand_item_txt(d, w) for d, w in _items)
self._npc_errand_note(npc_id, u'我本来要%s，还没办完，又被派去 %s %s了' % (_all_txt, ...))
```

**一条痕迹带三件 > 三条各带一件**（出窗概率小 3 倍）。

### 3.2 `_errand_backlog_brief()`：折成一句

`（你手上还有 N 件没办完就被叫走的事：去 X 办「甲」、去 Y 办「乙」。要不要提、怎么提由你自己决定；别提这条提示。）`

- 空账 ⇒ 返回 `''`，调用方**一个字都不加**；
- **只给事实，不写死台词**（提不提交回模型 —— 第114轮口径）；
- TTL 一天（`ERRAND_GIVEN_UP_TTL`）、上限 8 件（`ERRAND_GIVEN_UP_MAX`）、
  同一（地点+事由）**去重**且挪到最新。

### 3.3 两条线各挂一次

| 线 | 挂点 | 为什么 |
|---|---|---|
| NPC | `_build_npc_context()` **尾部** | 与【此刻】同层，空账时逐字不变 |
| Ralsei | system 尾部，**在 `if _ctx:` 里面** | `lean` / `_sys_fixed`（事件台词）走不进来 ⇒ 逐字节稳定、KV 缓存不被打掉 |

### 3.4 预声明 `self._errand_given_up = {}`

★ 放在 **`init_npc_systems`** 里、紧挨 `self._npc_aliases`（**不是** `RalseiPet.__init__`）——
第149轮就栽在这上面：那批"9 字段预声明"根本不在 `__init__` 里，按 `__init__` 找是**假红**。
（即使漏了也不会炸：`_errand_given_up_add` 拿不到表会就地建 —— 但预声明仍要写，别依赖兜底。）

## 4. 四处"差一点写错"

### ① ★★ 三个帮手写成方法 ⇒ 第152轮同款**第 4 次**

第一版把它们写成 `RalseiPet` 的方法。`assign_errand` 是**产品函数**，第150~155轮那些
轻宿主都直接挂它（`assign_errand = RalseiPet.assign_errand`）—— 宿主没有那个方法 ⇒
`AttributeError: '_Host' object has no attribute '_errand_given_up_add'`。
改成模块级函数、只按鸭子类型读 `owner`（表不在就**就地建**），宿主一行都不用改。
`check156 C3` / `C6` 就是钉这件事的。

### ② ★★ 补丁脚本自己的语法坏掉

第一版 `patch156.py` 外层用 `u'''…'''`、里面又写了 `u\"\"\"…\"\"\"` ⇒ 生成的收尾多一个
引号（`""""`）⇒ `main.py` 第 5404 行 `unterminated string literal`，只能 `git checkout` 回滚。
改法：外层三单引号 + **落盘前先 `ast.parse(raw)`**。

### ③ ★★★ `check156` 首跑 4 红，**四条全是判据自己错**

| 红 | 真因 |
|---|---|
| `A7` | 判据算错了：A→B→A 只发生 **2 次**改派 ⇒ 欠账天然是 `[A, B]`，末项就该是 **B**。要验"去重"必须 A→B→A→**B** |
| `B1` | 判据数错：`_hb` 只派 2 次 ⇒ 欠账只有 1 件，断言"2 件"当然找不到（要 3 次派活才有 2 件） |
| `C2` | 判据找错了地方：门控调用在 `ok, why = self._npc_errand_gate(...)` 这条**赋值**里，不在 `if` 的 `test` 里 ⇒ 在 `n.test` 里找它**永远找不到**。改成"先定位门控调用，再取它之后第一个顶层 `If`"，并加"这一支里真的 `return`"当分母闸 |
| `D1` | 被测物错：`A8` 的说明写成 `'…上限 %d 件…' % (...)`，是个 `BinOp` 不是字面量 ⇒ 挪到 detail |

### ④ ★★ 顺手抓到一条**恒真判据**（`A8`）

第一版写 `_n8 <= ERRAND_GIVEN_UP_MAX`：分子分母**是同一个常量** ⇒ 把上限从 8 调到 20，
`_n8`（10）照样 `<= 20`，**还是绿**。这正是第85/134/136轮那一族"看着在守、其实没守"。
改成 `_n8 == ERRAND_GIVEN_UP_MAX and _n8 < 10`，并补两处负控制（`M2` 调大上限 / `M3`
删掉截断）—— 两条都必须红。
