## 2. 设计：为什么用稳定哈希，不用随机

★★★ 这一段是本轮最重要的决定。

```python
seed = '%s|%s|%s|%s' % (MISFIRE_SALT, it['id'], it['day'], it['text'])
h = hashlib.sha1(seed.encode('utf-8', 'ignore')).hexdigest()
```

- **用 random 的后果**：同一用例这次绿下次红。而"有时红"的判据**等于没有判据**，
  回归也永远不可重放 —— 这与本项目"回归必须可重放"是直接冲突的。
- **用稳定哈希的后果**：同一件事每次都错成同一个样子。**这恰恰更像人** ——
  人对同一段往事是**稳定地记错**，不是每次随机编。
- 换 `MISFIRE_SALT` 就整体换一套"错法"，便于将来调。

`MISFIRE_RATE = 0.30`（约三成）。

## 3. 两类变换：只改"准不准"，不改语义

| 变换 | 做什么 | 例子 |
|---|---|---|
| `SOFTEN` | 细节降级：抹时刻、数量词变模糊 | `15:30 我跑了2次` → `我跑了好几次` |
| `TIMESHIFT` | 时间漂移：往后推一档 | `今天的下午` → `昨天的下午`；`刚才` → `早些时候` |

★★★ **`SOFTEN` 只减不增** —— 冒出一个原本没有的数字，那就是**编造**，不是记错。
判据 `C1` 就是钉这一条（输出数字集合 ⊆ 输入数字集合）。

★★ **`TIMESHIFT` 是否保留"的<早上/晚上>"由规则表第三位决定**。
第一版不加这个，`刚刚的晚上` 被漂成「**早些时候的晚上**」—— 读着别扭。实测抓到才改的。

★★★ **刻意不做**"把两件事混成一件"（CONFLATE）：那会改**归属**
（把 A 的事记到 B 头上），最容易变成编造。留作后续，要做必须先立"可证伪"的判据。

## 4. 四类永不走样（"重要的事不会"的落点）

| 类别 | 为什么 |
|---|---|
| `is_key` | 关键记忆（用户明确标注"重要的事"） |
| `is_digest` | 日摘要本身就是"梗概"，再糊一次没有意义 |
| `PROTECTED_KINDS`（升级/进化/成就/完成的任务/重要日子/用户偏好） | 这些记错会真的误导行为 |
| `kind == 'inner'` | 内在活动**已经有**自己的"好像"口径（第193轮），再叠一层就假了 |

输出上还多一层可见信号：走样时那句话用「**好像**说过」，不走样仍是「说过」。
