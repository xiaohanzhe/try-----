## 2. 真缺口：覆盖 = 他彻底忘了

`ErrandBoard.assign` 对同一人是**覆盖**：旧差事从 `_active` 里消失，不进 `done`、
不留 `result`、也不走 `_npc_errand_commit`。改派一次后实测三处：

| 观测点 | 值 |
|---|---|
| 看在办 | 1 条（**新的那条**） |
| `done` | 0 |
| `npc_memory` | **0** |

⇒ 师傅过两天问"柜台擦了吗"，他只会茫然。

## 3. 补两处

| 位置 | 补什么 |
|---|---|
| `assign_errand` | 门控通过后**先取**旧差事（`board.active_of`），**派成之后**落一条记忆「我本来要去 A 办「甲」，还没办完，又被派去 B 办「乙」了」 |
| `_errand_ack(..., prev=None)` | brief 补一句"他手上原本还有一件事 —— 去「A」办「甲」，已经**作废**了。要不要跟用户提、怎么提，你自己决定"。**台词一个字都不写死** |

## 4. ★★★ 本轮真正的收获：那两句话什么时候是**假话**

第一版把"写痕"放在 `board.assign` **之前**，理由是"覆盖之后旧对象就没了"。
用「这句话会不会是假话」过一遍，探针实测抓到两条**假记忆**：

| # | 场景 | 第一版写下的记忆 | 事实 |
|---|---|---|---|
| P1 | 同一件事重说一遍（地点、事由都一样） | 「又被派去 **oneshot** 办**「擦柜台」**了」 | 本来就是去那儿擦柜台 —— 自相矛盾 |
| P2 | 派发**失败**（看板在派发前被关掉，`assign` 返 `None`） | 「又被派去 **ut** 办了」 | 他**还在去 oneshot 的路上** |

⇒ 定死两条不变式：

1. **"取"和"写"是两件事。** 取旧引用必须在 `assign` 之前（覆盖后 `_active` 里就没了），
   但**写痕必须在派成之后**（`_new is not None`）。第一版把这两件事混成了一件。
2. **同一件事重说一遍 ≠ 改派。** `assign` 会重新计时，但地点与事由一个字段都没变
   ⇒ 一件都没被作废，写"被改派"是**无中生有**。判据是模块级
   `_errand_same_job(prev, dest_scene, what)`，**只比地点 + 事由**
   （写成"同一个地方就算同一件"会把真改派一起吃掉 —— `A8b` 就是守这个）。

★ **为什么它必须是模块级函数**：`assign_errand` 与 `_errand_ack` 两处都要用，而它是
纯判断、不该问 `self` 要。写成方法会让第150~153轮那些"只挂产品函数"的轻宿主当场
`AttributeError`（§152.7 同款，而且那类异常常被 `except` 吞掉、症状是"什么都没发生"）。

## 5. 三条教训

### ① 破坏"删整段"必然连坐"数文案"的判据

`M1` 的期望我写的是 `A1 A1b A4 A5 A8b C2 C3`，实得**多一个 `C4`**——
因为 `C4` 数是"含『又被派去』的字符串恰好 1 条"，把整段删掉就是 0。
⇒ 这不是判据污染，是**同一条信号的又一个观测面**；期望要照实写全（现已改）。

### ② 拆一道守卫会连坐一片

`M2`（去掉 `_prev is not None`）实红 **8 条**：`A1 A1b A2 A4 A6 A7 A8 A8b`——
因为那道闸正是"首次派活不许编造"，拆掉它，**每个带"首次派活"的夹具都多一条幽灵痕迹**。
⇒ 这 8 条不是 8 个独立信号，期望照实写全，注释里点明"同一条闸的 8 个观测面"。

### ③ ★★★ 旧夹具第 3 次被漏 —— 症状极隐蔽

产品给 `_errand_ack` 加了**可选** `prev=`，而 `check152` 的桩是
`def _errand_ack(self, *a)` ⇒ 收不住关键字 ⇒ `handle_errand_command` 里那行
**当场 `TypeError`**。

症状不是"红"，而是：**`exit=1` 但 `FAIL=0`，PASS 从 37 掉到 28**（28 之后就没跑到
汇总行）。G2 表格里只有"退出码 + 比对=DIFF"这两列能看出来 —— 这也解释了为什么
它比"报一条红"更难发现：**判据没输，只是没跑到**。

修法：桩改 `(*a, **kw)`，**一条判据都不动**（+5/−1）。
⇒ 纪律：**凡给产品函数加关键字参数，先把全仓 `def <同名>(` 数一遍**（本轮 `grep`
只有 3 处：`check152` 的 `(*a)`、`check154` 的、以及 `mutate154` 里的锚点文本）。

## 8. 遗留 / 结转

1. **改派仍会"重新计时"**：同一件事被再说一遍时，`assign` 会从头算 travel/work，
   本轮只保证"不写假记忆"，**没有**把"重说一遍"变成"只是催一下、别计时"。
   真要改，得先定"催"的语义（是否缩短 work、是否保留已完成进度），不是一行判断的事。
2. **一次改派只留一条痕**：连改三次会有三条（`A4` 守着），但**没有**"最早那件"的追溯
   （被换掉的旧事由只存在于每一句话里，没有聚合视图）。
3. 派活 / 叫停 / 交差三条 ack 的"用户不在场也照样发起"仍未统一（第153轮 §8.3 原样保留）。
4. 第150~153轮结转未动：纯空格 `npc_id` 不拒；地点别名只到作品级前缀；否定闸整句从严；
   `_item_enter_scene` 无内部调用者；`current_scene` 双语义；`max_sentences` 读了不用。
