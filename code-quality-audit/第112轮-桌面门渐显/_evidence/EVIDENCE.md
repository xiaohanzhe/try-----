## 一、★★★ 核心结论：抓帧看不到门 / 宠物 —— **不是产品缺陷，是抓图方式**

### 现象
真机 `QScreen.grabWindow(0)` 抓出来的 PNG **只有壁纸**，看不到 4 扇门、也看不到 Ralsei。

### 定位过程（`_tools/diag112c.py`，真机）

| 检查 | 结果 | 含义 |
|---|---|---|
| `screen.geometry()` | `(0,0,2560,1600)` | 真机屏幕 2560×1600 |
| `scene_canvas.geometry()` | `(0,0,2560,1600)` | ★ **整屏化真的生效了** |
| `scene_canvas.isVisible()` | `True` | 控件是可见的 |
| `scene_canvas.grab()` | **画出了 4 扇门 + Ralsei** | ★★ 内容真的在画 |
| `grabWindow(0)` | 100% 不透明（= 全是壁纸） | 抓不到我们那一层 |

### 根因
场景层是一个 `WA_TranslucentBackground` 的**分层透明窗口**。Windows 下这类窗口由
**DWM 单独合成**，**不进** `QScreen.grabWindow(0)` 的取像范围。
⇒ "抓图里没有门"是**抓图 API 的局限**，不是渲染没发生。

### 反证
`scene_canvas.grab()`（**直接抓窗口控件**，绕开 DWM）抓到 **2.98% 非透明像素**
（13586/456036），肉眼可见 4 扇门各就各位、alpha 各不相同。

⇒ **修正后的取证口径**：验证"场景层画了什么"用 **`canvas.grab()`**，
   **不要**用 `grabWindow(0)`；验证"最终屏幕观感"用 **合成**（见 `composite112.py`）。

## 三、★★★ 抓出的**真问题**（用户两条抱怨都是对的）

### 问题 1：门**不在屏幕四周**，而是挤在屏幕中间
- 房间是 **320×240**，门按"四边中点贴房间边框"摆（`(138,0)`/`(138,184)`/`(0,70)`/`(284,94)`）—— **这一步没错**。
- 但 `SCENE_FIT_FRACTION = 0.5`（第110轮砍半）⇒ 画面在 2560×1600 屏上只占
  **1066×800**、居中于 `(747,400)`。
- ⇒ 门的**房间边缘** = 屏幕的**中间**。用户看到的"挤在中间、不在边框"**完全属实**。

**结论**：门位置在房间坐标系里是对的；问题在**画面只占屏幕 50%** 这一层。
`SCENE_FIT_FRACTION` 是第110轮引入的"画面比例"自由度 —— 用户要"贴屏幕边框"，
就得把它调回 `1.0`（铺满）或至少大幅提高。**这是一处待用户拍板的取舍**
（铺满 ⇒ 场景/宠物变大；砍半 ⇒ 门离开边框）。

### 问题 2：Ralsei 尺寸
- 实测 `_cached_scale_factor = 3.33125`，精灵原始高 ≈41px ⇒ **屏上高 ≈137px**。
- 这与 `scene_camera.SCENE_FIT_FRACTION` 的注释完全对上（"Ralsei 约 273px → 137px"）。
- 用户说"还是那么大"（相对**场景**观感）—— 因为场景被砍到 50% 而宠物是乘同一个
  scale 得到的，观感上"人比房间大"。**用户已定：「先不动，等我看完实机再定」**。
