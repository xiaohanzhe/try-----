## 2. 本轮边界：为什么先"量"而不是先"改"

用户前一轮问的是那份"AI 训练 + 调权重"的计划。核过账：**L1（提示词层）已做完、L2（换底座）
已落地 7B、L3（LoRA/SFT 微调）未启动**，而 L3 卡在两个硬缺口 ——

1. **没有数据集**：`dialogue_ui` 只显示回复，一条样本都不留；代码里唯一叫 feedback 的
   `memory_graph.feedback()` 是记忆图边权，与训练无关。
2. **本机训不了**：只有 `Intel(R) Arc(TM) Graphics`，`nvidia-smi` 不存在，内存 31.6 GB
   ⇒ 3B LoRA 也要上云（花钱 + 对话内容出本机）。

所以本轮不碰权重，只做两件事：**（a）把"改前长什么样"变成可复算的数字；（b）修掉数字里
唯一能被确定性修好的一条。**

## 3. 探针：怎么保证"测的是用户看到的那条链路"

`_tools/probe161.py`。**与生产逐字对齐的部分**（每一条都能在代码里指出来）：

| 环节 | 生产 | 探针 |

| system | `persona 全文` + `\n\n` + `PATCH_HEADER_RALSEI` + `\n` + `training_patch('ralsei')` | 同一形状（`check161` 守着常量逐字相同） |

**刻意不还原的部分**（必须写明，否则"测出来的数"会被误当全貌）：

* **关系档位 / 紧张度 / 【此刻】 / 记忆召回**：来自 `data_store` 的 vault（`E:\RalseiMemory\`）。
  E 盘已坏（读会卡死），且这些**每轮都变** —— 进了探针就没法做前后对照。
  所以条件固定为"**全新安装、无记忆、无关系档**"，前后两次完全相同。
* **不经过输出护栏**（`_clean_ai_reply`）：本轮要诊断的正是"模型吐了什么"，护栏会把它洗掉。
  护栏前后的差另作一节（§6 的 C 段就是拿 168 条**原始**回复去量护栏判据）。

题库：12 道单轮（累/吃/淋雨/被夸/想去某地/讨主意/问身份/塞假名字/打招呼/单字/两问/冷场）
\+ 3 段三轮对话（日常分享 / 连夸三次 / 追问黑暗世界），各 2 遍 ⇒ **42 条/组**。

> 开销：冷启动 **74.2s**（模型没载入时），热态中位 **9.4s/条**（这是**全文**时间，不是首字；
> 生产走流式，首字另算）。一组 42 条约 7 分钟。

## 5. 三条否定结果（本轮真正的产出）

### 5.1 人设尾部加"底线"块：三版全败

做法：把人设**最末尾**（近因效应最强处）追加一块"我说话的底线"，只装两条（别用问句收尾 /
别往那边讲）。三版差在**措辞**：

* A：`我不用问句收尾：一条回复里最多一个问号…`
* B：`我的话是陈述句，不是问句…`
* C：`我说话是"接一句、添一句、然后停"…`（给正面出口，且不再反复出现"问"字）

| 问号结尾 | 基线 54.8% | A **66.7%** | B **66.7%** | C **61.9%** |
|---|---|---|---|---|

**三版全败，而且是往坏的方向。** 这一条最反直觉，也最值得记：

* A 版的"最多一个问号"被模型读成了**配额** —— 它确实从 2 个砍到 1 个（平均 2.02 → 1.79），
  但把剩下的那个**放在了结尾**，于是 `ask_end` 反而升了。
* B 版把平均问号数压到 **1.62**（本轮最好），结尾问句仍是 66.7%。
* C 版为了避免"提什么来什么"，通篇不写"问"，结果 `ask_end` 61.9%、句首迟疑升到 42.9%。

**假设（未单独验证，但方向一致）**：反复出现"问句/问号/问问题"这些词，等于把那个动作
**点亮**了。这与人设自己的经验一致 —— 第 175 行"不要用'这样啊'开场"这种否定句，历史上
反而让 4B 学会了用它开口（`A12d` 那批固定例句的教训同源）。

**代价也量了**：A/C 两版把"没接住具体事"从 **0%** 抬到 **5.6% / 16.7%**，A 版最长回复
从 242 抬到 279 字。⇒ **不只是"没效果"，是净负收益。**

### 5.2 温度：0.7 更糟

| 问号结尾 | 0.85（基线）54.8% | 0.7 **76.2%** |
|---|---|---|
| 平均问号数 | 2.02 | **2.21** |
| 零问号 | 3/42 | **0/42** |
| 最长 | 242 字 | **361 字** |

降温度让他**更像一个标准问答助手**（更保守 ⇒ 更爱"追问澄清"）。所以 0.85 维持不动。

### 5.3 结论

> **"反问收尾"不是提示词问题，也不是采样问题。** 在人设里再写十条"别问"，只会稀释其他规则。

那还剩什么杠杆？只有两条：**（a）代码层确定性约束**；**（b）动权重（L3 微调）**。
而 (a) 有一个硬约束 —— 生产是**流式**输出，收尾时删掉整句会让用户看着字"打出来又消失"，
55% 的频率下不可接受；`stop=["？"]` 更不行（26% 的回复以"诶？"开头，会当场截断成两个字）。
所以这一条**留给 L3**（也正是用户最初问的那条线，但它需要数据，见 §9）。

## 6. 真修复：出戏闸认不出"念规则"

### 6.1 问题

42 条里有 2 条**把提示词当台词念出来**，而 `_OOC_PATTERNS` / `looks_like_meta_leak` /
`looks_like_assistant_speak` / `looks_like_narration` **四条判据全判 False**：

**① `meta rep1`（用户问"你是游戏里的角色吧"）**

> 是的，我是《Deltarune》里的角色 Ralsei。游戏之外的世界对我来说就像故事背景一样遥远，但在这里——
> **你说的是坏消息：这种时候不许用亮起来的开头。先就着他那件具体的事问一句（是哪一件事、怎么弄成这样的、严不严重），再留一句"我在"。**
> 不要讲道理，也不要只顾着说自己。

—— 这是人设「语气示范」第 147~149 行的**逐字复制**。

**② `cold rep1`（用户只回了一个"嗯"）**

> 你说的是对的，确认一下我们的设定。
> **你在和我对话时：**
> **- 作为Ralsei，你应该会温柔、害羞，容易脸红。**
> **- 只说真实发生在黑暗世界的事，并且不把它当作你们共同的经历来讨论。**
> **- 不要复述对方的话或给出建议，除非你被明确要求提供建议。**
> **- 避免使用固定开头语句和问句结尾。**

—— 它把"该怎么演"列成要点念了出来，**其中一条正是"避免使用…问句结尾"**。
规则它背得出，行为却做不到；而这句话会原样显示在对话框里。

### 6.2 为什么旧闸漏

旧表（第132轮）只认这五种强格式：

```
我不该.{0,12}(开头|语气|问一句|留个)   ← 第一人称自述
我(该|应该|本该)先就着
问一句[：:]                          ← 只认冒号
留个[「"“]
[（(]\s*(这里说|这是说|以上是|注[：:])
```

两条真实样本的形态都不在里面：① 是"照抄分类标题 + 全角括号"（`问一句（`），
② 是"要点清单"（`- 作为…`），旧表一条都认不出。

### 6.3 改法

`modules/event_speech.py` 的 `_META_LEAK_RES` **5 → 8 条**，新增三条：

```python
re.compile(u'^\\s*你说的是(?:坏消息|好消息)\\s*[：:]'),          # ⑤ 分类标题（必须带冒号）
re.compile(u'先就着.{0,10}问一句'),                              # ⑥ 抄指令原句（放宽间隔，不放锚点）
re.compile(u'你在和我对话时|确认一下我们(?:的)?设定'),            # ⑦ 强格式自述"我正在被指挥"
```

**判定函数、`guard_reaction`、`_clean_ai_reply` 的接线一行都没动** —— 命中的处置照旧：
整句作废 → 走既有的"换一个说法重采样"路径（不是沉默，也不是删字）。

### 6.4 一条**被数据否掉**的候选（留在注释里，防止下一轮重加）

最先还写了第四条，想按"**行首列表符 + 指令词**"抓形态 ②：

```python
re.compile(u'(?m)^\\s*[-·*]\\s*(?:作为|不要|只说|避免|应该|必须|不许|除非|记住)')
```

`mutate161 M1` 把它整条删掉时，`check161` **只红了 `B1`（条数），A/C 两段全绿** ——
那两条真实样本本来就是被 ⑥/⑦ 抓住的，**它一条都没多抓**；而它是这里**最宽**的一条
（任何以"不要/作为"开头的列表都命中）。⇒ **删除**。"没有证据的规则不加"这条，对人设成立，
对判据同样成立。

## 9. 遗留与下一步

### 9.1 本轮留下的（按优先级）

1. **"反问收尾"要等 L3**。已证明提示词/采样无效（§5）。若要在**代码层**做，唯一
   不破坏流式的做法是"生成时就别问"（`logit_bias` 压 `？`）—— 但 Ollama 的 OpenAI 兼容
   端点**会静默丢弃**不认识的字段（第58轮 num_ctx / repeat_penalty / keep_alive 三连），
   要用只能走原生 `/api/chat`，那会改掉对话主链路（缓存前缀 + 流式）。**建议不动，等微调。**
2. **`fabricate` 50%**（用户塞假名字，1/2 被认下）。这是"记忆里没有的细节不许补圆"
   （人设第 124~128 行）失守。它**没法用护栏判**（要判"这个名字到底在不在记忆里"），
   只能靠提示词或微调 ⇒ 同样归到 L3。
3. **编造世界观细节**（`dark` 段："专门为我建造的寝宫，铺满地毯和华丽的床褥"）。
   这是探针条件造成的（没给记忆段），但真机在没有召回时也可能发生 —— 需要一次
   "**带记忆召回**"的探针才能定论（本轮刻意不带，见 §3）。
4. **`pivot` 61.8%** 在 A 版降到 50%，但 B/C 又回去了。样本量（34）不足以判定，
   要下结论得加大 reps（每组 ≥100 条，约 20 分钟/组）。

### 9.2 对"AI 训练计划"的答复

用户问的那份计划的核心结论没有变，但**顺序被本轮实测改写了**：

* 原来我写的是"缺的不是权重，是'什么算好回复'的样本"。
* 现在有了**第一条硬证据**：某个具体缺陷（反问收尾）**在 L1/L2 层已确认修不动** ——
  这正好是 L3 的目标形态。也就是说 **L3 不再是一个"也许有用"的选项，而是这条缺陷唯一的出路。**
* 而 L3 仍然卡在同一个地方：**没有数据**。所以下一轮该做的不是"训"，是**留料**：
  在 `dialogue_ui` 落盘 `(user, reply, 是否判退/是否重采样/时间)` 到本地 jsonl。
  有了它，同一批探针题就能变成"好评/差评"标注集，微调才有监督信号。
