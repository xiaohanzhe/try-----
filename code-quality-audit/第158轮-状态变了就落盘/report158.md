## 3. 改法：四处落盘点

```python
# ① assign_errand：派成之后（★ 排在 return _prev 之后、被 _new is not None 守卫）
if _new is not None:
    self._npc_errand_save(force=True)
return _new

# ② cancel_errand：原 `_npc_errand_save()` → 
self._npc_errand_save(force=True)

# ③ _npc_errand_tick：结构性变化才强写
_structural = bool(dropped) or bool(out.get('finished'))
self._npc_errand_save(force=_structural)

# ④ 退出兜底（紧跟 _npc_plan_save(force=True)）
self._npc_errand_save(force=True)
```

### 3.1 为什么 `_structural` 只认 `dropped` 与 `finished`

`touched` 里混着**每拍都可能发生**的"把他压在目的地"（`roam.put`）。
写成 `force=touched` 就是**每拍写盘**（0.5s 一次、还是整本 JSON）—— 主循环会被拖垮，
而它想守的那件事（不丢状态）本来就只跟"作废 / 办完"有关。所以：

- `dropped`（被门控中途拦下 ⇒ `board.abort`）与 `finished`（办完 ⇒ `done` 里多一条）
  是**状态跃迁**，丢了会"同一件事办两遍"或"他永远回不了家"；
- 只压位置丢了 ⇒ 下一拍 `working_positions()` 还会再压一次，代价为零。

`check158 B6` 与 `mutate158 M6/M7` 成对钉住这条（M6 把力换成 `touched` ⇒ `A8` 红；M7 漏掉
`finished` ⇒ `A7` + `B6` 红）。

### 3.2 为什么派活的落盘必须在 `return _prev` 之后

"催"（同一件事再说一遍）在上面就 `return _prev` 走了（第155轮）。落盘若排在它前面，
"我催了他一句"就会写一次盘 —— **没变化就不该写**。`check158 B2` 用行号相对位置守这一条，
`mutate158 M2`（整段拿掉）与 `M10`（门控支多插一处）会把它打红。

## 4. 四处"差一点写错"（都靠实测抓出来的）

### 4.1 夹具少一个方法 ⇒ 落盘那行永远不执行（差点把产品判错）

`cancel_errand` 的落盘排在 `_npc_seed_bodies(self._npc_scene_id())` / `_npc_plan_save()`
**之后**，且整段包在 `try/except` 里。轻宿主只挂了产品函数、**没有 `_npc_scene_id`**
⇒ `AttributeError` 被 `except Exception` 吞掉 ⇒ **落盘那行永远不执行**。
症状极其误导：**改前改后都"复活"**，看着像"修了没用"。

⇒ 补齐 `_npc_scene_id` / `_npc_plan_save` 两个桩之后重测，改前**仍是** 6/6（P2 依旧复活）、
改后才转绿 —— 证明那条复活是**真节流**，不是异常吞掉。

### 4.2 `load() or ErrandBoard()` 会把"只剩已办"的档丢掉

`ErrandBoard.__len__` 只数 **`_active`** ⇒ 一个"在办 0 条、已办 1 条"的看板 `len()==0` 为假
⇒ `or` 右边生效 ⇒ **整本被换成空板**，重启后"已办 + 结果"全没。

`probe158` 的 P5 第一版就栽在这：盘上明明写着 `done: 1`，读回却是 0/0。
产品侧走的是 `if _er is not None:`（`init_npc_systems` 行 3704）—— **照抄它**。

### 4.3 补丁脚本自己的两个坑

- **锚点换行**：`main.py` 全 CRLF，锚点写 `\n` ⇒ `count()` 恒 0（第一次跑就 abort，没写坏文件）。
- **逐片段拼 `\r\n` 迟早漏一个**：第二块补丁先按 LF 拼、最后统一转 CRLF，并在写盘前用
  "裸 LF > 0 就中止"的闸兜住 —— 第一版正是被这道闸拦下的（9 个裸 LF）。

### 4.4 `A10` 幂等判据被"陈旧盘"污染 + 会崩

- 第一版在"两次 assign 之后直接取快照"⇒ 比的其实是**盘上陈旧 vs 盘上最新**，
  于是 M1（派活退回节流）会把它打红 —— 那是 `A1/A2` 的职责，属**错误归因**。
  改成"先强写一次把盘拉到当前状态，再取快照"。
- 第一版 `io.open` 直接读档 ⇒ 破坏（M2 整段删除落盘）时**文件不存在 ⇒ 崩**，
  后面的 B/C 两段整段没跑，`--dry` 里 M2 只显示 `A1 A2 A9`（**崩溃点不是守卫点**，
  第157轮 `A2` 同一个坑）。改成"文件不在 ⇒ 返 `None`、判红不抛"。
