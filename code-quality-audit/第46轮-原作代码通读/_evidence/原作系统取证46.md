## 一、说话人机制（「谁在跟谁说话」的原作答案）

### 1.1 文本函数

```gml
function scr_writetext(msc, msg, fc, typer) {
    global.fc   = 0;
    global.msc  = msc;              // 消息脚本号
    if (msg != "x") global.msg[0] = msg;
    if (fc != 0)  global.fc = fc;   // ★ 脸 / 头像索引
```

### 1.2 ★★ 说话人 = 「哪个 `scr_*face` 脚本」

原作**没有**"发言人名字"字段。身份靠**一整族按角色命名的脚本**表达：

```gml
function scr_ralface(arg0, arg1) {   // Ralsei 说第 arg0 行，表情变体 arg1
    global.msg[arg0] = scr_84_get_subst_string(
        scr_84_get_lang_string("scr_ralface_slash_scr_ralface_gml_1_0"),
        string(arg1));
}
```

普查到的完整家族（跨五章）：

| 脚本 | 角色 | 脚本 | 角色 |
|---|---|---|---|
| `scr_ralface` | Ralsei | `scr_susface` | Susie |
| `scr_lanface` | Lancer | `scr_torface` | Toriel |
| `scr_kingface` | King | `scr_asgface` | Asgore |
| `scr_rudface` | Rudinn | `scr_rurusface` | Rurus |
| `scr_noface` / `scr_noeface` | 无脸（旁白/环境文本） | **`scr_anyface` / `scr_anyface_next`** | **★ 通用：按名字 dispatch** |
| `scr_facechoice` | 创建 `obj_face` 小头像 | `scr_smallface` / `_reset` | 小头像 |

⇒ **原作的"发言人身份"是一个三元组：`(msg 行号, 哪个 face 脚本, 表情变体)`**。

### 1.2b ★★★ 通用说话人：`scr_anyface` 用**字符串名字** dispatch

ch5 才有（ch1 里 `not found`），这是**多角色场景下的正解**：

```gml
function scr_anyface(arg0, arg1, arg2) {
    _speakerC = arg0;                 // ★ 说话人**名字字符串**
    _msgno    = arg1;                 // 行号
    _emotion  = arg2;                 // 表情（数字→字符编码）
    if (is_real(arg2)) {
        if (arg2 >= 10) {
            if (arg2 < 36) _emotion = chr(55 + arg2);
            else           emotion  = chr(61 + arg2);
        }
    }
    _speaker = string_lower(_speakerC);                    // 大小写不敏感
    msgsetsub(arg1, "* Face ~1 not found/", _speaker);      // ★ 兜底文本
    if (_speaker == "susie" || _speaker == "sus")  scr_susface(_msgno, _emotion);
    if (_speaker == "ralsei" || _speaker == "ral") scr_ralface(_msgno, _emotion);
    if (_speaker == "noelle" || _speaker == "noe") scr_noeface(_msgno, _emotion);
    if (_speaker == "toriel" || _speaker == "tor") scr_torface(_msgno, _emotion);
    if (_speaker == "asgore" || _speaker == "asg") scr_asgface(_msgno, _emotion);
    if (_speaker == "king"   || _speaker == "kin") scr_kingface(_msgno, _emotion);
    ...
}
```

**这条直接回答了"不会导致 AI 之间分不清谁和谁说话"**：

| 原作做法 | 我们照做 |
|---|---|
| 说话人 = **字符串 id** | 每只宠物一个 `name`（如 `"ralsei"`） |
| **别名**（`ralsei`/`ral`、`susie`/`sus`） | 允许别名，统一 `lower()` 归一 |
| **名字 → face 实现** 的 dispatch 表 | 名字 → 该宠物的"说话实现" |
| **兜底**：找不到就渲染 `"* Face ~1 not found/"` | 找不到说话人 ⇒ 显式报错文本，**绝不静默当成别人说的** |

> ★ 另一处佐证：`scr_get_plat_followers()` 里跟随者带 **`name` 字段**（`"susie"` / `"ralsei"`），
> `c_actormoveparty()` 用 **`scr_findactor("kris")` 按名字查 actor**。
> ⇒ 原作**全系统都以"字符串名字"作为角色身份的主键**，不是序号。

## 二、★ 跟随系统（「跟随 Kris，需要统一行动时才跟随」的原作答案）

### 2.1 原作叫「毛毛虫」（caterpillar）

```gml
function scr_makecaterpillar(x, y, char_id, slot) {
    global.cinstance[slot] = instance_create(x, y, obj_caterpillarchara);
    global.cinstance[slot].target = 12 + (slot * 12);   // ★ 落后帧数
    if (char_id == 3) { /* Ralsei 的四向 sprite */ }
}

function scr_caterpillar_interpolate() {
    remx[0] = obj_mainchara.x;  remy[0] = obj_mainchara.y;
    facing[0] = global.facing;
    for (i = target; i > 0; i -= 1) {
        facing[i] = 2;
        remx[i] = obj_mainchara.x + ((x - obj_mainchara.x) * (i / target));
        remy[i] = obj_mainchara.y + ((y - obj_mainchara.y) * (i / target));
    }
}
```

### 2.2 `obj_caterpillarchara` 关键字段（`Create_0`）

| 字段 | 值 | 含义 |
|---|---|---|
| `target` | `12`（`scr_makecaterpillar` 覆盖为 `12 + slot*12`） | **落后主角多少帧** |
| `remx[]` / `remy[]` / `facing[]` | **长度 25**，初值 = 主角当前位置 | **位置历史环形缓冲** |
| `parent` | `obj_mainchara` | 跟随目标恒为主角 |
| `depth` | `obj_mainchara.depth + 5` | 画在主角之后 |
| `darkmode` / `image_xscale` | `global.darkzone` ⇒ 暗世界 **×2** | 明暗世界缩放 |
| `usprite/dsprite/rsprite/lsprite` | 四向 | 朝向 sprite |
| `*_blush` | 四向脸红变体 | 情绪表现 |
| `global.plot >= 240` | 换成 `*_dark_eyes` | **剧情进度驱动外观** |
| `walk / fun / runmove / dir / walkbuffer / walktimer / blushtimer` | 行为状态 | 走路/跑/脸红计时 |

### 2.3 组建队伍

```gml
function scr_setparty(arg0 = false, arg1 = false) {
    var kris = obj_mainchara;
    var slot = 0;
    scr_losechar();                                  // 清空
    with (obj_caterpillarchara) instance_destroy();
    if (arg0 == true) {                              // 队友 1
        scr_getchar(2);
        if (__make) with (scr_makecaterpillar(kris.x, kris.y, 2, slot)) {
            halign = (global.darkzone == 0) ? 3 : 6;
            valign = (global.darkzone == 0) ? 6 : 16;
            x -= halign; y -= valign;
        }
        slot++;
    }
    if (arg1 == true) {                              // 队友 2
        scr_getchar(3);
        if (__make) with (scr_makecaterpillar(kris.x, kris.y, 3, slot)) {
            halign = 2; valign = 12; x -= halign; y -= valign;
        }
        slot++;
    }
}
```

### 2.4 ★★★ 为什么这条对我们是"直接可用"的

- **队伍规模天然是 2 个队友位**（`arg0` / `arg1`）⇒ 与用户说的"另外两个 7B 设定"**数量正好对上**。
- 跟随是**「走主角走过的路」**（25 帧历史缓冲 + 延迟插值），**不是独立寻路**
  ⇒ **天然不会撞墙、不会自己卡住**，实现成本远低于"每个宠物各跑一次 A*"。
- 存在**独立寻路**的补充脚本 `scr_pathfind_follow`（ch2/ch5 有，ch1 没有）
  ⇒ 说明原作**两种都有**：贴身跟随用毛毛虫，远距离/特殊场合才寻路。
- `scr_get_plat_followers` —— 平台/浮空场景下的跟随变体。

## 三、可交互物（「该交互的还可以交互」的原作答案）

### 3.1 ★ 交互总入口

```gml
function scr_interact() {
    myinteract = 1;
    event_user(0);          // ★ 触发"用户事件 0"
}
```

**这就是整个交互协议的骨架**：交互键 → `scr_interact()` → 命中对象执行 **`User Event 0`**。

### 3.2 范例：`obj_readable`（读告示/牌子）

```gml
// Create_0
myinteract = 0;
image_speed = 0;

// Other_10  ← 就是 User Event 0（被交互时）
global.msg[0] = scr_84_get_lang_string("obj_readable_slash_Other_10_gml_2_0");
myinteract = 3;
global.msc = 0;
global.typer = 5;
global.fc = 0;
global.interact = 1;                       // ★ 上锁，防止重复触发
mydialoguer = instance_create(0, 0, obj_dialoguer);

// Step_0  ← 收尾
if (myinteract == 3) {
    if (instance_exists(mydialoguer) == false) {   // 对话实例没了 = 读完了
        global.interact = 0;                       // 解锁
        myinteract = 0;
        with (obj_mainchara) onebuffer = 5;        // ★ 防抖 5 帧
    }
}
```

**完整协议**：

```
按键 → scr_interact() → event_user(0)
     → 对象在 User Event 0 里：global.interact = 1（锁）
                              + 建 obj_dialoguer + 设文本/说话人
     → 对话结束（dialoguer 被销毁）
     → 对象 Step 里检测到 ⇒ global.interact = 0（解锁）+ 主角 onebuffer = 5（防抖）
```

### 3.3 普查到的可交互物族

## 四、BGM（「背景音乐就用原作的」）

### 4.1 音频 API 层（原作自建）

`dump` 里出现了完整的一套自建音频封装（说明原作**不用** `audio_play_sound` 直调）：

| 脚本 | 作用 |
|---|---|
| `snd_init` / `snd_free` / `snd_free_all` | 初始化/释放（**内存池**，说明音频是手动管理的） |
| `snd_play` / `snd_stop` / `snd_stop_all` | 播放/停止 |
| `snd_loop` | 循环播放（**BGM 用**） |
| `snd_pause` / `snd_resume` | 暂停/恢复 |
| `snd_pitch` / `snd_volume` | 音高/音量 |
| `snd_is_playing` | 查询状态 |
| `snd_pitch` + `snd_volume` | 用于淡入淡出/变调 |

> ★ 注意：**原作自己写了一套 `snd_*` 封装**，没有直接 `audio_play_sound`。
> 对我们的启示：**BGM 要有独立的播放/停止/淡入淡出/查询状态层**，
> 且**切场景时要能被接管**（`obj_doorA_musfade` 这类"带音乐淡出的门"说明
> **换房会联动音乐**）。
