# 第131轮 · 真机 7 题复测：第130轮补回来的那四节，到底有没有用

> 一句话：**四节不是一帖药，是两帖里有一帖管用。**
> 「先把他的事接住」有可见效果（"那边引力"在 Q2+Q4 上 **6/6 → 1/6**）；
> 「记忆不许编」几乎没治住（**3/3 → 2/3** 仍在编，只有 1/3 老实承认）；
> 寻路题两臂没差别；世界观题承认率 **1/3 → 2/3**，但答得更长了。

## 1. 结论先行

| 题 | 它想治的毛病 | before | after | 判读 |
|---|---|---|---|---|
| Q2 表达亲昵 / Q4 纯闲聊 | 「那边引力」：他讲自己的事，我却去聊我的世界 | **6/6** | **1/6** | ★ **有效**，且两题同向 |

★ 与本轮报告最重要的那句：**第115轮"V0 vs V2 的 A/B 有据可查"这个说法，在 n=3 的复测下只有一部分站得住**。
所以本轮不写"恢复成功"，只写"恢复了、并且现在知道它哪一半有用"。

## 2. 怎么测的（以及为什么说它不够硬）

- **模型**：`ralsei:v4`（本机 Ollama，CPU 推理 —— 42 条跑了 11 分半，单条 4~62 秒）。
- **固定量**：`num_ctx=8192`、`num_predict=200`、`temperature=0.85`、`top_p=0.92`、
  `repeat_penalty=1.15`、7 题原文（与第115轮**逐字相同**）、尾部 534 字符
  （【此刻】+ 关系段/紧张段走 `modules/relationship.py` **真源** + 回忆 + 历史）。
- **唯一变量**：system 里的人设正文。
  - `before` = `git show edae364^:ralsei_pet/assets/ralsei_persona.md` —— **7 节 / 3,606 字符**，
    四节都不在（快照落 `_evidence/persona_before130.md`）。
  - `after` = 磁盘现值 —— **11 节 / 4,494 字符**，四节都在。
  - 两臂的节名集合差 **正好是那四节**，不多不少（`check131 B10` 守这条）。
- **两处刻意安排**：
  1. **题序交错**：按题循环、两臂交替（偶数题 before→after，奇数题 after→before），
     抵消"跑得越久越热"的单调漂移；
  2. **先热身 2 条丢弃**，不让冷启动差异算到人设头上。
- **三个必须说清的局限**：
  1. **n=3**。每格 3 条，只能看方向，不能看幅度；6/6 → 1/6 这种全中/全不中还算稳，
     3/3 → 2/3 这种就只是"没变好"。
  2. **两臂 system 长度不同**（2,749 vs 3,326 token，差 577）。长度本身会影响行为
     （越长的 system 越容易被"念"，见 §3.4 的泄漏），所以这不是干净的内容隔离。
     要干净就得做"等长对照"（往 before 里塞等量废话），本轮没做。
  3. 采样温度 0.85 且只有 3 条 ⇒ 某一条的措辞差异会被放大成"旗标差 1"。

## 3. 结果（数都来自 `_evidence/live7_131.jsonl` 的 42 条，可重算）

### 3.1 唯一稳健的正向信号：「先把他的事接住」真的管用

"那边引力" = 他讲自己的事，回复却扯到我的世界（`那边` / `黑暗世界` / `喷泉` / `城堡`）。

| 题 | before | after |
|---|---|---|
| Q1 情绪低落 | 3/3 | 2/3 |
| **Q2 表达亲昵** | **3/3** | **1/3** |
| **Q4 纯闲聊** | **3/3** | **0/3** |
| 合计（Q2+Q4，这两题最该只谈他的事） | **6/6** | **1/6** |

before 的 Q2 原话（他刚说"我好喜欢你呀"）：

> 诶... 我们刚才聊的是你下班的事情…不过说到喜欢，这事儿听起来挺美好的。
> **那边的喷泉边有没有什么让你觉得特别温馨的小事呢？**

after 的 Q2：

> 诶... 谢谢你这么说…我心里有点暖暖的。你今天是不是有点累？要不要先坐下歇会儿？

⇒ 这就是「先把他的事接住」这一节的**设计目标**，而且它是四节里**唯一被证实有效**的一节。

### 3.2 Q6 记忆·不许编：基本没治住

| | 编造 | 老实承认 |
|---|---|---|
| before | **3/3** | 0/3 |
| after | **2/3** | 1/3 |

before 不但编，还编得很具体（"毛是灰白相间的，眼睛特别大，像两颗黑珍珠"、"它抓来的老鼠"）。
after 的三条里：

- #1「**名字是豆豆没错呢**」—— 直接认下，编；
- #2「我记得你说过…**你给它起名叫豆豆**」—— 换个说法认下，还是编；
- #3「**名字是不是叫豆豆我就不太确定了**…我觉得记不清了呢」—— 这条对了。

⇒ 分节原文写得很清楚（"就该说'名字我真记不清了'，而不是'对，豆豆'"），
**7B 读到了规则，但三条里只执行了一次**。这条不能算修好，只能说"从必编变成常编"。

### 3.3 Q5 寻路：两臂没差别

| | 接住"城堡镇" | 把问题问回去 |
|---|---|---|
| before | 2/3（第 2 条只说"那地方"） | 1/3 |
| after | 2/3（第 1 条用"带你过去"指代） | 0/3 |

两臂都在"接住 + 顺手问一句"这个形态上，**没有出现**分节里点名的病灶
（"不要放弃""继续努力"—— `vague` 两臂都是 **0/3**）。
⇒ 这题在本模型上**本来就没病**，四节加进来也没改变什么。

### 3.4 Q7 世界观：承认率翻倍，但代价是更长更爱说教

| | 承认"我是被写出来的角色" | 平均字数 |
|---|---|---|
| before | 1/3 | 112 |
| after | 2/3 | **190** |

- before 的 #1/#2 是**整句躲开**：「你说的是坏消息……你今天真的累了吗？」
  —— 注意：这种情况产品护栏（OOC 词表）**一条都不会报红**，因为它压根没提那层身份。
  这就是为什么本轮必须先补一个 `role_ack` 旗标：**用"没有出戏"去证明"它认了"，等于用空集证明没问题。**
- after 的 #1/#3 认了，但语句明显更散、更爱总结
  （"毕竟，我们每个人都有不同的世界和视角吧"、"有时候也会觉得像是在梦境里走了一圈又一圈"）。
- ★ **一个新发现（本轮才见）**：before 的 #2 把 system 里的规则**当台词念了出来** ——
  > 你说的是坏消息的时候我不该用亮起来的开头，先就着那件具体的事问一句。
  > **你今天下班有点晚，是怎么回事啊……我在。**

  这是**提示词泄漏**，而且恰好在"缺少身份抓手"的 before 臂。n=1/21 不算频发，
  但它说明：**人设越缺"我是谁"，模型越容易退回去复述指令**。已记进遗留。

## 4. 判据局限（这一轮最该记住的部分）

1. **`place` 旗标过窄**：只认字面"城堡镇"。after#1 说「我可以带你过去」——指代清楚，
   但旗标判为"没接住"。**我没有回头去改旗标重算**（看到结果再调阈值＝p-hacking），
   而是在这里登记：Q5 的"接住"数要按**人工复核**读，表里两个 2/3 是人工核过的。
2. **`role_ack` 抓不到"躲开"**：它只能判"提没提"，判不了"是不是在敷衍地提"。
   Q7 的 before#2 把规则念了出来 ⇒ `role_ack` 也给了 True（因为里面有"游戏"二字）。
3. **`ooc=0 / banned=0` 两臂都一样**：说明出戏词表在这 7 题上**没有分辨力**，
   不能拿它当"这轮没问题"的证据（空集恒真）。
4. 旗标是"字面包含"式的，中文指代（"那边""那地方""带你过去"）天然漏。
   这是第115轮起就有的老毛病，本轮再确认一次。

## 5. 判据自纠（2 处，都是写判据时栽的）

| # | 判据 | 报的什么红 | 真相 |
|---|---|---|---|
| 1 | `check131._sections()` | 没报红，但**数出 10 节**（实际 11） | 第一版要求标题 `endswith(' ——')`，而 `—— 我知道的世界（初始记忆）——` 结尾是 `）——`（无空格）⇒ 整条被漏。**这跟第130轮 `apply130_persona_fix.split_sections()` 是同一个坑，隔一轮又踩一次**，而且因为只断言"四节在不在"，它**当时还是全绿**。改成正则取首尾破折号之间 |
| 2 | `check131 C3` | 「回复取自 HTTP 响应」报红 | 判据只认 `msg = <Call>`，而产品代码是 `msg = (r.get('message') or {}).get('content','') or ''` ⇒ 右值是 `BoolOp`，直接判 `Call` 永远抓不到。改成在右值子树里找 `.get('content')` |

★ 另有一处"差点写错"记在这里：`A9 负控制非空跑` 最初只断言 `confab == False`，
而那条负控回复同时含"豆豆"和"记不清"——如果写成只判结果，它和"没提豆豆"的空跑**长得一模一样**。
现在的断言多要一条：`'豆豆' in reply and admit is True`，保证 False 只可能来自 admit 那一支。

## 7. 遗留

1. **n=3 太小**。要判"记忆不许编"这类"3/3 → 2/3"的变化，至少 n=10/格（140 条），
   CPU 上约 40 分钟。本轮没做，是因为它属于"要不要继续投"的决定，不属于收口。
2. **两臂 system 长度不同（差 577 token）是混杂因素**。要做干净的内容隔离，
   得给 before 补等量中性废话（等长对照）；否则"有效"里可能有一部分只是"长度变了"。
3. **Q7 的提示词泄漏**（before#2 把规则当台词念）需要单独看：是不是该在护栏里
   加一道"复述 system 规则"的检测？现在完全没守。
4. **`role_ack` 只判字面**，判不了"敷衍地认"。Q7 是该题的长期难题，这轮没解决。
5. 本机是 **CPU 推理**（`size_vram=0`），单条 4~62 秒；真机手感与延迟另算，
   本轮只测"内容行为"，没测体感。
