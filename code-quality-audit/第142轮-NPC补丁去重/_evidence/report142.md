# 第142轮 · 那 38 条不是"重复"，是 38 份诊断

> 一句话结论：第139轮登记的「38 位 NPC 的 patch 同型重复」**前提不成立**。
> 那 38 条里那句 `一次最多两三句，短一点，像随口说出来的。`（简称 ①）是
> `TOO_LONG`（**回复超 200 字**）实测触发的处罚条，带 ① 的 38 人 **100%** 有过超长回复，
> 「既没超长也没超句」却带 ① 的 **0 人**。**不能删。**
>
> 连带订正：第139轮删 `ralsei` 那条时说的"人设第三份复述"归因是错的
> （`ralsei` 实测最长 211 字，确实踩过 `TOO_LONG`）。
>
> 另外修掉一个我上一轮发出去的 bug：`check141` 的 D2 判据把计数标记**打印**了出来，
> 导致 `run_all` 多数一次（套件自报 30、汇总报 31）。

## 一、前提被推翻：三条证据

### 证据① 代码侧 —— ① 是"实测超长"的产物，不是模板

`code-quality-audit/第113轮/_tools/common113.py`：

```python
if len(t) > MAX_CHARS:                              # 200 字
    bad.append(('TOO_LONG', '%d 字 > %d' % (len(t), MAX_CHARS)))
...
PATCH_RULES = { ...
    'TOO_LONG': '一次最多两三句，短一点，像随口说出来的。',
}
...
for c in ('MARKDOWN', 'AI_SELF', 'SLAVE', 'NOT_CN', 'ACTION_PAREN', 'META',
          'TOO_LONG', 'TOO_MANY_SENTENCES', 'PARROT', 'REPEAT', 'ENGLISH', 'EMPTY'):
    ...
    if len(want) >= 3:
        break
```

⇒ 触发条件是**字数超 200**（与句数无关）；`build_patch` 按优先级取**前 3 条**，
`TOO_LONG` 排**第 7 位**。patch 里出现 ① ＝ 这个角色真的踩过超长，
而且前面 6 项没把 3 个槽位占满。

### 证据② 语料侧 —— 77 份 raw30 / 5592 条真机回复

| 组 | n | 实测有 >200 字的回复 | 实测有 >3 句的回复 |
|---|---|---|---|
| **带 ①** | 38 | **38 人（100%）** · 共 247 条 · 最长 465 字 | 38 人（100%） |
| 不带 ① | 39 | 8 人（20.5%） · 共 89 条 | 38 人（97.4%） |

**「既没超长也没超句」却带 ① 的：0 人。**

另一侧也自洽：**有 8 人实测超长却没拿到 ①**（`hy_axis` / `hy_bowll` /
`hy_chujin_ketsukane` / `hy_clover` / `hy_dalv` / `os_cedric` / `ralsei` /
`ut_papyrus`）—— 因为更高优先级的违规把 3 个槽位占满了。
⇒ **没有 ① ≠ 没违规**，这条也解释了 38 这个数字为什么不是 76。

### 证据③ 规格冲突 —— 删 ① 不是去重，是收紧

76 份人设里那句**只有一种写法**：

> · 一次开口通常 **1~2 句**，最长不超过 200 字；像真人那样说话，不要写成说明书。

而 ① 写的是「**最多两三句**」 —— **更宽**。删掉 ① 等于把规格从 ≤3 收紧到 1~2，
那是行为改变，不是删重复。

第139轮在 `ralsei` 身上之所以"删了 A/B 无差别"，是因为 `ralsei` 的人设自己写
「一次只说 1~3 句」，两边语义相同。**这 38 位不具备这个前提。**

> 顺带记一笔：`queen` 的人设要求"不用标点"，而"1~2 句"对她本就无法度量 ——
> 同一个人设文件里的两条规则天然打架，与第141轮 §141.4 记的是同一处。

## 二、第139轮的归因订正

第139轮的报告把 ① 写成"人设句数规格的第三份复述（派生品）"。按本轮取证：

- `ralsei` 实测最长 **211 字**、有 1 条 >200 ⇒ 它当初**确实踩过 `TOO_LONG`**；
- 所以 ① 对它是**有依据的诊断**，不是重复。

**但删掉后的 56 条真机 A/B 无差别仍是实测结论**，所以**现状保留、不回滚**。
要记的是：**它能删 ≠ 别人也能删**。这条已经写进 `common113.py` 的注释，防止有人照先例批量删。

`probe139_ab.py` 里那句「96 位角色人人一条」也是**错的**（实际 38 位），本轮一并订正。

### 本轮判据自身踩的三个坑

1. **`C1`/`C2` 只读了 `_index.json` 那一份副本** —— 删 `cards/asgore.json` 里的 ① 时
   它们照样绿，等于没守住真正会发出去的那份文件。改成**三处副本一起判**（M1/M2 才抓得住）。
2. **`A2` 只看 `list(specs)[0]`** —— 有多个写法时取哪个取决于 set 的迭代顺序，判据会时红时绿。
   改成"**所有**写法都必须含 1~2 句"。
3. **`D1`（防计数）自己的描述里打印了计数标记** —— 于是它把这行多算了一次：
   套件自报 18、`run_all` 报 19。

   而套件自报 30。当时我看到 31 没当场归因（以为是"31 条判据"）。
   **数字对不上就必查**，这是"DIFF 必看"的同一个教训换了个面。

## 五、遗留

1. **`…` 当逗号的规格漏洞**（第141轮）：人设只写「别当句号」，实测 97.4% 是当逗号。
   要治先统一 76 份人设措辞。
2. **英文角色的长度指标全失真**（`ut_sans` / `hy_*`）：切句尺不含 ASCII `.`。
3. **"没 ① ≠ 没违规"共 8 人**（`hy_axis` / `hy_bowll` / `hy_chujin_ketsukane` /
   `hy_clover` / `hy_dalv` / `os_cedric` / `ralsei` / `ut_papyrus`）——
   他们的超长提醒被前 3 槽挤掉了。要不要改成"长度类单独占一个槽"，需要先量
   （把长度类提前会让 `META` / `NOT_CN` 这类更严重的掉出去）。
4. **`check138` 每跑一次就刷脏 `phase138.json`**（第141轮登记）。
5. **`eval113.merge_patches` 重建会把 ① 塞回 `ralsei`**（因为它确实踩过 TOO_LONG）——
   派生字段重建问题，靠 `check139 A1` 兜底。
6. 第140轮遗留：`max_sentences` 仍"读了不用"。
