首次 `git push` 连续失败，三种报错轮番出现，**均与令牌无关**：
1. `schannel: server closed abruptly (missing close_notify)`
2. `CONNECT tunnel failed, response 502`

排查结论：
- 本机环境变量 `HTTP_PROXY=HTTPS_PROXY=http://127.0.0.1:54231`（沙箱代理）——走它对 `github.com` 返 **502**；
  本机另有 `127.0.0.1:7897`（Clash，IE 代理项残留的地址，`ProxyEnable=0` 但端口在监听）。
- `curl.exe -v -x http://127.0.0.1:7897 https://github.com` 显示
  `CONNECT tunnel established, response 200` 之后紧接 `schannel: failed to receive handshake`
  → **代理是通的，是 github.com 的 TLS 握手被重置**（同时间 `api.github.com` 走同一代理 200）。
- **解法**：`git -c credential.helper= -c "http.proxy=http://127.0.0.1:7897" -c http.extraheader="Authorization: Basic <b64>" push origin main`，
  外面套 **3–5 次重试 + `Start-Sleep 5`**，实测第 4 次成功。属间歇性，重试即可，不必改配置。
- 另注意：`curl` 会**自动读取 `HTTPS_PROXY` 环境变量**——"直连 200"的假象就是这么来的，测直连必须显式清空环境变量。
