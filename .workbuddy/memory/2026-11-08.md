## 第173轮 · `obj_doorAny` 实例物化（把纸上的路网铺到地上）

**起点**：第172轮落了 798 条 Any 门边进 `_routes.json`，收口时留了一句「路网已画在图上但还没铺到地上」。
本轮实测确认：产品场景里 `src == 'obj_doorAny'` **恒为 0** ⇒ `build_props()` 遍历不到 ⇒ 798 条边**零消费方**。

**根因不是忘了写，是素材缺失导致的过滤**：`gen_objects44.object()` 的规矩是「查不到 sprite 帧 ⇒ 返回 None」，
而 `assets/scenes/objs/` 里**没有 `spr_doorAny_0.png`**（`spr_doorA..F` 都有）⇒ 881 条实例被静默跳过。

**做法**：幂等追加，不重跑生成器（重跑会冲掉 68/117 轮增量 —— §130「派生字段必被重建冲掉」）。
产物 `{pos:[x,y], src:"obj_doorAny", depth}`，**故意不写 sprite**（原作 `visible=false`，
`is_drawable_object()` 会滤掉；写个指向不存在文件的 sprite 才是假话）。

**四本账**（`check173` A 段全部独立重算，不抄注入器自报数）：

| 口径 | 条数 | 来源 |
|---|---|---|
| 原作侧实例表 | 881 | 第172轮 `analyze172.json`（跨轮锚定） |
| 第42轮普查 | 830 | `inst42*` 五章（恰好已无重复坐标） |
| 已登记房间（= 本轮物化） | **820** | 830 按「有没有场景载体」二分 |
| 未登记房间（如实落空） | 10 | 7 个 `(章,房间)` 键 |

逐章：`ch1 0 / ch2 26 / ch3 187 / ch4 361 / ch5 246` = 820。
落盘：**77 个场景文件**（30 分片 + 47 独立文件）。

**端到端**（`build_props` → `route_for_door` 实测，不是查源码猜的）：
**801 / 820 条真的解析出目标场景**；19 条解析不出，**逐条**落在「该场景在原作里就没有 Any 门边」的场景里；
**227 个场景**同房多扇门分流到**不同**目标（第172轮 `_pick_by_pos` 真的在起作用）；目标场景全部真实存在。

### ★★★ 本轮最贵的一课：`_index.json` 与场景文件不齐

第一版注入器只给了 **705 条**（不是 820），另 **125 条**被算成"落在未登记房间"。查出：

```

盘上场景容器里的 (章,房间) 对 = 2079
差 87 —— 盘上 88 个独立场景文件里，正好 87 个没有 original_room_id
```

那 87 间房「登记了，但场景文件不自带房间号」⇒ 注入器整块跳过 ⇒ 115 条门白白落空。

**修法**：房间号回退到 `_index.json`。依据是产品运行时本来就只读 index
（`main.py::_scene_rooms()` 第 4694~4698 行）⇒ 注入器与**运行时同源**，
而且不必改 87 个场景文件的 schema（那会波及房间反查 / 卡片派生）。
修完 `705 + 115 = 820`。
