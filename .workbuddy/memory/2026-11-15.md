## 一、用户第 5 句是硬命中

我原来的排除闸是「**裁出的图颜色数 ≤ 2 ⇒ 蒙版 ⇒ 解码失败**」。
这条闸的**隐含前提是"原版头像一定有颜色"** —— 一旦有单色原作，它就会把
**正确的单色图判成解码失败**。正是记忆里的「判据过窄 = 误报」（第159轮）。

**实证（全部肉眼确认）**：

| 图 | 尺寸 | 唯一色 | 构成 | 结论 |
|---|---|---|---|---|
| 黄魂 `p083` | 2048² | 2 | 纯白占 19.2% + 全透明 80.8% | 遮罩/剪影，原作如此 |
| UT `spr_face_undyne0..8` | 45×38 | 2 | 黑 72% + 白 28%、100% 不透明 | 结局字幕黑白小头像 |
| UT `spr_floweyface_l` / `spr_vulkinface` / `spr_asgore_face0` | — | 2 | 白线稿 | 原作单色 |
| 黄魂 `spr_portrait_*` 全族 124 个 | 110×106 | 2~3 | 黑底 72% + 白线 28%、**零透明** | 线稿层，见下 |

⇒ **判据修正**：颜色数**不能**单独当解码判据。改成组合量——`opaque%` / `flat%`（水平相邻同色率）/
4-邻域连通块数 + **肉眼看**。噪声也"颜色很多"；蒙版与正确单色图都是 1~2 色，
**颜色数根本区分不了这两者**。

## 二、自写 QOI 解码器：整条路作废

已确认仍对的：黄魂 117 页 = 34 PNG + 84 `BZh`(bzip2)；`BZh` 解压后是 GM QOI，
**12 字节头**由 `dataLen` 实证（64²页 6328=12+6316；2048²页 448279=12+448267）。

**为什么放弃**：对 `page#0`（64×64，需 4096px）暴力试起点 0~19：

```
start= 0 出 4096/4096 px，用  493/6328 B，透明 4091
start=12 出 4096/4096 px，用  483/6316 B，透明 3973
start=19 出 4096/4096 px，用  503/6309 B，透明 3973
```

**任何起点都"解满"但只吃 ~500 字节** ⇒ 不是起点问题，是 op 映射/结构假设整体不成立
（大量 `0xC0|n` 被当 RUN）。宽容解码出图是**彩条噪声**（肉眼已否定）。

## 三、正确入口：UTMT 整页导出

`probe_api190.csx` 反射出来的真相（**别再猜**）：

```
inst   MagickImage GetEmbeddedTexture(UndertaleEmbeddedTexture embeddedTexture)
static Void SaveImageToFile(IMagickImage`1 image, String filePath)
prop GMImage Image          ← TexData 上
prop Boolean FormatQOI      ← UTMT 自己知道哪些页压缩了
prop Boolean FormatBZ2
```

三条硬事实：
1. **UTMT 0.9.2 用 ImageMagick / Magick.NET，不用 `System.Drawing`**
   ⇒ `using System.Drawing.Imaging;` 直接 **CS0234**，`Bitmap` 不存在。
2. 整页导出 = `GetEmbeddedTexture(tex)` → `MagickImage` → `SaveImageToFile`。
3. `FormatQOI/FormatBZ2` 直接告诉答案（黄魂 83 页 QOI+BZ2，UT 0 页）。

**实测**：黄魂 **117/117 成功**，**98 页彩色**；UT 42/42 成功。

## 四、★★★ E 盘坏点会伪装成"代码写错了"

```
System.ExecutionEngineException: In page error:
Attempted to access a memory page that is not present ...
   at System.Reflection.Internal.MemoryBlock.BinarySearchReference(...)
   at Microsoft.CodeAnalysis.CSharp.OverloadResolution...
```

- rc = **3221225478**（0xC0000602 FailFast），日志**只有这一句**
- 发生在加载 Magick.NET 元数据时 ⇒ 看着像 csx 编译失败，实际是**磁盘页读不出来**
- E 盘原件 md5 逐一核对 **213 文件全 OK** ⇒ **偶发**
- 同一份 csx 从 **D 盘副本**跑 ⇒ rc=0，117/117 全成功

**处置**：新增 `utmtpath190.py`，所有脚本改**优先 D 盘副本**；
`mkutmt190.py` 复制 + 逐字节校验（359 文件一致）。

## 五、★ 另一个坑：`Type.GetType` 会当场猝死

`Type.GetType("System.Drawing.Bitmap, System.Drawing")` 在 .NET 10 + Roslyn 脚本下
走 `RuntimeAssembly.GetTypeCore`，直接 **FailFast 0xC0000006**，**try/catch 拦不住**。
⇒ 探测程序集只能用纯托管遍历（`AppDomain.CurrentDomain.GetAssemblies()` + `GetTypes()`）。
