### 旧诊断（记在 `.workbuddy/memory/2026-09-19.md` §六 + 速查本遗留④）
「`E:\RalseiMemory\logs\ralsei_pet.log` 在 exFAT 上 `os.rename` 撞**已存在**目标 → `WinError 1` → 永不滚动」。

### 实测：**不成立**（三次独立复现全部"正常"）
在 E 盘（exFAT）真机实测：

| 实验 | 结果 |
|---|---|
| `os.rename` 目标不存在 | OK |
| `os.rename` 目标已存在 | **`WinError 183`**（FileExistsError）——不是 1 |
| `os.replace` 目标已存在 | OK（覆盖语义） |
| `TimedRotatingFileHandler.doRollover()` 目标已存在 | **OK**（3.11 先 `os.remove(dfn)`） |
| 真实 emit 路径触发切割、目标已存在 | **OK** |

→ **"撞已存在目标 → WinError 1" 这条因果链是错的**。3.11 的 `doRollover`
（`C:\Python311\Lib\logging\handlers.py`）**自带** `if os.path.exists(dfn): os.remove(dfn)` 守卫。

### 真正的机制（两个版本行为不同，**这才是关键**）
| 解释器 | `doRollover` 撞已存在目标时 |
|---|---|
| **3.11（本机真机在用的那个）** | `os.remove(dfn)` 再 rename → **能切** |
| **3.13（托管版，本机不用）** | `if os.path.exists(dfn): return`（**"Already rolled over" 早退**）→ **不切、且不推进 `rolloverAt`** |

3.13 那条早退是**已知的 3.x 行为变更**；但**本机真机走 3.11，所以此路不通**。

### 现存的可观测事实（与诊断无关，是真问题）
- 程序目录 `ralsei_pet/logs/`：`.2026-09-07` … `.2026-09-15` **齐**，base 停在 **Sep 16 21:15**
- E 盘 `logs/`：只有 `.2026-09-16`（Sep 16 22:55）+ 一个来历不明的 `.old`；base `ralsei_pet.log`
  **仅 321 B、停在 Sep 19 16:18**
- 时间线：**Sep 16 21:15 日志目录由"程序目录"迁到"E 盘"**（第十二轮 vault 迁移）→
  E 盘**只成功切过一次**（`.2026-09-16`）→ 之后 **Sep 17/18/19 的日切文件全缺**
- 但 3.11 实测"能切" → 剩下的唯一解释是**当时 E 盘处于不稳定态**（铁律 §1.5「E 盘是外接盘、
  会掉线」）或**残留 `.old`/句柄争用**，属**运行时环境**问题，不是代码缺陷

### ★ 新踩的坑（两条，都是"能力自评失准"型，比能力不足更危险）

**坑 1：双向转发成环 → `RecursionError` 崩在构造期（真机抓到，G2 抓不到）**
- 第一版宿主侧 `__getattr__` 用 `hasattr(ctrl, name)` 探测控制器有没有该方法。
- 根因是一个被忽略的**时序事实**：`RalseiPet.__init__` **L405** 调 `init_movement()`
  → `randomize_movement_pattern()` → `getattr(self, 'game_state', {})`，
  而 `game_state` 直到 **L426** 才赋值。那一刻：
  `宿主__getattr__('game_state')` → `hasattr(控制器,'game_state')` →
  控制器回落 `getattr(宿主,'game_state')` → 回起点 → 无限递归。
- 修法：宿主侧改 `getattr(type(ctrl), name, None)`（**只看控制器类上定义的方法**，
  不碰实例属性）；控制器侧收紧为「名字在宿主实例字典里 **或** 在宿主类型 MRO 上」。
  两侧都成**显式白名单**，环不存在。
- **教训**：这是**构造期**崩溃（窗口根本起不来）。G2 里只有 16 个套件会 `RalseiPet()`，
  部分还是轻量桩 → **光靠 G2 抓到它的概率很低**。是自写的 `verify_w1_3_e2e.py` 抓到的。
  → **「方法体逐字等价」≠「产品还能跑」，两者必须独立证明。**

**坑 2：校验脚本假红 —— `refs()` 把「定义」与「引用」混算**
- 用属性名/裸名计数去断言"该方法只定义一次"，结果把控制器内部的
  `self.end_guess_number()` 三处**调用**也算成"定义"，报"实际 4 次"这种假红。
- 修法：拆 `defs_of()`（只数 `FunctionDef` 节点）与 `refs()`（数引用），严格分开。

**坑 3（附带）：反例控制 needle 未命中 → 假通过**
- needle 写 `"max_attempts"`（ASCII 双引号），源码里是 `'max_attempts'`（单引号）
  → `replace` 一次都没命中 → 篡改是**空操作** → "篡改后仍相等" → **反例控制假通过**。
- 修法：三段递进 —— 先断言 needle 命中 ≥1、再断言文本确实改变、最后断言判据判不等。

### ★★ 本轮踩了三条**真产品缺陷**，全部"逐字等价测不出来"
（源码一字未改，改的是"这个名字 / 这个 `self` 指向谁"。这是本项目**第四次**踩到
「方法体逐字等价 ≠ 产品还能跑」。）**全部由 e2e 探针抓到，unit 逐字等价当时全绿。**

**坑 1：`QRect` / `QTimer` 变未定义名字 → `NameError`**
方法体裸用这两个名字，在 `main.py` 靠**模块级**导入解析；搬走后作用域没了。
修：控制器顶部 `from PyQt5.QtCore import QTimer, QRect`（与 main.py 同款）。

**坑 2：`QTimer(self)` 语义变了 → `TypeError`**
宿主里 `self` 是 `QMainWindow`（Qt 接受做 parent）；控制器里 `self` 是 `object` →
`TypeError: argument 1 has unexpected type 'VideoController'`。
修：白名单改写 **`QTimer(self)` → `QTimer(self.p)`**（恰好 1 次，带命中断言），
语义完全保持（parent 仍是那个 `QMainWindow`）。
→ **通则**：`self.xxx` 是「**取出**宿主的值」（`__getattr__` 回落能救）；
`QTimer(self)` 是「**把控制器自己交出去**」（回落救不了，交出去的是 `self`）。
**搬任何方法前先搜 `f(self)` / `f(self,` 形态。**

**坑 3：`__setattr__` 缺失 → 状态被劈成两份（最隐蔽）**
`__getattr__` 只解决**读**。控制器里 `self.is_watching_video = True` 走
默认 `object.__setattr__` → 写进**控制器自己的 `__dict__`**。实测：
`host.is_watching_video == False` / `ctrl.is_watching_video == True`
→ 「看完视频」分支**永不触发**（宿主那份永远 False），而观看循环自己看到 True。
修：控制器实现 `__setattr__`，转发判据 = 「宿主**已拥有**该名字」
（`name in pet.__dict__` 或 `type(pet).__mro__` 上有）→ **未来新增属性名自动覆盖**。
⚠️ **必须跳过 `'p'`**（否则宿主引用被转发掉 → 全线崩）。

**坑 4（设计选择）：`_log` 必须是宿主模块的**同一个 logger 对象**
`_log` 是 `main.py` 模块级全局，两条回落白名单都不满足；自己
`getLogger('modules.video_controller')` 会**换 logger 名** → 文件落点/级别/格式都变。
修：加**普通方法** `_log_()`，从 `sys.modules[type(self.p).__module__]._log` 取同一个对象。
⚠️ 类体赋值不行（无 self）、`@property` 也不行（会挡住模块级 `_log`）。

**坑 5（坑 3 的直接推论）：新状态名必须预声明在宿主 `__init__`**
`video_watching_timer` 是**本轮才出现的新名字**，判据"宿主已拥有"不满足 →
首次赋值仍落控制器。修：`main.py` L1169 显式 `self.video_watching_timer = None`。
→ **通则：每搬一个方法，若它创建宿主尚不存在的新属性，必须同步加进宿主预声明区。**
