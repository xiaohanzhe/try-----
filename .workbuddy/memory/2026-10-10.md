### 1. 推送第101轮（用户口径：「我网络一直是好的啊，你继续就行」）
- 停等条件（"推送前停下等我确认网络"）**由用户本轮解除** ⇒ 直接推。
- **首跑"假成功"**：`gitpush.py --push-only` 输出全绿（`rc=0`、`ls-remote` 与
  `rev-parse origin/main` 双向一致、`=== 结论 = PUSHED ===`），**但远端纹丝不动**
  （`refs/heads/main` 仍是 `a473bc2`）。
- **根因两条（同一病根：写死）**：
  1. `gitpush.py` 第 39 行 `REPO` 硬编码 `C:\Users\23002\Desktop\项目文件夹\try - 副本`
     ⇒ 所有 git 调用的 `cwd` 指向**主仓库**，不是调用方所在的 worktree。
  2. push refspec 固定 `'main'`；本 worktree 分支是 **`workbuddy/main-a7556e9c`**
     ⇒ `git push origin main` 推的是**主仓库那个已同步的 main** ⇒ `Everything up-to-date`。
- **修**（提交 `e81b2df`，1 文件 / +31 / −2）：
  ① `_resolve_repo()` 从脚本自身位置向上找 `.git`（普通仓库下是目录、worktree 下是**文件**）；
  ② `PUSH_REFSPEC = 'HEAD:main'`（把当前 HEAD 推到远端 main，仍是快进、不强推）；
  ③ 新增自证日志 `[0r] REPO / branch / refspec`。
- **推送结果**：`a473bc2..e81b2df  HEAD -> main`，含两条提交
  （`3102d34` 第101轮主体 + `e81b2df` 工具修复）。
- **独立核验（不复用工具输出）**：`ls-remote ×3` 全 = `e81b2df`；
  `fetch origin main` 后 `merge-base --is-ancestor` 三个 sha
  （`e81b2df`/`3102d34`/`a473bc2`）**全 True**；`log a473bc2..FETCH_HEAD` 恰好两条。
- ❗★ **核验探针自己撒过一次谎**：漏给 `http.sslCAInfo`（脚本 `_base_opts` 里有）
  ⇒ TLS 失败、`fetch` 没落地 ⇒ 三条 `ancestor=False` **全是假阴性**，差点误判"没推上去"。
  ⇒ **"判据也是被测物"再次应验：报红先怀疑判据。**
