### Task #10 对话框抖动 + 滚动（提交 `024b6aa`，已推送并核验）
- 根因：`dialogue_ui.py` 里 `▼` 是**拼进正文 HTML 的内联字符**，宽度参与换行 →
  每 530ms 一次闪烁都可能让最后一行多占一行 → 文档高度变化 → `setFixedHeight`+`resize`
  → 整框高度来回跳（文字上下抖）；且闪烁走 `setHtml` 全量重建，重建把滚动条复位到顶部，
  旧的 `_last_scroll_max` 守卫在 maximum 未变时不再跟随 → 表现为"没法下拉看最新内容"。
- 修复：`▼` 改为 `_frame` 上的独立 `QLabel` 覆盖层（右下角，实测与正文视口右边界留 15px，
  4 角都在圆角内），闪烁只切可见性；`_refresh_display` 记录/恢复滚动位置（贴底才跟随，
  用户翻上去就保留）；拖动滚动条期间不抢位置；`resizeEvent` 重贴角。
- 关键实测结论（勿再摸索）：**QTextEdit 的样式表 `padding` 不影响 viewport 尺寸**，
  viewport 相对 widget 恒内缩 10px（+滚动条 14px）。所以别再靠 padding 预留"光标留白"。
- 验证：`code-quality-audit/第八轮/verify_round8_dialogue.py`（offscreen 真跑渲染管线，
  20 项断言）→ 挂进 G2 `round8_dialogue`。

### Task #11 建楼楼层判定（提交 `cc9471d`，已推送并核验）
- 根因：`main.py` 用 `new_floor != self.current_floor` 比较**两份 floor dict 的内容**判定
  "楼层有没有变"。floors 每轮由 `update_floors` 整体重建，`platform_height` 依赖当前可见
  窗口数量、`z_order` 随焦点变化 → 同一窗口重建出的 dict 必然不等 → 误判"换了楼板"→
  `start_fall("window_move")` 摔倒。同链还会走成"窗口→桌面"→ `start_falling()` 凭空掉到屏幕底。
- 另外两处同源缺陷：① `handle_gravity_fall` 落到屏幕底边后**没更新 `current_floor`** →
  下一秒又判成"窗口→桌面"的变化 → 每 1 秒凭空重复一次假坠落；② 落点判定也用 dict 内容比较，
  且把"桌面"当普通落点 → 从窗口上开始的坠落会在原地"悬停落地"（根本没掉下去）。
- 修复：新增 `_floor_identity_key`（窗口 hwnd / 'desktop'）/ `_floor_rect_changed` /
  `_follow_floor_move`；`check_window_movement` 重写为"先按 hwnd 找到脚下楼板的最新矩形
  → 按位移决定跟随/失足 → 再用稳定标识判断楼层是否真换"；`handle_jump` 里原有的局部
  `_floor_id` 统一到同一实现（去重）。落地后同步 `current_floor`；桌面移出"落地点"。
- 设计取舍（按"建楼要求"文档定）：**窗口→另一块窗口不再摔倒**（原文："我用新窗口盖住旧窗口
  = 又铺了一层新楼板，宠物现在站在新楼板上"）；只有"窗口→桌面（楼板真的没了）"才 `start_falling`。
  挪窗按位移两级阈值：<30px 只跟随、>30px 跟随+重心不稳摔倒、>400px 不跟随改为失足掉落。

  `check_window_movement`/`handle_gravity_fall`，16 项断言，含 AST 级"已无 dict 内容比较"）
