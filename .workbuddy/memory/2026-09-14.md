### Task #10 对话框抖动 + 滚动（提交 `024b6aa`，已推送并核验）
- 根因：`dialogue_ui.py` 里 `▼` 是**拼进正文 HTML 的内联字符**，宽度参与换行 →
  每 530ms 一次闪烁都可能让最后一行多占一行 → 文档高度变化 → `setFixedHeight`+`resize`
  → 整框高度来回跳（文字上下抖）；且闪烁走 `setHtml` 全量重建，重建把滚动条复位到顶部，
  旧的 `_last_scroll_max` 守卫在 maximum 未变时不再跟随 → 表现为"没法下拉看最新内容"。
- 修复：`▼` 改为 `_frame` 上的独立 `QLabel` 覆盖层（右下角，实测与正文视口右边界留 15px，
  4 角都在圆角内），闪烁只切可见性；`_refresh_display` 记录/恢复滚动位置（贴底才跟随，
  用户翻上去就保留）；拖动滚动条期间不抢位置；`resizeEvent` 重贴角。
- 关键实测结论（勿再摸索）：**QTextEdit 的样式表 `padding` 不影响 viewport 尺寸**，
  viewport 相对 widget 恒内缩 10px（+滚动条 14px）。所以别再靠 padding 预留"光标留白"。
- 验证：`code-quality-audit/第八轮/verify_round8_dialogue.py`（offscreen 真跑渲染管线，

### Task #12 斜抛轨迹 + 空中二次抓住 + 卡动画（提交 `654da19`，已推送并核验）

三条用户反馈：斜抛要由初速方向/大小决定、被甩飞时偶尔卡动画不继续、坠落中抓不住且像撞墙。

- **[1] 斜抛初速**：`mouseReleaseEvent` 删掉"把竖直分量强行掰向上"
  （`_vy = -350 - abs(_vy)*0.5`）——它让"横甩/下甩"全变成上抛，方向完全与松手无关。
  改为等比缩放 `_LAUNCH_SCALE=0.55` + 按**矢量和**限幅 `_MAX_LAUNCH_SPEED=1600`
  （逐分量限幅会把角度掰弯，必须用矢量和）。现在水平甩就是水平斜抛、下甩就直接往下走。
- **[2] 落点判定**：`_hit_launch = (_vy0_launch < 0 and _vy > 0 and _ny >= _launch_y)`。
  只有初速朝上才存在"升到最高点再落回起跳高度"；否则一路落到实心地面。
  配套新增 **`_fall_vy0`（只在飞行第一帧记录起跳竖直速度）** —— 原来每帧重读 `_fall_vy`
  （帧末被写成当前速度），下降段读到正数，"初速朝上"判定随之失效。
- **[3] 空中二次抓住**：新增 `_catch_falling_in_air()` + `_tick_catch_brake()`。
  `mousePressEvent` 先结束**两种**坠落状态，把接住瞬间线速度装进缓冲窗口，再按
  "速度线性衰减到 0 的积分"滑行：`v(t)=v0·(1-t/dur)` → `s(t)=v0·t·(1-t/(2·dur))`，
  终点总位移 `v0·dur/2`（700px/s → 105px）。`update_movement` 里在**拖拽保护之前**推进。
  - **反例（勿回退）**：曾误写 `s(t)=v0·t·(1-t/dur)` —— 那是"没积分"的速度式乘时间，
    轨迹成顶点在 `t=dur/2` 的抛物线，实测 `xs=[400,429,446,452,446,429,400]`：
    宠物先冲出去再**退回原地**。判据是"位移必须单调不减"。
- **[4] 状态互斥 / 卡动画**：
  - `start_fall`/`start_falling`/`trigger_splat` 三处都清 `is_gravity_falling`，
    不再"靠调用方记得清"；避免 `is_falling` 与 `is_gravity_falling` 同时为真 →
    永远走 `handle_gravity_fall`、`_fall_phase` 不再推进 = **永久停在 `jump_ball`**。
  - `check_window_movement` 在 `is_falling`/`is_gravity_falling`/`is_jumping`/拖拽 时提前 return。
  - `update_animation`：一次性动画**数不出帧**（`len(sprites[anim])==0`）时解除
    `_play_once_active` 并回落 idle，修掉动画永久冻结。
- **[5] 属性清理统一常量（本轮最有价值的防复发改造）**：落地/恢复三处清理点原本是
  **内联属性名元组**，新增 `_fall_vy0` 时三处全漏 → 第二次甩飞沿用上一轮起跳竖直初速 →
  下甩误判"要回到起跳高度" → 一路飞到 2.5s 兜底超时才落地（就是用户报的"卡动画"）。
  现在拆两个模块级常量：
  `_FALL_VELOCITY_ATTRS`（落地那刻清速度/落点标记，**必须保留 `_fall_phase`**，
  否则阶段机被重置回 flying 重新入场）与 `_FALL_STATE_ATTRS = ('_fall_phase','_fall_phase_start') + 上面那组`。
