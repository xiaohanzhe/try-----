- **并发 = 排队、零并行**：`OLLAMA_NUM_PARALLEL` 官方默认 **1**（纯 CPU）。

  ⇒ 每个 NPC 首次开口 58~107s**（27~29 ms/token × 人设长度）。

### 决定性的四条实测（推翻了 2 个原有认知）
1. **兼容端点 `/v1/chat/completions` 静默丢弃 `keep_alive`** —— 设 30m 与不传的 `expires_at`
   增量**完全相等**。⇒ 按直觉"把配置里的 keep_alive 调长"**什么都不会发生**。
   这是继 `num_ctx` / `repeat_penalty` 之后**第三个**被该端点丢掉的字段。
2. **`keep_alive` 黏在"模型载入实例"上 + 每个请求都给它续期**（静置 70s 真在倒计时：
   600→530→再来一个请求又回 600）⇒ **不需要周期心跳**，方案从"心跳"降成"**看门狗**"：
   只在新载入那一刻补设一次；用户走开就自然过期、内存自动归还。
3. **模型一卸载，前缀缓存全丢**：同前缀 冷 **55.79s** → 热 **0.149s**（**375 倍**）→ 卸载后 **61.07s**。
   这是保温值得接线的**唯一**依据。
4. **兼容端点不截断长提示词**（`usage.prompt_tokens` = 2371 == 原生 `prompt_eval_count` = 2371），
   且会回 `prompt_tokens_details.cached_tokens`（**冷 0 / 热 2370**）。
   ⇒ 顺带**更正了 `main.py:_ai_chat_options` 与 `ralsei_v4.modelfile` 里过期多年的
