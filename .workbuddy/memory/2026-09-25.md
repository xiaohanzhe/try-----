## 二十七、★ 收尾时修掉一个工具级死循环（`2f235e2`）

**症状**：每轮 push 完，工作区永远剩 1 个文件
（`第38轮/_evidence/提交推送日志.txt`）⇒ 逼出「为日志再提一次」的无限循环。
本轮实际多提了 **2 次**（`b8b97fa`、`e8780ef`）才发现是**工具问题**，不是"这轮没提干净"。

**根因**：`_tools/gitpush.py` 的 `LOG` **硬编码指向仓库内 tracked 文件**，
且每次运行用 `w` 模式**覆盖写** ⇒ **工具自己把仓库写脏**。

**修法（最小改动，不动既有语义）**：
- `LOG` 改落 `E:\Download\_tmp\`（不可用则退 `TEMP`）⇒ 仓库不再被工具写脏。
- 原 tracked 文件 `git rm --cached` 移出索引（**磁盘副本保留，不删**）。
- `.git/info/exclude` 加**本地**忽略（**不动仓库 .gitignore**，不影响协作者）。

**验证**：本次 push 后工作区**完全为空** ✅（死循环确已破）。

★ 教训一：**"每次收尾都剩一个文件"要怀疑工具**，不要当成自己的疏忽。
★ 教训二（本段亲身再踩）：用 `python -c` 内联含反引号的中文时，
  shell 会**执行反引号里的内容并把输出插进文本** ⇒ 必须 **Write 写脚本文件再跑**。
