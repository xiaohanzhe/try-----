# 2026-10-30 · 第120轮：UT 场景「空壳」补上画面（含一处自纠）

> 详版：`参考-契约与历轮（详版）.md` §120｜报告：`code-quality-audit/第120轮-ut场景背景与物件/_evidence/report120.md`

## 做了什么

承接 §115 / 第119轮 §18.7 登记的头号阻塞项：ut 的 358 个场景 `objects` 全空、
`bg` 全 null，走进去是纯黑空房间。

1. **定根因**：UT 的 `game.droid` 是 **GMS2** 结构。`room.Backgrounds` / `room.Tiles`
   是 GMS1.4 旧槽位，在 UT 里**恒为空** —— 之前所有脚本都在读它们，所以"永远空"。
   真数据在 `room.Layers`（背景层 / Assets 层 legacy tile / Instances 层）。
2. **取证**：ut `ROOM 338 / LAYER 2,667 / LBG 428 / SPR 481`；
   outertale `ROOM 358 / LAYER 2,798 / LBG 453 / LSP 76 / SPR 537`。
   房间实摆 tile：ut 68,863 块、ot 69,163 块。
3. **烘图** `bake120.py`：按 depth（大=靠后=先画）合成。四个坑见 §120.3，最狠的两个：
   `ExportAsPNG` 第三参 `includePadding` 必须 `true`（否则 44/137 张尺寸不一致）；
   `obj_overworldcontroller` 自绘 ⇒ 不加 `custom` 过滤会每间房左上角多一颗红心。
4. **接线** `apply120.py`：按**房间名**不按 id（20 个场景 id 是 338~357，不是 UT 下标）；
   只拷被引用到的图。产物 `bg/ut_*.png` 338 张 / 2.47 MB。
5. **渲染验证** `verify120_render.py` 11/0：走 `SceneAssetCache → Camera → plan_frame`
   真链路，不只看 JSON。
6. **回归锁** `check_bg120` 23 条，已进 G2。

## ★★★ 自纠：20 间 ut 场景被贴了 outertale 的图（已撤）

第二轮接线我用 `apply120.py --game outertale --only-missing` 给 ut 缺图的房间
补了外传同名图。**这个做法是错的**，当时没查就跑了。

事后取证（同一份 TSV）：

```
ut ROOM = 338 · ot ROOM = 358
ut ∩ ot = 338（ut 全含）· ut 独有 = 0 · ot 独有 = 20
```

⇒ outertale 的包 = UT 全部 338 间 + 自己独有 20 间。`_zone.ut.rooms.json` 的
358 个场景里，多出来的 20 个名字**在 UT 的 game.droid 里 0 命中** ——
它们是第77轮从跨作品大图 `bigmap66.json` 迁入时混进 ut 章的。

给它们贴外传像素 = 拿外传美术冒充原作画面 ⇒ 撤线（`bg: null` / `bg_source: "none"`），
删 20 张图（先落 sha256 清单到 `_evidence/ot20_manifest.tsv`，可用 `bake120.py` 重现）。

★ `revert120_ot.py` 自己栽过一次：`refs` 扫的是"尚未写回"的 json ⇒ 孤儿数恒 0 ⇒
20 张图会留下发霉。修法 `refs -= reverted`。**dry-run 抓到的。**

## 教训（写进长期）

1. **「资产 visible」≠「运行时可见」**：还要看 `Create_0` 的 `self.visible` 赋值
   （最后一条为准）与 `Draw_0` 有没有 `draw_self`。
2. **画外传的图当原作画面＝编造**。跨作品按名字对图之前，必须先证两个包的房间集合
   关系（本轮的 338/358/20 就是这么查出来的）。
3. **写入通道又坏了一次**（已有文件 `r+` 全拒、新建正常）：用工具层编辑绕过；
   `run_all.py` 的 `_out/*.txt` 先删再跑即可（新文件可写）。
