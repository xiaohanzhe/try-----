## 第143轮 · 对话链截断补 ASCII `.`（英文 NPC 不再被切成半个单词）

### 为什么做这一轮

第142轮结尾留的建议是「下一轮接 ①（`…` 当逗号），它是第140/141/142 连续三轮都指向的同一个洞」。
但那一轮顺手在 `measure142b.py` 里发现一个疑点：`END` 常量注释写
「与 `common113._sentences` 同口径（不含 `…`）」，而 `_sentences` 的正则里**明明有** `…`。
注释和实现相反 ⇒ 先核这个，再谈治不治。

### 核出来的第一件事：速查本那句令牌是错的

原句：`★ 数句子不含 …、切点含 …（两套标点）`。逐处读源码：

| 位置 | 字符集 | 含 `…` |
|---|---|---|
| `event_speech._SENTENCE_ENDS`（事件链 24/40） | `。！？!?` `\n` `…` | ✅ |
| `common113._sentences`（训练侧数句） | `[。！？!?…]+` | ✅ |
| `main._clean_ai_reply` 第 3 步（对话链 200/220） | `。！？!?` `\n` | ❌ |
| `extreme113.RE_SENT`（密度分母） | `[。！？!?；;\n]+` | ❌ |

⇒ 「数句子不含 `…`」是错的。**真正不含 `…` 的只有对话链那一处**。
这类"令牌记反"比记漏更危险：想"统一标点"的人会去改**事件链**（改错地方）。

### 真缺陷：不是缺 `…`，是缺 ASCII `.`

语料 77 人 / 5592 条，超 `max_chars`(200) 的 336 条（中 170 / 英 166）：

- `cut == -1`（一个切点都没有 ⇒ `t[:200]` **硬截**）：**中文 0 / 英文 61（36.7%）**
- 61 条尾字符**没有一条**是句末标点：`…'tty fragile in'` / `' such a tough '` / `'see beyond the'`

四变体（同一批 336 条）：

| 切点集 | 硬截 中/英 |
|---|---|
| `。！？!?\n`（原） | 0 / 61 |
| + `…` | 0 / 59 |
| **+ `.`** | **0 / 2** |
| + `…` + `.` | 0 / 1 |

⇒ 采用 `+ .`。**不加 `…`**：只解 2 条，却抢走 8 条本该切在 `。`、5 条本该切在换行的切点，
而 `…` 在语料里 97.4% 当逗号 —— 切在它后面就是半句话。两条链上限不同（24/40 vs 200），
**分叉是刻意的**（`B4`/`B6` 两头钉住）。

中文侧：切点落在 `.` 上的 15 条**全是真句末**（角色本来就在台词里夹英文）；
336 条里切在 `.` 上共 114 条，**疑似小数/缩写点 0 条**。
