# 2026-08-18 工作日志

## 修仙短片项目 — 桌宠动画帧 Bug 修复

### 问题
Ralsei 桌面宠物（PyQt5）的动画帧序/播放异常：walk 方向切换时动画从头开始、idle/laugh 等静止动画冻结在单帧不循环。

### 根因与修复（3 处，均在 `ralsei_pet/src/main.py`）

**Bug 1 — 重复的 `change_animation` 方法定义**
- 文件中存在两个 `change_animation` 定义（原行 4453 和 6009）。Python 后定义覆盖前定义，导致第一个（含同组帧保持 + 方向同步逻辑）成为死代码，第二个（始终 `current_frame = 0`）生效。
- 修复：将第一个方法的独有逻辑（`is_same_group` 帧保持、方向同步）合并到第二个方法中，删除第一个定义。
- 验证：`re.findall(r'def change_animation\(')` 结果为 1。

**Bug 2 — `update_animation` 中冗余的 `current_frame = 0`**
- `update_animation` 在调用 `change_animation` 后又显式执行 `self.current_frame = 0`，覆盖了 `change_animation` 内部的帧逻辑。
- 修复：删除两处冗余赋值（`is_same_category` 和非同类分支各一处），改由注释说明帧逻辑由 `change_animation` 内部处理。

**Bug 3 — 静止动画帧冻结**
- `_need_advance` 条件排除了 idle/laugh/dance 等静止动画组，使其进入 else 分支——该分支强制 `current_frame = min(1, frame_count - 1)`（即固定第 1 帧），并用 `_last_idle_frame` 跳过所有后续精灵更新。
- 修复：扩展 `_need_advance` 条件加入 `idle, laugh, dance, sing, wave, pose, smile, surprised, item, roll, victory, tea, hug, nuzzle, act, defend, attack, cry, fall`；else 分支改为显示 `current_frame` 而非强制帧 1；删除 `_last_idle_frame` 优化。
- 验证：`_last_idle_frame` 在文件中引用数为 0。

### 全面审查结论
对全文 8 处 `self.current_frame =` 赋值逐一审查，确认：
- 3 处在 `change_animation` / `__init__` 内部（正确）
- 2 处在 `update_animation` 帧推进/回绕逻辑（正确）
- 3 处在施法代码中（`current_frame = 0`，施法必须从第 0 帧开始，合理覆盖）
- **无更多冗余帧重置需要清理**

### 测试验证
- 语法检查通过（`py_compile`）
- `_last_idle_frame` 引用数 = 0
- `change_animation` 定义数 = 1
- 修复前测试：idle 状态 5 秒内帧变化 = 0（冻结）；修复后：帧变化 = 20（6FPS 正常循环）

### Bug 5 — interact_with_folder / interact_with_file KeyError 崩溃
- 活跃版本用 `file_info['name']` 直接索引，但调用方传入的 `element` 字典只有 `['type']` 和 `['path']` key
- 修复：改用 `.get('name', os.path.basename(path))` 安全访问

### Bug 6 — 后台线程 QCoreApplication.postEvent 误用
- `_async_api_request` 中后台线程用 `QCoreApplication.postEvent(self, lambda:...)` — postEvent 不接受 lambda，会在后台线程抛 TypeError
- 修复：改用 `QTimer.singleShot(0, lambda:...)` 正确跨线程调度

## 第三轮复检 — 功能性 Bug 修复

### Bug 7 — play_animation_once 机制完全失效 ✅
- `play_animation_once` 设置 `self.next_animation` 但全文无任何代码读取它
- 30+ 处调用点（wave/laugh/surprised/happy/dance/sing 等）的一次性动画在下一帧就被 `update_animation` 的状态逻辑覆盖
- 修复：
  1. `__init__` 添加 `_play_once_active`、`_play_once_frame_counter`、`_play_once_callback` 标志
  2. `update_animation` 中添加 `_play_once` 检查：播放期间跳过 `change_animation` 状态切换
  3. `_need_advance` 添加 `_play_once` 条件，并补充 `happy/sad/neutral/look_up` 动画组
  4. 帧推进后检测：播完所有帧后恢复 `next_animation` 并执行回调

### Bug 8 — move_to_edge_and_shrink UI 冻结 1 秒 ✅
- 50 步 × `time.sleep(0.02)` = 1 秒主线程阻塞
- 修复：重写为 `QTimer.singleShot(20, ...)` 非阻塞动画

### Bug 9 — 双情绪系统不一致 ✅
- `self.emotions`（旧，0-100）和 `self.emotion_system`（新，-100~100）独立运行
- `update_animation` 用旧系统的 `is_happy` 等标志，`update_animation_by_emotion` 用新系统，互相覆盖
- 修复：在 `update_emotion_decay` 末尾调用 `_sync_emotions_to_system()`，将旧系统值映射同步到新系统

### Bug 10 — _react_to_video() 方法未定义（AttributeError 崩溃）✅
- `_update_video_watching` 中 10% 概率调用 `self._react_to_video()` 但该方法从未定义
- 修复：创建 `_react_to_video` 方法（随机 8 种反应 + 对话 + 情绪变化 + 动画播放）

### Bug 11 — os.listdir 无 try/except（崩溃风险）✅
- 两处 `os.listdir(desktop_path)` 和一处 `os.path.getmtime` 无异常保护
- 修复：包裹 try/except，失败时返回空列表

### Bug 12 — _tick_spell_flow 静默吞异常 ✅
- 动画循环每帧调用的 `_tick_spell_flow()` 用 `except Exception: pass` 静默吞掉所有错误
- 修复：改为 `except Exception as e: traceback.print_exc()` 输出完整堆栈
