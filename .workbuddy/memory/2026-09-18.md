### 硬结论（6 条证据）
1. **E1 模型事实**：`ralsei:latest` = `qwen2.5:3b` 衍生（3.1B / Q4_K_M / ctx 32768）；
   `/api/show` 的 `parameters` 为 **None** → temperature/top_p/repeat_penalty/**num_ctx 全走服务端默认**。
2. **E2 决定性**：**App 自带 system 会整体替换 Modelfile 的 SYSTEM**（不是叠加）。
   实测 `prompt_eval_count`：不传 system = **1237**（2003 字角色圣经生效）；
   传 system = **41**。→ 用户写的角色圣经**从未生效过**。凶手：`main.py:7141-7158`。
3. **E3 窗口截断**：5400 字符长提示词 → `prompt_eval_count = 2050` ⇒ **num_ctx ≈ 2048**，
   而角色设定占 1237 → 历史/记忆必被静默截断。
4. **E4 A/B 受控实验**（同模型同问题同温度，只换提示词）：
   - **V0 现状：4 题中 3 题复读「你还好吗／要不要休息一下」** —— 源头就是现行 system 里
     把口头禅写成了示例，3B 直接当模板抄。**回看 2026-09-12 报告的 5 条实测回复，其中 3 条已带这句**
     —— 问题当时就在，只是被当成"自然"了。**这是本轮最重要的发现：上一轮"训练"自己埋的雷。**
   - V1 恢复角色圣经：有角色味但**把用户当 Kris、跑进剧情**（设定通篇绑定 Kris/Susie/黑暗世界），不能直接用。
   - V2 人味工程：质变，但 3B **照抄 few-shot 原句 + 跨示例串味**。
   - V3 V2+temp0.9：给出全场最好的两条（羞涩 + "只是觉得还不够好吗"的角色层次），
     但 Q3/Q4 **失控自问自答续写 + 跑旁白**，200 tokens 用满。
5. **E5 延迟**：常规 1.1~6.6s、长回复 11.5s、失控 15.8s；配 `stream: False` 假打字机
   → 用户先静止看 2 秒"……"，是"假人感"来源。
6. **E6 大部分台词没过 AI**：131 处写死 `add_dialogue`；**34 条子串硬拦截**排在 AI 之前

   `_build_ai_context()` 把【此刻】拼在**用户消息最前面**（`main.py:7133`）。

## 教训（本轮新增）
1. **别用 PowerShell 管道读模型的中文元数据**：`ollama show --modelfile` 经管道读出来全是 GBK 乱码
   （`浣犳槸涓€涓鑹叉壆婕?AI`），我一度误判"模型里的角色设定坏了"。
   改走 **Ollama REST API + 显式 UTF-8** 直读，确认 2003 字设定完好。**凡涉中文元数据，走 API 不经管道。**
2. **注入的 `current_time` 会滞后于系统真实时间**：本轮注入值写"2026-09-16 00:22"，
   `Get-Date` 实测 **2026-09-18 00:07**。**落盘前必须用 `Get-Date` 校准**，
   否则报告/日志文件名日期就是错的（本轮已 `git mv` 改名 + `--amend` 修正）。
3. **提示词里的"示例口头禅"对 ≤3B 模型是毒药**：会被当成必答模板复读。
   小模型的 few-shot 必须标"风格示范，不要照抄"并配输出护栏（去重/截断/重采样）。
4. **A/B 受控实验是判断"到底是模型不行还是接线不对"的唯一办法**：
   固定模型/问题/温度，只换提示词，一次就分清了。
5. **GitHub 主站会整段不可达而 `api.github.com` 仍正常**：
   此时 `git push` 必失败（9 次尝试 + 7 个备用 IP 全 000），但 **api.github.com 通**。
