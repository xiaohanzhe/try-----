## ★★★ 根治：push 真正的卡点 = **`git-credential-manager.exe` 挂住**（非网络、非体积）

1. push 60 分钟不返回、零输出（`| tail` 把进度也吞了）。
2. `ls-remote` **只要 1.7 秒** ⇒ **读路径健康**，问题在写路径。

### 逐帧定位（两张表，决定性）
- **schannel 卡点**：`== Info: schannel: remote party requests renegotiation`
  ⇒ Windows schannel 在 GitHub 中途重协商上**挂死**。（已记于铁律：改用 openssl 后端）
- **GCM 卡点（★ 真凶）**：`03:03:07` 解析 helper selector → **`03:04:05` 才启动 GCM**
  ⇒ **空转 58 秒**；随后 `git credential fill` **直接挂住不返回**（需交互式认证）。

### 修法（已验证：**4.1 秒推完 1.6 MB；26.1 秒推完 42 MB**）
用 Windows **CredReadW** 直接取出凭据管理器里已存好的 token
（target=`git:https://github.com`，user=`236837805`，`gho_...` 40 位），
再走 `-c http.extraheader=Authorization: Basic <base64>`
＋ `-c credential.helper=` ⇒ **完全不调用 GCM**。
脚本：`E:\Download\_tmp\push_token.py`（含 schannel→openssl、HTTP/1.1、postBuffer、脱敏打印）。

```bash
python push_token.py "<repo>" "HEAD:main"
# 内部等价于：
git -c credential.helper= \
    -c http.proxy=http://127.0.0.1:7897 \
    -c http.sslVerify=false \
    -c http.sslBackend=openssl \
    -c http.version=HTTP/1.1 \
    -c http.extraheader="Authorization: Basic <b64(user:token)>" \
    push origin HEAD:main
```
