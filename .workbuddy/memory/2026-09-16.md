### 三处硬伤
1. `_generate_floors` 用 `rect.contains(rect)` 判"被盖住" —— 那是**完全包含**；被遮 90% 的窗口仍算
   **一整块**可站楼板 → 宠物站在看不见的地方。→ 改**可见区域矩形相减** `visible_subrects`。
2. `get_current_floor` 只判 `rect.contains(pos)`、完全不看遮挡 → 站在被盖住的部分也算数。
   → 站立/下落/跳跃**全部**改判"点是否落在可见区域"。
3. **`main.py` 用 `Qt.WindowStaysOnTopHint` 强制置顶** → 遮挡关系**从渲染层就失效**（"根本没遮挡关系"的
   真正来源）。而 `floor_manager` 里 `get_insert_after_hwnd` + `set_window_behind`（`SetWindowPos` 把宠物
   插到所站楼板之上）**早就写好、全项目零调用**，是死代码 → 本轮接活，新增 `_apply_pet_z_order()`，
   4 处接线（1s tick / 落地 / `show()` 之后 / 松手）。**顺序铁律：`show()` 会"提到前面"，必须它之后再调。**

### 关键实现
- `_cut` 最多切 4 块且**产出天然两两不重叠** → 面积可直接求和（不需要去重/容差）。
- `MIN_FLOOR_VISIBLE_AREA = 40*40`：语义是**"够不够站"**而非"有没有缝"（1px 缝 1000px² 不成层，
  4px 缝 4000px² 成层 —— 故意如此）。
- `platform_height = (n-i)*5` **按名次**（最前 = 最高），桌面恒 0 层；可见面积跌破阈值 = 该层"暂时不存在"，
  **且它不再遮挡更低窗口**。
- `get_current_floor` **几何优先**；`WindowFromPoint` 只在几何判到桌面时做"**只向上**"的兜底
  （做成主判据会让 G2 变随机测试）。
- Windows 口径：DWM `DWMWA_EXTENDED_FRAME_BOUNDS`=9 取可见边框；`DWMWA_CLOAKED`=14 滤幽灵窗口；
  `WindowFromPoint`+`GetAncestor(GA_ROOT=2)` 防返子控件；**按进程排除自身**（原来靠标题含"Ralsei"→
  会误伤同名窗且漏掉本进程对话框）；排除 `WS_EX_TOOLWINDOW`/`WS_EX_NOACTIVATE`。
  **64 位坑**：`WindowFromPoint`/`GetAncestor` 的 `restype` 必须显式 `c_void_p`，否则 HWND 高位截断且**静默失效**。
- 删掉 `window['platform_height'] = z_order*5`（第二套编号口径）；`is_floor_valid` 不再要求四边逐一相等
  （DWM 1px 抖动会让楼板反复"消失" → 无故坠落）。
