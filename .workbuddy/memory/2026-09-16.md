### 挖出的三个问题（两个真 bug）
1. **间接初始化环（真 bug，顺序相关、潜伏）**：`logger_utils → data_store → memory_store → logger_utils`。
   先 `import data_store` 的进程里，`memory_store` 以**半成品**被回头使用 → `find_device_dir` 未定义 →
   `vault_root()` 误判"设备离线" → `data_root()` 降级中转站 → `logger_utils._log_dir()` **把错误结果缓存**，
   日志永久写在中转站（E 在线也一样）。第十二轮的 `_LazyLogger` 只断了**直接**环。
   修：新增 `modules/lazy_log.py`（共享惰性日志器，不 import 任何项目内模块），`memory_store` 去掉
   模块级 `get_logger`，`data_store` 同步改用共享类。
   真机 app **没被咬到**——`main.py` 第 21 行的 `from logger_utils import get_logger` 在 sys.path 设置
   （122–135 行）之前，必然 ImportError 走兜底；真正的 logger_utils 由第 138 行起的模块导入触发，
   即"先 logger_utils"（安全侧）。
2. **迁移落选留档（真 bug，实现与自身文档不符）**：`migrate_from_staging()` 在"**源比目标旧**"时只
   `skip`，而函数文档写的是"落选的那份挪成 `<名字>.old`"（只实现了"目标更旧→留档目标"）。
   后果：该文件**永远搬不走**、`staging_has_data()` 恒 True，"本地只作中转站"落空。
   真机撞上：`logs/ralsei_pet.log` staging 50317 / vault 更新版并存 → 被 skip → 中转站不空。
   修：源更旧时把源留档 `dst + '.old'`（校验长度）后删源，记入 `moved`（标 `-> .old`）。
3. **自检 C2 无鉴别力（测试缺陷）**：环境同时设 `RALSEI_DATA_DIR=<tmp>` 与 `RALSEI_MEMORY_DEVICE=off`
   → 正确(vault)与错误(中转站)路径**是同一个目录**，断言恒真 → 间接环漏网。
   修：用 `RALSEI_MEMORY_DIR` 模拟在线 vault 且路径**与中转站不同**，覆盖两种导入顺序。
   新增回归锁 **B19**（源更旧→落选留档）、**D11**（memory_store 不在 import 期 import logger_utils）、
   **D12**（lazy_log 模块顶层不碰 logger_utils）。自检 54 → **58** 项。

### 教训（已写进 MEMORY.md）
- **"底层模块一律用惰性 logger"** 要贯彻到底：只要链上**任何一环**在 import 期要 logger，环就还在。
- **回归锁必须有鉴别力**：断言两侧若可能同值，等于没测。做"正确/错误"断言时先问"如果坏了，这行会不会还是 True"。
- 判断外接盘在线看 `Win32_DiskDrive`/`Get-Disk`，别看注册表 `MountedDevices`（那是历史记录）。
