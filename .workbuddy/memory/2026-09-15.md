### 新增 `modules/memory_graph.py`（566 行 / 21 方法，本轮核心）
- 分层：`TIER_STRONG/MID/WEAK`，基数 `{strong:1.0, mid:0.55, weak:0.25}`，
  升档门槛 `_TIER_MIN_COUNT={strong:3, mid:2}`（count + 反馈量共同决定）；
  `edge_weight(edge, weak_penalty)`、`normalize_assoc()` 兼容旧的 int 字典与新 dict 格式。
- **hub 惩罚**：`node_weight = IDF × 度惩罚`，落在 `[0.25, 1.0]`；`refresh_df()` 全量重算 DF。
- **路径打分**：`paths()` 用带早剪枝的 DFS，得分 = Π(边权) × Π(节点权) × `HOP_DECAY^hops`（0.72），
  低于 `min_path_score` 立即剪；栈里带 `in_tier` 以支持中转资格判断。
- **PPR**：`ppr(seeds, budget, iters=6, alpha=0.15)` —— 固定迭代、**只参与加权、不参与准入**。
- `rerank()` MMR 式去重（`overlap_threshold` 0.6 / `max_per_day` 3）、`feedback(paths, success, lr)`
  用 `tanh` 压边权、`consolidate()` 离线巩固、`tune(metrics)` 按指标自调参数、`cap_keys()`。
- `RecallBudget` dataclass：`max_hops/max_nodes/max_edges_per_node/max_paths/max_candidates/max_ms/
  max_llm_calls/min_path_score` —— **预算是一等公民**，任何一环超预算即截断。

### 被实测修正的两处（本轮最有价值）
1. **静态 tier 门槛会把多跳整体锁死**：原 `HOP_TIER_FLOOR={1:weak,2:mid,3:strong}` 在真实语料
   （452/460 条是弱边）下只剩 hop=1，"写代码→咖啡"永远出不来。改为 `{1:weak,2:weak,3:mid}`
   + **中转资格**（`_BRIDGE_MIN_RANK=mid`：弱边**可以到达、不可以再出发**）。

   准入**永远**由路径分说了算。

### P0-2 建边拓扑：一次被自己实测推翻的"择优"（**本轮最大教训**）
- **第一步精确率实验**：11 句×7 seed 手标注真词表 → star 55%/0.83 边每点、chain 55%/0.86，**都优于 clique 50%/3.26**。直觉结论：换 star。
- **第二步多跳闸门实验（决定性）**：强制 `代码`与`咖啡`**从未同句**，靠 `熬夜` 当桥（`写代码写到熬夜了`/`熬夜就靠咖啡撑着`），三阶段×三拓扑：
  - clique：stage1(弱边 n=1) **no**（弱边不许中转）/ stage2(中边 n=2) **YES hops=2 score=0.1238** / stage3(强边) **YES 0.3196** → **PASS**
  - star / chain：**三阶段全 no，哪怕给到强边也断链** → FAIL
- **根因**：star 是"核心词↔其他词"，同句**非核心词之间无直连**；`代码`与`熬夜`若都不算核心词就没边，路径长度超跳数上限，强边也救不回。chain 同理。
- **决策：默认仍是 `clique`**。密度靠**输入端**压（抽干净词 + 分层 + hub 惩罚 + 路径分），**不靠砍边** —— 砍掉的多跳补不回来。
  `EDGE_TOPOLOGY='star'|'chain'` 保留为可切换实验档；模块头留档"它们为什么不被默认选用"，防下一轮凭直觉再改。

### C. 踩到的真坑：`logger_utils ↔ data_store` 初始化环（本轮最值钱）
- **症状**：`logs/` 解析到程序目录 `ralsei_pet/logs`，不是数据根。
- **根因**：`data_store` 顶层 `from logger_utils import get_logger` → `logger_utils` 初始化要解析日志目录 → `import data_store` → 此刻 `data_store` 还没执行完、`artifact_path` 不存在 → 抛错被吞 → 日志目录被**永久钉死兜底值**。
- **修法（双层）**：① `data_store` 改用**惰性日志器** `_LazyLogger`（`__getattr__` 才要 logger），import 期不再回头碰 logger，环直接断；② `logger_utils._log_dir()` **失败时不缓存**兜底值（只缓存成功），`_init_logging` 拆成"重入护栏外壳 + 实现"，防再次成环无限递归。
- **回归锁 C2**：子进程跑"先 import data_store"的顺序，断言日志目录仍落在数据根内（证据 `_evidence/round12_import_order.txt`：两种顺序一致）。

### D. 顺带纠正的错判（E 盘）
- 我上一轮说过 E 盘是"Fixed 固定盘、可安全当下载目录"。**不全对 —— 它会掉线。** 本轮施工途中它就从 `Get-Volume` 消失（只剩 C/D，`Get-Disk` 只有一块 NVMe）。所以"本地中转站"不是洁癖，是**可用性必需**：没有它 E 一拔程序就写不了数据。
